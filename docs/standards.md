# 규칙

## 원본과의 차이를 작게 유지한다

이 프로젝트는 원본(GenOffice)의 문서 엔진 개선을 계속 골라 받아온다.

- 코드 내부 이름을 바꾸지 않는다. 패키지 이름(`@genoffice/*`), 환경변수 이름(`GENOFFICE_*`), 코드 안의 식별자, 파일 이름이 대상이다. 바꾸는 것은 화면에 보이는 이름과 PC에 등록되는 이름뿐이다.
- 손대지 않아도 되는 줄을 건드리지 않는다. 줄바꿈·정렬·순서·이름을 정리 삼아 고치지 않는다. 지울 것은 지우고, 남는 코드는 글자 그대로 둔다.
- 화면 언어 파일을 지우거나 합치지 않는다. 언어 21개를 모두 유지한다.
- 문서 엔진 패키지의 동작을 바꾸지 않는다. 저장·내보내기 결과가 달라지는 수정이 필요해 보이면 멈추고 사람에게 묻는다.

## 글과 언어

- 코드, 주석, 커밋 글은 영어다. 영어가 아닌 글은 번역 자원(화면 문구, 도움말)과 사람이 읽는 문서에만 둔다. 검사: `npm run check:english-comments`.
- 화면 문구는 21개 언어 모두 채운다. 언어별 파일은 키가 서로 같아야 한다. 큰 사전은 언어별 조각 파일(`i18n/<영역>/<언어>.ts`)이고 `zh`가 키 목록을 정한다. 조각마다 `satisfies Record<keyof typeof zh, string>`이 붙어 있어, 키가 빠지거나 남으면 형 검사가 실패한다. 조각들을 다시 하나의 큰 객체로 합치지 않는다.
- `useI18n()`의 `t`를 훅 의존성 배열에 넣지 않는다. 참조가 매번 바뀌어 효과가 끝없이 다시 돈다. 키를 저장해 두고 그릴 때 번역한다.
- 한국어·영어 문구는 직접 쓰고, 나머지 19개는 번역으로 채운다. 영어를 그대로 복사해 채우지 않는다.
- 앱 안 도움말은 주제마다 21개 언어 파일이 있고, 모든 언어가 영어판과 같은 구조(제목 수, 표의 행 수, 목록 수, 그림과 링크)를 가져야 한다. 검사: `npm run check:help-langs`.

## 제품 이름

- 제품 이름은 `packages/i18n/src/product.ts` 한 곳에서 정한다. 다른 곳에 "IeumOffice"나 "이음오피스"를 직접 적지 않는다.
- 문구 파일과 도움말에는 제품을 `GenOffice`라고 적는다. 화면에 나갈 때 제품 이름으로 바뀐다(`brandText`, `createI18n`이 자동 적용). 번역 파일의 `GenOffice`를 한꺼번에 바꾸지 않는다.
- 번역 사전을 거치지 않고 화면에 나가는 글(창 제목, 메뉴, 사용자에게 보이는 AI 지시문, 뒷단의 오류 글)은 `brandText(글, 언어)`를 거친다.
- 원본의 이름을 글자 그대로 보여야 하는 곳(출처 표시)은 `{{GenOffice}}`라고 적는다. 도움말 본문에는 이 표기를 쓰지 않는다. 화면에 나간 도움말에 원본 이름이 보이면 검사(`apps/shell/tests/product-identity.test.ts`)가 실패한다.
- 설치 식별자, 실행 파일 이름, 등록 이름은 빌드 설정과 상수가 서로 맞아야 한다. 같은 검사가 지킨다.

## 원본 제작사 표기를 다시 들이지 않는다

- `npm run check:no-genspark`가 저장소의 추적 파일 전체에서 원본 제작사와 그 서비스의 표기를 찾는다. 허용 목록 밖에서 한 건이라도 나오면 실패한다. 원본 변경을 받아온 뒤에는 반드시 돌린다.
- 허용 목록은 좁게 유지한다. 지금 들어 있는 것: `LICENSE`, `NOTICE`, 파일 안의 저작권 고지 줄, 소개 문서의 출처 단락, 가리기 기능이 문서에 적는 이름공간 주소 한 줄, 엑셀 처리 프로그램의 임시 폴더 이름, 예전 설정 파일 시험 자료, 검사 명령의 이름 자체, 검사 도구와 그 테스트. 항목마다 이유를 도구 안에 적는다.
- `LICENSE`, `NOTICE`, 파일 안의 저작권 고지, "GenOffice를 바탕으로 만들었다"는 표시는 지우지 않는다.

## 문서 안에 저장되는 것은 바꾸지 않는다

- 저장된 문서 안에 들어가는 식별자(가리기 이름공간 주소 등)와 문서 곁에 저장되는 보조 파일 이름(`.genoffice-assets.json` 등)을 바꾸지 않는다. 바꾸면 원본 프로그램과 문서를 주고받지 못한다.

## 화면 색

- 화면 틀의 색은 토큰으로만 쓴다(`var(--surface)`, `var(--text)` 등. 정의는 `packages/ui/src/tokens.css`). 화면 CSS 규칙과 틀 관련 인라인 스타일에 `#hex`·`rgb()`를 직접 적지 않는다. 직접 값은 변수 정의 줄(`--x: #…;`)에서만 허용된다. 검사: `npm run check:theme-colors`(새로 고친 줄에 적용).
- 토큰을 새로 만들면 `tokens.css`의 세 묶음(밝게, 어둡게, 시스템 어둡게 대체)에 모두 넣는다.
- 강조색은 앱마다 따로다. 각 앱의 `styles.css`가 `--accent` 계열을 정하고, 공용 규칙은 `var(--accent)`를 쓴다.
- 문서 내용의 색은 테마가 다시 칠하지 않는다. 쪽 바탕, 셀 채움, 슬라이드 내용, PDF 쪽 그림, 내보내기·인쇄용 스타일, 차트 색, 형광펜 색, 도장, 워드아트, 마인드맵의 색(지도 테마와 색 띠)은 문서 자료다. 틀 토큰을 참조하지 않고, 저장·내보내기·인쇄 결과는 두 테마에서 같아야 한다. 어두운 쪽 보기는 화면 표시 단계의 색 바꾸기일 뿐이고 인쇄·내보내기에는 보이지 않는다.
- 캔버스에 그리는 편집 표시(선택 틀, 안내선, 손잡이)는 앱의 색 표(`canvas-colors.ts` 등)에서 테마에 맞는 값을 읽는다. 그리는 호출에 색을 직접 적지 않는다.

## 모듈 경계

- 화면(renderer)과 preload 코드가 `@genoffice/ai-provider`에서 **값**으로 가져오는 것은 브라우저용 진입점(`/browser`)뿐이다. 대표 진입점에서는 형(`import type`)만 가져온다. 프로그램을 실행하는 진입점은 뒷단에서만 가져온다.
- 편집기 전용 AI 창구는 이름 앞에 편집기 이름을 붙이고(`sheets:ai-…`, `slides:ai-…`), 껍데기 앱 안에서도 항상 불리는 등록 함수에 넣는다. 공용 이름(`ai:…`)은 워드 뒷단이 이미 등록하므로, 같은 이름을 다시 등록하면 실행 중에 죽는다. 원본에서 온 예외가 하나 있다. PPT 편집기는 `ai:generate-image`, `ai:analyze-media` 등 몇 개를 이름을 붙이지 않은 채 등록하고, 그래서 워드 편집기가 같은 일에 `docs:`를 붙인다. 새 창구에는 이 예외를 따르지 않는다.
- 구독 창구는 앱 뒷단에서 `ensureSubscriptionIpc`로만 등록한다. `registerSubscriptionIpc`를 직접 부르지 않는다. 같은 이름을 두 번 등록하면 실행 중에 죽는다.
- 실행해 둔 프로그램의 추적 시작(`initSubscriptionChildTracking`)은 프로세스에서 한 번만 한다. 껍데기 앱이 한다.
- 제공자를 정하는 곳은 `selectAiProvider` 하나다. 편집기가 자기 규칙으로 제공자를 고르거나 다른 제공자로 넘기지 않는다.
- 보내기 전의 판단은 `packages/ui`의 `aiSendGate`·`useAiSendGate`를 쓴다. 편집기마다 따로 만들지 않는다.
- 화면에 보이는 AI 실행 오류 글은 `packages/ui`의 `aiRunErrorText`로 만든다. 뒷단에 21개 언어 글을 새로 두지 않는다.
- 앱의 `dependencies`에 적은 작업 공간 패키지는 그 앱의 `externalizeDepsPlugin` `exclude` 목록에도 넣는다. 빠지면 설치본이 실행 직후 죽는다.
- 첨부할 수 있는 형식 목록은 `packages/file-parse`의 `attachable.ts` 한 곳에 둔다(`ATTACHABLE_EXTS`·`ATTACHABLE_IMAGE_EXTS`·`ATTACHABLE_MAX_BYTES`·`ATTACHABLE_IMAGE_MAX_BYTES`). 편집기마다 자기 목록을 만들지 않는다. 화면(renderer)은 Node에 묶인 `file-parse`를 값으로 읽을 수 없어서 그림 확장자만 각 앱의 몫으로 둘 수 있지만, 그 값은 모든 앱에서 같아야 한다.
- preload나 화면이 가져다 쓰는 `packages/electron-utils` 모듈이 Electron에 묶여 있으면(루트 진입점), `package.json`의 `exports`에 하위 경로로 내보내 그쪽으로만 가져온다. 루트 진입점을 preload·renderer 번들로 끌어들이지 않는다.

## 구독 연동에서 어기면 안 되는 것

- 구독 로그인 정보를 읽거나 복사하거나 저장하는 코드를 쓰지 않는다.
- AI 실행과 상태 확인에서 프로그램을 셸을 거쳐 실행하지 않는다. `spawnSubscriptionProgram`·`runSubscriptionProgram`을 쓴다.
- 요금 경로를 바꾸는 환경변수를 프로그램에 넘기지 않는다. 환경은 `subscriptionChildEnv`로 만든다.
- 테스트가 실제 `claude`·`codex` 프로그램에 닿지 않게 한다. 제공자가 `claude-code`나 `codex`로 정해지는 테스트는 연결부를 반드시 가짜로 바꾼다. 가짜로 바꾸지 않으면 테스트가 사용자의 구독 한도를 쓴다.
- 실제 구독으로 하는 확인은 필요한 횟수만 한다. 반복문이나 대량 호출로 시험하지 않는다.

## 의존성

- 의존성 라이선스는 허용 목록 안에서만 쓴다. 검사: `npm run licenses`.
- 잠금 파일은 `npm ci`로 그대로 쓴다. `npm install`은 이 PC의 npm 버전에서 잠금 파일을 불필요하게 바꾼다. 의존성을 실제로 바꿀 때만 쓰고, 바뀐 줄을 확인한다.

## 커밋과 가지

- 커밋 글은 영어, Conventional Commits 꼴이다(`feat(scope): …`, `fix(scope): …`, `refactor(scope): …`, `chore: …`, `docs: …`).
- 작업은 가지에서 하고, `main`으로의 병합은 사람이 정한다.
- 커밋 작성자 주소로 개인 이메일을 쓰지 않는다. GitHub의 비공개 주소를 쓴다.

## 합치기 전에 통과해야 하는 검사

```
npm run typecheck
npm run lint
npm run format:check
npm test
npm run licenses
npm run check:theme-colors
npm run check:english-comments
npm run check:help-langs
npm run check:skill-version
npm run check:no-genspark
```

- 새 동작에는 단위 테스트를 둔다. 테스트는 `<작업 공간>/tests`에 둔다.
- Windows에서는 원본 코드 그대로도 실패하는 테스트가 있다. 통과의 기준은 "손대지 않은 원본 사본에서 같은 테스트 파일을 돌렸을 때도 실패하는 것만 실패한다"이다. 원본 사본에서 통과하는 테스트가 하나라도 실패하면 통과가 아니다. 원본에서도 실패하는 테스트를 "고치려고" 관련 없는 코드를 바꾸지 않는다.
