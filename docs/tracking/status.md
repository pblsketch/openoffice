# 진행 현황

기준 버전: 0.12.3 (2026-10-22). 0.12.2 뒤의 main(AI 편집 자원 줄이기 #26, 로그인 창 안내 #27, 여러 개 선택 #28, PDF 미리보기 닫기 #29, PPT "글꼴이름 Bold" #30, 패치한 한글 엔진 #32·#47·결정 0050, 상표 고지 #33, 오래된 Claude 카드의 경로 #34, 마인드맵 글자 크기 #35·결정 0045, AI 연결 도우미 #36·결정 0047, 사용자 스킬 #46·결정 0048·0049, AI 입력 칸의 @문서·결정 0051, 저작권·상표 정비 #48·결정 0052, 외부 기여 #41·#42)에 엑셀 저장 결과를 먼저 열어 보기(#38), 한글 저장 형식 고르기(#39), 칸 안의 표 지우기(#40), Windows 기본 앱 등록(`RegisteredApplications`·`Capabilities`)을 `release/0.12.3`으로 합쳤다(#50). 이 PC(Windows)에서 합치기 전 검사 아홉 가지가 통과하고(lint는 저장소 코드 기준, 작업 사본의 `.dryforge/qa` 스크립트 제외), 단위 테스트의 실패는 손대지 않은 main 사본에서도 같은 개수로 실패하거나 따로 돌리면 통과하는 것뿐이다. CI의 test·e2e와 Mac·Linux 빌드가 통과했다. test의 docs `odt-open-save`는 편집기용 docx 사본을 두 번 만들어 비교하다가 ZIP 시각(2초 단위) 경계에서 한 번 어긋났고, 다시 돌려 통과했다. 2026-10-22에 `v0.12.3`을 프리릴리스로 올리고, 이 PC의 공식 0.12.2 설치본(베타 채널)이 0.12.3을 받아 "다시 시작 및 설치"까지 끝나는 것을 저장소 주인이 확인했다. 설치 뒤 기본 앱 등록이 레지스트리에 들어간 것도 봤다. 같은 날 Mac·Linux 파일을 붙이고 정식 최신 릴리스로 바꿨다.

이전 기준 버전: 0.12.2 (2026-10-20). 0.12.1 뒤의 main(화면 나누기·결정 0037, 빠른 미리보기, 열린 문서 첨부·결정 0035, 슬라이드 메모 읽기·결정 0039, 암호 걸린 엑셀·PPT 열기·결정 0041, 의견 보내기·결정 0036)에 슬라이드 설치 글꼴 수정(#19), read_url(#20, 결정 0040), PDF 읽기 도우미(#22, 결정 0043), 업데이트 창의 릴리스 본문(결정 0044)을 `release/0.12.2`로 합쳤다(#23). 이 PC(Windows)에서 합치기 전 검사가 통과하고, 단위 테스트의 실패는 손대지 않은 main 사본에서도 같은 개수로 실패하거나 따로 돌리면 통과하는 것뿐이다. Linux CI의 e2e가 통과했다. 빌드한 앱을 실제 마우스·키보드로 조작해 새 기능을 확인했고(실제 구독은 PDF 1쪽 번역과 링크 읽기 대화 한 차례), 그 과정에서 업데이트 창 본문의 빈 문단과 PDF "번역 나란히" 아이콘 크기를 고쳤다. 2026-10-20에 `v0.12.2`를 프리릴리스로 올리고, 이 PC에서 공식 0.12.1 설치본이 베타 채널로 0.12.2를 받아 "다시 시작 및 설치"까지 끝나는 것을 확인했다(권한 확인 창 없이 설치되고 앱이 스스로 다시 켜졌으며, 최근 문서와 설정이 남았다). 같은 날 Mac·Linux 빌드를 붙이고 정식 최신 릴리스로 바꿨다.

0.12.2 준비 기록 (2026-10-18). main에 탐색기·바탕화면·홈 파일 목록에서 스페이스바로 문서를 훑어보는 빠른 미리보기(Quick Look)와 HWP·HWPX·마인드맵의 "연결 프로그램" 아이콘, 그리고 여섯 편집기의 AI 창에서 열린 문서와 최근 문서를 골라 첨부하는 기능(결정 0035)을 합쳤다. 이 PC(Windows)에서 합치기 전 검사가 통과하고, 단위 테스트의 실패는 합치기 전 main에서도 같은 테스트가 실패하는 것뿐이며, lint 오류 하나(빠른 미리보기의 쓰지 않는 import)를 고쳤다. 설치 파일을 만들어 설치본으로는 아직 확인하지 않았다.

이전 기준 버전: 0.12.1 (2026-10-16). 0.12.0 뒤의 main(PDF 도구 1~3단계, HTML 슬라이드 목록, 무료 모델 두 개)에 오래된 Claude 카드(#7), 에이전트 모드(결정 0032)와 사이드바 진입점, Google 드라이브(결정 0033), ODT(결정 0034)를 `release/0.12.1`로 합쳤다(#16). 이 PC(Windows)에서 합치기 전 검사 아홉 가지가 통과하고, 단위 테스트의 실패는 원본 사본에서도 실패하는 것, Chrome이 없거나 생성 시험 파일이 없어 생긴 것뿐이다. Linux CI의 단위 테스트와 e2e, macOS 빌드가 통과했다. 공개 설치 파일은 Google 클라이언트 값 없이 만들어 드라이브 기능이 들어 있지 않다(결정 0033의 "공개 시점"). 설치본으로 `.odt` "연결 프로그램"과 0.12.0에서의 자동 업데이트는 아직 확인하지 않았다.

이전 기준 버전: 0.12.0 (2026-10-15). 무료 AI 연결, PDF 구조·변환·AI 읽기·번역, 슬라이드 디자인 템플릿, 마인드맵(2단계), 한글 편집기를 한 가지(`release/integration`)로 합쳤다. 합친 가지에서 전체 검사가 통과하고, 테스트는 원본 코드나 각 가지에서도 실패하던 것과 동시에 돌릴 때만 시간 초과로 실패하는 것뿐이다(따로 돌리면 통과). 모든 편집기가 빌드되고, 서명 없는 설치 파일(`IeumOffice-Setup-0.12.0.exe`)이 만들어진다. 2026-10-15에 GitHub 릴리스 `v0.12.0`(제목 "v0.12.0 (베타)", 정식 최신 릴리스)으로 공개했다. 저장소 주인이 빌드한 앱을 설치 없이 띄워 편집기들을 확인했다. 구독 로그인을 창 없이 브라우저에서 하는 방식(결정 0029)은 실제 계정으로 확인하지 않은 채 나갔다.

## 남은 것 (순서대로)

0. **Google 드라이브 연결(결정 0033, 가지 `feat/google-drive`).** 코드와 단위 테스트, 21개 언어 문구, 문서는 됐다. 남은 것: 저장소 주인의 Google Cloud 프로젝트와 시험 단계 클라이언트(`docs/operations.md`의 "Google 드라이브 준비하기"), 그 클라이언트로 실제 계정 확인, Google 앱 검증 신청. 검증 전에는 공개 설치 파일에 넣지 않는다. `main` 병합은 저장소 주인이 정한다.

1. **사용자 스킬과 에이전트 창 웹 기준의 확인 마무리(결정 0048, 0049).** 빌드한 앱(격리한 데이터 폴더)에서 실제 구독으로 확인했다(2026-10-22). 워드 AI 창: Claude로 칩을 붙여 보내기(문서에 한 번만 들어감), 말로 스킬 만들기 → 비운 양식 미리보기 탭 → 저장, 칩 없이 부탁했을 때 AI가 스스로 스킬을 쓰고 대화에 표시와 양식 단추만 남김, 단추로 연 양식 사본을 새 탭에서 채우기, Codex로 칩 보내기(웹 검색 꺼짐·자체 스킬 안내 꺼짐으로 실행). 에이전트 창: Claude의 `/` 칩·웹 검색 허락 카드·세션 동안 허락·스킬 만들기 카드와 양식 고르기 칸·저장, Codex의 저장된 결과·실시간 웹 검색, 명령의 인터넷 켬(응답 200)과 끔(실패), 프로젝트 폴더마다 설정 기억. 중단·정상 종료·강제 종료 뒤 앱이 띄운 `claude`·`codex`가 남지 않았다. 확인 중에 고친 것: 에이전트 창의 보낸 메시지 칩이 기본 스킬의 번역 제목 대신 영문 이름으로 보이던 것, 세션 동안 허락을 눌러도 이미 떠 있던 같은 종류의 질문이 남던 것, Codex 검색 줄에 검색어가 비던 것, 스킬 제안 도구가 "열린 문서 고치기"로 보이던 것. 남은 것: 에이전트 창의 설치 제안 카드, 양식을 골라 저장하는 에이전트 카드와 그 비운 양식, 워드 밖 일곱 편집기에서 칩을 붙여 보내기.

2. **첫 릴리스(0.12.0)의 확인 마무리.** 공개는 끝났다. 창 없는 구독 로그인을 Claude·Codex 실제 계정으로 한 번씩 확인한다. 첫 릴리스에서 실제 자동 업데이트(내려받기 → 재시작 → 설치)를 확인하고, 릴리스 절차 문서의 "확인 필요" 표시와 소개 문서의 해당 한계 문장을 지운다. 릴리스 전에 설정의 로그아웃과 다른 계정으로 로그인 버튼을 실제로 한 번 눌러 확인한다.
3. **도움말 그림 다시 찍기.** 없어진 화면을 담은 그림 10장을 본문에서 빼 둔 상태다. 빌드된 앱으로 다시 찍고 21개 언어 본문에 다시 넣는다. 구독 연결 주제에는 그림이 아직 없다.
4. **마인드맵과 새 문서 만들기의 마지막 확인.** 이 앱이 저장한 지도(새 파일, 제목을 고친 것, 가지를 옮기고 지운 것, 테마를 고른 것, 미리보기 그림이 없는 것)가 XMind 웹 앱에서 열리는지 본다. 실제 구독으로 여섯 가지(지도 편집, 문서 → 지도, 지도 → PPT, 워드·PDF → PPT, 지도 → HTML, 긴 자료 → PPT)를 한 번씩 확인하고, 긴 자료로 만든 PPT가 충분한지는 사용자가 판단한다. 설치본에서 `.xmind`를 열어 고치고 저장한다. 브랜드 그림, 테마 96가지의 고르는 화면, 주요 화면을 사용자가 승인한다.
5. **가리기의 남은 길.** 워드 문서(다른 파일로 읽을 때 닫힌 쪽으로 실패하는 안이 제안됨), PPT 편집기와 마크다운 편집기에서 표시 없이 저장되는 두 경우, `.txt`·`.json`으로 저장한 마크다운, 터미널 명령어와 MCP의 읽기. 앞의 넷은 사용자의 결정을 기다린다(`findings.md`).
6. **Codex 구독으로 이미지 만들기.** 로그인 파일을 건드리지 않는 방법으로만 넣는다. 이미지 도구가 있는 요금제의 계정으로 다시 확인해야 한다.
7. **PDF 새 기능의 확인 마무리.** 빌드한 앱에서 확인한 것: 변환 창의 범위 오류, Markdown 변환 뒤 탭 열기, EPUB 저장과 폴더 열기, 그림만 내보내기, AI 페이지 읽기의 페이지 고르기·요금 안내가 있는 확인 창·검색의 "AI로 읽은 글에서 찾음"·이어하기 제안, 번역 창(아랍어에서 PDF 형식 막힘)·확인 창·지금까지 반영해 내보내기. 실제 구독(Claude, haiku)으로도 확인했다: 스캔 페이지 1쪽 AI 읽기와 검색, 2쪽 문서의 한국어 번역(Markdown과 PDF, 7개 블록 모두 번역), 번역 멈추기와 앱 종료 뒤 앱이 띄운 `claude`가 남지 않음. 남은 것: 변환 중 취소를 앱에서 직접 해 보기(지금은 단위 테스트로만 확인), 멈추기 직후 몇 초 안에 `claude`가 끝나는지 재 보기(확인 때는 약 40초 간격으로만 봤다).
8. **PDF 새 기능의 남은 것.**
   - 로컬 OCR 모델로 페이지 읽기(pdf-craft의 DeepSeek OCR 같은 것). 이번 범위에서 뺐다.
   - EPUB 열기와 번역. 지금은 EPUB을 쓰기만 한다.
   - 워드 변환의 수식(OMML). 문서 엔진(`docx-engine`)을 고쳐야 해서 따로 승인이 필요하다.
   - 대역 PDF. 대역은 Markdown·EPUB에만 있다.
   - 새 기능(변환, AI 페이지 읽기, 번역, 보관소)의 앱 안 도움말 주제.
   - 다른 이름으로 저장한 사본과 영구 가림 사본이 보관된 결과를 옮겨 받지 못한다. 앱 안 "저장"만 옮긴다.
   - 라틴 문자 문서의 기본 목표 언어. 문서 언어를 문자 체계로만 추정해 프랑스어·독일어 문서도 영어로 읽고, 화면 언어가 영어면 기본값이 영어 문서와 같아진다. 번역 창에서 바꿀 수 있다.
   - 아랍어·히브리어·힌디어 번역 PDF. 번역문을 PDF에 배치하지 못해 고를 수 없게 해 두었다. Markdown·EPUB은 된다.
   - 페이지 범위를 고른 번역 PDF가 모든 페이지를 담는다. 고른 페이지만 번역되고 나머지는 원본 그대로다.
9. **한글 편집기의 다음 단계.** 표 안의 표에 행·열 넣기와 표 칸 안에 표 넣기(rhwp 0.8.7에 표 칸을 가리키는 표 만들기·행 넣기 호출이 없고, 편집기 자체도 칸 안의 표 만들기를 막는다. 엔진을 고쳐야 한다), 암호 문서를 암호를 지킨 채 저장하기, 한컴 글꼴이 없는 PC에서의 조판 확인과 OFL 글꼴 넣기, 암호 문서를 암호를 받아 읽기, 큰 표 문서를 읽을 때 메인 프로세스가 기다리지 않게 하기(지금은 파일 색인만 작업자 스레드에서 읽는다).
10. 그 밖에 미뤄 둔 것: 유료 코드 서명(Mac판의 자동 업데이트도 이것을 기다린다), Intel Mac·Linux 배포, 한글 글꼴을 자체 저장소로 내려받게 하는 것. 디자인 템플릿 쪽에서는 이미 있는 슬라이드를 다른 템플릿으로 바꾸기(다시 그리면 발표자 메모·메모·전환·링크·개체 틀이 사라지고, 넣어 둔 그림을 옮기지 못하고, 실행 취소 기록이 50단계라 되돌리기도 어렵다), 원본의 나머지 템플릿 22개, 앱 안 도움말, 마크다운·HTML·PDF 편집기의 템플릿 글꼴.
11. 마인드맵과 새 문서 만들기의 다음 단계: XMind 테마 읽기, 표식 붙이기, 경계 그리기, 그림 넣기, 개요 보기, 예전 XMind 8 형식 가져오기, 워드·마크다운으로 만들기, 긴 자료의 품질 개선, 터미널 명령어의 `.xmind`, 마인드맵 도움말(21개 언어), 다시 만들기.
12. **Mac 베타(결정 0031)의 남은 확인.** 첫 빌드는 통과했고 v0.12.0 릴리스에 올렸다. Mac 사용자 한 명이 설치·실행과 AI 구독 연결이 된다고 알려 왔다(2026-10-15, 기기 사양은 모름). 다른 한 명은 설치된 Claude가 2.1.237로 최소 버전(2.1.248)보다 낮아 "버전이 낮습니다"가 떴다. 무엇을 할지 알기 어려워, 그 카드가 찾은 버전·최소 버전·`claude update`를 함께 보여 주게 고쳤다. 아직 보고가 없는 것: 앱을 끈 뒤 남는 프로세스, Windows와 주고받은 문서, 한글 문서의 글꼴, 스캔 PDF 글자 인식, 다음 버전에서의 새 버전 알림. 보고가 오면 여기에 적는다.

13. **에이전트 모드(결정 0032)의 확인 마무리.** 실행부, 세션 관리, 세션 MCP 서버, 에이전트 창이 들어갔다(가지 `feat/agent-mode`). 빌드한 앱에서 실제 구독으로 확인했다(2026-10-15). Claude·Codex로 시작 → 명령 허락 → 열린 워드 문서 고치기 → 창 닫기 뒤 프로세스 정리, Codex로 열린 엑셀·PPT 고치기와 새 파일 열기까지 됐다. 도움말 주제 "에이전트 모드"(21개 언어)도 들어갔다. 남은 것은 `main` 병합 판단과, Claude `auto` 모드·MXC가 없는 PC의 실제 확인이다. 풀리지 않은 문제는 `findings.md`의 "에이전트"로 시작하는 항목들이다.
14. **ODT 연결 프로그램 확인.** 0.12.2 설치본에서 `.odt`·`.hwp`·`.hwpx`·`.xmind`의 "연결 프로그램" 목록(`OpenWithProgids`)에 이음오피스가 형식별 아이콘과 함께 들어가고, 기본 프로그램(`UserChoice`)은 바뀌지 않는 것을 레지스트리로 확인했다(2026-10-20). 남은 것: 탐색기에서 오른쪽 단추로 골라 워드 탭으로 열리는지 눈으로 한 번.
15. **PDF·마크다운 편집기에 첨부 넣기.** 지금은 두 편집기에 파일 첨부 자체가 없어 "이음오피스 문서에서 첨부" 단추(결정 0035)도 없다. 다른 여섯 편집기처럼 첨부 읽기와 단추를 넣는다. 그리고 결정 0035의 "이음오피스 문서에서 첨부"를 빌드한 앱에서 여섯 편집기의 화면으로 한 번씩 눌러 확인한다.

16. **의견 보내기 설문(결정 0036).** 설문을 저장소 주인 계정으로 만들어 게시했고, 문항 넷(객관식 필수·장문형·단답형·단답형)과 설명(이미지는 `pblsketch@gmail.com` 으로 메일 안내), 겉모습(사이트의 `form-banner.png` 배너, 테마 색 `#4338ca`, 배경 `#ecebfa`)을 채웠으며, 주소를 `apps/shell/src/main/feedback.ts`에 넣었다. 코드·문구·배선은 `tests/feedback.test.ts`가 지킨다. 남은 일: 실제 빌드에서 도움말 메뉴와 설정 → 정보로 설문이 열리고 클립보드의 세 줄이 붙여 넣어지는지 확인한다.

17. **화면 나누기의 손 확인.** 2026-10-20에 빌드한 앱에서 실제 마우스로 ③ 탭을 오른쪽 끝에 끌어 나누기·구분선 끌기와 ④ 탭 우클릭의 "나누기 풀기"를 확인했다. 남은 것은 ①·②다. 자동 시험(`e2e/split-view.spec.ts`)이 끌기 API로 나누기·초점 역할 전환·사본 만들기·복원·겹쳐 저장 확인을 덮는다. 빌드한 앱에서 손으로 남은 것: ① 비포커스 칸의 진행 중 AI 실행이 접힘·복귀를 견디는지, ② 슬라이드 쇼(전체화면)가 두 칸을 덮었다가 끝나면 복원되는지, ③ 구분선을 실제 마우스로 끌어 비율 바꾸기·반반·한쪽 닫기, ④ 탭 우클릭 메뉴의 나누기·풀기(자동 시험은 끌기 API와 소스 검사로 대신함).

18. **read_url의 빌드한 앱 확인(결정 0040).** 2026-10-20에 main에 합쳤고, 빌드한 앱의 PDF AI 창에서 공개 링크 읽기 한 차례(도구 카드 "완료 · 1단계")와 명령줄의 GitHub blob→raw 변환·사설 주소 거절을 확인했다. 남은 것: 비공개 저장소 토큰, 토큰 없을 때의 안내, 그림 주소 거절. 이 기능 가지가 main에 병합되면, 빌드한 앱의 AI 창에서 공개 스킬 링크 읽기, 설정의 GitHub 읽기 토큰으로 비공개 저장소 읽기, 토큰 없이 같은 링크에서 나오는 안내, 사설 주소·그림 주소 거절, 도구 카드 문구를 눈으로 확인한다(AI 창 항목은 채팅 차례를 한두 번만 쓴다). 명령줄로는 이미 확인했다.

19. **한글 문서의 겹침 수정(결정 0050).** 쪽·종이 기준 어울림 제목 표와 같은 문단의 글자처럼 취급 표("학습목표" 상자)가 겹치던 것, 쪽이 바뀌는 문단 뒤의 그림이 앞 쪽 본문 위에 그려지던 것, 마지막 본문 줄이 각주와 겹치던 것을 엔진 패치로 고쳤다(가지 `fix/hwp-wrap-overlap`). 이어서 제목 표 아래에서 시작하는 쪽을 저장 위치대로 그리고(제목 표 다음 문단의 상자가 제목 표를 덮던 것), 예전 한글이 두 줄로 저장한 제목 문단을 한글 2024처럼 합치고, 생성 문서의 긴 각주를 그리는 높이로 예약하는 패치 다섯 개를 더했다. `main`에 합친 뒤(#32) 빌드한 앱에서 신고한 두 문서를 다시 열어 보다가, 국어과 최종안의 Ⅴ·Ⅵ장 제목 쪽에서 제목 두 벌이 겹쳐 보이는 것을 찾아 표의 셀 영역 배경을 병합 칸 끝까지 칠하는 패치를 더했다(모두 아홉). 한글이 쪽마다 저장한 문서의 긴 각주 쪽은 일부 남았다. 엔진은 `vendor/rhwp-core`에 빌드해 두었고, 첫 번째 수정을 상위 rhwp에 PR로 냈다([edwardkim/rhwp#8121](https://github.com/edwardkim/rhwp/pull/8121), 한컴 2024 인쇄 PDF 대비 Native 93.55%·WASM 93.27%). 4·8번은 [#8144](https://github.com/edwardkim/rhwp/pull/8144), 9번은 [#8145](https://github.com/edwardkim/rhwp/pull/8145)로 냈다. 2026-10-23 같은 교재의 머리말이 잘린다는 신고로, 머리말·꼬리말의 종이·쪽 기준 표와 글상자를 그 틀에서 재는 패치와 바탕쪽 없는 구역이 앞 구역 바탕쪽을 잇는 패치를 더했다(모두 열하나, 가지 `fix/hwp-header-footer-frame`). 꼬리말 표·글상자도 같은 결함이 있었다. 10·11번은 상위에 아직 내지 않았다. 남은 것: 상위 PR의 결과에 따라 패치 정리. 풀리지 않은 차이는 `findings.md`의 "한글 엔진"으로 시작하는 항목이다.
