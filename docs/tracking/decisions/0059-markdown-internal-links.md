# 0059 — 마크다운 편집기에서 내부 링크를 따라가고, 위키링크는 글자로 둔 채 화면에서만 꾸민다

## 맥락

마크다운 편집기는 링크를 눌러도 아무 일이 없었다. 편집 중 클릭은 글자 고치기이고(`openOnClick: false`), 새 창 요청은 웹·메일 주소만 바깥 브라우저로 열고 나머지는 막았다. 그래서 `[글](다른노트.md)`, `[글](#제목)` 같은 문서 사이 링크는 쓸모가 없었다.

Obsidian 등으로 쓴 노트에는 위키링크(`[[노트]]`, `[[노트#제목|별칭]]`)와 그림 임베드(`![[그림.png]]`)가 많다. 편집기는 이것을 그냥 글자로 다루고, 저장할 때 `\[\[`로 바꾸지 않게만 해 두었다.

## 결정

- **`Ctrl+클릭`(Mac은 `⌘+클릭`)으로 링크를 따라간다.** 그냥 클릭은 지금처럼 글자 고치기다. `Ctrl`을 누르고 있으면 링크 위에서 손가락 모양이 된다.
  - `#제목`, `[[#제목]]`: 같은 문서의 그 제목으로 간다. 제목 글자 그대로(대소문자·공백 무시)를 먼저 맞추고, 다음으로 GitHub식 앵커(`two-words`)를 맞춘다.
  - 웹·메일 주소: 지금처럼 뒷단의 `safeExternalUrl`을 거쳐 바깥 브라우저로 연다. 그 밖의 주소 형식(`file:`, `obsidian:`, `javascript:` 등)은 따라가지 않는다.
  - 상대·절대 경로(`[글](../a/b.md#제목)`): 이 탭이 연 파일의 폴더를 기준으로 푼다. 확장자가 없으면 `.md`도 찾아본다.
  - 위키링크(`[[노트]]`, `[[폴더/노트]]`, `[[파일.pdf]]`): 노트의 보관함에서 찾는다. 보관함은 노트 위로 올라가며 처음 만나는 `.obsidian` 폴더가 있는 곳이고, 없으면 노트의 폴더다. Obsidian처럼 이름만으로 보관함 어디에서든 찾고, 같은 이름이 여럿이면 노트와 폴더를 더 많이 공유하는 것, 그다음 얕은 것을 고른다. 확장자가 없으면 `.md`를 붙여 찾는다(`[[그림.excalidraw]]`는 `그림.excalidraw.md`도 찾는다). 숨은 폴더는 보지 않는다.
  - 찾은 파일은 껍데기 앱의 문서 라우터(`openDocumentPath`)로 연다. 이미 열린 탭이면 그 탭으로 가고, 편집기가 맡지 않는 형식이면 라우터가 "지원하지 않는 형식"을 알린다. 프로그램을 실행하는 길(`shell.openPath`)은 쓰지 않는다.
  - 링크에 제목이 있고 대상이 마크다운이면, 그 파일을 보여 주는 탭에 제목을 한 번 맡기고 알린다. 탭은 화면 배치가 끝난 뒤 그 제목을 화면 위쪽으로 올린다.
- **경로는 뒷단만 만든다.** 화면은 링크 글자만 보낸다. 뒷단이 그 탭에 허가된 파일을 기준으로 경로를 풀고, 길이 상한(4096자)을 넘는 글은 받지 않는다.
- **네트워크 경로는 건드리지 않는다.** `\\서버\공유`, `//서버` 꼴은 파일이 있는지 보는 것만으로도 Windows가 사용자의 로그인 정보를 그 서버로 보낼 수 있다. 링크 글자가 그렇거나 푼 경로가 그렇게 되면 바로 거절한다. 노트 자신이 네트워크 폴더에 있으면 보관함 검색을 하지 않는다.
- **위키링크는 문서에서 글자로 남는다.** 편집기는 ProseMirror 장식(decoration)으로만 링크 모양을 입힌다. 새 문서 노드를 만들지 않으므로 저장(`sourceSplice`)과 전체 직렬화는 위키링크를 보지 못하고, 고치지 않은 블록의 바이트는 그대로다. 코드 칸과 코드 블록 안의 `[[…]]`는 꾸미지 않는다. 글을 고칠 때는 바뀐 최상위 블록만 다시 훑는다.
- **`[[`를 치면 보관함의 노트(`.md`) 목록이 뜬다.** 이름 앞부분이 맞는 것 → 이름 안에 든 것 → 경로에 든 것 순이고, 50개까지다. 넣는 글은 이름이 보관함에서 하나뿐이면 이름, 아니면 보관함 안 경로다. 고르면 `[[이름]]`이 글자로 들어간다. 제목 없는 노트에는 목록이 없다.
- **보관함 목록은 잠깐 다시 쓴다.** 파일 목록은 10초 동안 다시 쓰고, 2만 개에서 멈춘다. 링크가 목록에서 찾지 못하면 목록을 한 번 새로 만든다(방금 만든 노트).
- **그림 임베드(`![[그림.png]]`, `![[그림.png|300]]`)는 글자 뒤에 그림을 보여 준다.** 그림 확장자만 받고, 보관함 안(링크를 따라간 실제 경로 기준)에 있는 20MB 이하의 파일만 보여 준다. 뒷단은 푼 그림의 실제 경로를 그 탭에 허가하고, `md-asset://`는 문서 폴더 안의 그림에 더해 이렇게 허가된 그림도 내보낸다. 탭이 닫히면 허가가 사라진다. 그림은 화면에만 있고 문서에는 들어가지 않는다. 노트를 다른 곳에 저장하면 다시 찾는다.
- **AI 도구에는 이 기능을 주지 않는다.** 링크를 여는 것은 사람의 `Ctrl+클릭`뿐이다.

## 택하지 않은 것

- **위키링크를 새 문서 노드나 표시(mark)로 만들기.** 보기에는 더 자연스럽다(별칭만 보이기 등). 하지만 블록을 다시 직렬화할 때 원문이 바뀔 위험이 생기고, 표 안의 `\|` 같은 변형을 모두 되살려야 한다. 이 편집기의 약속(고치지 않은 블록은 바이트 그대로)을 지키는 쪽을 골랐다.
- **노트를 끼워 넣는 임베드(`![[다른노트]]`)와 블록 링크(`^id`)로 가기.** 범위가 크다. 블록 링크는 파일만 연다.
- **파일 이름을 바꿀 때 다른 노트의 링크 고치기.** 사람이 보지 않는 사이에 여러 파일을 고쳐 쓰게 된다.
- **링크를 그냥 클릭으로 열기.** 링크 글자를 고치려고 누른 것과 구분되지 않는다.
- **HTML 편집기에 같은 길 주기.** 이번에는 마크다운만이다. 같은 뒷단 모듈을 쓰면 된다.

## 결과

- 고친 곳은 `apps/markdown`과 껍데기 앱의 한 줄(`configureMarkdownRuntime`의 `openLinkedPath`)이다. 문서 엔진은 건드리지 않았다.
- 새 화면 문구 6개(21개 언어): `Ctrl+클릭으로 열기` 풍선 도움말, 파일·제목을 못 찾음, 먼저 저장해야 함, 열 수 없는 링크, `[[` 목록이 빔.
- 원문 편집기(`Ctrl+E`)에는 링크 따라가기가 없다. PDF·워드·이미지 내보내기에서 위키링크는 글자 그대로이고 임베드 그림은 나오지 않는다.
- 앱 안 도움말의 "Markdown 편집기" 장에 "노트 사이의 링크" 절을 21개 언어로 더했다. 도움말 검색어에 `link`, `wiki`, `obsidian`과 중국어 "링크"를 넣었다.
