# 0048 — 사용자가 스킬을 등록하고 모든 AI 창에서 부른다. 일반 AI 창에서는 앱이 스킬 글을 넣는다

## 맥락

사용자가 이음오피스에서 자기 스킬을 등록하고 목록을 관리하며, AI 창에서 `/`나 `$`로 부르기를 원했다. 스킬 형식은 공개 표준(폴더 하나에 `SKILL.md`, 앞머리에 `name`·`description`)이 되어 여러 에이전트 프로그램이 같이 쓴다.

에이전트 모드(0032)는 이미 PC의 스킬 폴더를 묶어 Claude Code에 넘기고 있었다. 하지만 관리 화면이 없었고, 일반 AI 창에서는 스킬을 쓸 길이 없었다. 일반 AI 창은 구독 프로그램을 도구 0개, 슬래시 명령 끔으로 띄운다(0001). 프로그램의 스킬 기능을 켜면 스킬 본문의 셸 명령이 모델 호출 전에 실행될 수 있다(Claude Code 문서).

공개 스킬 장터의 악성 스킬이 보고됐다(한 조사에서 3,984개 중 13.4%가 치명적 문제, 다른 조사에서 2,857개 중 341개가 악성).

## 결정

- **스킬은 공개 표준 형식으로 둔다.** 이음오피스가 만든 스킬은 다른 프로그램으로 옮겨도 쓴다. 화면 제목(`ieum-title`)과 양식(`ieum-template`)은 표준의 `metadata`에 둔다. 파일 이름은 표준 영어 이름, 화면은 한글 제목이다. 저장소 주인이 골랐다. (화면은 결정 0053에서 이름으로 바뀌었다.)
- **일반 AI 창에서는 앱이 스킬 본문을 요청에 넣는다.** 스킬 관련 도구(`use_skill`, `read_skill_file`, `propose_skill`)도 앱이 정의하고 실행한다. 구독 프로그램은 지금처럼 도구 0개다. 스크립트는 실행하지 않는다. 스크립트가 든 스킬은 "에이전트 창에서 완전히 동작"으로 표시한다. 저장소 주인이 이 한계를 받아들였다.
- **출처와 처음 상태.** 기본·내 스킬은 켜진 채, Claude·Claude 플러그인·Codex 스킬 폴더의 스킬은 목록에 보이되 꺼진 채로 시작한다. 모든 창이 같은 켜기·끄기를 따른다. 저장소 주인이 골랐다. 스스로 쓰기 목록이 길어지면 매 요청의 한도를 더 쓰기 때문이다.
- **AI가 스스로 쓰고, 썼다는 것을 보인다.** 스킬마다 "부를 때만"으로 바꿀 수 있다. 저장소 주인이 골랐다.
- **고른 스킬은 첨부처럼 칩으로 보인다.** 관리 화면은 설정의 "스킬" 항목이다. 저장소 주인이 골랐다.
- **가져오기는 폴더·zip·깃허브 링크이고, 모두 미리보기를 거친다.** 깃허브는 공개 저장소만, 세 주소(`github.com`, `api.github.com`, `codeload.github.com`)에만 연결하고, 사람이 누를 때만 연결한다. 업데이트도 사람이 "업데이트 확인"을 누를 때만 확인한다.
- **말로 스킬을 만든다.** "지금 한 작업을 스킬로 저장해 줘"라고 하면 AI가 확인 카드를 띄우고, 사람이 [저장]을 눌러야 저장된다. 완성한 양식 문서를 함께 넣을 수 있고, 채운 값을 비운 사본을 새 탭에서 확인한 뒤 저장할 수 있다. 가린 내용이 있는 문서는 그대로 양식이 되지 않는다. 남의 스킬을 고치면 내 스킬 사본이 되고 원래 스킬은 꺼진다. 저장소 주인이 골랐다.
- **양식 스킬을 부르면 양식 사본을 새 문서로 열어 내용만 채운다.** AI가 스스로 쓴 경우에는 탭을 바로 열지 않고 단추만 보인다. 저장소 주인이 골랐다.
- **기본 스킬은 다섯 개다.** 회의록 정리(MIT), 공지·소식지·FAQ 쓰기(Apache-2.0), AI 티 없애기(MIT), 문장 다듬기(MIT), 스킬 찾기(MIT, 에이전트 창 전용). 설치 수, 공식 계정, 앱에 넣어 배포할 수 있는 라이선스, 일반 창에서 동작하는지를 기준으로 저장소 주인과 골랐다. 두 글 다듬기 스킬은 영어 글 기준이라 화면 제목에 밝힌다(결정 0053에서 `humanizer`의 표시는 뺐다).
- **이름이 `genoffice`, `ieumoffice`인 스킬과 `~/.codex` 안은 읽지 않는다.** 원본이 등록한 것을 읽지 않는 규칙, 그리고 Codex 로그인 폴더 때문이다. 스킬 폴더 밖으로 이어지는 링크도 따라가지 않는다.
- **쓰는 곳은 `~/.ieumoffice/skills` 하나다.** 지우기는 운영체제 휴지통으로 옮긴다.

## 택하지 않은 것

- **일반 창에서 프로그램의 스킬 기능을 켠다.** 스킬 본문의 셸 명령이 모델 호출 전에 실행될 수 있어 도구 0개 원칙과 맞지 않는다.
- **스킬 장터 화면.** 앱이 그 공급망을 떠안는다. 에이전트 창의 "스킬 찾기"가 찾고, 설치는 같은 미리보기를 거친다.
- **다른 프로그램 스킬을 모두 켠 채 시작.** 이 PC에만 160여 개가 있다. 스스로 쓰기 목록이 길어져 한도를 더 쓴다.
- **자동 업데이트 확인.** 배경에서 스스로 실행하지 않는다는 규칙과 맞지 않는다.
- **유명한 문서 스킬(docx·pptx·xlsx·pdf) 넣기.** 재배포가 허용되지 않는 라이선스이고, 파일을 자체 스크립트로 만들어 앱이 문서를 고치는 방식과 겹친다.

## 결과

- 일반 AI 창, 홈 AI 질문, 에이전트 창이 같은 스킬 목록을 쓴다(에이전트 창은 0049).
- 0.12.1부터 에이전트 창에서 쓰던 Claude 스킬은 업데이트 뒤 꺼진 채로 시작한다. 이전 사용자에게 한 번 안내한다. 저장소 주인이 받아들였다.
- 마크다운·HTML·슬라이드 덱 전체 생성처럼 원래 제목 없는 문서를 기본 폴더에 저장하는 편집기는 양식 사본도 같은 동작을 한다.
- 고친 문서: `docs/security.md`("사용자 스킬"), `docs/business-rules.md`("스킬"), `docs/contracts.md`("사용자 스킬"), `docs/architecture.md`, `PRIVACY.md`, 첫 연결 안내, 도움말 "스킬".
