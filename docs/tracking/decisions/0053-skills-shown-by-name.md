# 0053 — 스킬은 이름으로 보이고, 새 스킬은 만들 때 영어 이름을 정한다

## 맥락

결정 0048은 "파일 이름은 표준 영어 이름, 화면은 한글 제목"으로 정했다. 기본 스킬 다섯 개에는 앱이 21개 언어의 제목을 붙였고(`AI 티 없애기(영어 글 기준)`처럼), 내 스킬은 `metadata.ieum-title`을 보였다.

0.12.3을 쓰면서 저장소 주인이 두 가지를 짚었다.

- 스킬을 번역한 제목으로 보이니 어색하다. Claude Code와 Codex는 스킬을 `/humanizer`처럼 이름으로 보이고, 이음오피스의 스킬도 그 프로그램들과 같은 형식이다.
- `humanizer`는 한국어 글에도 다른 것보다 잘 맞는다. "영어 글 기준"이라는 표시가 맞지 않는다. `copy-editing`은 지시문과 딸린 자료(쉬운 영어 단어 목록 등)가 영어 마케팅 글 전용이라 표시가 맞다.

이름으로 보이면 걸리는 것이 하나 있었다. 이름 규칙은 영문 소문자·숫자·하이픈만 남기므로, 한글로만 된 제목으로 만든 스킬은 `skill-a8k2p` 같은 무작위 이름이 붙는다. 이대로 이름만 보이면 직접 만든 스킬을 알아볼 수 없다.

## 결정

- **모든 스킬은 이름으로 보인다.** 설정 → 스킬, AI 창의 `/` 목록과 칩, "〈이름〉 스킬을 썼습니다", 스킬 카드가 같다(`skillDisplayName`). 기본 스킬의 한 줄 설명은 지금처럼 화면 언어로 보인다. 저장소 주인이 골랐다.
- **앱이 지어 준 무작위 이름(`skill-` 뒤 여섯 글자)인 스킬은 만들 때 적은 제목을 보인다.** 이름을 바꾸면 이름으로 보인다.
- **새 스킬은 만들 때 영어 이름을 정한다.** AI의 `propose_skill`은 제목 대신 이름을 반드시 낸다(무엇을 하는 스킬인지 드러나는 영어 단어). 카드와 설정의 편집 화면에서 이름 칸이 맨 위에 늘 보이고, "고급"과 제목 칸은 없앴다. 저장소 주인이 골랐다.
- **제목은 저장하지 않아도 된다.** 새 스킬에는 `ieum-title`을 쓰지 않는다. 고친 스킬은 원래 있던 제목을 그대로 둔다. 예전 프롬프트처럼 AI가 제목만 내면 카드가 제목에서 이름을 지어 채운다.
- **`humanizer`의 "영어 글 기준" 표시를 뺀다.** `copy-editing`은 설명에 영어 글이라고 남기고, 도움말에는 영어 마케팅 글 기준이라고 적는다.

## 택하지 않은 것

- **이름과 번역한 제목을 같이 보이기.** 정보는 많지만 지금의 어색함이 남는다.
- **이음오피스에서 한글 제목을 붙여 만든 스킬만 제목으로 보이기.** 고칠 것은 가장 적지만, 같은 목록에 이름과 한글 제목이 섞인다.
- **이름에 한글 허용.** 보기에는 자연스럽지만 공개 표준(영문 소문자·숫자·하이픈)을 벗어나, 그 스킬을 Claude Code나 Codex로 옮기면 인식되지 않을 수 있다.
- **기본 스킬을 한국어용으로 새로 쓰기.** 저장소 주인이 `humanizer`가 한국어에도 잘 맞는다고 봐서 지금은 하지 않는다.

## 결과

- 결정 0048의 "화면은 한글 제목"을 이 결정이 바꾼다. 스킬 폴더 형식과 `ieum-title`의 뜻(있으면 무작위 이름 대신 보이는 제목)은 남는다.
- 기본 스킬의 번역 제목 문구(`builtinSkillTitle.*`, 21개 언어)를 지웠다. 설정과 카드의 "제목", "고급", "제목으로 정한 이름" 문구도 지웠다.
- 고친 문서: `docs/business-rules.md`("스킬"), `docs/contracts.md`("사용자 스킬"), 도움말 "스킬"(21개 언어).
