# 0100 — 사람이 고른 MCP 서버를 앱이 클라이언트로 붙이고, 도구마다 허락을 받아 AI 창과 에이전트 창에 내놓는다

## 맥락

2026-11-01에 받은 의견이 출발점이다. 한 변호사가 판례·법령을 확인할 때 법령 MCP 서버를 부르는 서면 스킬을 쓴다. AI 창에는 바깥 MCP가 없어서 확인 단계만 빠진 초안이 나왔다. AI는 그 단계를 건너뛰었다는 말도 하지 않았다. 확인을 거친 것처럼 보이는 초안이 가장 위험하다.

그래서 두 가지를 함께 넣는다. 하나는 사람이 고른 MCP 서버를 AI 창에 연결하는 것이고, 다른 하나는 AI가 하지 못한 단계를 답에 밝히게 하는 것이다.

막고 있던 규칙은 셋이다.

- 기본 AI 창의 구독 프로그램은 도구 0개(문서 편집 차례는 `StructuredOutput` 하나, 결정 0082)로만 돈다(절대 규칙 3). 구독 프로그램에 사용자 MCP 설정을 열어 주면 이 안전장치가 깨진다.
- 사용자 글은 명령이 되지 않는다(`docs/security.md` "프로그램 실행"). 서버 안내서에 흔한 실행형 서버(`npx …`, `uvx …`)는 사용자가 적은 명령을 실행해야 돈다.
- 바깥으로 나가는 도구는 문지기를 지난다(결정 0033, 0062). 남이 운영하는 서버는 새 바깥 길이고, 그 서버가 돌려준 글은 새 지시 주입 길이다.

저장소 주인은 연결이 편하기를 원했다. 주소만 넣으면 브라우저 로그인으로 끝나고, 서버 안내서의 설정 글을 붙여넣으면 그대로 등록돼야 한다. 주인은 MCP·보안 전문가가 아니어서 대부분 보안상 좋은 쪽을 골랐고, 편함을 고른 곳은 셋이다. 에이전트 창에서 "받은 내용 지키기" 서버를 경고만 하고 붙이는 것, 패키지를 늘 최신판으로 실행하는 것, 실험 표시 없이 일반 기능으로 내는 것이다.

## 결정

**앱이 MCP 클라이언트다.** 모든 서버 연결은 껍데기 앱 뒷단 한 곳(`apps/shell/src/main/mcp-client/`)에서 맺고, 모든 창이 함께 쓴다. 편집기 창과 홈 창은 preload 다리(`window.aiOfficeMcpTools`)로 묻는다. 구독 프로그램에게는 사용자 서버를 주지 않는다. 기본 AI 창에서 구독 프로그램이 가진 도구는 그대로다. 서버의 도구는 앱 도구로 붙어 드라이브 도구와 같은 문지기를 모두 지난다.

- 클라이언트는 아무 능력도 알리지 않는다(`capabilities: {}`). 서버가 sampling, elicitation, roots를 요청하면 거절한다. sampling을 받으면 남의 서버가 사람의 구독을 쓰게 된다.
- 도구가 아닌 MCP 기능(prompts, resources)과 결과 가운데 글이 아닌 것(그림·소리·자원 링크)은 쓰지 않는다.

**서버는 두 종류다.**

- 주소 서버: Streamable HTTP, 서버가 모르면 예전 SSE로 한 번 더. 요청은 등록한 주소의 출처로만 간다. 다른 출처로 넘기는 응답은 따라가지 않는다(로그인 흐름의 인증 서버는 예외). 인터넷 주소는 `https://`만, `http://`는 이 PC와 사설망 주소일 때만 확인을 받고 받는다. `http://` 주소는 요청마다 이름을 다시 풀어 다시 판정한다.
- 내 PC 서버: 앱이 이 PC에서 프로그램을 실행한다. 이것이 "사용자 글이 명령이 되지 않게"의 예외다. 범위는 좁다. 실제로 실행할 명령(실행 파일 전체 경로, 인자, 환경 변수 이름, 앱이 덧붙이는 것)을 보이고 사람이 "실행 허락"을 눌러야 처음 실행한다. 확인 화면의 계산과 실제 실행은 한 함수를 거친다. 허락은 사람이 본 그 계획의 지문에 붙는다. 명령·인자·환경 변수 이름이 바뀌거나 같은 명령이 다른 프로그램으로 풀리면 그 서버를 실행하지 않고 다시 허락받는다. 셸 없이 실행 파일을 인자 배열로 직접 띄우고, 작업 폴더는 앱이 만든 빈 폴더, 환경은 최소 시스템 변수와 등록한 변수뿐이다. 앱과 함께 끝난다.

**실행 환경은 처음 쓸 때 받는다.** 내 PC 서버에 필요한 Node.js나 uv가 PC에 없으면 크기를 보이고 묻는다. 사람이 "받기"를 눌러야 받는다. 판과 지문(SHA-256)은 앱 판마다 코드에 고정한다. 이번 판은 Node.js v26.13.0 LTS, uv 0.13.6, uv가 받는 CPython 3.13.18이다. 받는 크기는 운영체제마다 Node.js 41–63MB, uv 14–17MB, uv의 Python 22–35MB이고, 화면은 실제 크기를 보인다(설계 때의 "약 30MB"는 맞지 않았다). 받은 것은 앱 데이터 폴더의 `mcp-runtimes/`에만 둔다. 사람이 한 번 받기를 허락한 실행 환경은 앱이 올라가 고정 판이 바뀌면 묻지 않고 새 판을 받는다.

**도구마다 허락 상태가 있다.** `always`(항상 허용), `ask`(물어보고 사용), `off`(사용 안 함). 처음 값은 서버가 `readOnlyHint: true`를 붙인 도구만 `always`, 나머지는 `ask`다. `ask` 도구는 실행 전에 그 AI 창 대화 안에 허락 카드를 띄운다. 단추는 [이번만 허용] [이 대화에서 항상 허용] [막기]이고, 사람이 누르기 전에는 실행하지 않는다. 멈추거나 창을 닫으면 막은 것이다.

- 이 카드는 결정 0062의 주소 확인과 다르다. 0062는 운영체제 대화 상자를 골랐다. 편집기 8개의 화면을 각각 고쳐야 했고, 실행 중인 도구를 화면이 붙잡는 방식도 편집기마다 달랐기 때문이다. 이번에는 저장소 주인이 대화 흐름 안에서 묻는 쪽을 골랐다. 공용 부품 하나(`packages/ui`의 `McpPermissionCard`)를 10곳에 같은 방식으로 붙여 그 비용을 줄였다. 0062의 주소 확인은 그대로 운영체제 대화 상자다.

**승인 지문으로 바뀐 것을 잡는다.** 사람이 마지막으로 승인한 도구 모양(이름·설명·입력 형식)과 서버 안내 글의 SHA-256을 둔다. 서버가 붙이는 표시(읽기 전용 등)는 지문에 넣지 않는다. 도구 모양이 바뀌면 그 도구만 "확인 필요"가 되고, 승인할 때까지 어느 창에도 오르지 않는다. 서버 안내가 바뀌면 안내만 빼고 도구는 계속 쓴다. 새 도구는 처음 값으로 켜고 "새 도구 n개"를 보인다. 이 표시는 사람이 설정에서 그 서버의 도구 목록을 열면 사라진다. AI 창의 도구 목록은 저장된 승인 정의로 만든다. 그래서 서버에 아직 붙지 않았어도 첫 차례부터 도구가 오른다.

**받은 내용 지키기.** 서버마다 켜고 끄며, 처음에는 켜져 있다. 켜진 서버 S가 오류가 아닌 결과를 돌려주면, 그 대화가 새로 시작될 때까지 S가 아닌 모든 바깥 도구(웹 도구, 다른 서버의 도구)를 거절한다. 사용자 MCP 도구는 모두 바깥 도구로 친다(`mcp__` 앞붙이). 드라이브 뒤의 거절(결정 0033)과 주소 확인(결정 0062)도 그대로 걸린다. 홈 AI 질문 창에도 바깥 도구 문지기, 받은 내용 지키기, 사용자 서버를 씌운다. 홈 창에 드라이브 도구를 새로 더하지는 않는다. EPUB 편집기 preload가 바깥 도구 다리를 열지 않아 인터넷 도구 스위치가 듣지 않던 기존 결함도 이번에 고친다.

**에이전트 창은 앱이 중계한다.** 세션을 시작할 때 켜진 사용자 서버마다 같은 이름의 중계 MCP 서버를 연다. 루프백, 빈 포트, 세션마다 새 토큰이다. 쓸 수 있는 도구가 하나도 없는 서버에는 열지 않는다. 중계는 받은 호출을 같은 허브로 넘기므로 서버의 열쇠와 환경 변수는 구독 프로그램에 가지 않는다.

- 시작 검사는 "정해 둔 도구 + 앱 MCP 서버의 도구 + 이번 세션에 연 중계 서버와 그 도구"로만 넓힌다. 그 밖이 보이면 지금처럼 `unsafe-tools`다.
- 사람에게 묻는 일은 중계가 한 번만 맡는다. `ask` 도구는 에이전트 창의 카드로 묻는다([막기] [이 세션에서 항상 허용] [이번만 허용]). Claude는 중계 서버 도구를 앱 도구로 분류한다. "이 프로젝트는 믿고 맡기기"(Claude Code의 `auto` 모드)에서는 요청이 앱에 오기 전에 프로그램이 판단하므로, 세션 설정의 허용 규칙(`permissions.allow`)에 서버마다 `mcp__〈이름〉`을 더한다. Codex에는 중계 서버에 `default_tools_approval_mode: 'approve'`를 주고, 사용자 Codex 설정에 같은 이름의 서버가 있으면 세션 설정으로 덮는다.
- 에이전트 창의 프로그램은 자기 웹·명령 도구가 있어 받은 내용 지키기를 지킬 수 없다. 그런 서버가 붙으면 시작 경고에 "이 창에서는 〈서버〉에서 받은 내용이 밖으로 나갈 수 있습니다"를 더하고 그대로 붙인다.

**못 한 단계를 밝힌다.** 스킬 본문이 AI에게 가는 두 길(`use_skill`, 칩)에 같은 문장을 붙인다. "이 스킬의 단계 가운데 여기서 할 수 없는 것(스크립트 실행, 없거나 실패한 도구)이 있으면 답에 밝히고, 거친 것처럼 쓰지 마라." 스킬이 `mcp__〈서버〉__〈도구〉`를 적었는데 그 서버를 지금 쓸 수 없으면 그 사실을 앞에 붙이고, 설정 → 스킬과 칩 안내에 "MCP 서버 필요: 〈서버〉"를 보인다. 에이전트 창의 지시문에도 같은 문장을 둔다.

**보관.** 서버 목록, 허락 상태, 승인 지문은 앱 데이터 폴더의 새 파일 `mcp-servers.json`에 둔다. `ai-settings.json`에 두지 않는다. 그 파일은 터미널 명령어가 읽고 봉인을 푼다(결정 0063). 비밀값(열쇠·헤더 값·OAuth 토큰·클라이언트 비밀값·환경 변수 값)은 운영체제 암호화로 봉인하고, 암호화를 쓸 수 없으면 메모리에만 둔다. 비밀값은 화면 쪽 창, 편집기, 에이전트 프로그램, 로그, 대화 기록, 오류 글에 나가지 않는다.

**구현하면서 정한 것.**

- 연결하지 못한 주소 서버는 다음 호출 때 다시 붙는다. 로그인 필요, 다른 출처로 넘기기, 안전하지 않은 주소는 사람이 다시 시도하거나 로그인하거나 연결 확인을 눌러야 풀린다.
- 내 PC 서버의 명령이 바뀌면 진행 중인 호출까지 바로 멈춘다. 설계의 "이미 시작한 호출은 끝까지"보다 보안 검토를 앞세웠다.
- 서버의 표준 오류 출력은 끝 몇 줄만 메모리에 두고 설정의 "자세히"에서만 보인다. 로그에는 쓰지 않는다.
- Windows는 `HOMEDRIVE`, `HOMEPATH`, `LOGONSERVER`, `SYSTEMDRIVE`, `USERDOMAIN`, `USERNAME`, `WINDIR`을 모든 하위 프로세스에 넣는다. 그래서 확인 화면에 시스템 변수로 보인다.
- 로그인할 때마다 OAuth 클라이언트를 새로 등록한다(돌아오는 루프백 포트가 바뀌기 때문이다). 인증 서버는 PKCE `S256`을 알려야 한다.
- 주소 서버의 주소를 바꾸면 그 서버의 로그인 토큰을 잊는다. 옛 서버에 폐기를 요청하지는 않는다.

## 택하지 않은 것

- **구독 프로그램에 사용자 MCP 설정을 열어 준다.** 가장 간단하지만 기본 AI 창의 "도구 0개" 안전장치가 깨지고, 허락과 문지기를 앱이 걸 수 없다.
- **다른 프로그램의 설정 파일을 앱이 직접 읽어 가져온다.** Claude·Codex의 설정 파일은 로그인 정보 바로 옆에 있어 절대 규칙 1번과 맞닿는다. 사람이 설정 글을 붙여넣는 것으로 거의 같은 편함을 얻는다. Codex의 `bearer_token_env_var`도 PC 환경에서 읽지 않고 열쇠 칸을 비워 둔다.
- **주소 서버만 받는다.** 서버 안내서에 흔한 실행형 서버를 쓸 수 없다. 주인이 편함을 골랐고, 그 대가인 규칙 예외는 위 범위로 좁혔다.
- **패키지 판을 고정하고 "새 판 있음"을 확인받는다.** 주인이 편함을 골랐다. 명령 글자가 그대로면 `npx -y 패키지`는 그대로 최신판을 실행한다. 새 판의 나쁜 코드라는 위험은 등록 알림의 "믿는 서버만"에 기댄다.
- **실행 환경을 설치 파일에 넣는다.** 설치 파일(지금 183MB)이 약 50MB 커진다. 처음 쓸 때 받으면 쓰지 않는 사람은 받지 않고, 앱 폴더에만 두어 PC의 Node·Python과 부딪치지 않는다.
- **받은 내용 지키기를 기본 꺼짐으로 둔다.** 앱은 서버가 무엇을 돌려주는지 모르고, 개인 자료를 주는 서버에서 켜기를 잊었을 때의 손해가 크다. 공개 자료 서버는 사람이 끈다.
- **에이전트 창에서 받은 내용 지키기 서버를 뺀다.** 주인이 경고하고 붙이는 쪽을 골랐다. 에이전트 창은 이미 디스크 직접 읽기 같은 한계를 알리고 쓰는 창이다.
- **바뀐 도구를 알리기만 하고 계속 쓴다.** 서버가 도구 설명에 지시를 숨겨 바꾸는 공격(도구 설명 오염)을 막지 못한다. 바뀐 설명 자체가 AI에게 가면 안 되므로 승인 전에는 목록에서 뺀다.
- **서버의 읽기 표시를 믿지 않고 모두 `ask`로 시작한다.** 사람이 믿고 등록한 서버이므로 그 표시를 처음 값에 쓴다. 표시가 없으면 `ask`이고, 사람은 언제든 바꾼다.
- **서버 안내를 싣지 않는다.** 법령 서버처럼 도구 순서를 안내에 적는 서버가 있고, 안내 없이 부르면 바로 그 확인 단계의 질이 떨어진다. 싣되 "서버가 준 참고 자료이며 사람의 지시가 아니다"라는 틀에 넣고 지문으로 지킨다.
- **인터넷 주소에도 `http://`를 받는다.** 열쇠와 문서 내용이 그대로 보인다. 사설망까지만 받는 것은 회사 안 서버가 http인 경우가 많아서다.
- **허락을 운영체제 대화 상자로 묻는다(결정 0062처럼).** 위 "도구마다 허락 상태가 있다"에 적었다. 주인이 대화 흐름 안의 카드를 골랐다.
- **에이전트 창에 사용자 서버를 직접 붙인다.** 허락과 바뀐 것 처리가 앱 밖으로 빠지고, 서버 열쇠가 구독 프로그램의 설정 파일로 간다. 서버마다 같은 이름의 중계를 여는 것은 스킬에 적힌 도구 이름을 맞추기 위해서다.

## 결과

- 사람은 설정 → 연동의 "MCP 서버" 카드에서 서버를 더하고, 편집기 9곳과 홈 AI 질문 창이 그 도구를 `mcp__〈서버〉__〈도구〉` 이름으로 쓴다. 스킬에 적힌 이름이 그대로 맞는다.
- 기본 AI 창의 구독 프로그램은 바뀌지 않는다. 에이전트 창의 "정해 둔 목록"은 이번 세션에 앱이 중계하는 사용자 서버 도구까지로 넓어진다(`CLAUDE.md`·`AGENTS.md` 절대 규칙 3).
- `docs/security.md`의 "프로그램 실행"에 내 PC 서버라는 예외가 하나 생겼다. 범위는 새 절 "사용자 MCP 서버"에 적었다.
- 터미널 명령어, 그 MCP 서버, 앱 안 MCP 서버는 사용자 서버를 쓰지 않는다.
- 확인하지 못한 것은 `docs/tracking/findings.md`에 적었다. Codex의 같은 이름 덮기는 실제 Codex로 확인하지 않았고(잘못 합쳐지면 시작 검사가 막는다), 다른 출처로 넘기는 응답의 처리는 흉내 낸 `net.fetch`로만 시험했다. `http://` 주소의 이름 다시 풀기는 짧은 틈을 남긴다. 다시 연 대화의 받은 내용 지키기는 드라이브와 같은 한계를 가진다. 주소의 질의 문자열에 든 열쇠는 봉인되지 않는다.
- 마지막 검토 뒤에 고친 것(2026-11-02). "실행 허락"은 확인 화면이 보인 계획(풀린 실행 파일 경로, 앱이 덧붙인 인자까지, 환경 변수 이름과 출처)의 지문을 돌려보내야 받고, 그사이 계획이 바뀌었으면 받지 않는다. 허락한 계획의 지문(`approvedPlan`)은 `approvedLaunch` 옆에 두고, 실행할 때마다 다시 계산한 계획과 비교한다. 그래서 PC의 Node가 없어져 앱이 받은 Node로 풀리면 다시 묻는다. 앱 업데이트로 받은 실행 환경의 판이 바뀌어도 경로가 바뀌므로 다시 묻는다. 받기는 지금처럼 묻지 않고, 명령 허락만 다시 받는다. 인터넷 도구 스위치를 끄면 지시문의 서버 덩어리도 빠지고 창은 쓸 수 있는 서버를 0개로 본다. 창이 닫히면 그 창의 호출을 끊는다. 주소 서버의 결과도 내 PC 서버처럼 뒷단에서 거르고 잘라, 창과 중계에는 거른 글만 간다.
- 바깥 시험자의 화면 시험(E2E) 뒤에 고친 것(2026-11-02). 서버 상태에 `unchecked`("확인 전")와 `ready`("준비됨 · 쓸 때 연결")를 더했다. 전에는 앱이 한 번도 붙지 않은 서버, 주소가 틀린 서버도 "연결됨"이었고 AI에게는 도구가 0개였다. 등록하면 앱이 바로 연결 확인을 한다(로그인이 필요하면 브라우저를 열지 않고 "로그인 필요"에서 멈추고, 내 PC 서버는 실행 허락 뒤). 내 PC 서버가 한 번만 시작에 실패해도 "연결 못 함: 시작 실패"와 "자세히"·"다시 시도"를 보인다(실행기의 3번 잠금은 그대로). 실패 까닭에 `http-error`(서버가 HTTP 오류로 답함)를 더하고, 까닭은 카드에 한 번만, 이 PC·사설망 주소에는 인터넷 탓을 하지 않게 했다. 붙여넣은 `${변수}`·`${env:변수}` 값은 저장하거나 보내지 않고 비운 채 묻는다(PC 환경은 읽지 않는다). 그 밖에 바뀐 것: 고칠 때 주소가 그대로면 http 확인을 기억함, 서버 더하기 뒤 첫 칸에 초점과 Enter로 등록, 숫자 인터넷 주소의 http는 주소 칸에서 바로 막음, 읽지 못한 붙여넣기 글을 남기고 문법 실수의 줄을 알림, 모르는 `type`은 무시한 항목으로 알리고 보통 방식으로 연결, 실행 확인 화면에서 PC 기본 변수를 접어 둠, 확인 필요·켤 수 없는 도구에 눌린 허락 칸을 보이지 않음, 연동 화면의 두 MCP 칸에 방향을 한 줄로 적음, 글자를 쓸 수 없는 이름은 주소·패키지 이름으로 제안, AI 창 목록의 "이 대화에서 끔"과 "설정에서 켜기", 작업 단계 줄의 "〈서버〉 · 〈도구〉"와 "막음", 허락 카드의 도구 설명과 "지우거나 바꿀 수 있음" 표시(창 다리의 도구에 `destructive`).
- 사람 확인(저장소 주인)은 둘이 남았다. 실제 원격 서버 하나에 열쇠로 붙어 스킬이 도구 이름 그대로 부르는지, 실제 내 PC 서버 하나를 실행 환경 받기부터 해 보는 것이다.
