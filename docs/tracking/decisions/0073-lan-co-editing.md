# 0073 로컬 네트워크 실시간 공동 편집

## 배경

같은 네트워크 안에서 여러 사람이 한 문서를 동시에 편집하는 기능을 넣는다. 화면에 참여자의 커서와 이름이 표시되어야 하고, 문서는 PIN 번호를 입력해야만 들어올 수 있어야 한다.

우리 앱은 별도 서버나 계정 시스템이 없는 로컬 프로그램이다. 게다가 문서 포맷마다 사용하는 편집기와 내부 데이터 모델이 제각각이다.

- 워드, 마크다운: TipTap
- HTML: CodeMirror
- 엑셀: Univer
- 파워포인트: 백엔드 자체 문서 모델
- 마인드맵: mind-elixir, xmind 엔진
- PDF: 저장 전까지 프론트엔드가 들고 있는 편집 데이터 묶음
- 한글(HWP): rhwp
- EPUB: 백엔드 책 세션

## 결정 사항

- **문서를 공유하는 호스트 PC가 직접 연결을 받는다.** 중앙 서버나 계정은 두지 않는다. 셸 앱 백엔드가 TCP 포트(기본 `47631`, 사용 중이면 빈 포트)를 하나 열어 연결을 처리한다. 포트는 공유 중인 문서가 하나라도 있을 때만 열리고, 공유가 모두 끝나면 닫힌다.
- **6자리 PIN으로 접근을 제어한다.** 문서마다 6자리 PIN을 발급한다. PIN 자체는 네트워크로 보내지 않는다. 게스트와 호스트는 PIN을 비밀번호로 쓰는 SPAKE2 키 교환(ristretto255 곡선)으로 세션 키를 만들고, PIN이 같을 때만 서로의 확인 값이 맞는다. 확인을 마친 게스트만 문서 데이터를 받을 수 있다.
- 같은 IP에서 5번 틀리면 해당 IP를 10분간 차단한다. 키 교환 요청이 오면 호스트가 답을 보내기 전에 한 번 틀린 것으로 먼저 세고, PIN이 맞으면 되돌린다. 연결을 한꺼번에 여러 개 열어도 추측 횟수는 늘지 않는다.
- 전체 누적 실패 횟수가 20번에 도달하면 현재 열려 있는 모든 공유 세션의 PIN을 재발급하고 호스트에게 알린다. 이미 접속해 있던 참여자는 유지한다.
- 키 교환을 마치기 전에는 4KB를 넘는 메시지를 거부하며, 연결 후 10초 안에 키 교환이 끝나지 않으면 연결을 끊는다.
- 문서당 최대 접속 인원은 16명으로 제한한다.
- **키 교환을 마친 뒤 주고받는 데이터는 모두 암호화한다.** 세션 키에서 방향별 키를 따로 만들고, 모든 프레임을 ChaCha20-Poly1305로 암호화한다. nonce는 방향별 카운터라서 변조되었거나 순서가 바뀌었거나 다시 보낸 프레임은 복호화에 실패하고, 그 즉시 연결을 끊는다. PIN이 6자리로 짧아도 패킷을 엿본 사람은 PIN을 오프라인으로 대입해 볼 수 없다. 중간에 끼어든 사람도 연결 한 번에 PIN을 한 번 추측할 수 있을 뿐이고, 그 시도는 위의 실패 횟수 제한에 걸린다. Electron의 내장 암호 모듈에는 ChaCha20-Poly1305가 없어서 `@noble/ciphers`를 쓰고, 곡선 연산에는 `@noble/curves`를 쓴다.

- **백엔드는 메시지 내용에 관여하지 않고 중계만 한다.** 셸 앱 백엔드는 헤더(라우팅 정보)만 보고 메시지를 전달한다. 문서 상태의 기준(Single Source of Truth)은 호스트의 편집기 탭이며, 게스트는 초기 상태를 호스트 탭에서 직접 받는다. 동기화 상태는 단일 Yjs 문서(`packages/collab`)로 관리하고, 각 편집기 위에 얇은 어댑터를 얹어 연결한다.
- **워드, 마크다운**: TipTap 어댑터를 쓴다. 원격 변경이 들어오면 변경된 최상위 블록만 교체하며, 이 변경은 로컬 실행 취소(Undo) 스택에 쌓이지 않는다.
- **HTML**: CodeMirror 어댑터를 쓴다. 미리보기, 인스펙터, AI 편집 모두 원본 소스를 직접 수정하는 구조라 기존 경로를 그대로 타면 동기화된다.
- **엑셀, 파워포인트, 마인드맵**: 호스트가 순서를 확정하는 연산 로그(`OpLog`) 방식을 쓴다. 게스트의 편집 연산은 호스트에게 '제안' 형태로 전달된다. 만약 순서가 꼬이거나 호스트에서 거절당하면, 게스트는 호스트의 현재 문서 바이트를 통째로 다시 받아 상태를 맞춘다.
- **PDF**: 프론트엔드가 들고 있는 미저장 편집 묶음을 공유 상태에 그대로 올려 동기화한다.
- **EPUB**: 게스트가 편집을 요청하면 호스트의 백엔드 책 세션에서 실행한 뒤, 그 결과를 전체 참여자에게 브로드캐스트한다.
- **한글**: 호스트만 편집할 수 있고, 게스트는 변경 내역을 실시간으로 열람만 한다. 두 사람의 편집을 합치려면 rhwp 편집기 내부를 고쳐야 하기 때문이다.

- **게스트 탭은 임시 사본으로 동작한다.** 호스트가 '지금 저장할 때 디스크에 기록될 바이트'를 뽑아주면, 게스트의 셸 앱은 이를 OS 임시 폴더(`genoffice-collab-*`)에 저장한다. 이후 템플릿 사본을 열 때와 동일한 로직으로 해당 편집기의 '제목 없음' 새 탭을 띄운다(단, EPUB은 '제목 없음' 상태가 없으므로 임시 파일을 직접 연다).
- 게스트는 세션이 유지되는 동안 문서를 저장할 수 없고, 자동 복구본도 생성하지 않는다. 탭을 닫을 때 저장 여부를 묻지도 않는다.
- 공유 세션이 종료되면 게스트의 탭은 일반 '저장되지 않은 문서' 상태로 남는다.
- 임시 폴더는 탭을 닫거나 앱을 종료할 때 삭제한다. 미처 지우지 못한 폴더는 하루가 지난 뒤 다음 앱 실행 시점에 정리한다.

- **저장은 호스트만 한다.** 게스트가 내용을 고치면 호스트 문서가 '수정됨(dirty)' 상태가 되고, 호스트가 평소처럼 저장을 누를 때 게스트의 편집본까지 합쳐서 파일에 반영된다. 최종 저장 결과물은 호스트가 혼자 편집했을 때와 완전히 동일하다.
- **실행 취소(Undo)는 본인 작업만 되돌린다.** 다른 참여자의 편집 내역은 내 실행 취소 기록에 섞이지 않는다.
- **UDP 브로드캐스트로 로컬 네트워크 내 공유 문서를 찾는다.** 문서를 공유하는 동안 2초마다 `47633` 포트로 UDP 패킷을 쏜다. 패킷에는 호스트 이름, TCP 포트, 문서 제목, 편집기 종류만 담기며 PIN은 제외된다. 참여 창이 열려 있을 때만 이 패킷을 수신하며, 필요하면 IP와 포트를 직접 입력해 들어갈 수도 있다.
- **사용자 프로필(이름, 색상)은 데이터 폴더의 `app-settings.json`(`collabProfile`)에 저장한다.** 초기값은 OS 계정 이름과 랜덤 색상으로 세팅한다.
- **암호가 걸린 문서는 공유를 막는다.** 화면에 띄운 문서는 이미 복호화된 바이트를 메모리에 들고 있는 상태라, 그대로 공유하면 게스트에게 평문이 넘어가기 때문이다.

## 결과 및 한계

- 같은 네트워크의 사용자들이 PIN을 입력해 한 문서를 동시에 편집하고 서로의 커서와 이름을 실시간으로 볼 수 있다.
- 통신 내용은 암호화되므로 같은 네트워크에서 패킷을 스니핑해도 문서 내용, 편집 내용, PIN을 볼 수 없다. 다만 공유 문서를 찾게 해 주는 UDP 알림은 암호화하지 않으므로, 공유 중에는 문서 제목과 호스트 PC 이름이 로컬 네트워크에 노출된다.
- 처음 공유를 켤 때 Windows 방화벽 허용 팝업이 뜬다. 여기서 차단하면 다른 PC에서 접속할 수 없다.
- 공동 편집 중 비활성화되는 기능은 편집기마다 다르며, 구체적인 목록은 각 편집기 폴더의 `AGENTS.md`에 정리한다.
- 마크다운 편집기에서 '원문 편집기(Raw editor)' 모드로 여는 일반 텍스트(`.txt`)나 `.json` 파일은 공유 대상에서 제외한다. 게스트 쪽에서 새 탭을 열 때 무조건 블록 편집기 모드로 열리는 문제가 있기 때문이다.
