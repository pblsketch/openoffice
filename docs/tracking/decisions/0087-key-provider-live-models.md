# 0087 API 키 제공자의 모델 목록은 그 회사에 물어 채운다

## 맥락

키 제공자(Gemini, Claude API, OpenAI 등)의 모델 목록은 앱에 고정되어 있었다. 2026-10-29 사용자 의견: Gemini 키를 넣었더니 Flash만 고를 수 있고, 사고·Pro 모델을 쓰고 싶다. 확인해 보니 목록이 이미 낡아 있었다. Google은 10월 13일 플래그십 추론 모델 `gemini-4-argon`을 정식으로 냈고, 10월 8일 `gemini-3.7-flash`를 내렸다. 앱에는 앞의 것이 없고 뒤의 것이 남아 있었다. 설정의 모델 칸은 드롭다운뿐이라, 목록에 없는 모델은 이름을 알아도 쓸 수 없었다. 새 모델이 나올 때마다 앱 업데이트를 기다려야 하는 구조다. 다른 키 제공자도 사정이 같다.

## 결정

- **뒷단(메인 프로세스)이 키 제공자마다 그 회사의 모델 목록을 묻는다.** 대화가 쓰는 것과 같은 주소와 키로 묻는다. Anthropic은 `GET /v1/models`, Gemini는 `GET /v1beta/models`, OpenAI 호환 회사와 중개 서비스는 `GET {base}/models`다. 목록 조회는 모델 호출이 아니어서 요금이 나가지 않는다.
- **묻는 때는 둘뿐이다.** 앱을 켜고 5초 뒤 한 번, 그리고 키나 주소가 바뀌어 저장됐을 때 그 제공자만 다시 묻는다. 키가 없는 제공자에는 묻지 않는다. 선택기를 연다고 요청이 나가지는 않는다. 사용자가 직접 넣은 로컬·사용자 서버(`custom`)는 전처럼 설정 화면이 따로 묻는다.
- **결과는 설정 파일의 `providers.<id>.models`에 둔다.** 이 값은 뒷단만 쓴다. 화면이 보낸 설정의 `models`는 검사에서 버리고, 저장할 때 파일에 있던 목록을 그대로 옮긴다. 화면이 들고 있던 낡은 목록이 새 목록을 덮지 못하게 하려는 것이다. 답이 없으면(주소 없음, 거절, 시간 초과) 있던 목록을 그대로 둔다. 물어보는 사이에 키가 바뀌었으면 그 답은 버린다.
- **대화 모델만 남긴다.** 임베딩·음성·이미지·영상·실시간 음성·검열 모델은 이름과 목록이 알려 주는 성질(`supportedGenerationMethods`, `supported_parameters`의 `tools`, 출력 형태, `capabilities`)로 거른다. 이 앱의 연결 방식으로 도구를 쓸 수 없는 모델(OpenAI의 GPT-6·Codex·`-pro`, OpenCode 중개의 GPT·Grok·Muse)도 뺀다. 날짜가 붙은 사본은 날짜 없는 별칭이 함께 있을 때 뺀다.
- **선택기는 앱의 추천 목록 다음에 새 모델을 붙인다.** 추천 목록의 순서는 그대로 두고, 목록에만 있는 모델을 최신순(회사가 날짜를 주면 날짜, Gemini는 판 번호)으로 그 뒤에 둔다. 저장된 모델이 어디에도 없으면 맨 위에 둔다. OpenRouter 무료 연결은 예외로 무료 모델만 보인다. 유료 모델이 섞이면 요금이 나갈 수 있다.
- **설정의 모델 칸에 "다른 모델 직접 입력…"을 둔다.** 회사 목록에도 아직 없는 이름을 적어 쓸 수 있다.
- **무료 등급 키로 무료 등급이 없는 모델을 고르면 그렇게 알린다.** Gemini는 이때 무료 등급 한도 0으로 429를 준다. 지금까지는 이것을 "오늘 무료 사용량을 다 썼다"로 읽었는데, 기다려도 풀리지 않는다. 새 오류 종류 `free-tier-model`로 나누고 "무료로 쓸 수 있는 모델을 고르거나 결제를 켜라"고 안내하며, 다시 시도하지 않는다.
- 고정 목록도 고친다. Gemini에 `gemini-4-argon`을 더하고, 저장된 `gemini-3.7-flash`는 Google이 돌려보내는 `gemini-3.8-flash`로 옮긴다. 기본 모델은 무료 등급이 있는 3.8 Flash로 둔다. Gemini 4도 3처럼 온도 값을 보내지 않는다.

## 택하지 않은 것

- **고정 목록만 자주 고치기.** 회사가 20개가 넘고, 새 모델이 나와도 앱 업데이트 전까지는 쓸 수 없다. 이번 의견이 바로 그 경우였다.
- **선택기를 열 때마다 묻기.** 편집기 9개의 선택기에 각각 창구를 이어야 하고, 쓰지 않는 제공자까지 자주 묻게 된다. 켤 때 한 번과 키를 바꿀 때로 충분하다.
- **목록을 화면이 저장하기.** 직접 입력 주소(`customEndpoints[].models`)는 그렇게 하지만, 키 제공자는 여러 창이 같은 파일을 고친다. 뒷단 하나가 쓰는 편이 덮어쓰기 경쟁이 없다.
- **회사 목록을 그대로 다 보이기.** OpenAI 목록에는 음성·이미지·검열 모델과 날짜 사본이 섞여 있어, 고르면 실패할 이름이 절반을 넘는다.
- **선택기에 보이는 수 제한.** 중개 서비스(OpenRouter 등)는 수백 개를 내놓지만, 자르면 고를 수 없는 모델이 생긴다. 추천 목록이 위에 있으므로 길이는 받아들인다.

## 결과

- `packages/ai-provider/src/key-models.ts`가 목록을 묻고 거른다. `key-model-refresh.ts`가 언제 묻는지와 설정 파일에 어떻게 쓰는지를 맡는다(`@genoffice/ai-provider/key-models`). `apps/docs/src/main/docs-main.ts`의 공용 AI 창구가 앱 시작과 설정 저장 뒤에 부른다.
- `keyProviderModels(provider, stored, listed)`가 선택기와 설정 화면이 함께 쓰는 목록을 만든다.
- 설정 파일 약속(`docs/contracts.md`), 보내는 것 목록(`PRIVACY.md`, `docs/security.md`)에 이 조회를 적었다.
- 한계: `/models`가 없는 회사(일부 중국 회사)는 고정 목록만 보인다. 목록이 도구 지원 여부를 알려 주지 않는 회사는 이름으로만 거르므로, 도구를 못 쓰는 모델이 섞일 수 있다. 이미지를 받지 못하는 새 모델도 제공자 단위의 이미지 설정을 따르므로, 화면 그림을 보내다 거절될 수 있다. 그런 모델을 고르면 대화가 실패하고, 추천 목록의 모델로 돌아가면 된다. 날짜를 주지 않는 회사(Atlas Cloud 등)의 새 모델은 그 회사가 준 순서대로 붙는다.
- 2026-10-29 실제 응답으로 확인했다(키 없이 열린 목록, 가짜 키): OpenRouter 377개를 최신순으로, Atlas Cloud 117개를 받았다. OpenRouter가 같은 모델을 `:batch` 변형으로 한 번 더 내놓아, 원래 모델이 있으면 빼도록 했다.
