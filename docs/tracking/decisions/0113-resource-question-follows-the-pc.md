# 0113 — 자원 경고는 문서마다 그만 물을 수 있고, 메모리 기준은 PC의 메모리를 따른다

## 맥락

외부 사용자 신고(2026-11, 0.12.11, macOS)가 왔다. 메모리 32GB인 Mac에서 책을 쓰는데 "문서가 리소스를 과도하게 사용하고 있습니다" 창이 짧은 간격으로 계속 떠서, 일을 이어 가려면 매번 "계속 기다리기"를 눌러야 했다. 남은 메모리는 넉넉했다고 한다.

자원 감시(`apps/shell/src/main/renderer-watchdog.ts`)는 30초마다 렌더러를 본다. 메모리 1536MB나 CPU 한 코어의 90%를 열 번(5분) 연달아 넘으면 데이터 폴더에 진단을 남기고 묻는다. "계속 기다리기"는 아무것도 바꾸지 않아서 15분 뒤에 또 묻는다. 메모리 기준은 PC의 메모리와 상관없이 같았다. 신고자가 메모리와 CPU 가운데 어느 쪽에 걸렸는지는 모른다.

원본(GenOffice)은 2026-10-22 스냅샷에서 같은 문제를 고쳤다. 그 스냅샷을 받아올 때 엔진 쪽만 옮겨서 이 수정이 빠져 있었다.

진단 파일(`renderer-watchdog-<시각>.json`, `.cpuprofile`)은 물을 때마다 데이터 폴더에 쌓였고, 지우는 곳이 없었다.

## 결정

- **원본의 수정을 그대로 받아온다.** `renderer-watchdog.ts`와 시험 `renderer-watchdog.test.ts`를 원본 판으로 바꾼다.
  - 창에 세 번째 단추 "다시 알리지 않기"가 생긴다. 누르면 그 문서가 열려 있는 동안 다시 묻지 않고 진단도 남기지 않는다. 다른 문서는 따로 묻는다.
  - 메모리 때문에 물었던 문서는 그때보다 메모리가 25% 넘게 늘었을 때만 다시 묻는다. CPU 때문이면 지금처럼 15분마다 다시 묻는다. 코어 하나를 계속 쓰는 것은 끝나지 않는 반복일 수 있다.
  - 단추 글은 21개 언어 모두 채운다.
- **메모리 기준은 PC 전체 메모리의 8분의 1이고, 1536MB보다 작아지지 않는다.** 8GB PC는 지금과 같은 1536MB, 16GB는 2048MB, 32GB는 4096MB다. 기준을 넘어도 묻기만 한다. 작업을 끊거나 문서를 끝내지 않는다.
- **진단은 최근 다섯 번만 남긴다.** 새 진단을 쓴 뒤 오래된 것을 지운다. 데이터 폴더의 다른 파일은 건드리지 않는다.

## 택하지 않은 것

- **"계속 기다리기"를 누르면 그 문서는 다시 묻지 않기.** 단추가 하나 줄지만 원본과 갈라진다. 원본은 "지금은 기다린다"와 "그만 묻는다"를 나눴다. 이 파일을 원본과 가깝게 두면 다음 받아오기에서 충돌이 적다.
- **남은 메모리(`os.freemem()`)를 기준으로 하기.** macOS에서는 캐시로 쓰는 메모리를 빼고 세어서, 메모리가 넉넉한 Mac에서도 작게 나온다. 신고자 같은 Mac에서 오히려 더 자주 묻게 된다.
- **CPU 기준을 바꾸기.** 신고에서 CPU에 걸렸다는 근거가 없다. CPU 때문에 묻는 일은 "다시 알리지 않기"로 멈출 수 있다.
- **진단을 남기지 않기.** 끝나지 않는 반복이나 메모리 누수의 원인을 찾을 때 쓴다.

## 결과

- 신고와 같은 상황에서, 메모리 때문이었다면 32GB Mac은 문서가 4GB를 넘기 전에는 묻지 않는다. 물었더라도 25% 더 늘기 전에는 다시 묻지 않는다. CPU 때문이었다면 "다시 알리지 않기"를 한 번 누르면 그 문서를 닫을 때까지 묻지 않는다.
- 8GB PC에서 언제 묻는지는 처음 한 번은 그대로다. 같은 문서를 다시 묻는 횟수만 줄어든다.
- 시험: `apps/shell/tests/renderer-watchdog.test.ts`(원본 그대로), `apps/shell/tests/renderer-watchdog-pc-memory.test.ts`(PC 메모리에 따른 기준, 그만 묻게 한 문서와 다른 문서, 진단 다섯 개).
- `renderer-watchdog.ts`에서 원본과 다른 곳은 메모리 기준(`memoryLimitFor`)과 진단 정리(`pruneOldReports`) 두 군데다. 원본을 받아올 때 이 둘을 남긴다.
