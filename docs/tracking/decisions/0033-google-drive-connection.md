# 0033 — 앱이 스스로 Google 앱이 되어 드라이브 전체에 연결한다

> 권한과 고르기는 결정 0085가 바꿨다(2026-10-29): `drive.file` + Google 선택 창, 학습 설정 확인, 무료 연결 제외. 이 기록의 연결·저장·토큰 보관·AI 도구의 읽기 전용과 바깥 도구 차단은 그대로다.

## 맥락

저장소 주인이 "Claude·Codex 데스크톱 앱처럼" 사용자의 Google 드라이브를 연결하길 바랐다(2026-10-15). 그 앱들에서는 연결 버튼 하나로 AI가 드라이브 전체를 찾아 읽는다.

그 앱들의 연결은 회사 서버에서 돈다. Anthropic·OpenAI가 Google에 등록한 앱으로 로그인하고, 토큰은 그 서버에 있고, AI는 서버 쪽 도구로 드라이브를 읽는다. 드라이브 전체를 보는 권한(`drive`, `drive.readonly`)은 Google이 "제한" 등급으로 둔 권한이라, 두 회사는 Google의 앱 검증과 매년 외부 보안 심사를 거친다.

이 앱에는 서버가 없다. 사용자가 Claude·ChatGPT에 이미 연결해 둔 드라이브를 빌려 쓰는 길은 막혀 있다. 기본 AI 창의 구독 프로그램은 도구 0개, 사용자 MCP 연결 없음으로만 돈다(절대 규칙 3, `docs/security.md`). 그 연결만 열어 주면 이 안전장치가 깨지고, 구독을 새 경로로 쓰는 약관 판단도 걸린다.

2026-10-15에 확인한 Google의 조건:

- `drive.file`(앱이 만들었거나 사용자가 Google 선택 창에서 고른 파일만)은 일반 등급이다. `drive`·`drive.readonly`·`drive.metadata.readonly`는 제한 등급이다.
- 제한 등급을 쓰는 앱은 공개 전에 앱 검증을 받는다. 홈페이지와 같은 도메인의 개인정보 처리방침, Search Console의 도메인 소유 확인, 권한을 받는 과정을 보여 주는 영어 시연 영상이 필요하고, 몇 주가 걸릴 수 있다. 검증 전에는 "확인되지 않은 앱" 화면이 먼저 뜨고 새 사용자가 100명으로 묶인다.
- 보안 심사(매년, Google이 지정한 외부 기관)는 "제3자 서버에서 또는 그것을 거쳐 데이터에 닿을 수 있는" 앱에 요구된다. 이 앱은 서버가 없어 PC가 Google에 직접 닿지만, 드라이브 내용이 사용자가 고른 AI 제공자에게 갈 수 있다. 심사가 요구되는지는 Google이 검증 때 정한다.
- 시험 단계("Testing")의 앱이 받은 갱신 토큰은 7일 뒤 만료된다.
- Google Workspace API 사용자 데이터 정책은 받은 데이터를 그 사용자의 개인 모델을 넘어 AI 모델을 만들거나 학습시키는 데 쓰는 것을 금지한다. 이용자가 보이는 기능을 위해, 이용자의 동의로 넘기는 것은 허용된다.

## 결정

**드라이브 전체.** 앱은 저장소 주인의 Google Cloud 프로젝트에 등록한 "데스크톱 앱" OAuth 클라이언트로 `https://www.googleapis.com/auth/drive` 하나를 받는다. 읽기만 하는 `drive.readonly`로는 연 파일을 제자리에 저장할 수 없고, `drive.readonly`에 `drive.file`을 더해도 앱 목록에서 연 파일은 쓸 수 없다. 어느 쪽이든 제한 등급이라 검증 부담은 같다. 계정 표시는 드라이브의 `about`에서 읽고, `openid`·`email` 권한은 받지 않는다.

**로그인.** 시스템 브라우저에서 Google의 로그인 화면으로 한다. 앱 안에 로그인 양식을 만들지 않는다. 무료 연결(결정 0009)과 같은 방식이다. 루프백(`127.0.0.1`)의 임시 서버, 실행마다 새로 만든 PKCE(S256) 검증값과 `state`, 10분 제한. Google이 데스크톱 클라이언트에 주는 `client_secret`은 Google 스스로 비밀로 보지 않는 값이다. 결정 0029가 버린 "앱이 직접 OAuth를 연다"는 구독 회사의 로그인을 앱이 대신하는 일이었다. 이것은 앱 자신이 등록한 Google 앱으로서 하는, Google이 설치형 앱에 권하는 방식이라 그 결정과 부딪히지 않는다.

**토큰 보관.** 갱신 토큰은 Electron `safeStorage`(Windows DPAPI)로 암호화해 데이터 폴더의 `google-drive.json`에 둔다. 접근 토큰은 메모리에만 둔다. 암호화를 쓸 수 없는 PC에서는 저장하지 않고, 앱을 끄면 연결이 끊긴다. 키 제공자의 키처럼 평문으로 두지 않는다. 연결 끊기는 Google에 토큰 폐기를 요청하고 파일을 지운다. 화면 쪽 창은 토큰을 받지 않는다.

**클라이언트 ID는 빌드 때 넣는다.** `GENOFFICE_GOOGLE_CLIENT_ID`·`GENOFFICE_GOOGLE_CLIENT_SECRET`이 빌드 환경에 있을 때만 들어가고, 없으면 드라이브 기능은 화면에 나오지 않는다. 저장소에는 적지 않는다. 다른 사람이 소스로 만든 빌드가 이 앱의 Google 등록을 쓰지 않게 하기 위해서다.

**공개 시점.** Google 검증을 통과하기 전에는 공개 설치 파일에 클라이언트 ID를 넣지 않는다. 그동안은 저장소 주인의 시험 단계 클라이언트로 만든 빌드에서만 쓴다(시험 사용자 100명까지, 7일마다 다시 로그인).

**드라이브에서 열기.** 홈의 "Google 드라이브"에서 내 드라이브·공유 문서함·최근·검색으로 파일을 고른다. 고른 파일은 데이터 폴더의 `drive-cache`에 내려받아 보통 파일처럼 탭으로 연다. Google 문서·스프레드시트·프레젠테이션은 `.docx`·`.xlsx`·`.pptx`로 받아 연다. 앱이 열 수 없는 형식은 목록에 보이되 열지 않는다.

**드라이브에 저장.** 내려받은 파일의 탭에서 저장하면 같은 드라이브 파일에 올린다. 올리기 전에 드라이브 쪽 파일이 내려받은 뒤에 바뀌었는지(`headRevisionId`) 본다. 바뀌었으면 덮어쓰지 않고, 사람이 "덮어쓰기", "드라이브에 사본으로 저장", "이 PC에만 저장" 가운데 고른다. Google 문서 형식의 파일은 원본을 덮어쓰지 않는다. 처음 저장할 때 같은 폴더에 Office 파일(`이름.docx` 등)을 새로 만들고, 그 뒤의 저장은 그 파일을 고친다. Office 파일로 덮어쓰면 Google 문서의 댓글·제안이 사라질 수 있기 때문이다. 올리기에 실패하면 PC의 사본은 남고, 탭이 실패를 알린다.

**AI 도구.** 드라이브가 연결돼 있고 사용자가 "AI가 드라이브를 찾아 읽기"를 켜 두었으면(연결할 때 켬, 설명을 보이고), 편집기의 AI 창에 두 도구를 준다. `drive_search`(이름·본문 검색, 파일 목록)와 `drive_read`(파일 하나의 글)이다. AI 도구는 읽기만 한다. 드라이브에 쓰고, 지우고, 공유하는 도구는 없다. 쓰기는 사람이 누른 저장뿐이다.

- `drive_read`는 파일을 임시 폴더로 받아 `parseFileToText`로 읽는다. 가리기가 다른 파일 읽기와 똑같이 적용된다(결정 0016).
- 한 번의 AI 실행에서 `drive_read`가 쓰인 뒤로는 모델이 정한 글을 밖으로 내보내는 도구(웹 검색, 주소로 그림 가져오기)를 그 실행이 끝날 때까지 거절한다. 문서 속 글에 조종당한 모델이 드라이브 내용을 검색어나 주소에 실어 내보내는 길을 막기 위해서다.
- 드라이브 도구는 사람이 화면에서 보낸 요청에만 있다. 터미널 명령어, MCP, 에이전트 모드에는 주지 않는다.

**드라이브에서 첨부(2026-10-15 추가).** 첨부가 있는 편집기(워드·엑셀·PPT·HTML·마인드맵·한글)의 AI 창에 "Google 드라이브에서 첨부"를 둔다. 껍데기 앱이 고르기 창 하나를 띄우고, 고른 파일과 폴더 바로 아래의 파일(20개까지)을 임시 폴더로 받아 경로를 편집기에 돌려준다. 편집기는 PC 파일처럼 첨부한다. 사람이 고르는 것이라 AI 접근 스위치와 상관없이 되고, 바깥 도구를 막지 않는다. 편집기마다 고르기 화면을 만들지 않고, 버튼은 `packages/ui`의 `DriveAttachButton` 하나다.

**개인정보.** `PRIVACY.md`의 "What leaves your PC"에 연결·목록·내려받기·올리기·AI 읽기를 적고, Google API 데이터 정책(Limited Use)을 따른다는 문장을 넣는다. Google 검증에는 소개 사이트에 올린 같은 글을 쓴다.

## 택하지 않은 것

- **사용자가 Claude·ChatGPT에 연결해 둔 드라이브를 빌려 쓴다.** 도구 0개 규칙을 깨고, 구독을 새 경로로 쓰는 약관 판단이 걸린다.
- **"고른 파일만"(`drive.file` + Google 선택 창).** 검증이 가볍고 연간 심사가 없지만, AI가 드라이브 전체에서 찾을 수 없다. 저장소 주인이 Claude처럼 전체를 고르며 버렸다. 검증이 막히면 돌아갈 자리로 남긴다.
- **Google 드라이브 데스크톱이 만든 `G:` 폴더만 연다.** 앱이 할 일이 거의 없지만 그 프로그램을 따로 깔아야 하고, Google 문서 형식을 열지 못하고, AI가 드라이브를 찾을 수 없다.
- **사용자가 자기 Google Cloud 프로젝트를 만들어 클라이언트 ID를 넣는다.** 검증이 필요 없지만 일반 사용자가 할 수 없고, 시험 단계라 7일마다 다시 로그인해야 한다.
- **토큰을 키처럼 `ai-settings.json`에 평문으로 둔다.** 드라이브 전체에 쓰는 권한이라 키보다 위험이 크다.
- **Google 문서를 Office 파일로 덮어써 제자리에 저장한다.** 파일 하나로 유지되지만 댓글·제안을 잃을 수 있다.

## 결과

- 사용자는 홈에서 드라이브 파일을 열고, 저장하면 드라이브에 올라간다. AI 창에서 "드라이브에서 지난달 회의록 찾아서 요약해 줘"가 된다.
- 저장소 주인이 할 일이 생긴다. Google Cloud 프로젝트와 OAuth 동의 화면 운영, Google API 약관 동의, 앱 검증 신청(소개 사이트 도메인, 개인정보 처리방침, 시연 영상), Google이 요구하면 연간 보안 심사. 검증 전에는 공개 설치 파일에 이 기능이 없다.
- 새 전송 경로가 셋 생긴다. 앱 ↔ Google 드라이브, 드라이브 내용 → AI 제공자, 로그인 때의 Google 토큰 요청. 앱이 처음으로 사용자 계정의 토큰을 직접 가진다.
- 원본에서 없앤 클라우드 기능(`removed-features.test.ts`)을 되살리는 것은 아니다. 원본의 것은 원본 제작사 계정의 프로젝트 목록이었고, 이것은 사용자의 Google 계정에 사용자가 직접 연결하는 것이다. 이름에 `cloud`·`account`를 쓰지 않는다.
