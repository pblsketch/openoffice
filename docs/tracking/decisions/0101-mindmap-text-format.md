# 0101 마인드맵 토픽 글자 서식은 토픽 전체와 글자 일부에 걸고, 사람이 바꾼 토픽에서만 파일에 쓴다

## 맥락

저장소 주인의 요청(2026-11-02)으로 마인드맵에서 굵게, 기울임꼴, 밑줄, 취소선, 글자 색을 바꿀 수 있게 하고, 마인드맵 편집기들이 흔히 주는 글자 크기, 글꼴, 정렬, 영문 대소문자도 함께 넣었다. 주인은 글자 일부에만 거는 서식까지 원했다.

지금까지 엔진은 토픽의 스타일 값을 읽어 보여 주기만 했다. 맞추기(`reconcileSheet`)는 스타일을 쓰지 않았다. 편집기가 스타일을 고치지 않았으니 맞을 수 있었다.

파일 형식은 토픽 전체의 서식을 `style.properties`(`fo:font-weight`, `fo:font-style`, `fo:text-decoration`, `fo:color`, `fo:font-size`, `fo:font-family`, `fo:text-align`, `fo:text-transform`)에, 글자 일부의 서식을 제목 옆의 `attributedTitle`(`[{ text, "fo:…": 값 }]`, 조각의 글을 이으면 `title`)에 둔다. 원래 프로그램은 `attributedTitle`이 있으면 그것을 보여 준다. 그래서 엔진이 `attributedTitle`을 모르는 채 제목만 바꾸면, 원래 프로그램에서는 고치기 전의 제목이 보이는 문제가 이미 있었다.

## 결정

- **엔진**(`text-style.ts`): 보기용 자료에 토픽 전체의 글자 서식 값과, 제목을 정확히 이루는 `attributedTitle` 조각(`titleRuns`)을 싣는다. 제목과 맞지 않는 조각은 보여 주지 않는다.
- **쓰는 조건**: 맞추기에 `restyledTopics`(사람이 서식을 바꾼 토픽 id)를 더한다. 이 목록의 토픽과 상태가 새로 더한 토픽에만 상태의 글자 서식을 쓴다. 그 밖의 토픽은 상태가 무엇을 보이든 파일 값을 둔다(결정 0093의 `removedPictures`와 같은 방식). 값은 엔진이 쓰는 꼴(`isWritableTextStyle`: `#` 16진 색, 100 단위 굵기, 1~400pt, 낱말 목록, 이름 하나뿐인 글꼴)일 때만 쓰고, 아니면 파일 값을 둔 채 화면을 파일대로 다시 그린다. 채우기 색과 모르는 속성, 스타일 id는 그대로 둔다. 글자 서식만 담던 스타일이 비면 스타일째 뺀다.
- **조각**: 서식을 바꾼 토픽, 제목이 바뀐 토픽, 새 토픽에서만 다시 쓴다. 조각이 새 제목을 이루고 서식이 있으면 쓰고, 아니면 `attributedTitle`을 뺀다. 그래서 AI나 대화 상자가 제목만 바꿔도 고치기 전 제목이 남지 않는다. 요약 토픽과 연결선도 제목이 바뀌면 조각을 뺀다. 사람이 손대지 않은 조각은 모르는 키까지 그대로 둔다.
- **편집기**: 서식은 고른 토픽 모두에 걸린다. 제목을 고치는 중에는 굵게·기울임꼴·밑줄·취소선·글자 색이 고른 글자에만 걸린다. 입력 상자는 라이브러리의 일반 글 상자(`plaintext-only`)로 두고, 조각은 이 편집기가 `textContent`로 만든 span이다. 서식 값은 span 옆에 따로 들고 있다가 읽고, 마크업에서 읽지 않는다. 토픽 전체에 건 서식은 같은 키를 조각에서 뺀다. 테마가 이미 그리는 값(굵은 큰 가지에 굵게 등)은 값으로 쓰지 않아, 걸었다가 풀면 원본 바이트로 저장된다.
- **화면**: 도구 줄에 굵게·기울임꼴·밑줄·취소선과 "글자 서식" 단추를 둔다. 글자 서식 칸(테마·메모·AI 칸과 같은 자리, 하나씩)에 글꼴, 크기, 모양, 공용 색 팔레트, 정렬, 대소문자, 서식 지우기를 둔다. 단축키는 Ctrl+B·I·U와 Ctrl+Shift+X이고, 키 위치로 읽어 한글 자판에서도 된다.
- **AI**: `edit_map`에 `set_format`(토픽 전체)을 더하고 `read_topic`이 서식을 알린다. 글자 일부 서식은 AI에 주지 않는다.

## 버린 대안

- **상태와 파일을 견주어 다른 서식은 언제나 쓰기**: 편집기가 서식 정보를 잃는 경우(붙여 넣기, 버그)마다 파일의 서식이 지워진다. 그림(0075, 0093)에서 막은 것과 같은 위험이다.
- **입력 상자를 서식 있는 편집기(`contenteditable="true"`)로 바꾸기**: 붙여 넣은 HTML이 그대로 들어올 수 있어, 파일의 글을 HTML로 해석하지 않는다는 규칙을 지키기 어렵다.
- **이 앱만의 키로 글자 일부 서식 저장**: 원래 프로그램이 보여 주지 않고, 파일에 이 앱만의 표식을 넣지 않는다는 엔진 규칙에 어긋난다.
- **글자 일부에 크기·글꼴까지 걸기**: 입력 상자에서 글꼴 목록이나 크기 칸으로 포커스가 가면 고른 글자가 풀린다. 파일에서 온 조각의 크기·글꼴은 그려 주고 보존한다.

## 결과

- 마인드맵에서 토픽 전체와 제목 일부에 서식을 걸 수 있고, Ctrl+Z 한 번으로 되돌린다. 되돌린 뒤의 저장은 원본 바이트 그대로다.
- 엔진이 처음으로 `style.properties`와 `attributedTitle`을 쓴다. 쓰는 곳은 `reconcile-tree.ts`의 `writeTextStyle`·`writeTitleRuns` 둘이다.
- 내보내기(PNG·PDF·인쇄)는 화면을 복사하므로 서식이 그대로 나오고, 토픽에 남기는 스타일 속성 목록에 새 속성이 더해졌다.
- 실제 앱 확인: `apps/mindmap/tests/real-run/format-run.ts`가 빌드한 단독 편집기에서 키보드로 고른 글자 서식, 서식 있는 조각 안에 치기, 칸의 팔레트, 저장 뒤 파일 값을 본다(2026-11-02 통과).
- 남은 확인: 이 앱에서 서식을 건 지도를 원래 프로그램에서 열어 보는 일은 사람이 한다. 밑줄(`underline`)은 원래 프로그램의 화면에 없는 값이라 거기서 보이지 않을 수 있다.
