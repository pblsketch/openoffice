# 0094 — 슬라이드 엔진에 강조 색·문자 간격과 도형 숨기기·이름을 더하고, 도형 병합 라이브러리를 들인다

## 맥락

슬라이드 편집기에 PowerPoint에서 자주 쓰는 편의 기능을 채우면서(서식 복사 확대, F4 반복, 스포이트, 선택 창, 애니메이션 복사, 같은 크기, 대/소문자 바꾸기), 앱 쪽만으로는 할 수 없는 것이 넷 남았다.

- **텍스트 강조 색(`a:highlight`)과 문자 간격(`spc`).** 엔진은 둘을 읽고, 문단을 통째로 다시 만드는 저장 길에서는 쓴다. 그러나 런 수가 같을 때 타는 제자리 패치(`patchRunProps`)는 둘을 쓰지 않았다. 편집기는 두 값을 돌려보내지도 않았다.
- **도형 숨기기(`p:cNvPr hidden="1"`).** 숨긴 도형은 열 때 원본 바이트만 지닌 조용한 통과 요소가 되어 그려지지도, 고쳐지지도 않는다. 숨기거나 다시 보이게 할 연산이 없었다.
- **도형 이름 바꾸기(`p:cNvPr name`).** 이름을 쓰는 연산이 없었다.
- **도형 병합.** 도형 윤곽의 합집합·차집합 계산이 필요한데 저장소에 그런 라이브러리가 없다.

저장소 규칙은 문서 엔진의 동작을 원본이 바뀔 때만 바꾸고, 바꿔야 하면 사람에게 묻게 한다. 저장소 주인이 엔진 수정과 새 의존성을 승인했다(2026-10-31).

## 결정

- **강조 색과 문자 간격은 "편집된 런만" 제자리 패치에서 쓴다.** 런에 `highlightEdited`·`letterSpacingEdited` 표시를 두고, 표시가 선 런만 `<a:highlight>`(스키마 순서대로, 채움·효과 뒤 글꼴 앞)와 `spc`를 쓰거나 지운다. 손대지 않은 런은 바이트 그대로다(테마 색 강조도 그대로 남는다). `setFont`가 `font.highlight`(`null`은 지움)와 `font.letterSpacingPt`를 받고, 편집기의 `EditRun`이 `highlight`·`letterSpacing`을 돌려보낸다. `applyEditParagraphs`는 값이 실제로 바뀐 런에만 표시를 세운다(문자 간격은 0.05pt 미만 차이를 같은 값으로 본다).
- **숨기기·이름은 도형 자신의 `p:cNvPr` 속성만 고친다.** 새 엔진 함수 `setElementHidden`·`setElementName`이 원본 조각의 첫 `p:cNvPr` 여는 태그에서 속성 하나만 바꾼다(차트를 편집 가능하게 표시하는 `markChartEditable`과 같은 방식). 숨기기는 열 때와 같은 해석이 되도록 연산이 끝에서 슬라이드를 다시 읽는다(`materializeSlide`, 붙여넣기와 같은 길). 그래서 숨기기·보이기 뒤에는 그 슬라이드의 요소 id가 모두 바뀐다. 연산 이름은 `setElementHidden`·`renameElement`이고 최상위 요소만 받는다.
- **도형 병합은 앱 화면 쪽에서 계산하고, 저장은 기존 연산만 쓴다.** 윤곽을 다각형으로 펴서 `polygon-clipping`(MIT, 의존: `splaytree` MIT·`robust-predicates` Unlicense — 후자는 이미 의존성 나무에 있다)으로 합치고, 결과를 `addElement` + `setShapeGeometry`(사용자 지정 도형) + 서식 연산으로 만든 뒤 원본을 지운다. 실행 취소 한 번으로 묶는다. 엔진은 바뀌지 않는다.
- **원본과 다른 점은 `packages/pptx-engine/AGENTS.md`와 `packages/pptx-ops/AGENTS.md`의 "원본과 다른 점"에 시험과 함께 적는다.** 원본을 받아올 때 그 시험이 통과하는지 본다.

## 택하지 않은 것

- **숨긴 도형도 열 때부터 온전한 모델로 만들기.** 그리면 안 되는 요소가 AI 문맥·내보내기·쇼·모핑 짝짓기 같은 모든 소비자에 들어가, 각각 숨김을 걸러야 한다. 열기의 해석은 그대로 두고, 바꿀 때만 다시 읽는다.
- **강조 색·문자 간격을 늘 쓰기.** 제자리 패치가 손대지 않은 런의 테마 색 강조를 `srgbClr`로 굳히고, 변경 없는 저장의 바이트 동일성을 깬다.
- **도형 병합을 엔진에 넣기.** 계산은 화면 좌표의 윤곽으로 충분하고, 저장은 이미 있는 사용자 지정 도형 쓰기로 된다. 엔진에 기하 라이브러리를 들이지 않는다.
- **병합 계산을 직접 짜기.** 겹친 꼭짓점·같은 선 위의 변 같은 경계 사례가 많아, 검증된 라이브러리를 쓴다.

## 결과

- 강조 색·문자 간격을 바꾼 런은 제자리 패치로도 저장된다. 바꾸지 않은 런의 바이트는 그대로다.
- 선택 창에서 숨긴 도형이 파일에 `hidden="1"`로 남고, 다시 보이게 할 수 있다. 숨기기·보이기는 그 슬라이드를 다시 읽으므로 선택이 풀리고 애니메이션 목록을 다시 읽는다.
- 도형 병합 결과는 사용자 지정 도형 하나(조각은 조각마다 하나)이고 처음 선택한 도형의 채우기·선·효과를 쓴다. 처음 도형의 글은 옮기지 않는다. 별·화살표처럼 화면이 사각형으로 근사해 그리는 도형과 선·그림·표·차트는 병합하지 않는다.
- 명령줄 도구·MCP에도 `setElementHidden`·`renameElement`와 `setFont`의 두 필드가 드러난다(연산 문서에 적었다).
- 원본을 받아올 때 `generate.ts`(`patchRunProps`), `index.ts`(`ElementFontPatch`·`applyFontPatch`·새 함수), `types.ts`, `pptx-ops`의 `edit-text.ts`·`text-ops.ts`·`element-ops.ts`·`types.ts`에서 충돌이 날 수 있다. 목록의 시험이 그 결과를 지킨다.
- 메인 검사본은 이 변경이 합쳐진 뒤 `npm ci`로 `polygon-clipping`을 받아야 한다.
