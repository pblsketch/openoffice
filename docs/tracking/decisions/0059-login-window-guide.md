# 0059 — 보이는 로그인 창은 앱의 안내를 먼저 보이고, 끝나지 않은 로그인은 창을 남긴다

## 맥락

결정 0029로 로그인은 창을 숨긴 채 브라우저에서 하고, 브라우저가 열리지 않을 때만 카드의 링크로 보이는 창을 연다. 그 창은 Claude·Codex 프로그램의 콘솔 그대로였다. 영어 안내 몇 줄과 긴 주소, "Paste code here if prompted >"만 보였다.

2026-10-23 시험 사용자가 그 창에서 "Invalid code. Please make sure the full code was copied."를 받고 막혔다. 저장소 주인은 터미널 창 자체를 낯설어하는 사람이 계속 나온다고 했다. 설치된 Claude Code 2.1.287의 `claude auth login`을 확인하니 이렇게 동작한다.

- 붙여 넣은 줄을 `#`에서 나눠 앞뒤 둘 다 있어야 받는다. 빈 줄, 반만 복사한 코드, 주소창의 주소는 모두 이 문구가 된다. 문구를 찍은 뒤에도 끝나지 않고 다음 줄을 기다린다.
- 입력한 글자를 화면에 보이지 않는다(결정 0029 뒤의 findings 항목). 붙여 넣기가 됐는지 사용자가 알 수 없다.
- 브라우저는 언제나 자동 복귀 주소로 연다. 코드를 붙여 넣는 화면은 창에 찍힌 주소를 사람이 직접 열었을 때만 나온다. 숨긴 로그인에서는 브라우저에 코드가 나오지 않는다.

카드도 문제를 키웠다. 링크 글이 "브라우저가 안 열리거나 코드가 나오나요?"여서 코드를 찾아 붙여야 한다고 읽혔다. 25초가 지나면 이 링크가 "로그인 창 열기" 버튼으로 올라오는데, 브라우저에서 아직 로그인하던 사람이 누르면 앱은 잘 돌던 숨긴 로그인을 끝낸다. 그 브라우저 탭은 허용을 눌러도 돌아갈 곳이 없다.

## 결정

- 보이는 로그인 창은 앱의 PowerShell이 연다. 창 제목을 "Claude 로그인"처럼 바꾸고, 화면 언어로 된 안내(그 회사 프로그램의 로그인 창이라는 것, 1·2·3 단계)를 먼저 찍은 뒤 같은 창에서 프로그램을 실행한다. 제목과 안내에 제품 이름을 넣지 않는다. 그 회사의 로그인을 이 제품의 기능처럼 보이게 하지 않기 위해서다(결정 0052, 구독 문구에 제품 이름을 막는 시험이 지킨다). 프로그램은 그 창의 콘솔을 그대로 쓰므로 붙여 넣는 입력을 직접 받는다.
- 안내는 Claude에 네 단계(브라우저에서 로그인, 브라우저가 안 열리면 주소 복사, 코드는 복사 버튼으로 복사해 마우스 오른쪽 버튼으로 붙여 넣고 Enter, "Invalid code"면 다시 붙여 넣기), Codex에 앞의 두 단계를 둔다. Codex는 코드를 붙여 넣는 흐름이 없다.
- 프로그램이 로그인을 끝내지 못하고 나가면 창은 바로 닫히지 않는다. 안내 한 줄을 더 찍고 Enter를 기다린다. 오류 문장을 읽을 수 있게 하기 위해서다. 앱의 로그인 취소는 그대로 창까지 끝낸다.
- 아랍어·히브리어·힌디어·태국어는 Windows 콘솔이 글자를 제대로 그리지 못해 창 안내만 영어로 보인다. 카드 글과 도움말은 그 언어 그대로다.
- 카드 글을 바로잡는다. 링크는 "브라우저가 열리지 않았나요?"이고, 25초 뒤의 안내는 브라우저에서 로그인하는 중이면 누르지 말라고, 누르면 하던 로그인이 멈추고 새로 시작한다고 말한다. 창이 열린 뒤의 카드 글은 창 맨 위의 안내를 따르라고 하고, 먼저 열려 있던 로그인 화면은 쓰이지 않는다고 알린다.

앱은 여전히 코드와 로그인 정보를 받지도 넘기지도 않는다. 사용자가 붙여 넣은 글은 콘솔을 거쳐 프로그램으로 바로 간다. 안내 글은 앱의 번역 사전에 고정된 글이고, 창을 연 화면이 보낸 글이 아니다. 실행 파일 경로, 인자, 안내 글은 모두 환경변수에 값으로 담기고, 두 PowerShell 글은 상수다. 프로그램이 시작하기 전에 그 변수들을 지운다.

## 택하지 않은 것

- **앱이 코드 입력란을 두고 받은 코드를 프로그램에 넘긴다.** 결정 0029가 버린 안과 같다. 앱 화면의 로그인 양식이고 회사의 이용 조건에 걸린다.
- **앱이 로그인 파일이 생기는 것을 지켜보고 연결을 먼저 표시한다.** 구독 로그인 저장소에 닿는 코드다(절대 규칙 1). 로그인이 끝나면 프로그램이 나가고, 앱은 그때 상태를 다시 묻는다.
- **`claude setup-token`으로 받은 토큰을 앱에 넣게 한다.** 앱이 구독 로그인 정보를 저장하게 된다.
- **브라우저 여는 일을 앱이 맡는다.** Claude는 `BROWSER` 환경변수가 있으면 그 프로그램에 로그인 주소를 넘긴다. 앱이 그 주소를 받아 브라우저를 열면 브라우저가 안 열리는 PC도 창 없이 끝날 수 있다. 그러나 앱이 로그인 요청 주소(`state` 값이 들어 있다)를 다루게 되고, 문서로 약속된 동작도 아니다. 저장소 주인의 판단이 필요해 이번에는 하지 않았다.
- **안내를 붙이지 않고 프로그램 창을 그대로 둔다.** 이 창에서 막혔다는 신고가 0.12.0, 0.12.2에 이어 이번이 세 번째다.

## 결과

- 보이는 창에서는 화면 언어의 안내 아래에 Claude의 영어 글이 이어진다. 프로세스는 숨긴 PowerShell → 보이는 PowerShell → 프로그램 세 단계가 되고, 앱이 쥔 것은 여전히 맨 앞 PowerShell이다. 취소와 종료 정리는 그 나무 전체를 끝낸다.
- 숨긴 로그인은 바뀌지 않았다.
- 이 PC에서 실제 창 글을 가짜 프로그램으로 돌려 확인했다(공백이 든 경로, 진짜 콘솔 입력, 넘긴 변수가 남지 않음, 끝나지 않은 로그인에서 창이 남고 취소로 끝남). 실제 Claude 로그인 화면과 안내가 함께 보이는 모습, 시험 사용자의 Windows Terminal에서의 붙여 넣기는 시험 사용자 PC에서 확인해야 한다.
