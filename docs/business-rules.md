# 동작 규칙

## 용어

| 용어           | 뜻                                                                                                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 구독 제공자    | 사용자 PC에 설치된 Claude Code 또는 Codex 프로그램을 통해 쓰는 AI. 식별자 `claude-code`, `codex`                                                                                                                     |
| 키 제공자      | 사용자가 API 키나 주소를 직접 넣어 쓰는 제공자 전체. 로컬 모델 연결도 여기에 든다                                                                                                                                    |
| 구독 로그인    | 구독 제공자 프로그램이 구독 요금제 계정으로 로그인된 상태                                                                                                                                                            |
| 종량 로그인    | 그 프로그램이 API 키나 종량제 계정으로 로그인돼, 쓴 만큼 요금이 나가는 상태                                                                                                                                          |
| 화면 경로      | 사람이 앱 화면에서 직접 시킨 요청                                                                                                                                                                                    |
| 자동 호출 경로 | 터미널 명령어나 MCP로 들어온 요청                                                                                                                                                                                    |
| 문서 작업      | PDF의 AI 페이지 읽기, 문서 번역, AI 핵심 표시, 긴 문서의 개요. 사용자가 시작을 확인하면 AI 요청 여러 번을 차례로 보내는 작업. 대역 보기의 페이지 번역도 같은 엔진으로 돌지만 시작 전 확인의 예외다(아래 "문서 작업") |
| 보관소         | PDF의 AI 결과(AI가 읽은 페이지, 번역, 구절 카드, AI 핵심 표시 제안, 문서 개요)와 끝나지 않은 작업의 기록을 PC에 두는 곳                                                                                              |
| 원본           | 이 프로젝트의 출처인 GenOffice와 그 설치본                                                                                                                                                                           |

같은 "연결됨"이라도 뜻이 둘이다. 구독 카드의 "연결됨"은 상태 `ready`(구독 로그인 확인)이고, 제공자 선택 결과의 "연결됨"은 지금 요청을 보낼 제공자가 정해졌다는 뜻이다. 키 제공자를 직접 골라 둔 사람은 구독이 하나도 없어도 뒤의 뜻으로 연결된 상태다.

## 구독 연결 상태

제공자마다 상태가 하나 있고, 값은 여섯 가지뿐이다.

| 상태            | 조건                                       | 사용자가 할 수 있는 일                                                   |
| --------------- | ------------------------------------------ | ------------------------------------------------------------------------ |
| `checking`      | 확인 중                                    | 기다린다                                                                 |
| `not-installed` | 프로그램을 찾지 못함                       | 설치 버튼, 공식 설치 안내 링크                                           |
| `signed-out`    | 설치됐으나 로그인 안 됨                    | 로그인 버튼                                                              |
| `ready`         | 구독 로그인 확인됨                         | 바로 쓴다. 프로그램이 알려 주면 요금제 이름이 함께 보인다                |
| `metered`       | 종량 로그인이거나 로그인 방식을 알 수 없음 | 요금 경고를 읽고 "그래도 사용"을 고르거나, 구독 계정으로 다시 로그인한다 |
| `error`         | 확인 자체가 실패                           | 다시 확인. 프로그램 버전이 낮으면 업데이트 후 다시 확인                  |

- 프로그램 버전이 낮은 `error`에서 Claude는 찾은 버전, 앱이 요구하는 최소 버전(`SUBSCRIPTION_MIN_VERSIONS`), 업데이트 명령 `claude update`를 함께 보여 준다. 최소 버전이 없는 Codex는 "업데이트한 뒤 다시 확인"만 보인다.
- Claude의 버전이 낮은 `error` 카드에는 앱이 실행한 프로그램 파일의 경로가 한 줄 더 보인다. 한 PC에 사본이 여럿일 수 있어서다(WSL 안의 사본, 예전 npm 설치). Windows에서는 "WSL(Ubuntu)이나 다른 폴더의 사본을 업데이트해도 이 파일은 바뀌지 않으니 Windows PowerShell에서 업데이트 명령을 실행하라"는 줄이 이어진다.
- `ready`는 로그인 방식이 구독일 때만이다. 방식을 알 수 없으면 `ready`가 아니라 `metered`다. 모르는 것을 구독으로 치지 않는다.
- 확인하는 때: 앱 시작 후 첫 조회, 설정 화면을 열 때, 설치나 로그인을 띄운 뒤 앱 창으로 돌아왔을 때. 두 제공자를 동시에 확인하고, 20초 안에 답이 없으면 `error`다.
- 설치 버튼은 그 회사의 공식 설치 명령을 눈에 보이는 새 터미널 창에서 실행한다. 앱이 설치 파일을 내려받지 않는다. 설치가 실패하면 상태는 `not-installed`로 남는다.
- 앱이 터미널 창을 직접 여는 일(설치 버튼, 업데이트 버튼, 코드를 붙여 넣는 로그인 창)은 Windows에서만 한다. Mac에서는 `not-installed` 카드에 공식 설치 안내 링크만 있고, 로그인하는 동안 "코드가 나오나요?" 링크가 없다. 브라우저가 로그인을 받아 가지 못하면 사용자가 터미널에서 로그인 명령을 직접 실행한다(결정 0031).
- 로그인 버튼은 그 프로그램의 로그인 명령을 창 없이 실행한다. 카드는 "로그인하는 중"이 되어 열린 브라우저에서 로그인하라고 안내한다. 로그인이 끝나면 상태를 다시 확인한다. 브라우저가 열리지 않거나 코드를 보여 주면 카드의 링크("브라우저가 안 열리거나 코드가 나오나요?")가 같은 명령을 보이는 창으로 다시 띄우고, 카드는 그 창에 코드를 붙여 넣으라고 안내한다. 창 없는 로그인이 10분 안에 끝나지 않거나 사용자가 창을 닫으면 상태는 그대로(`signed-out`) 남는다. "로그인하는 중"은 상태의 `signingIn`(`browser`, `window`)이고 모든 편집기의 카드가 같은 값을 본다.
- 브라우저 로그인이 25초(`AI_SIGNING_IN_STALLED_MS`) 안에 끝나지 않으면, 카드는 "브라우저가 열리지 않았거나 코드가 보이나요?"라는 안내를 더하고 로그인 창 링크를 "로그인 창 열기" 버튼으로 올린다. 시간은 그 카드가 로그인 중인 것을 처음 본 때부터 센다.
- 로그인하는 동안 카드에는 "로그인 취소" 링크가 있다. 누르면 앱이 띄운 로그인(숨긴 것이든 보이는 창이든)을 하위 프로세스까지 끝내고, "로그인하는 중" 표시를 바로 지우고, 그 제공자를 다시 확인한다. 진행 중인 로그인이 없으면 아무것도 하지 않는다.
- 프로그램 버전이 낮은 `error` 카드에는 "업데이트" 버튼이 먼저 나온다(결정 0047). 그 회사의 공식 업데이트를 눈에 보이는 새 창에서 실행하고, 창은 끝나도 닫히지 않는다. Claude는 앱이 찾은 실행 파일에 `update`를 준다. Codex는 찾은 파일이 npm 설치면 `npm install -g @openai/codex@latest`, winget 설치면 `winget upgrade --id OpenAI.Codex -e`다. 어떻게 설치됐는지 모르는 Codex(데스크톱 앱의 사본, 사용자가 지정한 경로)와 업데이트를 띄우지 못한 경우는 공식 설치 안내 페이지를 연다. 앱은 업데이트를 기다리지 않고, 앱 창으로 돌아오면 다시 확인한다.
- **종량 허용.** "그래도 사용"은 제공자별로 기억한다. 로그인 방식의 종류가 바뀌거나 로그아웃되면 허용은 지워진다. 앱에서 로그인이나 로그아웃을 실행한 경우에는 로그인 방식의 종류가 같더라도 지워진다(다른 계정일 수 있다). 허용했다고 자동 선택 후보가 되지는 않는다.
- ChatGPT 계정으로 로그인된 Codex는 요금제가 무료여도 `ready`다. 무엇이 되는지는 그 요금제가 정한다.

## 계정 보기, 바꾸기, 로그아웃

설정 → AI의 구독 카드에서만 된다. 첫 실행 안내의 카드와 AI 창의 카드에는 계정도 버튼도 나오지 않는다.

- 프로그램이 로그인돼 있고(`ready`, `metered`) 계정을 알려 주면, 카드에 그 계정(이메일)이 요금제 이름과 함께 보인다. 예: `user@example.com · max`.
- 이 값은 화면에 보여 주기만 한다. 설정 파일, 종량 허용 기록, 로그, 터미널 명령어·MCP의 출력에 남기지 않는다. 조직 이름은 읽은 즉시 버린다.
- **다른 계정으로 로그인**은 그 프로그램의 로그인 명령을 다시 실행한다(Claude `auth login`, Codex `login`). **로그아웃**은 그 프로그램의 로그아웃 명령을 실행한다(Claude `auth logout`, Codex `logout`). 앱은 로그인 화면을 만들지 않고 로그인 정보에 손대지 않는다.
- 두 동작 모두 이 PC의 그 프로그램 전체에 적용된다. 터미널에서 따로 쓰는 것도 함께 로그아웃되거나 계정이 바뀐다. 누르면 프로그램 이름과 이 사실을 적은 확인이 먼저 나오고, 확인을 눌렀을 때만 실행한다. 취소하면 아무것도 실행하지 않는다.
- 명령이 끝나면 상태를 다시 확인한다. 로그아웃 뒤의 상태는 `signed-out`이고, 종량 허용은 위 규칙대로 지워진다.
- 로그아웃이 실패하면 번역된 한 문장으로 알린다. 프로그램이 낸 글은 보여 주지 않는다.

## 제공자 선택

설정값은 `auto` 또는 제공자 식별자 하나이고, 기본은 `auto`다.

`auto`의 순서:

1. `claude-code`가 `ready`이면 Claude
2. 아니면 `codex`가 `ready`이면 Codex
3. 둘 다 아니면 "연결 필요"

- `auto`는 요금이 나가는 연결을 고르지 않는다. 키 제공자도, 허용된 종량 로그인도 후보가 아니다.
- 직접 고를 수 있는 것: `ready`인 구독 제공자, 사용자가 허용한 종량 로그인(유료 표시가 붙는다), 설정이 채워진 키 제공자. "설정이 채워졌다"는 모델과 키가 있다는 뜻이고, 직접 운영하는 서버는 모델과 주소가 있으면 된다.
- 직접 고른 제공자를 쓸 수 없게 되면 다른 제공자로 넘어가지 않는다. 연결 안내를 보여 준다.
- 무료 연결 카드에서 연결을 마치면 그 제공자가 "사용할 AI"로 저장된다. 연결 버튼을 누른 것이 그 제공자를 고른 것이다. `auto`의 후보가 되는 것은 아니다.
- "연결 필요" 상태에서 AI를 쓰려 하면 오류 문구가 아니라 연결 카드와 버튼이 나온다. 적어 둔 글은 입력창에 남는다.

| 상황                                                             | 결과                                                                                      |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 두 구독이 모두 `ready`, 선택 `auto`                              | Claude                                                                                    |
| Claude의 상태를 아직 모름(확인 중), Codex는 `ready`, 선택 `auto` | 정해질 때까지 기다린다. 요청은 붙잡아 둔다. Claude가 `ready`가 아닌 것으로 정해지면 Codex |
| Claude는 `ready`, Codex의 상태를 아직 모름, 선택 `auto`          | Claude. Codex를 기다리지 않는다                                                           |
| Claude는 `metered`(허용됨), Codex는 `ready`, 선택 `auto`         | Codex                                                                                     |
| 구독은 없고 키 제공자만 설정됨, 선택 `auto`                      | 연결 필요. 키 제공자는 직접 골라야 쓰인다                                                 |
| 종량 로그인을 직접 골랐으나 허용하지 않음                        | 실행하지 않고 `metered-not-accepted`                                                      |
| 저장된 설정에 없어진 식별자나 모르는 식별자가 있음               | 그 자리를 기본값으로 읽는다. 오류 창을 띄우지 않고, 다음 저장 때 지워진다                 |

## 무료 연결

구독이 없는 사람을 위한 연결이다. 정체는 키 제공자 둘(OpenRouter, Gemini)이고, "무료"인 것은 그 제공자의 무료 등급에서 도는 모델을 쓰기 때문이다.

| 제공자     | 연결 방법                                                                                                                                  | 쓰는 모델                                                                                                | 남은 양 표시                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| OpenRouter | "브라우저로 연결" → 시스템 브라우저에서 OpenRouter 로그인·허용 → 브라우저가 이 PC로 돌아오면 끝. 키를 복사하지 않는다                      | 이름이 `:free`로 끝나는 모델. 시험을 통과한 목록에서 OpenRouter가 지금 도구 호출과 함께 제공하는 첫 모델 | "오늘 무료 요청 N번 중 M번 남음"     |
| Gemini     | "키 만들기"로 Google AI Studio의 키 페이지를 연다 → 만든 키를 붙여넣고 "연결" → 앱이 모델 목록을 읽어 키를 확인(무료 사용량을 쓰지 않는다) | `gemini-3.5-flash-lite`. 모델 선택기에서 다른 Gemini 모델로 바꿀 수 있다                                 | 없다. Google이 알려 주는 방법이 없다 |

- 카드는 설정 → AI의 "무료로 쓰기"와 첫 실행 안내의 연결 단계에 있다. 키 제공자 칸(고급)과 같은 설정값을 쓴다. 고급에서 같은 제공자의 키를 바꾸면 카드에도 반영된다.
- OpenRouter 카드는 저장된 모델이 `:free`일 때만 "연결됨"이다. 고급에서 유료 모델로 설정해 둔 OpenRouter는 무료 연결이 아니다. Gemini 카드는 키만 있으면 "연결됨"이다.
- 무료 연결의 모델 선택기에는 무료 모델만 나온다. 유료 모델을 골라 요금이 나가는 일을 막는다. Gemini는 키 하나에 무료·유료 구분이 없으므로, 결제가 연결된 Google 프로젝트의 키는 요금이 나갈 수 있다고 카드에 적는다.
- "연결 해제"는 그 제공자의 키를 지우고 모델을 기본값으로 돌린다. 그 제공자가 "사용할 AI"였으면 `auto`로 돌아간다. OpenRouter 쪽에 만들어진 키는 앱이 지우지 못한다(OpenRouter 설정에서 지운다).
- 연결된 카드가 "사용할 AI"가 아니면 "이 AI 쓰기" 버튼이 나온다. 누르면 그 제공자를 고른 것으로 저장한다.
- 카드 아래에는 늘 같은 안내가 있다. 무료로 쓰는 동안 보낸 내용은 그 회사의 AI 개선에 쓰일 수 있다. Gemini 카드에는 18세 이상만 쓸 수 있다는 안내가 있다.
- 아무 AI도 연결되지 않은 상태의 "AI 연결" 안내(편집기의 AI 창, 홈의 질문 패널)와 첫 실행 안내의 연결 단계는 연결 도우미다(결정 0047). 먼저 "지금 쓰고 있는 AI가 있나요?"를 묻고 세 가지 답을 낸다. Claude 유료 구독(Pro·Max가 있어야 하고 무료 계정은 안 된다고 적는다), ChatGPT(ChatGPT 계정으로 Codex 프로그램에 로그인한다고 적는다), 아직 없음(무료 AI). 답 옆에는 이미 있는 것(설치됨, 연결됨, 로그인하는 중, 확인 필요)이 짧게 붙는다.
- 고른 길 하나만 펼친다. 구독 길에는 `프로그램 설치 → 로그인 → 연결 완료` 단계와 지금 단계, 그 아래 그 제공자의 카드 하나가 있다. 버전이 낮은 프로그램은 설치 단계로, 그 밖의 확인 실패는 로그인 단계로 친다. 무료 길은 AI 창에서는 "무료 AI 연결하기" 버튼(누르면 설정 → AI가 열린다)이고, 첫 실행 안내에서는 무료 연결 카드가 그 자리에 펼쳐진다. "다른 방법 고르기"로 질문에 돌아간다.
- 사용자가 고르지 않았으면 로그인 중인 제공자, 그다음 연결된 구독, 그다음(첫 실행 안내에서만) 연결된 무료 AI의 길이 저절로 펼쳐진다. 고른 길은 저장하지 않는다. 화면을 닫으면 다시 묻는다.
- 연결된 것이 없는 동안 도우미 아래에 "도움 요청용 정보 복사"가 있다. 복사되는 것은 제공자마다의 상태, 오류 종류, 프로그램 버전, 로그인 중인지, 종량 허용 여부와 `navigator.platform`·`navigator.userAgent`(앱 이름과 버전, Electron, Windows 버전)뿐이다. 계정, 경로, 프로그램이나 오류가 낸 글은 넣지 않는다.
- 설정 → AI의 카드는 도우미 없이 두 제공자를 그대로 보인다. 업데이트 버튼, 로그인 취소, 로그인 창 올리기는 같이 받는다.

## 모델 목록과 모델 이름

- 구독 제공자의 모델 목록에는 그 프로그램이 알려 주는 모델이 나온다. 항목마다 표시 이름과 실제 모델 식별자가 함께 보인다(예: "Opus 5.5"와 `claude-opus-5-5`). "기본 모델" 항목에는 그것이 지금 가리키는 모델이 적힌다(프로그램이 알려 줄 때).
- 지금 쓰는 모델을 보여 주는 자리(AI 창 아래의 선택 표시, 설정의 "사용할 AI")에도 모델 이름이 보인다. 자동일 때도 실제로 답할 모델이 보인다. 예: "자동 · Claude · Opus 5.5".
- 목록을 얻는 일은 모델 호출이 아니다. 구독 한도를 쓰지 않는다. Claude는 프로그램을 띄워 시작 응답만 읽고 끝내고, Codex는 프로그램의 모델 목록 조회를 쓴다.
- 목록은 연결 상태를 확인할 때, 앱이 쓸 수 있는 로그인(`ready`, 또는 사용자가 허용한 `metered`)의 프로그램에 묻는다. 허용하지 않은 종량 로그인으로는 프로그램을 띄우지 않고, 허용하는 순간에 묻는다. 상태가 먼저 나가고 목록은 도착하는 대로 뒤따른다. 목록이 늦거나 얻지 못해도 상태는 그대로고, 오류 창은 뜨지 않는다.
- 새 모델이 나와도 앱을 다시 시작할 필요는 없다. 모델 선택기를 열 때 2분에 한 번 구독 프로그램에 목록을 다시 묻는다(모델 호출이 아니므로 한도를 쓰지 않는다). 새 모델은 목록이 도착하는 대로 보인다.
- 목록을 얻지 못하면(프로그램이 낡았거나 조회가 실패) 앱에 들어 있는 고정 목록이 나온다.
- 저장하는 선택값은 프로그램이 받는 값 그대로다. 표시 이름은 저장하지 않는다. 빈 값은 프로그램의 기본 모델이다. 목록에 없는 값이 저장돼 있으면 그 값도 목록에 그대로 보인다.

## 보내기 전의 문지기 (모든 편집기 공통)

1. 연결 상태를 아직 모르면(확인 중) 요청을 붙잡아 둔다. 상태가 정해져 실행할 수 있으면 시작하고, "연결 필요"로 정해지면 시작하지 않고 버린다(적어 둔 글은 입력창에 남는다).
2. 구독 제공자를 처음 쓰게 되는 순간이고 첫 연결 안내를 아직 보지 않았으면, 안내를 먼저 보여 준다. 붙잡아 둔 요청은 사용자가 안내를 확인했을 때만 시작한다. 안내가 다른 이유로 사라지면 버린다.
3. 연결 필요면 요청을 보내지 않고 연결 카드를 눈에 보이는 곳으로 끌어온다. 대기열이 있으면 멈춘다.
4. 그 밖에는 실행한다.

## 실행 중 막혔을 때

- 한도 소진, 로그인 만료, 프로그램 사라짐이 생기면 그 실행은 멈춘다. 다른 제공자로 스스로 바꾸지 않는다.
- 멈춘 자리에 이유를 보여 준다. 한도 소진이면 풀리는 시각을 함께 보여 준다(프로그램이 알려 줄 때만).
- 다른 구독 제공자가 `ready`이면 "〈이름〉(으)로 계속" 버튼이 나온다. 누르면 제공자 선택값이 그 제공자로 바뀌어 저장되고, 저장이 끝난 뒤 같은 요청을 다시 실행한다. 바뀐 선택은 모델 목록에 보인다.
- 남은 연결이 허용된 종량 로그인뿐이면 같은 버튼에 요금 안내가 붙는다.
- 키 제공자로 넘어가는 버튼은 없다.
- 무료 연결의 오늘 사용량을 다 쓰면 `free-limit`으로 멈추고 "오늘 쓸 수 있는 무료 사용량을 다 썼습니다"를 보여 준다. 다시 쓸 수 있는 시각을 알면 함께 보여 준다(OpenRouter는 오류에 실린 시각, Gemini는 태평양 시간 자정). 이것도 막힌 실행이므로 `ready`인 구독이 있으면 "〈이름〉(으)로 계속" 버튼이 나온다.
- 키 제공자의 요청이 "혼잡(503·529)"이나 "분당 한도(429)"로 거절되면, 답을 하나도 받기 전이라면 앱이 잠깐 기다렸다가 같은 요청을 두 번까지 다시 보낸다(2초, 5초). 제공자가 20초보다 긴 대기를 요구하면 기다리지 않는다. 오늘 무료 사용량 소진은 다시 보내지 않는다. 그래도 거절되면 "AI 서비스가 혼잡합니다"로 멈춘다.
- 이미 문서에 적용된 변경은 남는다. 되돌리기로 무른다.

## 사용량 표시

- 구독 제공자가 사용률과 초기화 시각을 알려 주면, 사용률이 80% 이상일 때 "N% 사용 · 〈시각〉에 초기화"를 AI 창에 보여 준다. 80%는 코드에 정해 둔 값이고 사용자 설정이 아니다.
- 창은 5시간과 7일 두 가지다. 초기화 시각이 없는 창은 사용량 값으로 치지 않는다.
- Codex는 5시간(300분)·7일(10080분) 창을 알려 줄 때만 보인다. 무료 요금제는 다른 길이의 창 하나만 알려 주므로 아무것도 보이지 않는다.

## 안내문

- **첫 연결 안내**(구독 제공자를 처음 쓸 수 있게 된 때 한 번, 설정에서 다시 볼 수 있다): 문서 내용과 대화가 사용자 본인 계정으로 Anthropic 또는 OpenAI에 전송된다. 학습에 쓰이는지는 그 회사의 사용자 계정 설정이 정한다. 앱은 Codex의 대화 기록 저장을 꺼 두지만 Codex가 자체 진단 기록을 PC에 남길 수 있다. PDF 편집기가 띄우는 안내에는 "AI 페이지 읽기와 문서 번역 때 페이지 그림과 문서 전체의 글이 보내질 수 있다"가 더해진다.
- **Codex 안내**(Codex를 고르는 자리마다 한 줄): "앱에서 Codex 구독을 쓰는 것은 OpenAI가 공식 권장하는 방식이 아닙니다."
- **종량 안내**: "구독이 아니라 쓴 만큼 요금이 나갑니다."
- **자동 호출 안내**(스위치를 켤 때): "시간당 한도가 없어 프로그램이 요청을 얼마든지 보낼 수 있고, 그 요청에 문서 전체의 글과 페이지 그림이 담길 수 있습니다. 프로그램이 자동으로 구독을 쓰는 것은 두 회사가 권장하지 않으며, 계정에 제한이 걸릴 수 있습니다."
- **문서 작업 시작 전 확인**: 예상 호출 수, 쓰일 AI, 이미 해 둔 분량. 쓴 만큼 요금이 나가는 경로면 "〈제공자〉에서 요금이 부과됩니다"가 붙는다.
- Claude와 Codex는 글자로만 적는다. 두 회사의 로고를 쓰지 않고, 제품 이름·기능 이름에 두 회사 이름을 넣지 않는다. API 키 제공자도 마찬가지로 회사 로고 대신 일반 그림(열쇠)을 쓴다(결정 0052).

## 이미지 생성, 미디어 분석, 검색

**이미지 생성**

- 지금은 키 방식 이미지 제공자로만 만든다. Codex 구독으로 만드는 기능은 들어 있지 않고, 선택 목록에도 보이지 않는다.
- 선택된 제공자를 쓸 수 없으면 설정이 채워진 다른 키 방식 제공자를 쓴다. 여럿이면 제공자 목록 순서상 첫 번째다.
- 쓸 수 있는 제공자가 없으면 이미지 생성 도구는 "쓸 수 없음"으로 답하고, 슬라이드 등은 검색한 이미지를 쓴다.
- 이 대체는 요청을 시작할 때만 일어난다. 요청 도중 실패하면 오류로 끝내고 다른 제공자로 다시 시도하지 않는다.

**미디어 분석**

- 이미지 분석의 기본은 지금 선택된 AI 제공자에게 직접 보여 주는 것이다(구독 포함). 키 방식 분석 제공자를 골라 두었으면 그것을 쓴다.
- 영상·음성 분석은 영상 분석이 되는 키 방식 제공자가 설정된 경우에만 된다. 아니면 "쓸 수 없음"과 설정 위치를 답한다.

**검색**

- 웹·이미지 검색의 기본은 키가 필요 없는 무료 경로다. Parallel 무료 검색을 먼저 쓰고 실패하면 DuckDuckGo를 쓴다.
- 환경변수에 검색 키가 있어도 기본 경로는 무료 경로다. 환경변수의 키는 사용자가 **고른** 검색 제공자의 저장된 키를 대신할 때만 쓰인다.
- 검색은 구독을 쓰지 않는다.

## 자동 호출 경로

- 이 경로에서 구독을 쓰는 기능은 설정 스위치 하나로 켜고 끈다. 기본은 꺼짐이다. 켤 때 경고(시간당 한도가 없다, 문서 전체의 글과 페이지 그림이 보내질 수 있다, 계정이 제한될 수 있다)에 동의해야 켜진다.
- 스위치는 사용자가 동의한 경고의 판을 함께 기억한다(`headlessSubscriptionConsentVersion`). 시간당 한도가 있던 예전 경고에 동의해 켜 둔 스위치는 꺼진 것으로 읽는다. 새 경고에 다시 동의해야 켜진다.
- 꺼져 있으면 구독 제공자가 없는 것처럼 동작한다. 키 방식이 있으면 그것을 쓰고, 없으면 "쓸 수 없음"과 스위치의 위치를 답한다.
- 켜져 있으면 횟수 한도 없이 처리한다. 검색·사진 분석·PDF 명령 모두 같다. 남는 제한은 차례 하나다. 명령을 여러 번 따로 실행해도, MCP 호출과 섞여도 요청을 하나씩 차례로 처리한다(동시에 온 요청은 차례를 기다린다). 차례의 단위는 작업이 아니라 요청 하나다. 그래서 긴 번역 작업도 다른 호출자를 막지 않고 요청마다 번갈아 처리된다.
- 최근 한 시간 동안 처리한 요청 수는 장부에 남긴다. 정보용이다(`capabilities`의 `automatic_calls.used`). 장부가 망가지거나 쓸 수 없어도 요청을 막지 않는다.
- 허용된 종량 로그인은 이 경로에서 구독으로 치지 않는다. 키 제공자와 같게 다룬다.
- 검색은 이 경로에서도 항상 된다(무료 경로).
- PDF의 AI 페이지 읽기와 번역(`pdf ai-read`, `pdf translate`, MCP의 `pdf_ai_read`, `pdf_translate`)은 `--yes`(MCP는 `yes`)가 없으면 아무것도 보내지 않고 예상만 답한다. 가는 길이 쓴 만큼 요금이 나가는 경로(키 제공자, 허용된 종량 로그인)면 `--allow-paid`(MCP는 `allow_paid`)도 있어야 한다. 사용자가 대화용으로 키 제공자를 골라 둔 경우도 같다. 사람이 보지 않는 경로에서 요금이 나가지 않게 하려는 것이다.
- 문서 작업 규칙(아래 "문서 작업")은 이 경로에도 그대로다. 다른 점은 둘이다. 터미널 명령은 작업이 끝날 때까지 앞에서 돈다. MCP 도구는 작업을 MCP 서버 프로세스 안에서 띄우고 바로 답하며, 서버가 끝나면 작업도 멈춘다. 진행은 `pdf status`(`pdf_status`)로 본다.

## 문서와 편집

- 문서는 사용자 디스크의 파일이고, 확장자가 여는 편집기를 정한다.
- 원본 파일이 기준이다. 저장할 때 고친 부분만 바꾸고 건드리지 않은 부분은 그대로 보존한다.
- 화면 테마(밝게·어둡게)는 화면 표시만 바꾼다. 저장·내보내기·인쇄 결과는 테마와 무관하게 같다.
- AI가 문서를 고치면 사용자가 검토하고 되돌릴 수 있다(워드의 변경 내용 표시, AI 차례마다의 되돌리기 지점).
- **가리기**는 사용자가 문서의 일부를 AI에게 보이지 않게 표시하는 기능이다. 가리기가 있는 편집기에서 감춘 내용은 어떤 제공자에게도 가지 않는다. 표시는 문서 안에 저장되고, 원본 프로그램으로 가린 문서도 그대로 인식된다. 그 파일이 다른 곳에서 자료로 읽힐 때의 규칙은 아래 "가리기와 다른 파일로 읽기"에 있다.
- 제공자 선택이 바뀌어도 대화 기록과 문서는 그대로다. 다음 차례부터 새 제공자가 답한다.

**마인드맵(`.xmind`)**

- 이 편집기가 보여 주지 않는 요소(경계, 떠 있는 토픽, 말풍선, 요약 아래 가지, 다른 토픽·첨부로 가는 링크, 모르는 값)도 저장할 때 그대로 나간다. 지워지는 것은 사용자가 지운 토픽과 그 아래뿐이다. 그런 요소가 함께 지워지는 삭제는 사람에게는 개수를 알리고 확인을 받으며, AI는 하지 못한다.
- 바뀐 것이 없으면 저장 결과는 원본 파일과 바이트까지 같다. 바뀌었으면 `content.json`만 다시 쓰고 파일 안의 다른 항목은 원본 바이트 그대로 둔다. 미리보기 그림은 새로 만들었을 때만 바꾼다.
- 예전 형식(`content.xml`만 있는 파일), 암호가 걸린 파일, 읽을 수 없는 파일은 열지 않고, 어떤 경우에도 그 파일에 쓰지 않는다.
- 시트를 지우기 전에 되돌릴 수 없다는 확인을 받는다. 마지막 시트는 지울 수 없다.
- 테마는 사용자가 고를 때와 새 시트를 만들 때(새 파일 포함) 파일에 적는다. 새 시트에는 기본 테마가 적힌다. 그 밖에는 이미 있는 시트의 테마를 그대로 둔다. 이 앱이 적은 테마는 다시 열어도 같은 모양으로 보이고, 이 앱이 적지 않은 테마의 시트는 기본 모양으로 그리되 파일의 테마는 그대로 둔다. 지도의 색은 문서 내용이라 앱의 밝게·어둡게를 따라가지 않는다.
- 파일 안의 값을 믿지 않는다. 토픽 스타일은 색·숫자 꼴의 값만 화면에 들어가고, 그림은 파일 안의 것만 보이고, 링크는 안전한 주소일 때만 열리고, 제목과 글은 HTML로 해석하지 않는다.
- "XMind"라는 이름은 "XMind 파일(.xmind)을 열고 저장한다"는 호환 설명에만 쓴다.

## 가리기와 다른 파일로 읽기

"다른 파일로 읽기"는 파일이 자기 편집기가 아닌 곳에서 글로 읽히는 일이다. 다른 편집기의 첨부, 홈의 묻기(파일 읽기와 검색 발췌), 파일 검색 색인, 만들기 창의 자료, AI 없이 바꾸기가 여기에 든다.

- 가린 내용은 다른 파일로 읽기 어디로도 나가지 않는다. 가린 자리는 그 표시의 이름을 담은 `{{이름}}`(이름표)으로 읽힌다.

| 형식                                                                | 이름표로 읽히는 자리                                      |
| ------------------------------------------------------------------- | --------------------------------------------------------- |
| PPT(`.pptx`)                                                        | 가린 글 구간. 슬라이드 본문과 발표자 노트 모두            |
| 마크다운(`.md`, `.markdown`, 마크다운 편집기가 쓰는 `.txt`·`.json`) | 가린 구간 전체                                            |
| HTML(`.html`, `.htm`)                                               | 가린 요소의 내용, 가린 속성의 값, 스크립트 안의 가린 구간 |

- 가린 글자는 홈의 파일 검색으로도 찾아지지 않는다. 이 규칙 전에 만든 색인은 처음 한 번 통째로 새로 만든다.
- **닫힌 쪽으로 실패한다.** 가리기 표시를 처리하지 못하면 원문을 내주지 않고 그 파일을 읽지 않는다. 첨부되지 않고, 색인에 본문이 들어가지 않고, 바꾸기도 하지 않는다.
- **저장하지 않은 파일은 읽지 않는다.** 표시는 저장해야 파일에 들어가기 때문이다. 어떤 탭에 열려 있고 저장하지 않은 변경이 있는 파일은 첨부, 묻기의 파일 읽기, 엑셀의 첨부 통합 문서 합치기에서 "저장한 뒤 다시 시도하라"는 안내와 함께 거절되고, 만들기 창에서는 "만들기"를 막는다. 묻기의 검색 발췌와 검색 결과 재정렬로 나가는 발췌에서도 빠진다. 홈의 파일 검색 결과에 보이는 것은 막지 않는다(PC 밖으로 나가지 않는다).
- PC 밖으로 나가는 발췌(묻기의 검색, 재정렬)는 색인된 뒤로 디스크에서 바뀌지 않은 파일에서만 뽑는다. 저장한 뒤 아직 다시 색인되지 않은 파일의 예전 본문은 나가지 않는다.
- AI 없이 바꿀 때 가린 자리는 이름표로 옮겨진다. 가린 부분이 있는 마크다운을 바꾸기 전에 그렇다고 알린다.
- **미치지 않는 곳.** 워드(`.docx`)의 가리기 표시는 다른 파일로 읽을 때 적용되지 않고, 워드 편집기 자신도 그 표시를 인식하지 않는다. 터미널 명령어(`ieumoffice`)와 그 MCP 서버, 앱 안 MCP 서버의 읽기도 가리기를 적용하지 않는다. 엑셀에는 파일에 저장되는 가리기 표시가 없고, PDF의 가리기는 내용을 지운 사본을 만드는 다른 기능이며, 마인드맵에는 가리기가 없다. 고치기 전까지는 다음 세 경우에도 가리기가 지켜지지 않는다. PPT 편집기에서 서식 속성이 없는 실행을 가리면 표시 없이 저장되어, 파일을 다시 열거나 다른 파일로 읽을 때 그 글이 보인다. 마크다운 편집기에서 인라인 코드가 든 부분을 가리면 코드가 가린 구간 밖에 저장된다. `.txt`·`.json`으로 저장한 마크다운 문서를 마크다운 편집기로 다시 열면 그 편집기의 AI가 가린 글을 본다(다른 파일로 읽을 때는 가려진다). 자세한 것은 `docs/tracking/findings.md`.

## AI 실행 하나의 일생

- AI 실행은 사용자의 명시적 행동으로만 시작한다. AI 창에 요청을 적어 보냈을 때, 만들기 창에서 "만들기"를 눌렀을 때, 또는 문서 작업 버튼(PDF 편집기의 "AI로 페이지 읽기", "문서 번역")을 누르고 시작 전 확인에서 "시작"을 눌렀을 때다. EPUB 변환 창의 "AI로 채우기"도 누를 때만 한 번 보낸다. PDF 읽기 도우미(결정 0043)의 시작점도 모두 사람이 누르는 것이다. 선택 막대의 단축키 `E`·`T`와 "AI에게 묻기"의 설명·번역 칩(구절 카드), 카드의 "다시 만들기", AI 창의 추천 질문 단추, 대역 보기의 "이 페이지 번역"·"남은 문단 번역(N)", 문단의 "다시 번역", AI 창의 "개요 만들기"·"다시 만들기", AI 핵심 표시 시작 창의 "시작"이다. 스크롤, 문서 열기, 패널 펼치기, 보기 켜기로는 아무것도 보내지 않는다. 배경에서 스스로 시작하는 실행은 없다. 예외는 자동 호출 경로 하나다.
- 실행은 "모델에게 묻기 → 모델이 도구 호출을 요청 → 앱이 도구 실행 → 결과를 모델에게 돌려주기"를 반복한다. 모델이 도구를 더 요청하지 않으면 끝난다.
- 도구는 앱이 정의하고 앱이 실행한다. 모델은 요청만 한다. 앱이 넘긴 목록에 없는 도구를 요청하면 실행하지 않고 오류로 돌려준다.
- 실행은 셋 중 하나로 끝난다. 완료, 사용자 중단, 오류. 어느 쪽이든 그 실행이 띄워 둔 프로그램도 함께 끝난다.
- 응답이 정해진 구조에 맞지 않으면 실행 전체를 멈추지 않고 그 차례를 다시 시도한다. 구조가 깨진 답(쓰다 만 도구 호출)이 그 대상이다. 구조 없이 글만 온 답은 깨진 답이 아니라 도구 호출이 없는 답으로 받는다.

## 문서 작업 (AI 페이지 읽기, 문서 번역, AI 핵심 표시, 긴 문서의 개요)

PDF 편집기의 AI 페이지 읽기와 문서 번역은 AI 요청 여러 번을 차례로 보내는 긴 작업이다. PDF 읽기 도우미(결정 0043)의 AI 핵심 표시와 긴 문서의 개요도 같은 엔진으로 돈다. 모두 같은 규칙을 따른다. 터미널 명령어와 MCP의 같은 기능(AI 페이지 읽기, 번역)도 이 규칙을 따른다(위 "자동 호출 경로").

**시작**

- AI 페이지 읽기와 번역을 시작하는 길은 둘이다. PDF 편집기의 메뉴 버튼, 또는 AI 창의 요청("스캔된 페이지를 AI로 읽어 줘", "이 문서를 영어로 번역해 줘"). AI 창에서 요청하면 AI가 작업 창을 여는 도구(`start_ai_page_reading`, `start_document_translation`)를 부르고, 그 도구는 창만 열고 바로 끝난다. AI 핵심 표시는 리본 홈 탭의 "AI 핵심 표시"로, 긴 문서의 개요는 AI 창의 "개요 만들기"로만 시작한다.
- 어느 길이든 시작 전 확인이 먼저 나온다. 보여 주는 것은 예상 호출 수, 쓰일 AI 제공자, 이미 해 둔 분량(보내지 않고 건너뜀)이다. 쓴 만큼 요금이 나가는 경로(키 제공자, 허용된 종량 로그인)면 "〈제공자〉에서 요금이 부과됩니다"를 함께 보여 준다. 금액은 계산하지 않는다. 사용자가 "시작"을 눌러야 보낸다. 이 확인을 건너뛰는 길은 아래의 페이지 번역 하나뿐이다.
- **유일한 예외: 대역 보기의 페이지 번역.** "이 페이지 번역"·"남은 문단 번역(N)"은 구독으로 쓰는 중이면 한 번 누르면 바로 보낸다. 확인 창이 없다. 대신 단추 옆에 쓰일 제공자 이름이 작게 보이고, 툴팁에 "이 페이지의 글을 〈제공자〉에 보냅니다"가 적힌다. 요금 경로(키 제공자, 허용된 종량 로그인)면 그 탭에서 처음 누를 때 단추 자리가 "〈제공자〉에서 요금이 부과됩니다 · 번역 / 취소"로 바뀐다. "번역"을 고르면 그 탭에서는 다시 묻지 않고, 제공자가 바뀌면 다시 묻는다. 근거: 사람이 그 페이지를 보며 누른 단추이고, 호출이 1~2회로 작다. 저장소 주인이 사용자가 편한 쪽으로 정했다. 이 예외를 다른 작업으로 넓히지 않는다. "모든 페이지 번역…"은 지금의 문서 번역 창(시작 전 확인 포함)을 연다.
- 제공자 고정, 한도 소진·로그인 만료에서 바로 멈추기는 페이지 번역에도 그대로다.
- 쓰일 제공자는 대화와 같은 규칙으로 확인 전에 한 번 정하고, 작업이 끝날 때까지 바꾸지 않는다. 도중에 그 제공자를 쓸 수 없게 되거나 요금이 나가는 경로로 바뀌면 작업이 멈춘다. 다른 제공자로 넘어가지 않는다.
- 이어 가는 번역의 제공자나 모델이 보관된 번역과 다르면 시작 전 확인에서 알린다. 대역 보기의 페이지 번역은 알리지 않는다. 서로 다른 AI의 번역이 한 문서에 섞여도 된다(저장소 주인이 정했다). 페이지 번역은 그 언어의 번역 메타(제공자·모델)가 없을 때만 만들고, 있으면 바꾸지 않는다.
- AI 핵심 표시는 고칠 수 없는 문서(암호로 편집이 막힌 문서)에서 시작하지 않고 이유를 보인다. 저장된 파일의 글을 기준으로 하며, 저장하지 않은 편집이 있으면 시작 전 확인에 그렇다고 적는다. 그 문서에 다른 분류로 만든 예전 제안이 있으면 시작 전 확인에서 "예전 제안을 지울까요"(지우기 / 남기기)를 함께 묻는다.
- 그림을 읽지 못하는 모델이면 AI 페이지 읽기는 시작하지 않는다. 고른 페이지에 번역할 글이 없으면 번역은 시작하지 않고, 스캔 문서면 AI 페이지 읽기를 먼저 권한다. 연결이 없으면 연결 안내를 보여 주고 시작하지 않는다.

**분량**

- 페이지 수와 분량에 상한이 없다. 사용자는 예상 호출 수를 보고 시작을 정한다.
- AI 페이지 읽기는 페이지마다 한 번 보낸다. 번역과 AI 핵심 표시는 글 블록을 약 2,500토큰씩 묶어 한 번에 보낸다.
- 문서 개요는 문서 전체의 구조화 글(AI로 읽은 페이지는 그 결과)이 60,000자 이하면 호출 한 번이고, AI 창과 같은 보내기 전 판단만 거친다. 넘으면 문서 작업(`summary`)이 된다. 묶음마다 부분 요약을 받은 뒤 마지막에 한 번 합친다.
- 보관소에 이미 있는 페이지와 블록은 다시 보내지 않는다. AI 핵심 표시는 같은 분류로 이미 살펴본 블록을 다시 보내지 않는다. 사람이 고친 번역 블록은 끝난 것으로 쳐서 다시 보내지 않는다.

**도는 동안**

- 한 문서에는 문서 작업이 한 번에 하나다. 같은 탭, 같은 창, 다른 프로세스(터미널 명령어)에서 도는 작업을 모두 센다. 진행 중에 새 작업을 요청하면 거절하고 진행 상황을 보여 준다.
- 작업은 AI 대화와 따로 돈다. 작업이 도는 동안에도 AI 창으로 대화할 수 있다.
- 한 작업은 요청을 한 번에 2개까지 보낸다.
- 진행 표시(끝난 수/전체, 지금 페이지)와 "멈추기"가 있다.
- AI가 돌려준 글은 문서 데이터로만 쓴다. 그 안에 적힌 지시를 따르지 않고 도구를 부르지 않는다.

**멈출 때**

- 작업은 그 PDF 탭에 묶인다. 탭을 닫거나 앱이 끝나면 작업이 멈추고, 그 작업이 띄운 구독 프로그램도 함께 끝난다.
- 한도 소진(`rate-limit`)이면 즉시 멈추고 남은 것을 더 보내지 않는다. 다시 가능한 시각을 보여 준다(프로그램이 알려 줄 때). 로그인 만료처럼 다시 보내도 소용없는 오류도 바로 멈춘다. 다른 구독으로 계속하기는 위 "실행 중 막혔을 때"처럼 사용자가 고를 때만이다.
- `timeout`, `network`, `overloaded` 같은 오류는 그 페이지나 묶음을 한 번 다시 보낸다. 다시 실패한 것이 3개 잇달아 나오면 멈추고 알린다.
- 결과를 보관소에 쓰지 못하면(디스크 가득 등) 멈추고 알린다. 받았지만 보관하지 못한 것이 있으면 그 사실을 함께 알린다.
- 어떻게 멈추든 끝난 페이지와 블록은 보관소에 남는다.
- 번역이 멈추면 사용자가 고른다. 지금까지 번역된 부분만 반영하고 나머지는 원문으로 둔 파일을 내보내거나, 나중에 이어서 완성한다.

**이어하기**

- 작업은 스스로 다시 시작하지 않는다. 앱을 다시 켜도, 한도가 풀려도 마찬가지다.
- 끝나지 않은 작업이 있는 문서를 열면 "끝나지 않은 〈번역(언어)/AI 읽기/AI 핵심 표시〉 N% — 이어서 할까요?"를 한 번 보여 준다. "이어서 하기"는 그 작업의 시작 전 확인을 열 뿐이다(AI 핵심 표시는 그때의 분류와 페이지를 채운 시작 창). 거기서 "시작"을 눌러야 보낸다.
- 대역 보기의 페이지 번역과 문서 개요는 이어 할 작업이 아니다. 이어하기 제안에 나오지 않는다. 페이지 번역은 기존 번역 작업 기록(`translate.<언어>.json`)과 이어하기 제안을 건드리지 않고, 도는 동안만 별도 기록(`translate-page.<언어>.json`)을 남겨 다른 프로세스가 "작업 중"을 알게 한다. 멈추면 그 번역 칸에 이유를 보인다. 긴 개요가 멈추면 다시 누를 때 처음부터 만든다.

**보관소**

- AI가 읽은 페이지, 번역, 구절 카드, AI 핵심 표시의 제안, 문서 개요, 끝나지 않은 작업의 기록을 이음오피스의 데이터 폴더 안 `pdf-store`에 둔다. PDF와 노트의 연결 기록(`note-links.json`)도 같은 폴더에 있다. 앱과 터미널 명령어가 같은 곳을 쓰고, 같은 문서를 동시에 다뤄도 망가지지 않는다.
- 사용자가 지울 때까지 남는다. 설정 → 일반의 "PDF AI 결과 보관소"가 차지한 용량을 보여 주고, "모두 지우기"는 확인을 받은 뒤 전부 지운다. 노트 연결 기록도 함께 지워지지만 노트 파일은 그대로다. PDF 편집기의 "이 문서의 AI 보관분 지우기"는 확인을 받은 뒤 지금 문서의 것만 지운다(카드, 핵심 표시, 개요, 사람이 고친 번역 포함). 확인 문구에 "사람이 고친 번역 N개, 구절 카드 N개도 지워집니다"가 붙는다(0개인 항목은 빠진다). 노트 연결 기록과 노트 파일은 지우지 않는다. 그 문서의 작업이 도는 동안에는 지우지 않는다.
- 문서는 파일 내용으로 알아본다. 앱 안에서 PDF를 저장해 내용이 바뀌면, 내용이 같은 페이지의 AI 읽기 결과와 번역(사람이 고친 표시 포함), 구절 카드, AI 핵심 표시의 분류와 블록, 끝나지 않은 작업의 기록을 새 파일로 옮긴다. 문서 개요는 만들 때 쓴 페이지가 모두 남아 있을 때만 옮기고, 아니면 "문서가 바뀌었습니다 · 다시 만들기"를 보인다. PDF 넣기·페이지 교체·페이지 크기·자르기처럼 파일을 그 자리에서 다시 쓰는 페이지 작업 뒤에도 같은 규칙으로 옮긴다. 저장의 옮기기가 끝나지 못하면 "파일에 들어갔다"는 확정(메모로 남기기, 받아들인 핵심 표시)은 다음 저장까지 기다린다. 페이지 작업의 옮기기가 끝나지 못하면 결과는 예전 파일의 보관분에 남는다. 바뀐 페이지만 다시 하면 된다. 다른 이름으로 저장한 사본, 영구 가림 사본, 앱 밖에서 바뀐 파일은 새 문서로 본다. 예전 보관분은 지울 때까지 남는다.
- 번역은 문서와 목표 언어마다 하나다. "처음부터 다시 번역"은 확인을 받은 뒤 그 언어의 보관된 번역을 지우고 다시 한다. 그 언어에 사람이 고친 블록이 있으면 확인에서 "사람이 고친 문단 N개도 지웁니다" / "고친 문단은 남기기"를 고른다. 남기기를 고르면 고친 블록만 남기고 나머지를 지운 뒤 다시 번역한다. 터미널의 `pdf translate --restart`는 물을 수 없으므로 언제나 고친 블록을 남긴다.
- **고친 번역 블록.** 대역 보기에서 번역 문단을 두 번 눌러 고치고 저장하면, 그 블록은 사람이 고친 것(`edited`)으로 보관된다. 고친 블록은 서식 표시(굵게·기울임·링크·각주 표시·줄 안 수식)가 없는 글이다. 서식이 있던 문단을 고치면 입력란에 "서식이 빠집니다"가 보인다. 고친 글은 번역 PDF·Markdown·EPUB과 터미널 `pdf translate`의 출력에 그대로 쓰인다. 고친 문단의 "다시 번역"은 "고친 내용을 버리고 다시 번역할까요?"를 먼저 묻는다.

**결과**

- 원본 PDF는 바뀌지 않는다. 결과는 항상 새 파일이다. AI 핵심 표시의 결과는 파일이 아니라 보관소의 제안이고, 사람이 받아들인 것만 편집 중인 문서의 형광펜이 된다(아래 "PDF 읽기 도우미").
- 문서 번역 창의 형식 고르기에 "보관만(파일 만들지 않음)"이 있다. 이것만 고르면 결과 파일을 쓰지 않고 보관소에만 남긴다(대역 보기에서 읽을 때).
- AI가 읽은 페이지는 Markdown·EPUB 변환, AI 창의 페이지 읽기, 번역에서 그 페이지를 대신한다. 뷰어 검색에서는 위치 있는 글(본문 글자와 Windows OCR)에 검색어가 하나도 없을 때만 "AI로 읽은 글에서 찾음"을 페이지 단위로 더한다. 누르면 그 페이지로 가고 글자 강조는 없다. 글자 선택과 워드·PPT·엑셀 변환에는 쓰지 않는다.
- 번역 결과 형식은 번역 PDF, 번역 Markdown, 번역 EPUB이고 여럿을 고를 수 있다. 대역(원문 다음에 번역)은 Markdown·EPUB에만 있다. 목표 언어가 아랍어·히브리어·힌디어이거나 PDF에 암호가 걸려 있으면 번역 PDF를 고를 수 없고 이유를 보여 준다.
- 끝나면 번역한 블록 수, 번역하지 못한 블록, 넘친 블록, 원본 그대로 둔 페이지를 보여 준다.

**책 정보 "AI로 채우기"**는 문서 작업이 아니다. EPUB 변환 창에서 누를 때만 앞쪽 페이지의 글(3쪽부터 많아야 12쪽, 12,000자까지)을 AI에 한 번 보내 제목·저자·언어를 제안받는다. AI 창과 같은 보내기 전 판단을 거친다.

## PDF 읽기 도우미 (결정 0043)

PDF 편집기에서 긴 문서를 읽는 일을 돕는 기능 묶음이다. 위 "문서 작업"과 아래 규칙을 함께 따른다.

**모든 기능에 걸리는 규칙**

- AI는 사람이 누를 때만 나간다(위 "AI 실행 하나의 일생"의 시작점 목록). 한 번만 보내는 호출(구절 카드, 문단 다시 번역, 짧은 문서의 개요)은 AI 창과 같은 보내기 전 판단을 거친다. 여러 번 보내는 일은 위 "문서 작업"의 시작 전 확인을 거친다.
- 이 기능들의 모델 호출에는 도구를 주지 않는다. 답은 문서 데이터로만 쓴다.
- AI 결과의 기본 자리는 보관소다. PDF 파일은 사람이 "메모로 남기기"나 "받아들이기"를 누르고 PDF를 저장할 때만 바뀐다.
- "파일에 들어갔다"는 상태는 PDF 저장이 성공했을 때 확정한다. 그 전에는 "저장 대기"로 보인다. 저장하지 않고 닫으면 보관소는 바뀌지 않고, 다음에 열면 카드는 남기기 전 상태, 제안은 받아들이기 전 상태다.
- 고칠 수 없는 문서(암호로 편집이 막힌 문서)에서는 파일을 바꾸는 동작(형광펜·밑줄·취소선·메모 단축키, 메모로 남기기, AI 핵심 표시 시작)을 막고 이유를 보인다. 보관소만 쓰는 동작(구절 카드, 대역 보기, 개요)은 된다.
- 페이지 위 덧그림(카드의 점선, 핵심 표시 미리 보기 상자, 원문 잇기 테두리, 인용 강조)은 화면 전용이다. 저장·인쇄·내보내기에 나타나지 않는다.
- 셸 없이 띄운 PDF 편집기에서는 보관소·노트·새 문서 채널이 없어, 이 기능들의 단추가 이유를 보이고 아무것도 보내지 않는다.

**선택 막대 단축키**

- 글자를 선택해 선택 막대가 보이는 동안만 받는다. `H` 형광펜(칠해져 있으면 지우기), `U` 밑줄, `S` 취소선, `N` 메모, `E` AI 설명, `T` AI 번역, `Enter` "AI에게 묻기" 입력창.
- 키는 물리 키로 판정하므로 한글 입력 상태에서도 같다. 글자 조합 중, 입력란에 포커스가 있을 때, Ctrl·Alt·Meta가 눌렸을 때는 무시한다. 막대 단추의 툴팁과 접근성 이름에 키를 함께 적는다.

**구절 카드**

- `E`·`T`와 "AI에게 묻기"의 설명·번역 칩이 카드로 답한다. 이 칩들은 더 이상 AI 창 대화로 답하지 않는다. "구절 요약"·"구절 고쳐 쓰기" 칩과 직접 적은 질문은 지금처럼 AI 창으로 간다.
- 설명은 화면 언어로 답한다. 번역의 목표 언어는 번역 작업의 기본 목표 언어 규칙을 따른다.
- 같은 페이지·같은 구절·같은 종류(번역이면 같은 언어)의 카드가 있으면 보내지 않고 그 카드를 연다. "다시 만들기"를 눌러야 다시 보내고 같은 카드를 덮어쓴다.
- 카드에서 복사, 메모로 남기기, AI 창에서 이어 묻기(보내지 않고 선택 칩으로 넘긴다), 노트에 넣기, 다시 만들기, 지우기(보관소에서만, 이미 남긴 메모는 그대로)를 한다.
- 메모로 남긴 메모의 첫 줄은 화면 언어의 "AI 설명" 또는 "AI 번역(언어)"이고, 작성자는 사람이 새로 단 메모와 같은 값(PC 계정 이름)이다.
- 카드가 있는 구절 밑에 옅은 점선을 그린다(보기 탭에서 끄고 켠다, 기본 켜짐). 문서를 열 때 페이지 지문으로 위치를 다시 찾고, 그 페이지가 바뀌었거나 없으면 "위치를 찾지 못함"이다.

**주석 모아 보기**

- 사이드바에 "주석" 보기가 있다(축소판·목차와 한 번에 하나). 파일의 주석, 저장하지 않은 표시와 메모, 구절 카드, 미리 보기를 켰을 때의 AI 핵심 표시 제안이 한 목록에 나온다. 종류·색·페이지 범위·글로 거르고, 페이지 순이나 만든 순으로 정렬한다.
- 형광펜·밑줄·취소선은 표시 아래의 글을 보인다. 다른 프로그램이 만든 주석과 회전된 페이지도 같다. 받아들인 AI 형광펜은 분류 이름으로도 거른다.
- 패널 메뉴의 "Markdown으로 복사", "마크다운 문서로 열기", "워드 문서로 열기"는 지금 걸러진 목록을 그대로 쓴다. AI를 부르지 않는다. 뒤의 둘은 기본 폴더에 새 파일을 만들어 새 탭으로 연다.

**AI 창 추천 질문과 문단까지 가는 인용**

- 대화가 비어 있을 때 빈 화면 안내 아래에 질문 단추 셋이 있다(핵심 정리, 결론과 근거, 빠졌거나 약한 부분). 누르면 그 질문을 한 번 보낸다. 원래 있던 빠른 단추 둘은 그대로 위에 있다.
- AI 창의 답이 근거를 댈 때 링크에 그 페이지 원문에서 옮긴 짧은 인용을 함께 쓴다. 누르면 그 페이지로 가서 인용을 2초간 강조한다. 못 찾으면 페이지로만 가고 "위치를 찾지 못함"을 잠깐 보인다.

**대역 보기(번역 나란히)**

- 보기 탭의 "번역 나란히"를 켜면 페이지마다 오른쪽에 번역 칸이 붙는다. 켜기만 해서는 아무것도 보내지 않는다. 두 쪽 보기와 함께 켜지지 않는다.
- 저장된 파일로 문서 나무를 한 번 만들고, 보관된 번역 블록을 그대로 보인다. 번역이 없는 블록은 흐린 원문이다. 그래서 문서 번역 창으로 번역해 둔 문서는 켜자마자 보이고, 여기서 번역한 블록은 문서 번역 창이 다시 보내지 않는다.
- 언어는 가장 최근에 보관된 번역의 언어, 없으면 기본 목표 언어다. 번역 칸 폭과 글자 크기는 조절하고 기억한다. 원문 페이지가 너무 좁아지면 "번역 칸을 접을까요?"를 한 번 묻는다.
- 번역 문단과 원문 블록은 마우스를 올리면 서로 강조된다. AI로 읽은 페이지는 순서대로만 보인다. 여러 페이지에 걸친 문단은 시작 페이지에 한 번만 보인다.
- 저장하지 않은 페이지 넣기·지우기·순서 바꾸기가 있으면 "저장하면 번역 칸이 맞춰집니다"를 보인다.
- 페이지 번역과 고친 블록의 규칙은 위 "문서 작업"에 있다. 다른 문서 작업이 도는 동안 번역 단추는 기다림 표시가 된다.

**AI 핵심 표시**

- 시작 창에서 분류 묶음을 고른다. 연구·보고서(핵심 주장, 방법, 결과, 한계), 계약서·약관(의무, 기한, 금액, 해지·위약), 교재·설명서(정의, 핵심 개념, 예시, 주의), 직접 정하기(이름 1~5개). 분류마다 색이 하나다.
- 답에 든 문장이 그 블록의 글에 실제로 있지 않거나, 모르는 블록·분류를 가리키면 버린다. 끝나면 받은 제안 수, 버린 수, 위치를 찾지 못한 수를 보인다.
- 제안은 페이지 위 반투명 상자로 미리 보인다(보기 탭에서 끄고 켠다). 패널에서 하나씩, 분류마다 모두 받아들이거나 버린다. 위치를 찾지 못한 제안은 받아들일 수 없다.
- 받아들이면 그 분류 색의 형광펜이 편집 중인 문서에 생기고, 저장할 때 분류 이름이 주석 제목(`/Subj`)으로 들어간다. 버리기는 곧바로 보관소에 남는다.
- 분류가 다르면 새로 돌린 것으로 친다. 미리 보기와 패널은 가장 최근 것만 보인다.

**문서 개요**

- AI 창 맨 위의 접을 수 있는 "문서 개요" 칸. "개요 만들기"를 누르면 세 줄 요약, 요약, 핵심 용어(용어, 문서 안에서의 뜻, 처음 나오는 페이지)를 화면 언어로 만든다. 보내는 글이 길면 위 "문서 작업"의 규칙을 따른다.
- 결과는 보관소에 남고, 다시 열면 보관된 것을 보인다. "다시 만들기"를 눌러야 다시 보낸다. 용어를 누르면 뷰어 검색으로 찾는다. 칸마다 복사와 노트에 넣기가 있다.

**PDF마다 노트**

- PDF 하나에 마크다운 노트 파일 하나를 잇는다. 리본 보기 탭과 주석 패널의 "노트 열기", 각 항목의 "노트에 넣기"로 쓴다.
- 이어진 노트가 없거나 기억한 파일이 없어졌으면 저장 창이 뜬다. 기본 위치는 PDF와 같은 폴더, 기본 이름은 `〈PDF 파일 이름〉 〈화면 언어의 "노트"〉.md`다. 고른 파일이 이미 있으면 덮어쓰지 않고 그 파일을 잇는다(Windows 저장 창이 바꾸기 확인을 띄워도 파일은 그대로다). 없으면 `# 〈PDF 제목, 없으면 파일 이름〉` 한 줄로 만든다.
- 저장된 경로가 없는 PDF에서는 노트 단추가 막히고 "PDF를 먼저 저장하세요"를 보인다.
- 노트는 PDF 파일 경로로 먼저 찾고, 없으면 같은 내용(문서 해시)의 가장 최근 노트를 찾는다. 저장으로 내용이 바뀌어도, 같은 내용의 사본이어도 노트를 잃지 않는다.
- "노트 열기"는 노트가 이미 탭에 열려 있으면 그 탭을 앞으로 가져오고, 아니면 마크다운 편집기 탭으로 연다.
- "노트에 넣기"는 노트 탭을 열거나 앞으로 가져온 뒤 그 편집기의 문서 끝에 글을 넣고 "바뀜" 상태로 만든다. 파일에 직접 쓰지 않는다. 저장은 노트 탭에서 사람이 한다. 넣는 모양은 인용(`> 글`) 끝에 PDF로 가는 링크 `[p.N](〈노트 기준 PDF 상대 경로〉#page=N)`, 빈 줄, 메모·AI 답·개요 글이다. 노트와 PDF가 다른 드라이브에 있으면 `file:///` 주소를 쓴다. 이 링크는 브라우저 같은 다른 프로그램에서 그 페이지로 열린다. 앱 안 마크다운 편집기에서 눌러 PDF로 가는 기능은 아직 없다.

## 탭, 프로젝트, 지식 자료

- **탭**은 열린 문서 하나를 담는다. 홈 탭은 새 문서 만들기, 최근 파일, 폴더, 검색, AI 질문을 담는다.
- **프로젝트**는 파일들의 묶음이다. 파일마다 AI 대화 기록이 따로 남는다. 파일을 옮기거나 이름을 바꿔도 기록이 따라간다. 기록은 PC에만 저장된다.
- **지식 자료**는 사용자가 별표를 붙인 파일들이다. 홈의 AI 질문은 이 파일들을 검색하고 읽어 답하며, 답에 출처 파일을 밝힌다. AI 질문도 AI 실행이므로 제공자 선택과 보내기 전 판단을 똑같이 따른다. 연결 상태를 아직 모를 때 보낸 질문은 붙잡아 두었다가, 실행할 수 있게 되면 시작하고 "연결 필요"로 정해지면 버린다.
- **그룹으로 좁힌 질문.** 질문 칸에서 "전체" 대신 별표 그룹 하나를 고를 수 있다. 기본은 전체다. 그룹을 고른 실행의 목록·검색·읽기는 그 그룹의 파일로 좁혀지고, 그 실행에서 AI가 그룹 밖의 파일을 읽으려 하면 뒷단이 거절한다. 좁히기는 화면이 아니라 뒷단이 지킨다. 그룹에 속하지 않은 별표 파일은 전체에서만 읽힌다. 파일이 하나도 남지 않은 그룹으로는 묻지 않는다.
- **로컬 파일 검색**은 사용자가 추가한 폴더의 문서를 PC 안에서 색인해 찾는다. 색인은 PC에만 있다. 찾은 결과를 바깥 모델로 다시 정렬하는 기능은 기본 꺼짐이고, 켜면 검색어와 위쪽 결과 20개의 발췌가 사용자가 고른 서비스로 간다.

## 문서로 새 문서 만들기

- 자료(파일 하나 이상)와 요청 글로 새 문서를 만든다. 만들 수 있는 종류는 PPT, HTML, 마인드맵이다. 워드와 마크다운은 아직 대상이 아니다.
- 입구: 홈의 별표 그룹("이 그룹으로 새 문서 만들기", 그 그룹의 파일 전부), 홈의 선택 막대와 파일 줄 메뉴(고른 파일), 모든 편집기의 파일 메뉴 "이 문서로 다른 문서 만들기"(열려 있는 문서), 마인드맵 편집기의 도구 줄 단추. 어디서든 같은 만들기 창이 뜬다.
- 만들기 창에서 종류를 고르고, 자료를 빼거나 더하고, 원하는 바를 적는다(비우면 종류에 맞는 기본 요청이 쓰인다). 자료는 20개, 하나에 50MB(그림은 5MB)까지다. 읽을 수 없는 자료는 이유와 함께 빠진다.
- 저장하지 않은 변경이 있는 자료가 하나라도 있으면 "만들기"를 누를 수 없다. 창이 그 자료를 알려 주고 저장하는 버튼을 준다. 한 번도 저장하지 않은 문서는 저장하기 전에는 자료가 될 수 없다. 마지막 저장본으로 그냥 진행하는 길은 없다.
- **알림 두 가지**는 만들기를 막지 않는다. 자료의 글 길이 합계가 100,000자를 넘으면 "한도를 많이 쓴다", PPT·HTML을 만들 때 8,000자를 넘으면 "긴 자료는 뒤쪽이 덜 반영될 수 있다". 자료를 줄이는 방식은 각 편집기의 기존 상한 그대로다.
- "만들기"를 누르면 그 종류의 제목 없는 새 탭이 열리고, 그 탭의 편집기 AI가 자료를 첨부로 받아 평소 방식대로 만든다(PPT는 덱 생성, HTML은 기획 → 쪽 쓰기, 마인드맵은 지도 쓰기). 맡겨 둔 요청은 그 탭에서 한 번만 쓰인다. 탭이 열렸다거나 다시 불러왔다는 이유로 실행하지 않는다.
- 실행은 보내기 전의 문지기를 평소처럼 지난다. 막히면 요청 글과 첨부된 자료가 그 탭의 AI 창에 남고, 연결한 뒤 사용자가 직접 보낼 수 있다.
- **AI 없이 바꾸기.** 자료가 하나이고 종류가 맞을 때만 고를 수 있다. 지도 → 마크다운(개요 글), 지도 → PPT 뼈대(첫 시트의 중심 토픽이 제목 슬라이드, 큰 가지마다 한 장), 마크다운 → 지도(본문 문단은 바로 위 토픽의 메모). 구독을 쓰지 않는다. 결과는 저장하지 않은 새 탭으로 열린다.

## 에이전트 모드

결정 0032, 0049. 보안 쪽 규칙은 `docs/security.md`의 "에이전트 모드"에 있다.

- **입구는 홈 사이드바의 "에이전트" 항목 하나다("AI 질문" 아래, 새 창 표시가 붙는다).** 따로 뜨는 창이고, 창 하나가 세션 하나를 연다. 창을 닫으면 세션이 끝난다. 실행은 사람이 "시작"을 누르고 첫 메시지를 보낼 때만 시작한다.
- **고르는 것은 셋이다.** 프로젝트 폴더(대화 상자로 고른다. 최근 8개를 기억한다), 프로그램(Claude Code 또는 Codex), 허락 방식. 고른 프로그램과 허락 방식은 다음에도 쓰인다. 프로그램을 알아서 고르거나 다른 프로그램으로 넘어가지 않는다.
- **처음 한 번은 경고를 확인해야 시작할 수 있다.** 경고의 내용이 바뀌면 판 번호를 올리고 다시 확인받는다.
- **연결.** 구독 로그인(`ready`)이거나, 종량 로그인을 사람이 허용해 두었을 때만 그 프로그램을 고를 수 있다. 확인 중이면 기다리게 하고, 연결되지 않았으면 설정 → AI로 안내한다.

- Codex의 명령은 어느 방식에서든 격리 안에서 돈다. 사람이 허락한 명령도 같다. 묻는 두 방식에서 Codex는 목록 보기·파일 읽기 같은 알려진 읽기 전용 명령은 묻지 않고 격리 안에서 실행한다.
- "믿고 맡기기"에서 Codex는 격리 공간 안에서만 바로 하고, 격리 밖이 필요한 명령은 묻지 않고 실패한다. Claude Code는 Windows에서 격리가 없어 자체 `auto` 모드가 행동마다 대신 검사한다. 이 차이는 프로그램을 고를 때 화면에 적혀 있다.
- **열린 문서는 앱 MCP 도구로만 고친다.** 그 변경은 편집기에 바로 보이고 편집기의 되돌리기로 되돌릴 수 있다. 가린 내용이 있는 PPT는 이 길로 고치지 않는다.
- **새 문서는 프로그램이 프로젝트 폴더에 파일로 만든다.** 창의 도구 줄에서 "열기"를 누르면 앱 탭으로 연다. 프로젝트 폴더 안의 파일만 열 수 있다.
- **프로젝트 지침.** 폴더의 `CLAUDE.md`와 `AGENTS.md`(Codex는 `AGENTS.md`를 스스로 읽으므로 `CLAUDE.md`만)를 앱이 읽어 지시문에 붙인다. 32,000자까지다.
- 막히면(한도, 로그아웃, 도구 확인 실패) 그 요청이 실패로 끝났다고 알리고 멈춘다. 다른 프로그램이나 요금이 나가는 연결로 넘어가지 않는다.
- **웹은 각 회사 앱의 기본값을 따른다.** Claude Code는 웹 검색·웹 읽기를 쓰되 처음에 묻는다. 묻는 창에는 "이번 세션 동안 검색 허락", "이번 세션 동안 이 사이트 허락"이 있다. Codex는 시작 화면에서 "웹 검색"(저장된 결과 / 실시간 / 끄기, 기본 저장된 결과)과 "명령의 인터넷 접속"(끔 / 켬, 기본 끔)을 고르고, 프로젝트 폴더마다 기억한다. 처음 쓰는 폴더는 기본값으로 시작한다. 명령의 인터넷 접속을 켜면 "'이 프로젝트는 믿고 맡기기'에서는 묻지 않고 인터넷에 닿는다"는 경고를 보인다.
- **스킬.** 세션을 시작할 때의 켜기·끄기를 따른다(아래 "스킬"). 그 프로젝트 폴더의 스킬(`.claude/skills`, `.agents/skills`)은 묻지 않고 켜지고 다른 스킬과 구분하지 않는다. 입력칸에서 `/`·`$`로 스킬을 고르면 "이 `SKILL.md`를 읽고 따르라"는 지시가 요청 앞에 붙는다(두 프로그램 같음). 도는 중에 켜기·끄기를 바꾸면 "바뀐 스킬은 다음 세션부터 적용됩니다"가 보인다.
- **스킬 저장과 설치 제안.** 에이전트가 스킬을 만들면 창에 카드가 뜨고(양식은 열린 탭과 프로젝트 폴더의 파일 가운데 고른다), 에이전트가 찾은 스킬은 깃허브 미리보기로 뜬다. 둘 다 사람이 눌러야 저장·설치된다. 설치한 스킬은 다음 세션부터 실린다.
- **이전 사용자 안내.** 0.12.1~에서 에이전트 시작 경고를 확인한 적이 있는 사람이 처음 에이전트 창을 열면 "스킬은 이제 설정 → 스킬에서 켜고 끕니다" 안내를 한 번 보인다. 새로 경고를 확인한 사람에게는 뜨지 않는다.

결정 0048. 보안 쪽 규칙은 `docs/security.md`의 "사용자 스킬"에 있다.

- **스킬은 AI에게 주는 작업 설명서다.** 공개 표준 형식(폴더 하나에 `SKILL.md`, 앞머리에 `name`과 `description`)을 따른다. 이음오피스가 만든 스킬은 Claude Code·Codex로 옮겨도 그대로 쓴다. 화면 제목은 `metadata.ieum-title`, 양식은 `metadata.ieum-template`(스킬 폴더의 `assets/` 아래)에 둔다.
- **출처와 처음 상태.** 기본(앱에 든 5개)과 내 스킬(가져온 것, 만든 것)은 켜진 채로, Claude·Claude 플러그인·Codex 스킬 폴더의 스킬은 목록에 보이되 꺼진 채로 시작한다. 켜진 스킬은 처음에 "스스로 쓰기"이고 스킬마다 "부를 때만"으로 바꾼다. 모든 창(편집기 AI 창, 홈 AI 질문, 에이전트 창)이 같은 켜기·끄기를 따른다.
- **같은 이름.** 출처가 다르면 같은 이름이 함께 있을 수 있고 출처 표시로 구분한다. AI가 스스로 고를 때와 에이전트 묶음에서는 켜진 것들 사이에서 프로젝트 > 내 스킬 > 기본 > Claude > Codex > Claude 플러그인 순서로 앞선다. 사람이 `/`로 고르면 고른 그것을 쓴다.
- **관리(설정 → 스킬).** 켜기·끄기, 스스로 쓰기/부를 때만, 내용 보기, 내 스킬 직접 고치기·내보내기(zip)·지우기(휴지통), 기본 스킬 숨기기(되살리면 처음 상태), 남의 스킬은 "내 스킬로 사본 만들기"(원래 스킬은 꺼진다). 가져오기는 폴더·zip·깃허브 링크이고 모두 미리보기를 거친다. 깃허브 스킬은 "업데이트 확인"을 누를 때만 확인하고, 설치 뒤 고친 내용이 있으면 "고친 내용이 사라집니다"를 보인다.
- **부르기.** AI 입력칸의 맨 앞이나 공백 뒤에서 `/` 또는 `$`를 치면 켜진 스킬 목록이 뜬다(엑셀 AI 창의 `$`는 입력칸 맨 앞에서만). 고른 스킬은 입력칸 위의 칩이 되고, 보낼 때 앱이 본문을 요청에 넣는다. 보낸 말풍선과 저장된 대화에 칩이 남고, 다시 열어 이어 보낼 때는 지금 내용을 다시 읽는다(지워졌거나 꺼진 스킬은 "없음"). 넣는 글의 합계가 150,000자를 넘으면 보내지 않는다.
- **AI가 스스로 쓰기.** 켜진 "스스로 쓰기" 스킬의 제목·설명 목록이 지시문에 들어가고, AI가 쓰면 대화에 "〈제목〉 스킬을 썼습니다"가 보인다.
- **스킬 만들기.** "지금 한 작업을 스킬로 저장해 줘"처럼 말하면 AI가 확인 카드를 띄운다. 사람이 고치거나 [저장]을 눌러야 저장된다. 지금 문서를 양식으로 함께 넣을 수 있다. [비운 양식 만들기]는 채운 값을 비운 사본을 새 탭에 열어 확인하고 저장하게 하고, [원래 문서 그대로 저장]은 가린 내용이 있으면 막힌다. 남의 스킬을 고치면 내 스킬 사본으로 저장되고 원래 스킬은 꺼진다.
- **양식 쓰기.** 사람이 양식 스킬을 칩으로 부르면 양식 사본을 제목 없는 새 문서로 열고 그 탭의 AI 창이 이어서 채운다. AI가 스스로 양식 스킬을 쓰면 [이 양식으로 새 문서 열기] 단추만 보인다. 마크다운·HTML·슬라이드 덱 전체 생성처럼 원래 제목 없는 문서를 기본 폴더에 저장하는 편집기는 양식 사본도 같다.
- **일반 AI 창에서는 스킬의 스크립트가 돌지 않는다.** 스크립트가 든 스킬은 "에이전트 창에서 완전히 동작" 표시가 붙고, 칩으로 넣으면 한 줄 안내가 보인다.
- **기본 스킬 5개**: 회의록 정리, 공지·소식지·FAQ 쓰기, AI 티 없애기(영어 글 기준), 문장 다듬기(영어 글 기준), 스킬 찾기(에이전트 창 전용). 원 출처와 라이선스는 `NOTICE`에 있다.

## 출처 기록

- 만들기로 연 탭의 문서가 처음 저장되면 "이 문서는 이 자료들로 만들었다"를 데이터 폴더의 `document-links.json`에 적는다. 문서 파일 안에는 아무것도 넣지 않고, 기록은 이 PC에만 있다.
- 적는 것은 만든 문서의 경로, 넘겨받은 자료의 경로 목록, 시각, 방식(`ai`·`convert`)이다. 요청 글은 적지 않는다.
- 만들기가 실제로 시작된 탭만 적는다. AI는 넘겨받은 자료가 하나라도 붙은 채로 그 탭에서 실행이 시작된 경우(막혔다가 나중에 직접 보낸 경우 포함), 바꾸기는 바꾼 경우다. 시작과 처음 저장의 순서는 상관없다. 손으로 써서 저장한 문서, 저장하지 않고 닫은 문서, "다른 이름으로 저장"으로 생긴 새 파일에는 기록이 없다.
- 앱 안에서 이름을 바꾸거나 옮기면 만든 문서와 자료의 경로가 모두 따라간다. 다른 PC로 옮긴 파일에는 연결이 따라가지 않는다.
- 모든 편집기의 파일 메뉴에 "자료 보기"(열린 문서가 만든 문서일 때)와 "이 문서로 만든 문서"(열린 문서가 자료일 때)가 나온다. 누르면 그 파일이 열린다. 디스크에 없는 파일은 흐리게 보이고 누를 수 없다. 파일이 없다는 이유만으로 기록을 지우지 않는다.

## Google 드라이브 (결정 0033)

- 빌드에 Google 클라이언트가 없으면 드라이브는 어디에도 나오지 않는다. 있으면 홈의 사이드바에 "Google 드라이브", 설정 → 연동의 맨 위에 연결 카드가 나온다.
- 연결은 설정의 버튼으로만 시작한다. 브라우저에서 Google에 로그인하고 허용하면 끝나고, 카드에 계정 이메일이 보인다. 허용 화면에서 드라이브 항목을 끄면 연결하지 않고 그렇다고 알린다.
- 홈의 드라이브 화면: 내 드라이브(폴더를 따라 들어가기), 공유 문서함, 최근, 검색(이름과 본문). 앱의 편집기가 여는 형식과 Google 문서·스프레드시트·프레젠테이션만 열 수 있고, 나머지는 흐리게 보인다.
- 연 파일은 PC 사본이 탭으로 열린다. 최근 목록에 남은 사본을 다시 열면 드라이브를 거친다. 드라이브 쪽이 바뀌었고 사본에 올리지 못한 변경이 없으면 새로 받는다. 탭에 열려 있거나 올리지 못한 변경이 있으면 사본을 그대로 연다.
- 저장하면 2.5초 뒤 드라이브에 올린다. 같은 파일의 저장이 이어지면 마지막 것만 올라간다.
  - 드라이브 쪽이 그 사이 바뀌었으면: "드라이브의 파일 덮어쓰기 / 드라이브에 사본으로 저장 / 이 PC에만 저장"을 묻는다. 기본은 사본이다.
  - 보기 전용이거나 드라이브에서 사라졌으면: "사본으로 저장 / 이 PC에만 저장"을 묻는다.
  - "사본"은 같은 폴더에 `이름 (사본).확장자`로 만들고, 그 뒤의 저장은 사본으로 간다. 그 폴더에 쓸 수 없으면 내 드라이브에 만든다.
  - "이 PC에만"을 고른 사본은 그 뒤로 올리지 않는다. 드라이브에서 다시 열면 새로 시작한다.
  - Google 문서 형식은 처음 저장할 때 같은 폴더에 `이름.docx`(`.xlsx`, `.pptx`)를 만들고 알린다. 원본 Google 문서는 고치지 않는다. 같은 Google 문서를 다시 열어 저장하면 Office 파일이 또 하나 생긴다.
  - 올리기가 실패하면 30초, 2분, 10분 뒤 다시 하고, 세 번째에 실패를 알린다. 연결이 끊긴 동안의 저장은 다시 연결될 때, 앱을 끈 뒤에 남은 것은 다음 시작 때 올린다.
- AI: "AI가 드라이브에서 파일을 찾아 읽기"는 연결하면 켜진다. 켜져 있는 동안 모든 편집기의 AI 창에 `drive_search`(20개까지)와 `drive_read`(2만 4천 자씩)가 있다. 한 대화에서 드라이브 파일을 읽은 뒤로는 그 대화가 새로 시작될 때까지 웹 검색, 이미지 검색, 이미지 생성, 미디어 분석, 주소로 그림 넣기, 주소로 문서 읽기(`read_url`)가 거절되고, AI는 새 대화를 시작하면 다시 된다고 알린다.
- 드라이브에서 첨부: 워드·엑셀·PPT·HTML·마인드맵·한글 편집기의 AI 창에서, 드라이브가 연결돼 있으면 첨부 버튼 옆에 "Google 드라이브에서 첨부"가 생긴다. AI 접근 스위치와 상관없다(사람이 직접 고르는 것이기 때문이다). 누르면 고르기 창이 그 편집기 창 위에 뜨고, 파일과 폴더에 체크해 "첨부"를 누른다. 폴더는 바로 아래의 파일만, 읽을 수 있는 형식만 넣는다. 한 번에 20개까지이고, 빠진 수와 받지 못한 수는 첨부 줄 옆에 알린다. Google 문서 형식은 Office 파일로 받는다. 받은 파일은 PC 파일 첨부와 똑같이 다룬다(가리기, 보내기 전 판단, 새 대화에서 비워짐). 사람이 고른 첨부는 웹 검색 등을 막지 않는다. 마크다운과 PDF 편집기는 첨부가 없어 이 버튼도 없다. 고르기 창은 한 번에 하나다.
- 연결 끊기: 확인을 받은 뒤 이 PC의 로그인을 지우고 Google에 앱의 접근을 거두게 한다. PC 사본은 남는다. Google이 연결을 끝낸 경우(권한 회수, 만료)에는 카드와 드라이브 화면이 그렇다고 알린다.

## 이음오피스 문서에서 첨부 (결정 0035)

- 워드·엑셀·PPT·HTML·마인드맵·한글 편집기의 AI 창에서, 첨부 단추 옆에 "이음오피스 문서에서 첨부"가 있다. 껍데기 앱 안에서 돌 때만 나온다(편집기를 혼자 띄우면 나오지 않는다). 드라이브 연결과 상관없다.
- 누르면 문서 고르기 창이 그 편집기 창 위에 뜬다. 사용자가 체크해 "첨부"를 누르면 고른 파일이 그 편집기의 평소 PC 파일 첨부와 똑같이 다뤄진다(가리기, 보내기 전 판단, 새 대화에서 비워짐). 한 번에 20개까지이고, 창은 한 번에 하나다. 창이 이미 열려 있으면 새로 띄우지 않고 그 창을 앞으로 가져온다.
- 목록은 화면을 나눴다면 옆 칸 문서가 먼저, 그다음 열려 있는 문서(떼어 낸 창 포함), 그다음 최근 연 문서다(결정 0051). 지금 문서와 같은 경로의 문서는 빠진다. 여러 그룹에 같은 파일이 있으면 앞 그룹 하나만 보인다.
- 저장하지 않은 문서와 저장 안 된 변경이 있는 문서는 목록에 흐리게 보이고 고를 수 없다. 이유("먼저 저장하라", "저장하면 붙일 수 있어요")가 함께 보인다(저장하지 않은 내용은 가리기 표시가 파일에 없어 읽지 않는다). 디스크에서 찾을 수 없는 파일도 흐리게 보이고 고를 수 없다.
- 형식과 크기로만 거른다. 내용은 열어 보지 않으므로, 확장자만 맞고 내용이 다른 파일이나 암호가 걸린 파일도 목록에는 남고, 실제로 붙일 때 그 편집기의 첨부 읽기가 거절하며 그 사실이 첨부 줄에 보인다. 형식 목록은 여섯 편집기가 한 곳(`packages/file-parse`)에서 가져온다.
- 고른 파일은 PC 안의 원래 경로 그대로 붙는다(드라이브 첨부처럼 사본을 만들지 않는다). 파일을 옮기거나 지운 뒤 붙이면 그때 읽기 실패로 알린다.

## 입력란의 `@`로 문서 붙이기 (결정 0051)

- 위 여섯 편집기의 AI 창 입력란에서 입력 맨 앞이나 공백 바로 뒤에 `@`를 치면 같은 목록(옆 칸 → 열린 문서 → 최근 문서, 지금 문서 제외)이 입력란 위에 열린다. 없어진 최근 파일은 숨긴다. 껍데기 앱 안에서 돌 때만 열린다. 메일 주소(`a@b.com`), 엑셀의 `=@A1`·`표[@열]`에서는 열리지 않고, 한글 조합 중에는 새로 열리지 않는다.
- `@` 뒤에 친 글로 파일 이름을 걸러 낸다(대소문자 무시, 이름이 그 글로 시작하는 문서가 먼저). 공백을 넘어서도 맞는 문서가 있는 동안 열려 있고, 맞는 것이 없어지거나 Esc를 누르면 닫힌다. Esc로 닫은 `@`는 그 `@`를 고치거나 다른 `@`를 쓸 때까지 다시 열리지 않는다(커서가 잠시 다른 곳에 갔다 와도 닫힌 채다).
- 저장 안 된 변경이 있는 문서와 저장하지 않은 문서는 흐리게 이유와 함께 보이고, ↑/↓가 건너뛰며 눌러도 붙지 않는다.
- Enter·Tab·클릭으로 고르면 그 편집기의 평소 첨부 길로 붙인다. 붙기에 성공하면 친 `@글`이 `@파일 이름 `으로 바뀌고, 거절되면 글은 그대로 두고 첨부 줄에 이유가 보인다. 이미 붙은 문서를 또 고르면 글만 들어간다. 고른 `@이름`에서는 목록이 다시 열리지 않는다. 글과 첨부는 따로 움직인다(글을 지워도 첨부는 남는다).
- 목록이나 지금 첨부에 이름은 같고 경로가 다른 문서가 있으면 `@계획서.docx(2학기) `처럼 바로 위 폴더 이름을 붙인다. AI가 받는 첨부 목록에도 이름이 겹치는 첨부에만 `(folder: …)`가 붙는다. 드라이브 사본처럼 앱이 만든 폴더에 든 파일에는 붙이지 않는다.
- 맨 아래 "더 찾아보기…"는 위의 고르기 창을 연다. 고른 문서 중 붙은 것들의 `@이름`이 친 `@글` 자리에 들어가고, 취소하면 글은 그대로다.
- 손으로 친 `@글자`는 막지 않고 평범한 글로 보낸다.

## 제품 정체성과 원본과의 공존

- 화면의 제품 이름은 한국어에서 "이음오피스", 그 밖의 언어에서 "IeumOffice"다. 출처 표시 문구 안의 "GenOffice"는 바뀌지 않는다.
- 설치 식별자, 설정·데이터 폴더, 파일 연결 등록 이름, 중복 실행 방지 이름은 원본과 다르다. 두 프로그램을 한 PC에 함께 깔아도 서로 영향을 주지 않는다.
- PC에 등록되는 바깥 이름은 `ieumoffice`다(터미널 명령어, MCP 등록 이름, 에이전트 스킬 이름과 폴더, 홈 폴더 아래 `.ieumoffice`).
- 이 앱은 원본이 등록한 것(`genoffice` 명령어, `.genoffice` 폴더, `genoffice` 연동 항목과 스킬 폴더)을 읽지도 고치지도 않는다.
- 저장된 문서 안의 식별자와 문서 곁의 보조 파일 이름(`.genoffice-assets.json` 등)은 원본과 같다. 두 프로그램은 같은 문서를 주고받을 수 있다.

## 슬라이드 디자인 템플릿

- 파워포인트 편집기의 AI 창에서 기본 템플릿(12개)이나 사용자가 저장한 스타일 하나를 고를 수 있다. 고르는 일은 AI를 부르지 않는다. 슬라이드가 있는 문서에서 골라도 지금 있는 슬라이드는 바뀌지 않고, 앞으로 AI가 만드는 슬라이드에만 적용된다. 이미 있는 슬라이드를 템플릿으로 다시 꾸미는 기능은 없다.
- 고른 것이 없으면 AI가 주제에 맞춰 스타일을 스스로 만든다. AI가 템플릿을 대신 고르지 않는다.
- 기본 템플릿을 골랐으면 그 템플릿의 스타일 글이 덱의 스타일이 되고, AI는 스타일을 묻지 않는다. 슬라이드를 더 만들거나 한 장을 다시 만들 때도 같은 스타일을 쓴다.
- 저장한 스타일을 골랐으면 그 스타일 글과(있으면) 배치 뼈대를 쓴다. 금지 규칙은 그대로 적용된다. 기본 템플릿에서 저장한 스타일만 아래의 예외를 물려받는다.
- 쪽 생성기의 금지 규칙 가운데 템플릿의 대표 장식과 부딪히는 것(카드 위 색 띠, 카드 왼쪽 막대, 제목 옆 막대, 모서리 장식)은 그 템플릿이 그 장식을 정했을 때만 적용하지 않는다. 이 예외는 기본 템플릿과, 기본 템플릿에서 저장한 스타일에만 있다. 나머지 금지 규칙은 그대로다.
- 템플릿을 고른 채로 말한 스타일 요구(예: "파란색 위주로")는 템플릿보다 우선하고, 그 문서에 쌓여 다음 생성과 다시 연 뒤에도 적용된다. 합쳐 600자를 넘으면 오래된 것부터 버린다. 템플릿을 바꾸거나 빼면 함께 사라진다.
- 대화에서 다른 템플릿이나 저장한 스타일의 이름을 대면 그것으로 만들고 문서의 선택도 바뀐다. 덧붙인 요구는 사라진다. 이름을 처음 대는 그 요청에 AI가 함께 넘긴 스타일 설명은 쓰지도 남기지도 않는다(AI가 지어낸 설명이 요구로 섞이지 않게 하려는 것이다). 그 요청에서 말한 요구는 다음 요청에서 다시 말해야 적용된다. 댄 이름이 기본 템플릿에도 저장한 스타일에도 없으면 선택은 그대로 두고, 그 사실과 쓸 수 있는 이름 목록을 AI에게 알린 뒤 지금의 선택(없으면 AI가 만드는 스타일)으로 만든다.
- 고른 템플릿과 덧붙인 요구는 이 PC의 앱 데이터에만 문서 경로별로 기억한다. `.pptx` 안이나 곁에는 아무것도 쓰지 않으므로, 파일을 다른 PC로 옮기거나 앱 밖에서 이름을 바꾸면 기억하지 못한다.
- 템플릿 글꼴(한글 6개, 영문 제목용 4개 패밀리)은 설치 파일에 한 벌만 들어 있고 워드·엑셀·파워포인트 편집기에서만 쓸 수 있다. Windows에 설치되지 않으므로, 같은 PC의 파워포인트를 포함해 다른 프로그램에서 열면 다른 글꼴로 보인다. 템플릿 고르는 곳의 "글꼴 폴더 열기"로 파일을 찾아 사용자가 직접 설치할 수 있다.

## 글꼴과 업데이트

- 글꼴 목록에는 PC에 깔린 글꼴과 앱에 들어 있는 글꼴만 나온다. 앱에 들어 있는 글꼴에는 워드·엑셀·파워포인트 편집기의 템플릿 글꼴이 포함된다. 내려받는 글꼴은 없다. 사용자가 가진 글꼴 파일을 설치하는 기능은 있다.
- 문서가 PC에 없는 글꼴을 쓰면 기존의 글꼴 대체 동작을 따른다.
- 설치된 앱은 GitHub 릴리스를 확인해 새 버전을 알린다. 릴리스가 없거나 확인에 실패하면 아무 일도 일어나지 않고, 오류 창도 뜨지 않는다. 시험판은 업데이트 채널을 베타로 바꾼 경우에만 받는다.
