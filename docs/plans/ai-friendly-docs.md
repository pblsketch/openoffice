# 행정문서 점검(행안부 가이드라인) 설계

상태: **2단계까지 구현됨**(2026-10-29). `packages/doc-rules`에 규칙 10개와 판정 함수가 있고, 한글 편집기의 플러그인이 문서 프로필을 내며, 앱 틀의 점검 창이 그것을 판정해 보여 준다. 글꼴은 창에서 한 번의 실행 취소로 고치고(`replaceFont`), 나머지는 AI 입력 칸에 요청으로 넘긴다. 실제 공문서 58개(보도자료 40·보고서 18)로 기본값을 맞췄고(8.1·8.2), 실제 구독으로 한 번 돌려 위반 1·확인 필요 2가 확인 필요 1로 줄었다(5절). 워드(docx)와 CLI는 아직이다.

## 1. 한 줄 결론

행안부가 2026-08-24부터 적용한 「행정문서 작성 가이드라인 2.0」과 「AI 친화적 행정문서 작성방법」을, **열려 있는 문서를 읽어서 항목별로 짚어 주는 기능**으로 만든다. 검사는 AI를 부르지 않고 문서 구조만 보고 판정하고(무료·즉시·오프라인), 고치는 일만 원할 때 AI에게 맡긴다. 문서는 읽기만 하며, 자동으로 고치지 않는다.

## 2. 배경

### 가이드라인이 요구하는 것

행안부 보도자료(2026-08-24)와 붙임 문서에서 확인한 내용이다. 적용 대상은 행안부가 작성하는 모든 보고서(장관 보고 ~ 실·국장 보고)이고, 법적 강제는 아니다.

| 원칙               | 요구                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 문장은 서술식      | 주어·목적어·서술어를 갖춘 서술식. 번호는 Ⅰ. / 1. / 가. / 1) / 가) / (1) / (가) / ① / ㉮, 기호는 □ ○ - · 로 통일. 단어 중간 띄어쓰기와 줄임말 금지. 요약문은 선택 |
| 범용성·호환성      | 함초롬바탕·함초롬돋움·맑은고딕 같은 호환 글꼴. 휴먼명조·양재와당체 같은 아래아한글 전용 글꼴 금지(전체 목록은 하모니 알림방)                                     |
| 표·그림은 단순하게 | '표를 활용한 제목' 같은 디자인 표 금지. 표·그림 **위**에 제목. 다층 셀 병합 지양(단순 병합은 허용). 순서·체계는 번호와 화살표로                                  |
| 적용 방법          | 강조를 위한 밑줄·진하게·글자색·음영은 허용. 분량을 채우는 '보고서 꾸미기'는 금지                                                                                 |

보도자료에 딸린 사실이 하나 더 중요하다. 행안부는 **보도자료를 마크다운으로 병행 배포**하고 '온AI' 적용을 넓히고 있다. 문서의 형식 기준과 함께 "AI가 읽는 원문"이 배포물이 된다는 뜻이다.

### 왜 우리에게 맞는가

- 이 기준의 세 원칙 중 둘(글꼴, 표 구조)은 **문서 XML만 보면 정답이 나오는 검사**다. AI 추측이 필요 없다.
- 이음오피스는 HWPX(rhwp)와 docx(docx-engine) 문서 모델을 이미 갖고 있고, 문단·표·글자 모양·개체를 번호로 짚는 통로도 이미 있다(`apps/hwp/studio-plugin/agent-plugin.mjs`).
- 검사는 AI를 부르지 않으므로 무료이고, **기관용 배포 모드에서 AI를 꺼도 동작한다**. 보안성 검토에서 AI를 막아 둔 기관에도 넣을 수 있는 몇 안 되는 기능이다.

### 지금 없는 것

- 문서의 형식 규칙을 검사하는 코드가 없다. 글꼴·표 구조·번호 체계를 한 번에 훑는 곳도 없다.
- 공문서를 대상으로 한 규칙 묶음도, 그 규칙을 화면에 보여 주는 창도 없다.

## 3. 무엇을 검사하나

규칙은 **판정 근거**에 따라 셋으로 나눈다. 이 구분이 이 설계의 중심이다.

- **위반**: 문서 구조에서 정답이 나온다. 틀렸다고 단정해도 된다.
- **확인 필요**: 구조는 알겠는데 뜻은 사람이 봐야 한다(제목용 표인지, 병합이 과한지).
- **제안**: 취향·관행의 문제다(권장 글꼴 밖, 개조식 문장). 기본으로 켜지 않는다.

### 1단계 규칙 (AI 없이)

| ID                         | 판정      | 무엇을 보나                                                                                         | 근거      |
| -------------------------- | --------- | --------------------------------------------------------------------------------------------------- | --------- |
| `font.hangul-only`         | 위반      | 문서가 실제로 쓰는 글자 모양의 글꼴이 아래아한글 전용 목록에 있다                                   | 글꼴      |
| `font.outside-recommended` | 제안      | 권장 목록(함초롬바탕·함초롬돋움·맑은고딕) 밖의 글꼴을 쓴다                                          | 글꼴      |
| `table.nested`             | 위반      | 표 안에 표가 있다                                                                                   | 표 구조   |
| `table.deep-merge`         | 확인 필요 | 병합 칸이 표 격자의 1/3을 넘거나, 병합이 두 단계 이상 겹친다                                        | 표 구조   |
| `table.no-caption`         | 확인 필요 | 표 위에 제목으로 볼 만한 글이 없다(빈 줄은 건너뛰고 가장 가까운 글을 본다)                          | 표·문단   |
| `table.decorative`         | 확인 필요 | 1행 1열(또는 1×N) 표에 짧은 글만 들어 있고 바로 뒤에 본문이 이어진다 — 제목 대용 표로 보인다        | 표 구조   |
| `figure.no-caption`        | 확인 필요 | 그림 위에 캡션 문단이 없다                                                                          | 개체·문단 |
| `numbering.mixed`          | 확인 필요 | 한 문서에서 같은 깊이를 두 가지 표기로 쓴다(예: `1)`과 `(1)`이 같은 층에 섞임)                      | 문단 글자 |
| `numbering.order`          | 확인 필요 | 번호 깊이가 가이드라인의 사다리(Ⅰ. → 1. → 가. → 1) → 가) → (1) → (가) → ①)를 건너뛰거나 거꾸로 간다 | 문단 글자 |
| `blank.run`                | 제안      | 빈 문단이 3개 이상 연속한다(분량 채우기 의심)                                                       | 문단      |

`font.outside-recommended`·`numbering.*`·`blank.run`은 **기존 문서에서 대량으로 걸린다**. 그래서 처음 열 때는 기본으로 꺼 두고, 켜는 것은 사용자가 한다. 실제 공문서 40개로 재 보니 `table.no-caption`과 `figure.no-caption`도 40/40 문서에서 걸려 함께 껐다(8.1). 위반으로 단정하는 규칙은 `font.hangul-only`와 `table.nested` 둘뿐이다.

### 2단계 규칙 (AI가 판단)

| ID                      | 무엇을 보나                                                                |
| ----------------------- | -------------------------------------------------------------------------- |
| `prose.list-style`      | 문단이 "~함 / ~임 / ~추진" 같은 개조식이다. 가이드라인은 서술식을 요구한다 |
| `prose.summary-missing` | 긴 보고서인데 요약문이 없다(가이드라인은 선택 사항이므로 제안에 그친다)    |
| `table.title-format`    | 표 제목이 "○○ 개요" 꼴이 아니라 문장이다                                   |

### 일부러 넣지 않는 규칙

- **단어 중간 띄어쓰기**("일 정"): 한국어 띄어쓰기 판정은 오탐이 많다. `1)` 같은 명백한 것만 본다.
- **글자 크기·줄 간격·여백**: 가이드라인에 없다.
- **밑줄·진하게·음영**: 가이드라인이 허용한다. 세지 않는다.

## 4. 어떻게 만드나

### 자리

```
packages/doc-rules/
  src/profile.ts        문서 프로필(형) — 편집기가 넘기는 것
  src/audit.ts          audit(profile, ruleSet) → Finding[] (순수 함수)
  src/rules/administration-ko.ts   행안부 규칙 묶음(1단계)
  src/rules/registry.ts 규칙 묶음 목록
  src/fonts.ts          아래아한글 전용 글꼴 목록(우리 목록, 8절 참고)
  tests/
```

규칙은 **코드가 아니라 데이터**로 둔다. 지자체·교육청 지침은 조금씩 다르고, 나중에 `gyeonggi-ko` 같은 묶음을 더하거나 기관이 자기 묶음을 넣을 수 있어야 한다.

### 흐름

```
편집기 안(플러그인)  ── 문서 프로필 ──▶  앱 화면  ── 검사 ──▶  점검 창
   문단·표·개체를 번호로 훑는다          (TS, 순수 함수)      목록 + 위치로 가기
```

- **프로필을 뽑는 일만 편집기 안에서 한다.** HWP는 플러그인(`agent-plugin.mjs`)에 메서드 하나(`documentProfile`)를 더한다. 이미 있는 호출을 그대로 쓴다: `getCharPropertiesAt`·`getCellCharPropertiesAtByPath`(글꼴·모자 번호), `getStyleList`(스타일), `getParaPropertiesAt`(문단 모양), `tablesOf`(표, 표 안의 표 포함), `getControls`(개체 수), `textOf`(글자).
- **다리는 이미 열려 있다.** `apps/hwp/src/renderer/ai/agent-bridge.ts`의 `METHODS` 목록에 이름 하나를 더하면 화면에서 부를 수 있다. 이 통로는 AI 실행과 무관하므로 모델을 부르지 않는다.
- **docx는 화면이 이미 갖고 있는 문서 나무에서 뽑는다.** 표에 `tblCaption` 속성이 있어 제목 유무를 그대로 알 수 있다.
- **한도**: 프로필은 문단 2만 개, 표 500개, 개체 200개에서 멈추고 `truncated: true`를 남긴다. 걸리면 "일부만 보았다"고 화면에 적는다(조용히 넘어가지 않는다).

### 프로필에 담는 것

```ts
type Profile = {
  format: 'hwp' | 'hwpx' | 'docx' | 'odt'
  truncated?: boolean
  charShapes: { id: string; fonts: string[]; uses: number }[] // 실제로 쓰인 것만
  paragraphs: { index: number; text: string; styleId: string; empty: boolean }[]
  tables: {
    index: number
    paraIndex: number // 놓인 문단(칸 안이면 경로)
    rows: number
    cols: number
    mergedCells: number
    nested: boolean
    caption: string | null // docx는 tblCaption, HWP는 앞 문단
  }[]
  pictures: { index: number; paraIndex: number; caption: string | null }[]
}
```

`Finding`은 규칙 ID·판정·세기·`anchor`(편집기가 짚을 수 있는 자리)를 담는다. `anchor`는 HWP면 `{ sec, para, path? }`, docx면 문서 위치다. 위치로 가는 일은 이미 있는 `reveal`을 쓴다.

### 화면

- **점검 창**을 따로 연다. AI 창 안의 탭이 아니다.
  - 이유: 한글 편집기 안쪽은 한국어·영어만 지원하므로, 21개 언어로 보여야 하는 이 창은 **앱 틀**에 있어야 한다.
  - 여는 곳: 한글 탭의 AI 띠 옆에 단추 하나(`.ai-rail`과 같은 자리), 메뉴의 "문서 점검".
  - 내용: 위반 → 확인 필요 → 제안 순. 규칙 이름, 걸린 개수, 누르면 그 자리로 간다. 맨 위에 "위반 3 · 확인 필요 5 · 제안 12"와 "일부만 보았다" 표시.
  - AI 연결이 없어도 그대로 뜬다. 연결이 없으면 "AI에게 고치기 맡기기" 단추만 흐리게 둔다.
- **고치기 맡기기**: 창 아래 단추를 누르면 걸린 항목을 요약해 AI 입력 칸에 넣는다(보내지는 않는다). 사용자가 확인하고 보낸다. AI는 기존 도구(글꼴 바꾸기, 표 지우기, 문단 고치기)로 고치고, 한 번의 실행 취소 단계로 끝난다.
- 문구는 21개 언어로 넣는다. 규칙 이름과 한 줄 설명은 **한국어만** 둔다(대상이 한국 행정문서라서다). 창 맨 위에 그 사실을 한 줄로 적는다.

### 저장에 닿지 않는다

프로필 뽑기는 읽기만 한다. 문서 엔진의 저장·내보내기 결과를 바꾸지 않고, 새 문서 식별자도 넣지 않는다. `docs/standards.md`의 "문서 안에 저장되는 것은 바꾸지 않는다"를 그대로 따른다.

## 5. AI로 고치기 (2단계)

- **글꼴은 AI가 아니라 평범한 편집으로 고친다.** 플러그인의 `replaceFont(from, to)`가 그 글꼴을 쓰는 모든 글자 구간을 한 번의 실행 취소로 바꾼다. 점검 창의 글꼴마다 "함초롬바탕으로 바꾸기" 단추가 이것을 부른다. 39곳을 모델에게 하나씩 시키는 것보다 정확하고, 요금도 들지 않는다.
- **나머지는 AI에게 요청으로 넘긴다.** 창 아래 "AI에게 고치기 맡기기"를 누르면 걸린 항목과 지킬 것을 적은 요청이 **AI 입력 칸에 들어간다. 보내지는 않는다.** 사용자가 읽고 보낸다.
- 고치는 순서는 요청 글에 적어 둔다: 글꼴 → 표 구조 → 제목·번호 → 문장.
- **표 안의 표와 병합은 자동으로 고치지 않는다.** 내용이 사라질 수 있다. 요청 글에도 "표를 지우거나 칸을 합치지 말라"고 적고, 모델은 짚어만 준다.
- AI가 문서를 고치면 점검 창이 **1.2초 뒤에 문서를 다시 읽어** 숫자를 갱신한다(브리지를 지나는 변경을 세어서). 사용자가 직접 고친 것은 "다시 검사"로 본다.
- 검사와 고치기는 같은 규칙 묶음을 쓴다.

### 5.1 실제 구독으로 한 번 돌린 결과 (2026-10-29)

네 문단짜리 시험 문서(`1. 추진 배경` / `(1) 세부 내용` / 본문 / 1×1 표 `□ 사업 개요`, 첫 줄은 휴먼명조)로 **실제 Claude 구독**에 한 번 맡겼다. 3단계, 40초.

- **글꼴**: `replace_font`로 휴먼명조 → 함초롬바탕. 위반이 사라졌다.
- **번호**: `(1) 세부 내용` → `가. 세부 내용`. "건너뛴 번호 단계"가 사라졌다.
- **1칸짜리 표**: 지우지 않고 그대로 두었다. "표를 일반 문단으로 바꾸는 것이 좋지만 내용이 사라질 수 있으니 직접 판단하라"고 답했다. 요청 글의 금지 사항이 지켜졌다.
- 점검 창은 **손대지 않아도** 다시 읽어 `위반 1 · 확인 필요 2` → `확인 필요 1`로 바뀌었다.

이 실행으로 남은 것이 하나 드러났다. **표를 문단으로 되돌리는 도구가 없다.** 1×1 제목 상자는 보고서에서 가장 많이 걸리는 항목인데(8.2: 18/18 문서 350곳), 지금은 AI가 짚어만 줄 수 있다. 3단계 뒤에 `unwrapTable`(칸의 문단을 본문으로 옮기고 표만 없애기, 실행 취소 한 단계)을 붙이면 이 항목도 고칠 수 있다.

## 6. 하지 않는 것

- **"행안부 공식" "정부 표준"이라고 쓰지 않는다.** 행안부 내부 지침이고, 다른 기관은 아직 아니다. 화면에는 "행안부 가이드라인 기준"이라고만 적는다.
- **자동으로 고치지 않는다.** 저장할 때 서식을 바꾸지도 않는다.
- **금지 글꼴 목록이 공개본이라고 말하지 않는다.** 전체 목록은 하모니 알림방에 있고 이 PDF에는 없다. 우리 목록은 근사치이며, 문서마다 "우리 목록 기준"임을 밝힌다.
- **온AI·정부 클라우드·계정·통계를 붙이지 않는다.** 서버 없는 구조를 유지한다.
- **꾸미기 금지를 강제하지 않는다.** 알려 주기만 한다. 표 배경색·밑줄을 쓰는 기관 문서는 흔하다.

## 7. 단계

| 단계 | 내용                                                                | 확인 방법                                                   |
| ---- | ------------------------------------------------------------------- | ----------------------------------------------------------- |
| 0 ✅ | `packages/doc-rules`: 프로필 형, 검사 함수, 행안부 규칙 10개, 시험  | 순수 함수 단위 시험(가짜 프로필) 28개 통과                  |
| 1 ✅ | 한글 플러그인의 `documentProfile` + 점검 창(읽기 전용, 위치로 가기) | 빌드한 앱(견본 교과협의록), `e2e/hwp-doc-check.spec.ts` 2건 |
| 2 ✅ | "AI에게 고치기 맡기기" + 다시 세기                                  | 실제 구독 1회: 위반1+확인2 → 확인1(3단계), e2e              |
| 3    | 워드(docx) 같은 창                                                  | 견본 docx                                                   |
| 4    | (선택) `ieumoffice audit <파일>` — 창 없이 점검                     | CLI 시험                                                    |

0단계는 화면 없이 끝나고, 여기서 규칙의 오탐률을 먼저 잴 수 있다. **실제 문서 40개로 잰 결과는 8.1에 있고, 거기서 기본값 셋을 바꿨다.**

### 8.1 실제 문서 40개로 잰 결과 (2026-10-29)

행안부 보도자료 목록에서 내려받은 `.hwpx` 40개(2026년 10월분)를, **꺼 둔 규칙까지 모두 켜고** 돌렸다. 문단 중앙 25개·최대 138개, 표 중앙 6개·최대 39개, 그림 중앙 5개·최대 13개이고, 프로필을 뽑는 데 중앙 23ms·최대 202ms 걸렸다. 한도에 걸린 문서는 없었다.

| 규칙                       | 걸린 문서 | 걸린 곳 | 판단                                                                                                                                |
| -------------------------- | --------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `font.hangul-only`         | 30/40     | 168     | **사실.** HY견명조 25문서, 휴먼명조 24문서, HY헤드라인M 22문서. 가이드라인을 만든 부처의 보도자료가 가이드라인이 금지한 글꼴을 쓴다 |
| `table.nested`             | 5/40      | 26      | **사실.** 한 문서에 20곳이 몰려 있다                                                                                                |
| `table.deep-merge`         | 15/40     | 22      | 사실로 보인다. 대부분 본문 세로 병합이고, 라벨이 이유를 함께 적는다                                                                 |
| `table.decorative`         | 6/40      | 31      | 글자가 든 1×1 표만 남기고 나서의 수치                                                                                               |
| `table.no-caption`         | 38/40     | 76      | **기본 꺼짐.** 두 줄 이상만 봐도 38/40이다. 131곳 중 119곳이 첫 4문단의 머리말 표(보도시점·지면)                                    |
| `figure.no-caption`        | 40/40     | 224     | **기본 꺼짐.** 보도자료의 그림은 설명용 삽화이고, 거의 모두 문단에 홀로 놓인다                                                      |
| `font.outside-recommended` | 0/40      | 0       | 기본 꺼짐. 바탕·돋움을 호환 글꼴로 넣고 나서 0이 됐다                                                                               |
| `blank.run`                | 16/40     | 17      | 기본 꺼짐. 빈 줄 기준을 3에서 5로 올린 뒤의 수치(3일 때는 40/40)                                                                    |
| `numbering.*`              | 0/40      | 0       | 재지 못했다. 보도자료는 ○·□ 글머리만 쓰고 Ⅰ./1./가. 번호를 쓰지 않는다                                                              |

바꾼 것 다섯.

1. `table.no-caption`·`figure.no-caption`을 기본 꺼짐으로 내렸다.
2. `table.no-caption`은 **두 줄 이상인 표**만 본다(한 줄짜리는 머리띠이지 데이터 표가 아니다).
3. `table.decorative`는 **글자가 든 1×1 표**만 본다(빈 1×1 표는 여백용이다).
4. **글꼴 목록을 넓혔다.** `HY*`·`한컴 *`로 시작하는 이름은 아래아한글 전용으로 보고(목록에 없던 HY헤드라인M·한컴 고딕을 잡는다), 바탕·돋움·굴림·돋움체·바탕체는 호환 글꼴로 둔다. 넓히기 전에는 `font.outside-recommended`가 40/40 문서 698곳에서 걸렸는데, 그 대부분이 바탕·돋움이었다.
5. 빈 줄 기준을 3줄에서 5줄로 올렸다.

이 코퍼스는 보도자료라서 보고서와 관행이 다르다. 그래서 보고서를 따로 모아 다시 쟀다(8.2). 그래도 "대부분 문서에서 걸리는 규칙은 기본으로 끈다"는 원칙과 "글꼴 목록이 틀리면 조용한 규칙도 소음이 된다"는 것이 데이터로 확인됐다.

## 10. 정할 것

1. **범위**: 1단계를 한글(HWP·HWPX)만 할지, 처음부터 워드(docx)도 할지. 권고는 한글만 — 정부 문서는 대부분 HWPX이고 엔진 통로가 가장 좋다.
2. **화면**: 따로 창(권고)인지, AI 창 안의 탭인지.
3. **규칙 이름 번역**: 한국어만 둘지(권고), 21개 언어로 옮길지. 옮기면 문구 비용이 크게 늘어난다.
4. **기본값**: `numbering.mixed`를 위반으로 둘지 확인 필요로 둘지. 기존 문서에서 대량으로 걸릴 수 있다.
5. **CLI(4단계)를 지금 할지**: 창 없이 점검할 수 있으면 실제 문서 30개를 한 번에 훑어 오탐을 재기 쉽다. 대신 HWP 구조를 파일에서 바로 꺼내는 일(`packages/file-parse`)이 더 필요하다.
