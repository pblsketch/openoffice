# 워드 → 한글 문서 바꾸기 계획

상태: **방향 확정**(2026-10-15). "정한 것"(10절)은 결정 기록 [0032](../tracking/decisions/0032-docx-to-hwp-without-ai.md)에 옮겼다. 단계별 세부는 구현하면서 이 문서를 고친다.

## 1. 무엇을 하려는가

워드 문서(`.docx`)를 **서식을 살린 한글 문서**(`.hwp`·`.hwpx`)로 바꾼다. AI를 쓰지 않고 이 PC 안에서만 처리하며, 결과는 저장하지 않은 **새 한글 탭**으로 연다. 원본 워드 파일은 바꾸지 않는다.

계기는 2026-10-15 외부 시험 사용자의 의견이다. 한글 편집기의 AI 창에 워드 파일을 첨부하고 한글로 바꿔 달라고 하자, AI가 "문서에서 글자만 꺼낼 수 있고 서식은 보지 못한다"고 답했다. 그 답은 사실이다. 첨부는 `packages/file-parse`의 `docxToText`로 읽히고, 이 함수는 의도적으로 서식을 버린다. AI가 받는 것과 받지 못하는 것은 다음과 같다.

| AI가 받는 것             | AI가 받지 못하는 것                 |
| ------------------------ | ----------------------------------- |
| 본문 글자                | 글꼴, 글자 크기, 굵게·기울임·색     |
| 제목 단계(`#` 개수)      | 정렬, 줄 간격, 들여쓰기, 여백       |
| 목록 항목(`-`)           | 번호 모양, 목록 단계                |
| 표 칸의 글자(`칸 \| 칸`) | 칸 합치기, 칸 너비, 칸 색, 테두리   |
| 각주·미주, 글상자의 글자 | 그림, 머리말·꼬리말, 용지 크기·여백 |

사용자가 기대한 것은 한컴오피스의 "다른 이름으로 저장 → 한글 문서"와 같은 **파일 바꾸기**다. 지금 앱에는 그런 기능이 없다. 만들기 창의 "AI 없이 바꾸기"(`apps/shell/src/main/generate/convert.ts`)는 마인드맵↔마크다운, 마인드맵→PPT만 한다.

AI로 서식을 옮기게 하는 길(첨부에 서식 표시를 더 싣고 AI가 서식 도구를 하나씩 부르게 하기)은 택하지 않는다. 도구 호출이 문단 수만큼 늘어 **구독 한도를 많이 쓰고**, 느리고, 같은 문서도 할 때마다 결과가 다르다. 그리고 `file-parse`의 출력 모양은 다른 편집기와 색인이 기대고 있어 바꾸기 어렵다(`packages/file-parse/AGENTS.md`).

## 2. 핵심 아이디어: 필요한 부품이 이미 있다

| 부품                | 어디에                                                | 하는 일                                                                                                                                                 |
| ------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 워드 문서 읽기      | `packages/docx-engine`의 `parseDocx`                  | 문단, 글자 단위 서식(굵게·크기·글꼴·색), 문단 서식(정렬·간격·들여쓰기), 표(칸 합치기·폭·칸 색·테두리), 그림, 구역(용지·여백), 머리말·각주를 모델로 준다 |
| 스타일 풀기         | `docx-engine`의 `parseStyles`, `styleRunFormat`, 테마 | 문단 스타일·글자 스타일·문서 기본값을 읽는다. 바꾸기는 이것으로 "실제로 보이는 서식"을 계산한다                                                         |
| 한글 문서 만들기    | `@rhwp/core` 0.8.7(한글 편집기와 같은 엔진)           | 빈 문서 만들기, **HTML 붙여넣기**(`pasteHtml`), 용지 설정(`setPageDef`), 머리말·꼬리말, 각주, 그림 넣기, HWP·HWPX로 내보내기와 다시 읽어 확인           |
| AI 없이 바꾸기의 틀 | `apps/shell/src/main/generate/`                       | 자료 하나 고르기, 바꾸기 종류 목록, 결과를 새 탭에 넘기기(`queue…SeedFor`), 출처 기록(`document-links.json`)                                            |

가장 큰 지렛대는 rhwp의 HTML 붙여넣기다. 이 해석기는 한컴 한글과 MS 워드가 클립보드에 싣는 HTML을 받으려고 만든 것이라, 다음 서식을 읽는다(rhwp v0.8.7 소스 `html_import.rs`, `inline_content.rs`, `html_table_import.rs`에서 확인).

| 갈래 | rhwp HTML 붙여넣기가 읽는 것                                                                              |
| ---- | --------------------------------------------------------------------------------------------------------- |
| 글자 | 굵게, 기울임, 밑줄·취소선, 글꼴(라틴 `font-family`, 동아시아 `mso-fareast-font-family`), 크기, 색, 자간   |
| 문단 | 정렬, 줄 간격, 위·아래·왼쪽·오른쪽 여백, 첫 줄 들여쓰기, 줄바꿈(`<br>`), 글머리·번호 목록(`ul`·`ol`·`li`) |
| 표   | 칸 합치기(`colspan`·`rowspan`), 칸·표 폭, 높이, 칸 배경색, 칸마다 테두리, 세로 정렬                       |
| 그림 | `data:` 주소의 그림(글자처럼 놓인 그림 컨트롤이 된다). 칸 안의 그림도 받는다                              |

그래서 바꾸기의 뼈대는 이렇다.

```
.docx 파일
  │ parseDocx (읽기만, 엔진은 고치지 않는다)
  ▼
워드 문서 모델 ── 스타일·기본값·테마로 "보이는 서식" 계산
  │ 바꾸기 모듈: 서식을 인라인 style로 적은 HTML 만들기 (+ 옮기지 못한 것 목록)
  ▼
rhwp: 빈 한글 문서 → 용지 설정 → HTML 붙여넣기 → (2단계) 머리말·각주 → 내보내기 → 다시 읽어 확인
  │
  ▼
새 한글 탭(저장 안 됨) + "옮기지 못한 것" 알림
```

문서 엔진(`docx-engine`, rhwp)은 고치지 않는다. 두 엔진의 공개 호출만 쓰고, 결과는 새 문서다. 그래서 "엔진의 동작과 저장 결과를 바꾸지 않는다"(CLAUDE.md 절대 규칙 4)에 걸리지 않는다.

## 3. 무엇을 옮기는가

"모양이 비슷한 새 한글 문서"가 목표다. 워드와 한글은 글자 폭 계산과 줄·쪽 나눔이 달라서, 같은 서식이라도 **쪽이 나뉘는 자리는 다를 수 있다**. 화면 문구와 도움말에도 그렇게 적는다.

| 항목                                    | 0·1단계 | 2단계 | 하지 않음 | 방법·비고                                                                                         |
| --------------------------------------- | :-----: | :---: | :-------: | ------------------------------------------------------------------------------------------------- |
| 본문 글자, 문단                         |    ●    |       |           | HTML 붙여넣기                                                                                     |
| 굵게·기울임·밑줄·취소선, 글꼴, 크기, 색 |    ●    |       |           | 스타일까지 풀어 인라인 style로. 동아시아 글꼴은 `mso-fareast-font-family`                         |
| 정렬, 줄 간격, 여백, 첫 줄 들여쓰기     |    ●    |       |           | 단위: 반 포인트·트윕 → pt                                                                         |
| 표: 칸 합치기, 폭, 높이, 칸 색, 테두리  |    ●    |       |           | `gridSpan`·`vMerge` → `colspan`·`rowspan`                                                         |
| 글머리·번호 목록                        |    ●    |       |           | `ul`·`ol`. 엔진이 진짜 번호 매기기로 만드는지, 글자로 만드는지는 0단계에서 확인                   |
| 글자처럼 놓인 그림(PNG·JPEG·GIF)        |    ●    |       |           | `data:` 그림. 크기는 워드의 표시 크기                                                             |
| 용지 크기·방향·여백(첫 구역)            |    ●    |       |           | `setPageDef`                                                                                      |
| 제목 → 한글의 개요 스타일               |         |   ●   |           | 1단계는 크기·굵기만 옮긴다. 2단계에서 `applyStyle`로 개요 1~7에 맞춘다                            |
| 형광펜, 글자 배경, 위·아래 첨자         |    ●    |       |           | HTML 해석기가 읽지 않는다. 붙여넣은 뒤 `applyCharFormat`로 건다(0단계에서 1단계로 당김)           |
| 머리말·꼬리말(글자, 쪽 번호)            |         |   ●   |           | `createHeaderFooter` + 글자 넣기                                                                  |
| 각주·미주                               |         |   ●   |           | `insertFootnote`·`insertEndnote`                                                                  |
| 하이퍼링크                              | 글자만  |   ●   |           | `insertHyperlinkEx`                                                                               |
| 구역 여러 개(쪽마다 다른 용지)          |         |   ●   |           | 1단계는 첫 구역의 용지로 통일하고 알린다                                                          |
| 떠 있는 그림, EMF·WMF 그림              | 알림만  |   ●   |           | 떠 있는 그림은 글자처럼 놓는다. EMF·WMF는 `docx-engine`의 변환을 쓴다                             |
| 표 안의 표                              | 글자로  |       |     ●     | rhwp가 칸 안의 붙여넣은 표를 글자로 푼다(`apps/hwp/AGENTS.md` 테스트 절). 엔진이 생기면 다시 본다 |
| 글상자, 도형, 차트, SmartArt            | 글자로  |       |     ●     | 안의 글자만 문단으로 옮기고 알린다                                                                |
| 수식(OMML)                              | 글자로  |       |     ●     | 한글 수식 문법으로 바꾸는 일은 따로 크다. 상태 문서의 "워드 변환의 수식"과 같이 미룬다            |
| 메모, 변경 추적, 필드(차례 등)          |         |       |     ●     | 지금 보이는 글자만 옮긴다. 차례는 글자로 남는다                                                   |
| 한글 → 워드(반대 방향)                  |         |       |     ●     | 이 계획의 범위 밖. 필요하면 따로 계획한다                                                         |

옮기지 못한 것은 **조용히 버리지 않는다.** 바꾸기 모듈이 갈래별로 센 목록(예: "그림 2개를 글자처럼 놓음, 수식 3개는 글자로, 글상자 1개")을 돌려주고, 새 한글 탭이 열릴 때 알림으로 보여 준다.

## 4. 화면과 입구

| 단계  | 입구                                                  | 동작                                                                                                                |
| ----- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 1단계 | 만들기 창: 자료로 `.docx` 하나 → "한글 문서로 바꾸기" | 지금의 "AI 없이 바꾸기"에 종류 하나(`docx-to-hwp`)를 더한다. 저장하지 않은 자료는 지금처럼 막는다                   |
| 1단계 | 한글 편집기 AI 창                                     | 워드 파일을 첨부하고 바꿔 달라고 하면, AI가 할 수 있는 것(글과 표 구조만)을 말하고 이 기능을 안내한다. 지시문 한 줄 |
| 3단계 | 워드 편집기 파일 메뉴 "한글 문서로 내보내기…"         | 사용자가 가장 먼저 찾을 자리다. 저장한 파일로만 한다(저장 안 한 변경이 있으면 먼저 저장을 묻는다)                   |
| 3단계 | 터미널 명령어·MCP(`convert --to hwp\|hwpx`)           | `docs/contracts.md`의 약속에 더한다. 출력 구조는 밖에서 기대므로 그때 따로 정한다                                   |

결과 탭은 한글 편집기의 "새 문서"와 같게 다룬다. 첫 저장은 "다른 이름으로 저장"이고, 대화 상자는 **원본 워드 파일 이름에 확장자만 바꾼 이름**을 내민다(`보고서.docx` → `보고서.hwp`). 형식은 대화 상자에서 고를 수 있다.

## 5. 어디에 무엇을 두는가

| 위치                                                                       | 맡는 일                                                                                                                              |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 새 패키지 `packages/docx2hwp`(`@genoffice/docx2hwp`)                       | 워드 모델 → 서식 계산 → HTML, rhwp로 한글 문서 만들기, 옮기지 못한 것 목록. Electron 없이 node에서 돈다(테스트가 실제 엔진으로 돈다) |
| `apps/shell/src/main/generate/convert.ts`, `request.ts`, `generate-api.ts` | 종류 `docx-to-hwp`(자료 확장자 `docx`, 결과 `hwp`)를 더한다                                                                          |
| `apps/shell/src/main/generate/converted-tab.ts`                            | 결과 바이트를 새 한글 탭에 넘긴다                                                                                                    |
| `apps/hwp/src/main/seed-main.ts`(새 파일), 렌더러의 문서 열기              | 넘겨받은 바이트가 있으면 빈 문서(`blank.hwp`) 대신 그것을 연다. 슬라이드의 `seed-queue.ts`와 같은 꼴                                 |
| `apps/hwp/src/renderer/ai/hwp-skill.ts`                                    | 워드 첨부를 바꿔 달라는 요청에 대한 안내 한 줄                                                                                       |
| 21개 언어 문구, 도움말                                                     | 바꾸기 이름, "쪽 나눔은 다를 수 있다", 옮기지 못한 것 알림                                                                           |

이름 `docx2hwp`는 이미 있는 `pdf2docx`, `html2docx`와 같은 꼴로 짓는다. 새 패키지이므로 내부 이름 규칙(기존 이름을 바꾸지 않는다)과 부딪히지 않는다.

## 6. 기술 방침

- **서식은 "보이는 값"으로 풀어서 적는다.** `parseDocx`의 글자·문단 서식은 직접 서식뿐이고, 스타일과 문서 기본값은 따로 읽힌다(워드 편집기는 CSS로 겹쳐 그린다). rhwp의 HTML 해석기는 인라인 `style`만 보므로, 바꾸기 모듈이 "문서 기본값 → 문단 스타일 사슬 → 글자 스타일 사슬 → 직접 서식" 순서로 겹쳐 계산한다. 이미 있는 `styleRunFormat`과 테마 글꼴 풀기를 쓴다.
- **스타일 표는 옮기지 않는다(1단계).** 워드 스타일을 한글 스타일로 만들면 이름과 상속 규칙이 맞지 않는다. 글자마다 보이는 서식을 직접 건다. 제목만 2단계에서 한글의 개요 스타일에 맞춘다.
- **빈 문서는 한글 편집기의 새 문서와 같은 것에서 시작한다**(`apps/hwp/src/renderer/assets/blank.hwp`). 같은 기본 글꼴·문단 모양을 갖게 하려는 것이다.
- **만든 뒤 다시 읽어 확인한다.** 내보낸 바이트를 rhwp로 다시 열어 쪽 수가 같은지(`exportHwpVerify`), 글자가 원본의 글자와 같은지(공백 정리 뒤 비교) 본다. 어긋나면 탭을 열지 않고 이유를 보여 준다. 반쯤 된 문서를 주지 않는다.
- **메인 프로세스를 기다리게 하지 않는다.** 바꾸기는 작업자 스레드에서 돌린다(파일 색인이 한글 문서를 읽는 방식과 같다). 큰 문서의 한도(파일 크기, 쪽 수, 그림 총량)는 `limits.ts`에 둔다.
- **아무것도 PC 밖으로 보내지 않는다.** AI도, 구독 한도도 쓰지 않는다.
- **원본 워드 파일을 직접 읽는다(정책 예외, 결정 0032).** 지금 "AI 없이 바꾸기"는 자료를 `parseFileToText`로만 읽는다(가리기 때문, 결정 0016). 서식을 옮기려면 `parseDocx`로 읽어야 한다. 워드의 가리기 표시는 지금 앱 어디서도 인식하지 않으므로, 이 길이 감춰야 할 글을 더 드러내지는 않는다. 다만 규칙의 예외이므로 결정 기록(0032)으로 남기고, 워드 가리기가 생기는 날 이 길도 그것을 따르게(처리할 수 없으면 바꾸지 않게) 테스트로 묶어 둔다.

## 7. 단계

| 단계                   | 내용                                                                                                                                                                                                                  | 끝났다고 보는 기준                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **0단계: 시험**        | 손으로 만든 HTML을 node의 rhwp에 붙여넣어 3절 표의 "0·1단계" 항목이 실제로 살아나는지 확인한다. 실제 워드 문서 5개(공문 양식, 표 많은 서식, 그림 든 보고서, 목록 많은 안내문, 가로 용지)를 바꿔 한컴 한글 2024로 연다 | 항목별 "됨/안 됨/우회" 표. 한글에서 5개 모두 열린다. 안 되는 항목은 붙여넣은 뒤 엔진 호출로 우회할지 정한다 |
| **1단계: 기본 바꾸기** | `docx2hwp` 패키지(서식 계산, HTML, 용지, 확인), 만들기 창의 종류, 한글 탭 넘겨받기, 옮기지 못한 것 알림, AI 창 안내 한 줄, 21개 언어 문구와 도움말                                                                    | 8절의 확인을 모두 통과한다                                                                                  |
| **2단계: 더 옮기기**   | 머리말·꼬리말, 쪽 번호, 각주·미주, 개요 스타일, 하이퍼링크, 구역 여러 개, 떠 있는 그림·EMF·WMF                                                                                                                        | 같은 확인 + 항목마다 엔진 단위 테스트                                                                       |
| **3단계: 입구 넓히기** | 워드 편집기 파일 메뉴, 터미널 명령어와 MCP                                                                                                                                                                            | 계약 문서와 스킬 갱신, 명령어 테스트                                                                        |

### 0단계에서 확인한 것 (2026-10-15)

rhwp 0.8.7(앱과 같은 WASM)을 node에서 돌려 확인했다. 시험 코드는 저장소에 넣지 않았다(1단계에서 패키지로 새로 짠다). 붙여넣는 곳은 한글 편집기의 새 문서(`blank.hwp`)다.

**HTML 붙여넣기가 그대로 살리는 것.** 굵게·기울임·밑줄(CSS 형식과 `<b>`·`<i>`·`<u>` 모두), `text-decoration:line-through`, 라틴·동아시아 글꼴(`mso-fareast-font-family`가 한글·한자·일어 칸에 들어간다), 크기, 색(`#hex`·`rgb()`), 자간, 정렬, `%` 줄 간격, 위·아래·왼쪽·오른쪽 여백, 내어쓰기, 빈 문단, 문단 안 줄바꿈(`<br>`), 칸 합치기(`colspan`·`rowspan`), 칸 폭(pt), 칸 높이, 칸 테두리, 칸의 세로 정렬, 칸 안 문단의 정렬·글자 서식, `data:` 그림(본문과 칸 안, 크기는 `width`·`height` 속성의 px).

**HTML로는 안 되지만 붙여넣은 뒤 엔진 호출로 되는 것.** 모두 저장하고 다시 열어도 남는다.

| 항목                  | 붙여넣기에서                                            | 바꾸기가 할 일                                                                                            |
| --------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 형광펜·글자 배경      | `background-color`를 읽지 않는다                        | `applyCharFormat`의 `shadeColor`                                                                          |
| 위·아래 첨자          | `<sup>`·`<sub>`·`vertical-align` 모두 무시              | `applyCharFormat`의 `superscript`·`subscript`                                                             |
| 고정·최소 줄 간격     | `pt`·배수 줄 간격을 무시하고 `%`만 읽는다               | `applyParaFormat`의 `lineSpacingType`(값은 1pt = 200)                                                     |
| 쪽 나눔(앞에서 새 쪽) | `page-break-before` 무시                                | `applyParaFormat`의 `pageBreakBefore`                                                                     |
| 칸 색                 | 첫 칸의 색을 표 자체의 채움으로 써서 표 전체가 칠해진다 | HTML에 색을 넣지 않고 붙인 뒤 `setCellProperties`로 칸마다(한글 편집기 AI의 `shadeHeaderCells`와 같은 길) |
| 용지 크기·방향·여백   | 해당 없음                                               | `setPageDef`(세로 치수 + `landscape` 표시). 가로 용지가 맞게 그려진다                                     |

**바꾸기 쪽에서 피해 가야 하는 엔진의 동작.** rhwp에 알릴 거리다.

| 엔진의 동작                                                                                                    | 피해 가는 법                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 첫 문단은 문서의 빈 문단에 합쳐져 그 문단의 모양(정렬·여백)을 잃는다                                           | HTML 맨 앞에 빈 `<p></p>`를 둔다. 그 뒤로는 원본 문단 하나가 한글 문단 하나다(표도 한 문단)                                                       |
| 양수 `text-indent`(첫 줄 들여쓰기)를 왼쪽 여백에도 더한다. 둘째 줄부터 들어가 버린다                           | 들여쓰기만큼 `margin-left`를 빼서 적는다. 음수(내어쓰기)는 맞게 받는다                                                                            |
| 칸이 하나도 없는 `<tr>`(위 칸이 세로로 덮은 줄)을 버리면서 `rowspan`은 그대로 둔다. 합친 칸의 내용이 안 보인다 | 그런 줄을 빼고, 그 줄을 지나는 `rowspan`에서 센다                                                                                                 |
| 표 칸의 높이를 주지 않으면 한 줄보다 낮게 만든다                                                               | 칸마다 글꼴 크기에 맞는 높이와 한글 기본 칸 여백을 적는다(한글 편집기 AI의 표와 같은 값)                                                          |
| `<h1>`~`<h6>`를 문단으로 나누지 않고 서식도 버린다                                                             | 제목도 `<p>`로 적고 크기·굵기를 직접 적는다                                                                                                       |
| `<s>`·`<strike>`를 무시한다                                                                                    | `text-decoration:line-through`로 적는다                                                                                                           |
| 번호 목록(`<ol>`)도 글머리표 `•`로 만들고, 목록 안 목록은 한 문단에 붙인다                                     | 목록을 HTML 목록으로 넘기지 않는다. 워드 엔진의 `computeListMarkers`로 번호 글자("1.", "가.", "•")를 만들어 문단 앞에 붙이고 여백으로 단계를 준다 |
| `&#44032;` 같은 숫자 문자 참조를 풀지 않는다                                                                   | `&amp; &lt; &gt; &quot;`만 바꾸고 나머지는 글자 그대로 적는다                                                                                     |
| `<td>`의 `text-align`을 칸 문단에 주지 않는다                                                                  | 칸 안 `<p>`마다 정렬을 적는다                                                                                                                     |
| 그림의 CSS `width`·`height`(pt)를 무시한다                                                                     | `width`·`height` 속성을 px로 적는다                                                                                                               |
| 칸의 세로 정렬 기본값이 가운데다(워드는 위)                                                                    | 칸마다 `vertical-align`을 적는다                                                                                                                  |

**워드 쪽.** `parseDocx`의 스타일 표(`styles`)는 `basedOn` 사슬을 이미 풀어 둔다. 그래서 "문서 기본값 → 문단 스타일 → 글자 스타일 → 직접 서식"을 겹치면 보이는 서식이 나온다(제목 스타일의 크기·색, 기본 글꼴까지 확인). 번호는 `computeListMarkers`, 용지는 `readSectionSettings`, 칸의 가로·세로 합치기는 표 모델의 `colSpan`·`vMerge`로 얻는다.

**실제 문서 5개.** python-docx로 만든 공문 양식(칸 합친 표, 들여쓴 항목, 오른쪽 정렬 서명), 교과협의록 모양의 서식(가로·세로를 함께 합친 칸, 칸 색, 세로 가운데), 제목 스타일과 그림이 든 보고서(1.5줄, 첫 줄 들여쓰기, 고정 줄 간격), 목록과 형광펜·첨자·취소선이 든 안내문, 가로 용지 시간표다. 다섯 모두 바꾸기와 저장·다시 열기에 성공했고, 엔진 호출의 실패는 0건이다. 글자(표 칸 포함)는 원본과 다섯 모두 같다(목록 문서는 번호 "1.", "2."가 더해진 것만 다르다). 쪽 그림을 원본과 나란히 보니 표 모양·칸 색·합친 칸·글자 크기·정렬·가로 용지가 맞는다.

**아직 확인하지 못한 것.**

- **한컴 한글 2024로 열기.** 이 환경에는 한글이 없다. 다섯 결과 파일을 저장소 주인이 한글로 열어 본다. 1단계를 시작하기 전의 마지막 관문이다.
- 실제 사용자 문서. 시험 문서는 python-docx로 만든 것이라 Word가 저장한 문서보다 단순하다. 1단계의 문서 묶음(8절)에서 본다.
- 목록의 단계별 들여쓰기(번호 정의의 `indentLeft`·`hanging`을 아직 쓰지 않았다), 워드 배수 줄 간격을 한글 `%`로 옮기는 비율(시험에서는 1줄 = 160%로 두었다), 칸 안 글자의 첨자·형광펜.

**정리.** HTML 붙여넣기로 안 되는 항목이 적고, 안 되는 것도 붙여넣은 뒤 엔진 호출로 된다. 그래서 1단계 범위를 줄이지 않는다(결정 0032의 다섯째 항목은 쓰지 않는다). 3절 표에서 2단계로 두었던 형광펜은 1단계로 당긴다. 위·아래 첨자, 고정 줄 간격, 쪽 나눔도 1단계에 넣는다.

## 8. 확인 방법

| 무엇을                   | 어떻게                                                                                                                                                                                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 항목별 서식이 옮겨지는지 | 단위 테스트: `docx-engine`의 테스트 도우미(`tests/helpers/build-docx.ts`)로 워드 문서를 메모리에서 만들고 → 바꾸고 → rhwp로 다시 열어 글자 서식(`getCharPropertiesAt`), 문단 서식, 표 크기와 합친 칸, 용지 값을 읽어 견준다 |
| 글이 빠지지 않는지       | 실제 워드 문서 묶음(30~50개, 학교·관공서 서식 포함)을 모두 바꿔, `docxToText`와 `hwpToText`의 글자를 공백 정리 뒤 비교한다. 다른 것은 3절 표에서 "하지 않음"인 갈래뿐이어야 한다                                            |
| 한컴 한글에서 열리는지   | 같은 묶음을 한컴 한글 2024의 공식 자동화 창구로 열어 쪽 수·표 수·글자를 읽는다(한글 편집기 확인 때와 같은 방법). 하나라도 못 열면 1단계를 끝내지 않는다                                                                     |
| 모양이 비슷한지          | 10개 문서를 워드 편집기의 PDF와 한글 편집기의 PDF로 만들어 나란히 놓고 눈으로 본다. 쪽 나눔 차이는 허용하고, 표 모양·글자 크기·정렬이 다르면 고친다                                                                         |
| 앱 안 흐름               | 빌드한 앱에서 만들기 창 → 바꾸기 → 한글 탭 → 저장 → 다시 열기. 저장 안 한 자료의 차단, 출처 기록, 알림                                                                                                                      |
| 정해진 검사              | `docs/standards.md`의 "합치기 전에 통과해야 하는 검사" 전체                                                                                                                                                                 |

## 9. 위험과 대응

| 위험                                                  | 대응                                                                                                                                     |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| rhwp HTML 해석기가 일부 서식을 놓치거나 틀리게 읽는다 | 0단계에서 항목별로 확인한다. 빠지는 것은 붙여넣은 뒤 엔진 호출로 채운다. 엔진의 버그는 상위 프로젝트에 알린다(rhwp 소스는 고치지 않는다) |
| 스타일 상속 계산이 워드와 다르다                      | 워드 편집기가 같은 모델로 그리는 화면을 기준으로 삼아 테스트 표를 만든다. 문서 기본값·스타일 사슬·테마 글꼴을 각각 시험한다              |
| 쪽 나눔이 워드와 달라 사용자가 "망가졌다"고 본다      | 화면 문구와 도움말에 "모양이 비슷한 새 문서이고 쪽 나눔은 다를 수 있다"고 적는다. "변환"이라고 부르지 않는다(10절)                       |
| 결과를 한컴 한글이 열지 못한다                        | 만든 뒤 다시 읽어 확인하고, 문서 묶음을 한글 2024로 연다. 못 여는 문서가 있으면 그 갈래를 끄고 알린다                                    |
| 큰 문서가 앱을 멈추게 한다                            | 작업자 스레드, 한도, 진행 표시. 한도를 넘으면 시작하기 전에 알린다                                                                       |
| 가리기 규칙의 예외가 나중에 구멍이 된다               | 결정 기록에 조건을 적고, 워드 가리기가 생기면 이 길도 막히도록 테스트를 둔다                                                             |
| rhwp를 올리면 붙여넣기 동작이 달라진다                | 단위 테스트가 실제 엔진으로 돌아 바로 잡는다. rhwp 올리기 점검 목록에 이 묶음을 더한다                                                   |

## 10. 정한 것

저장소 주인이 2026-10-15에 다섯 제안을 모두 받았다. 결정 기록 [0032](../tracking/decisions/0032-docx-to-hwp-without-ai.md)에 옮겼다.

| 번호 | 물음                                                                                 | 정한 것                                                                                                         |
| ---- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 1    | "AI 없이 바꾸기"에서 워드 파일만 `parseFileToText` 밖(`parseDocx`)으로 읽어도 되는가 | 된다. PC 밖으로 나가는 것이 없고, 워드 가리기는 지금 어디서도 인식하지 않는다. 6절의 조건을 붙인다              |
| 2    | 결과의 기본 형식                                                                     | `.hwp`. 한글 편집기의 새 문서와 같고 `.hwpx`보다 오래된 한글에서도 열린다. 대화 상자에서 `.hwpx`를 고를 수 있다 |
| 3    | 1단계의 입구                                                                         | 만들기 창과 AI 창 안내. 워드 편집기 파일 메뉴는 3단계(만들기 창의 틀을 그대로 쓰는 1단계가 가장 작다)           |
| 4    | 화면 이름                                                                            | "한글 문서로 바꾸기"와 한 줄 설명 "서식을 살린 새 한글 문서를 만든다. 쪽 나눔은 다를 수 있다"                   |
| 5    | 0단계에서 HTML 붙여넣기로 안 되는 항목이 많이 나오면                                 | 1단계를 줄여(글자·문단·표만) 먼저 내고, 나머지는 엔진 호출로 하나씩 더한다                                      |
