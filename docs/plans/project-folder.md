# 프로젝트 폴더 계획 (AI 맥락을 폴더 단위로)

상태: **확정**(2026-10-29). 저장소 주인이 1절 끝과 11절을 정했다. 정한 것은 결정 0088에 옮겼다. 같은 날 실행 설계를 정하며 자세히 정한 것(새 프로젝트 위치, 믿음 확인 대상, 대화 목록, 기억 길이, 새 문서 저장 폴더 등)에 맞춰 이 문서를 고쳤다. 동작의 기준은 `docs/business-rules.md`의 "프로젝트 폴더"다.

## 1. 무엇을 하려는가

AI가 받는 맥락의 단위를 **문서 하나**에서 **폴더 하나**로 넓힌다. 사람이 PC의 폴더 하나를 프로젝트로 고르면, 그 폴더의 문서·지침·기억·대화가 그 프로젝트에서 하는 모든 AI 요청의 맥락이 된다.

지금 맥락이 끊기는 곳:

- **대화가 문서에 묶여 있다.** `project-store`가 대화를 문서 경로의 해시로 저장한다. 같은 일을 하는 한글 보고서와 슬라이드가 서로의 대화를 모른다.
- **배경 설명을 둘 곳이 없다.** "2학기 운영 보고서, 개조식, 기관명은 ○○" 같은 말을 문서를 열 때마다 다시 쓴다.
- **자료를 매번 다시 붙인다.** `@` 붙이기(0051)와 "이 문서로 다른 문서 만들기"(0017)는 그 한 번에만 통한다.
- **묶음이 셋인데 서로 따로 논다.** 홈의 별표 그룹(0020, 홈 AI 질문만 좁힘), 에이전트 창의 프로젝트 폴더(0032, 최근 8개), `project-store`의 "프로젝트"(원본에서 왔고 화면에서 쓰지 않음).

저장소 주인이 정한 것(2026-10-29):

- **AI 창의 입력란 아래에 "프로젝트 또는 폴더" 고르기를 둔다.** 고르기 목록은 찾기·만들기 칸, 고정됨, 최근, "새 프로젝트", "폴더 추가"로 이룬다.
- **맥락은 모두 그 폴더 안에 쌓는다.** 지침·기억·대화를 폴더 안에 파일로 둔다. 사람이 폴더만 옮기거나 복사하면 맥락이 따라간다. 이를 위해 "사용자 폴더에 파일을 저절로 만들지 않는다"(`security.md`의 "복구 사본과 세션 기록", 결정 0061)를 고친다.
- **기억은 저절로 쌓는다.** 사람이 하나하나 승인하지 않는다.

## 2. 큰 그림

```
AI 창(아홉 편집기, 홈 AI 질문)
 └ 입력란 아래 [프로젝트 ▾]  ← 고르면 그 실행에 프로젝트 맥락이 붙는다
       │ project:*
       ↓
프로젝트 길잡이(껍데기 뒷단, 새 파일)
 ├ 프로젝트 목록(이 PC가 아는 폴더, 고정, 최근)  → app-settings.json
 ├ 지침·기억 읽기, 기억 쓰기                     → <폴더>/.ieumoffice/
 ├ 폴더 파일 목록·찾기·읽기(가리기 적용)          → 기존 색인과 file-parse
 ├ 대화 저장                                     → <폴더>/.ieumoffice/chats/
 └ 믿음 확인(남이 쓴 지침·기억인지)               → app-settings.json의 지문
```

- **AI 창은 지금 것을 그대로 쓴다.** 편집 도구는 편집기마다 원래 것이다. 프로젝트가 더하는 것은 지시문에 붙는 글(지침·기억·파일 이름 목록)과 읽기 도구 몇 개, 그리고 기억 쓰기 도구 하나다. "AI 창 하나로 모든 문서를 다루기"는 편집기마다 화면 안 객체를 직접 잡은 도구 약 196개를 다시 지어야 해서 버린 안이다(0037도 같은 까닭으로 셸 수준 AI 화면을 버렸다). 이 계획은 그 길을 가지 않는다.
- **넣는 곳은 한 군데다.** 아홉 편집기와 홈 AI 질문이 모두 `panelUserSkills`(`packages/ui/src/use-skill-proposals.tsx:61`)를 스킬 목록에 펼쳐 넣는다. 같은 꼴의 `panelProjectSkill`을 `packages/ui`에 두면 `AgentSkill` 하나(지시문, 매 차례 `buildContext`, 도구)로 열 곳에 한 번에 들어간다. 지시문은 `loop.ts:957-961`에서 `MATERIAL_NOT_INSTRUCTIONS` 뒤에 이어진다. `composeWithDrive`에 넣으면 홈 AI 질문(`KbAskPanel.tsx:258`, `composeSkills`를 바로 씀)이 빠지므로 그 길은 쓰지 않는다.
- **구독 프로그램에 도구를 더 켜지 않는다.** 프로그램이 가진 도구는 지금 그대로다(절대 규칙 3, 0001, 0082). 새 도구는 모두 앱이 정의하고 앱이 실행한다. 에이전트 모드는 그대로 따로 두고, 같은 프로젝트 목록을 쓰게 한다(8절).
- **범위는 뒷단이 지킨다.** 0020과 같은 방식이다. 화면은 프로젝트 id만 넘기고, 뒷단이 그 실행의 범위 값을 만들고, 도구 호출마다 폴더 안인지 다시 본다.

## 3. 폴더에 쌓이는 것

```
<프로젝트 폴더>/
├── (사람의 문서들)
├── AGENTS.md, CLAUDE.md        ← 있으면 지침으로 함께 읽는다(에이전트 모드와 같음)
└── .ieumoffice/
    ├── project.json             판, 프로젝트 id, 이름, 만든 시각
    ├── instructions.md          지침(사람이 쓴다. AI는 고치지 않는다)
    ├── memory.md                기억(AI가 쌓는다. 사람이 고칠 수 있다)
    ├── memory.<시각>.bak.md     정리하기 전의 기억(최근 3개)
    ├── ignore                   AI가 보지 않을 파일·폴더(한 줄에 하나, 글롭)
    └── chats/
        ├── <대화 id>.json       대화 정보(제목, 시각, 쓴 PC, 마지막 편집기, 쓴 문서)
        └── <대화 id>.jsonl      대화 내용
```

- 폴더 이름 `.ieumoffice`와 파일 이름은 언어와 상관없이 고정이다. 바깥과의 약속이 되므로 `docs/contracts.md`의 "프로젝트 폴더"에 적었다. Windows 탐색기에서는 보이고, Mac·Linux에서는 숨겨진다.
- 모두 사람이 메모장으로 열어 읽고 고칠 수 있는 글이다. 대화도 줄마다 JSON 한 개라 다른 프로그램이 읽을 수 있다.
- **프로젝트의 정체는 `project.json`의 `id`다.** 경로가 아니다. 폴더를 옮기면 같은 프로젝트로 이어 가고, 복사하면 복사본에 새 id를 준다(복사본의 대화 목록은 비운 채 시작한다).
- **고정과 최근은 폴더에 두지 않는다.** 이 PC의 사정이라 `app-settings.json`에 둔다. 폴더를 다른 PC로 옮기면 그 PC에서 "폴더 추가"로 한 번 고르면 맥락이 모두 돌아온다.
- **드라이브 동기화 폴더.** OneDrive, Google 드라이브 데스크톱 등의 폴더를 고르면 지침·기억·대화가 함께 그 서비스로 올라간다. 사람이 그 폴더를 고른 것이므로 막지 않는다. 처음 고를 때 한 번 알리고 `PRIVACY.md`에 적는다.
- **클라우드 전용 파일을 내려받지 않는다.** 동기화 폴더의 "필요할 때 내려받기" 파일은 읽는 순간 내려받기가 일어난다. 프로젝트 폴더 안에서는 이런 파일(Windows의 `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`, `RECALL_ON_OPEN`, `OFFLINE`)을 색인에 이름만 넣고, 목록에는 "PC에 없음"으로 보인다. AI가 읽으려 하면 사람에게 묻는다. 이 특성을 알아낼 수 없는 PC에서는 알려진 동기화 폴더 아래 파일을 모두 이런 파일로 본다.
- **폴더에 쓸 수 없으면** 지침과 파일 읽기는 그대로 쓰고, 대화와 기억은 저장하지 않고 그렇다고 알린다. 앱 데이터에 몰래 대신 저장하지 않는다(폴더를 옮기면 맥락이 따라간다는 약속이 깨진다).

## 4. 화면

### 4.1 입력란 아래의 고르기

```
┌───────────────────────────────────────────────┐
│ 무엇을 할까요?                                  │
│                                               │
│ [+]                                    [보내기]│
└───────────────────────────────────────────────┘
 [▭ 2학기 운영 보고서 ▾]            Claude · 모델 ▾
```

목록:

```
┌───────────────────────────────────────────────┐
│ 🔍 프로젝트 찾기 또는 만들기                    │
│ 고정됨                                         │
│  ▭ 2학기 운영 보고서   D:\업무\2학기 보고서      │
│ 최근                                           │
│  ▭ 독서 토론 자료      C:\Users\…\독서 토론      │
│  ▭ 포럼 참고문헌       G:\…\포럼 참고문헌        │
│ ───────────────────────────────────────────── │
│  ＋ 새 프로젝트                                 │
│  📁 폴더 추가                                   │
│ ───────────────────────────────────────────── │
│  프로젝트 없이                                  │
└───────────────────────────────────────────────┘
```

- 입력란은 공용 `AiComposer`(`packages/ui/src/AiComposer.tsx`)다. 지금은 입력 상자 안의 바닥줄(`footerStart`: 모델 고르기, 첨부 단추들)까지만 있고 그 아래 자리가 없다. 상자 밖 아래 줄을 그리는 속성(가칭 `footerBelow`)을 하나 더하고, 고르기 부품(`ProjectPicker`)은 `packages/ui`에 둔다. 편집기마다 `AiPanel.tsx`(엑셀은 `AiChatPanel.tsx`, 홈은 `KbAskPanel.tsx`)에서 한 줄씩 넘긴다.
- **새 프로젝트**: 이름을 받아 새 폴더를 만든다. 만들 곳은 "기본 저장 폴더\<이름>"이 적혀 있다. 기본 저장 폴더는 설정 값이고, 정하지 않았으면 `문서\IeumOffice`다(11절 2). [다른 곳…]을 누르면 운영체제 폴더 고르기로 부모 폴더를 바꿀 수 있다. 같은 이름의 폴더가 있으면 만들지 않고 "'<이름>' 폴더가 이미 있습니다. 그 폴더를 프로젝트로 사용할까요?"를 묻는다([이 폴더 사용]·[취소]). [이 폴더 사용]이면 "폴더 추가"와 같이 정체와 믿음 확인을 거친다. 그 폴더가 이미 목록에 있는 프로젝트면 묻지 않고 "이미 목록에 있는 프로젝트입니다"를 알린 뒤 그 프로젝트를 연다. 만들면 폴더와 `.ieumoffice/project.json`을 만든다. 이 PC의 앱이 만든 것이므로 믿음 확인을 묻지 않는다.
- **폴더 추가**(홈의 프로젝트 화면에서는 [기존 폴더를 프로젝트로]): 운영체제 폴더 고르기. 거절하는 폴더는 에이전트 모드와 같다(`security.md`의 "에이전트 모드" 시작 조건). 드라이브 전체, 사용자 폴더 전체, 보호 폴더와 그것을 품은 폴더다. 고르는 순간에는 `.ieumoffice/`를 만들지 않는다. 처음 무엇을 써야 할 때(지침 저장, 기억, 대화, 이름 바꾸기) 만든다.
- 찾기 칸에 친 글과 맞는 프로젝트가 없으면 맨 위에 "'○○' 새 프로젝트 만들기"가 보인다.
- 줄에 마우스를 올리면 고정·고정 풀기, "폴더 열기"(Windows는 탐색기, Mac은 Finder로 연다), "목록에서 빼기"(폴더와 그 안의 파일은 그대로)가 보인다.
- 폴더가 없어진 프로젝트는 흐리게 "폴더 없음"으로 보이고, 누르면 폴더 고르기가 열린다(옮긴 폴더를 다시 고르는 길).

### 4.2 저절로 고르기

- **열린 문서가 프로젝트 폴더 안에 있으면 그 문서의 AI 창은 그 프로젝트를 고른 채로 열린다.** 폴더가 여럿 겹치면(프로젝트 안의 프로젝트) 가장 가까운 것이다. 사람이 "프로젝트 없이"로 바꾸면 그 문서는 다음에도 그 선택을 기억한다.
- 이 PC의 목록에 없지만 문서 위쪽 폴더에 `.ieumoffice/project.json`이 있으면, 고르기 자리 위에 "이 문서는 '○○' 프로젝트 폴더에 있습니다 [사용]"이 보인다. 누르면 "폴더 추가"와 같이 정체와 5.4의 믿음 확인을 거쳐 목록에 들어가고 골라진다. 저절로 쓰지 않는다.
- 프로젝트 밖의 문서에서 프로젝트를 고르면 그 실행부터 붙고, 그 문서에서 고른 것을 기억한다. 문서를 그 폴더로 옮기지는 않는다.
- 한 번도 저장하지 않은 새 문서는 "프로젝트 없이"로 시작한다. 만들기 창이나 AI가 만든 새 문서로 열린 탭은 그 프로젝트를 고른 채로 열린다.
- 홈 AI 질문은 처음에 "프로젝트 없이"이고, 그 뒤로는 홈에서 마지막으로 고른 값이다.

### 4.3 프로젝트 화면

홈 사이드바에 "프로젝트"를 더한다. 프로젝트 하나를 열면:

| 칸   | 내용                                                                                                                                                                                    |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 머리 | 이름(고치면 `project.json`만 바뀌고 폴더 이름은 그대로), 폴더 경로, [탐색기에서 열기], 믿음 상태("상태: 지침과 기억을 AI에게 보내는 중" 또는 "상태: 지침 없이 사용 중"과 [지침도 사용]) |
| 지침 | `instructions.md` 편집 칸과 [저장]. 루트에 `AGENTS.md`·`CLAUDE.md`가 있으면 아래에 "함께 읽음"으로 보이고 끌 수 있다                                                                    |
| 기억 | `memory.md`를 항목별로 보인다. 항목마다 지우기, [전체 고치기], [정리하기], 기억 쌓기 켜기/끄기, 길이 표시                                                                               |
| 파일 | AI가 보는 파일 목록(형식, 크기, "PC에 없음", `ignore`로 빠진 것은 따로). 줄마다 "AI가 보지 않게"(`ignore`에 한 줄 더함)와 되돌리기                                                      |
| 대화 | 이 프로젝트의 대화 목록(제목, 마지막 시각, 마지막 편집기, 다른 PC 표시). 누르면 그 대화가 마지막으로 쓰인 문서나 홈에서 열린다. 이름 바꾸기·지우기                                      |

- 폴더에 쓸 수 없으면 머리에 그렇다는 알림과 [다시 시도]가 보인다.
- 동기화 서비스가 `memory.md`의 충돌 사본을 만들었으면 기억 칸에 그 파일 이름을 알린다.
- AI 창의 "지침이 바뀌었습니다 [보기]"는 이 화면의 그 칸을 연다.
- 목록 위에는 [새 프로젝트]와 [기존 폴더를 프로젝트로]가 있다.
- 파일 칸에서 파일 이름을 누르면 그 파일을 앱에서 연다.
- 화면은 보일 때마다 폴더를 다시 읽는다. 지침이나 기억 전체를 고치는 동안 파일이 앱 밖에서 바뀌었으면 [저장]이 [다시 불러오기]·[그래도 저장]을 먼저 묻는다.

### 4.4 대화 목록

- 프로젝트를 고른 AI 창의 머리에 `[지금 대화 제목 ▾]`가 생긴다. 펼치면 찾기 칸, [새 대화], 이 프로젝트의 대화들(최근 순, 제목·마지막 시각·마지막 편집기, 다른 PC에서 쓴 대화면 "다른 PC")이 보이고, 맨 아래에 "이 문서의 이전 대화"가 있다. 줄마다 이름 바꾸기와 지우기(운영체제 휴지통으로)가 있다.
- 대화 제목은 첫 메시지의 앞부분으로 저절로 붙는다. 대화 파일은 첫 답이 올 때 만든다.
- **대화는 문서가 아니라 프로젝트를 따라간다.** 한글 창에서 시작한 대화를 슬라이드 창에서 이어 갈 수 있다. 다시 열 때는 지금처럼 `{role, text}`만 돌려놓는다. 도구 호출과 결과는 다른 편집기의 것이라 돌려놓지 않는다. 그 대화가 다른 편집기에서 했던 일은 "한글 '보고서.hwp'에서 도구 3번 실행" 같은 한 줄로 보인다.
- 문서를 열면 그 문서에서 마지막으로 쓴 이 프로젝트의 대화가 보인다. 없으면 빈 새 대화다.
- 두 창에서 같은 대화를 열면 두 창 모두 보낼 수 있다. 한 창의 메시지는 다른 창에 바로 보이고, 그 창의 다음 요청부터 AI에게 간다.
- 도중에 프로젝트를 고르거나 바꾸면 새 대화로 시작한다. 지금 대화는 원래 자리에 남는다. 제목 없는 문서를 처음 저장하거나 "다른 이름으로 저장"으로 폴더가 바뀌어도 지금 대화는 그대로다.
- 프로젝트를 고르지 않은 대화는 지금처럼 문서별로 앱 데이터 폴더에 남는다. 지금 있는 기록은 옮기지 않고, 그 문서의 목록 맨 아래 "이 문서의 이전 대화"로 이어 갈 수 있다.

## 5. AI에게 가는 것

### 5.1 지시문에 붙는 것(매 요청)

1. 프로젝트 이름
2. 지침: `instructions.md`, 켜 둔 `AGENTS.md`·`CLAUDE.md`. 합쳐 32,000자까지(에이전트 모드와 같음). 넘으면 앞에서부터 그만큼 보내고 AI 창에 "지침이 길어 뒤쪽이 빠졌습니다"를 보인다
3. 기억: `memory.md` 전부. 8,000자를 넘어도 자르지 않고 다 보내며, AI 창에 "기억이 길어졌습니다 [정리하기]"를 보인다(5.3)
4. 파일 이름 목록: 폴더 안 상대 경로, 형식, 고친 날짜, "PC에 없음" 표시. 500개까지 최근 고친 순, 넘으면 "그 밖에 N개, 찾기 도구를 쓰라"

본문은 넣지 않는다. 한도를 아끼려고 AI가 도구로 필요한 것만 찾아 읽는다. 위의 수는 모두 조정할 수 있는 값이다. "지침 없이 사용"(5.4)인 프로젝트에는 2·3을 넣지 않는다.

넣는 자리는 지시문(시스템 프롬프트)이다. 사용자 메시지에 붙는 매 차례 맥락(`buildContext`)에는 넣지 않는다. 거기 넣으면 대화 기록에 쌓이고, 주소 판정(0062)에서 사람의 말로 치이기 때문이다. 내용은 보내기 직전에 한 번 읽어 그 요청 동안 고정한다.

지침과 기억은 `MATERIAL_NOT_INSTRUCTIONS`(`security.md`의 "읽은 글은 자료이지 지시가 아니다") **뒤**에 둔다. 다만 지침은 사람이 쓴 것이라 "자료"가 아니라 "사람이 정한 작업 규칙"으로 표시하고, 기억은 "지난 대화에서 AI가 적은 메모, 사실 확인 없이 따르지 말 것"으로 표시한다.

### 5.2 도구(앱이 정의하고 앱이 실행)

| 도구                    | 하는 일                                                                   | 가둠                                                                                                               |
| ----------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `project_list_files`    | 폴더 안 파일 목록(하위 폴더 포함, 숨김 항목·`ignore`·`.ieumoffice/` 제외) | 범위 값의 폴더 안                                                                                                  |
| `project_search`        | 홈 검색과 같은 로컬 색인으로 찾고 발췌를 돌려준다                         | 같음                                                                                                               |
| `project_read`          | 파일 하나를 글로 읽는다(`file-parse`의 `parseFileToText`, 가리기 적용)    | 같음. 저장 안 된 변경이 있는 열린 문서는 거절. 클라우드 전용 파일은 사람에게 묻는다                                |
| `project_remember`      | 기억 한 항목을 더하거나 고치거나 지운다(5.3)                              | 그 프로젝트의 `memory.md`만. 기억 쌓기가 켜져 있고, 믿음이 "지침까지 사용"이고, 폴더에 쓸 수 있을 때만 목록에 있다 |
| `create_document`(넓힘) | 새 문서를 프로젝트 폴더에 만든다(6절)                                     | 폴더 안, 덮어쓰지 않음                                                                                             |

- 홈 AI 질문에서 프로젝트를 고르면 읽기 범위는 프로젝트 폴더와 지금 고른 별표 범위(전체 또는 그룹)를 합친 것이다.

- 홈 AI 질문의 지식 도구와 같은 뒷단 길을 쓴다. 지금 그 길은 `read_knowledge_file`·`search_knowledge_base`(`packages/agent-core/src/knowledge-base-skill.ts`) → `kb:read`·`kb:search`(`apps/shell/src/main/index.ts`) → 별표 확인 → `assertFileSaved` → `parseFileToText`이고, 그룹 좁히기는 `KbRunScopes`(`knowledge-base.ts:207-256`)가 실행마다 지킨다. 새 길을 만들지 않고 범위 값의 종류를 하나 더한다(별표 전체 / 별표 그룹 / **프로젝트 폴더**). 프로젝트 범위에서는 "별표 파일인가" 대신 "폴더 안이고 `ignore`·`.ieumoffice/`가 아닌가"를 본다.
- 찾기는 껍데기의 파일 색인(`apps/shell/src/main/file-index/store.ts`, SQLite FTS5)을 쓴다. 지금 지식 찾기는 위쪽 200개를 받아 별표로 거른다(`knowledge-base.ts:90-118`). 큰 폴더에서는 거르기 전에 200개가 다른 폴더 결과로 찰 수 있으니, 경로 앞부분 조건을 색인 질의에 넣는다(0단계에서 확인).
- 읽기 도구의 결과에 든 주소는 0062의 "대화에 나온 주소"로 치지 않는다. 폴더 파일 속 숨은 지시가 주소 가져오기로 내용을 내보내는 길을 막는다. 지침·기억은 대화 기록이 아니라 지시문에 있으므로 거기 든 주소도 처음부터 치이지 않는다.

### 5.3 기억이 쌓이는 방식

- **AI가 대화 중에 `project_remember`로 적는다.** 따로 모델을 부르지 않는다(한도를 더 쓰지 않음). 지시문은 "앞으로의 작업에 쓸모 있는 사실·선호·결정만, 한 항목 한 줄로, 날짜를 붙여" 적으라고 이른다.
- **사람은 승인하지 않는다.** 대신 적힌 순간 AI 창에 작은 줄 "기억함: 보고서는 개조식으로 [지우기]"(바꾸면 "기억 고침", 지우면 "기억 지움")가 보인다. 다시 열 때도 그 대화에 남는다.
- 기억을 쓸 때는 쓰기 직전에 파일을 다시 읽어 그 위에 고친다. 다른 창이나 메모장에서 고친 것을 잃지 않는다.
- **배경에서 혼자 정리하지 않는다.** 앱이 스스로 실행하지 않는다는 규칙 때문이다. 기억이 8,000자를 넘으면 AI 창에 "기억이 길어졌습니다 [정리하기]"가 보이고, 사람이 누르면 한 번 실행해 겹치고 낡은 항목을 합친다. 정리 전 내용은 `.ieumoffice/memory.<시각>.bak.md`로 남기고(최근 3개), 결과 줄 "기억을 정리했습니다(N개 → M개) [되돌리기]"로 되돌릴 수 있다.
- **기억 쌓기 끄기**: 프로젝트 화면에서 끌 수 있다. 끄면 `project_remember`가 목록에서 빠지고, 이미 있는 기억은 계속 읽는다.
- **가린 내용은 기억에 들어갈 수 없다.** 모델은 가린 원문을 받은 적이 없으므로 `{{이름}}` 자리만 적을 수 있다. 다만 사람이 대화에 직접 친 글은 기억될 수 있다. `PRIVACY.md`에 적는다.
- `memory.md`는 사람이 고치기 쉬운 꼴로 둔다.

```markdown
<!-- 이음오피스가 쌓는 기억. 고치거나 지워도 됩니다. -->

- 보고서는 개조식, 문장 끝은 "~함"으로 쓴다. (2026-10-29)
- 기관명은 "○○교육지원청"으로 줄이지 않는다. (2026-10-29)
```

### 5.4 믿음 확인

남에게 받은 폴더의 지침·기억에 숨은 지시가 있으면 그 프로젝트의 모든 AI 요청에 붙는다. **폴더를 처음 쓸 때 한 번 확인하고, 그 뒤로는 바뀌어도 묻지 않고 쓴다**(11절 4). 지침을 폴더에 두기로 한 이상 사람이 메모장으로 고치는 일이 흔하고, 매번 묻으면 읽지 않고 누르게 된다(0064가 "시작할 때마다 묻기"를 버린 이유와 같다).

- **처음 확인.** "폴더 추가"나 4.2의 [사용]으로 목록에 넣을 때, 그 폴더에 **이 PC의 앱이 쓰지 않은** 것이 있으면 확인 창을 띄운다. 대상은 `.ieumoffice/instructions.md`·`memory.md`, 루트의 `AGENTS.md`·`CLAUDE.md`, 그리고 다른 PC에서 쓴 대화다. 창은 앞의 넷의 내용과 그런 대화의 목록(제목, 시각)을 보이고 [지침까지 사용][지침 없이 사용][전체 보기][취소]를 보인다. 다른 PC의 대화를 넣은 까닭은, 가짜 대화를 심어 확인을 돌아가는 길을 막으려는 것이다. 고른 값은 `app-settings.json`에 프로젝트별로 적는다(폴더 안이 아니라 이 PC). 이 PC의 앱이 "새 프로젝트"로 만든 폴더와 그런 것이 없는 폴더는 묻지 않는다. 확인 창을 고르지 않고 닫으면 추가를 취소한다.
- **[지침 없이 사용]** 을 고르면 지침·기억·`AGENTS.md`·`CLAUDE.md`를 요청에 넣지 않고, 다른 PC에서 쓴 대화를 목록에 보이지 않으며, 기억 쌓기를 멈춘다. 파일 읽기 도구와 이 PC의 대화는 쓴다. 프로젝트 화면에서 언제든 [지침도 사용]으로 바꿀 수 있다(바꿀 때 같은 확인 창을 다시 보인다).
- **그 뒤로는 묻지 않는다.** 실행 때마다 지금 파일 내용을 읽어 붙인다. 확인 뒤 새로 들어온 다른 PC의 대화도 묻지 않고 "다른 PC" 표시만 붙인다.
- **"바뀜" 줄.** 앱이 지침·기억을 쓰거나 사람이 프로젝트 화면에서 고칠 때마다 그 내용의 해시를 `app-settings.json`에 적는다. 실행 때 해시가 다르면(메모장으로 고침, 동기화로 바뀜) 그대로 붙여 보내되, AI 창에 "지침이 바뀌었습니다 [보기]" 한 줄을 보인다. [보기]는 프로젝트 화면의 지침(또는 기억) 칸을 연다. 바뀐 줄을 따로 표시하지 않는다(옛 내용을 이 PC에 남기지 않으려는 것). 줄을 보인 뒤에는 새 해시를 적어 같은 변경으로 다시 띄우지 않는다.
- "목록에서 빼기"는 믿음 기록과 해시를 남긴다. 같은 폴더를 다시 추가하면 다시 묻지 않고, 그사이 바뀐 것은 "바뀜" 줄로 알린다. 복사본은 원본의 믿음을 이어받는다.
- **남는 위험.** 한 번 믿은 동기화·공유 폴더의 지침을 남이 바꾸면 다음 요청부터 붙는다. "바뀜" 줄이 이것을 알리는 장치다. 기본 AI 창은 프로그램 도구가 없어 숨은 지시가 닿는 범위는 그 편집기의 문서 고치기와 앱 도구다. 주소 가져오기는 5.2대로 지침·기억에 든 주소를 "대화에 나온 주소"로 치지 않아 사람에게 묻는다.
- **에이전트 모드.** 지금은 `AGENTS.md`·`CLAUDE.md`를 묻지 않고 붙인다(0064 "결정 밖"). 같은 프로젝트 목록을 쓰게 할 때(8절, 5단계) 같은 처음 확인을 거치게 맞춘다.
- 문서 파일 자체는 지금처럼 확인하지 않는다. 자료이지 지시가 아니다(`MATERIAL_NOT_INSTRUCTIONS`).

## 6. 새 문서는 프로젝트 폴더에

- 지금도 홈 AI 질문의 `create_document`는 묻지 않고 기본 저장 폴더(`configuredDefaultSaveDir`, 설정이 없으면 `문서\<제품 이름>`)에 이름이 겹치지 않게 쓴다(`knowledge-base.ts:294-302`). 이 계획은 그 폴더를 프로젝트 폴더로 바꾸는 것이고, 새 종류의 쓰기를 만드는 것은 아니다.
- 프로젝트를 고른 실행에서 AI가 새 문서를 만들면(홈 AI 질문의 `create_document`, 만들기 넘겨주기, 양식 스킬의 사본, 편집기가 생성 결과를 기본 저장 폴더에 저장하던 길) **지금 문서가 있는 폴더**(그 문서가 프로젝트 안에 있을 때), 아니면 **프로젝트 폴더 맨 위**에 저장한다. 홈은 맨 위다. 대화 상자 없이, 이름이 겹치면 `(2)`를 붙여 덮어쓰지 않고, 만들기가 성공했을 때만 쓴다. 한글은 앱이 대화 상자 없이 저장할 수 없어 제목 없는 탭으로 열고 저장 창의 기본 폴더를 위 규칙의 폴더로 둔다.
- 만들기 창은 연 문서(홈에서 열었으면 홈 AI 질문)의 프로젝트를 따라간다. 새 탭의 AI 창도 그 프로젝트를 고른 채 열린다.
- 프로젝트를 고른 제목 없는 문서의 저장 창 기본 폴더는 프로젝트 폴더 맨 위다.
- 여러 문서를 오가며 만드는 흐름(작업대, 아직 초안이며 저장소에 없음)을 나중에 만들 때, 그 작업은 프로젝트 안에서 생기고 만든 문서는 프로젝트 폴더에 저장한다.

## 7. 안전

- **새로 생기는 사용자 폴더 쓰기**: `.ieumoffice/` 아래 파일들(3절)과, 6절의 새 문서. 이 밖의 파일은 쓰지 않는다. 프로젝트 길잡이 하나만 쓰고, 경로는 폴더의 정식 경로(`canonicalPathKey`) 아래인지 매번 본다. 링크를 따라가지 않는다. 임시 파일에 쓴 뒤 이름을 바꾸고, 같은 파일에 대한 쓰기는 한 줄로 세운다.
- **에이전트 세션은 `.ieumoffice/`를 쓰지 못하게 한다(5단계).** 프로그램이 기억·지침을 직접 바꾸면 믿음 확인을 우회한다. 에이전트 모드의 보호 폴더 목록에 "프로젝트 폴더의 `.ieumoffice/`"를 쓰기 거부로 더한다. 읽기는 된다. 에이전트의 기억은 같은 `project_remember` 도구(앱 MCP)로만 쓴다. 1~4단계에는 이것이 없어, 에이전트가 프로젝트 폴더에서 `.ieumoffice/`를 바꿀 수 있다(`docs/tracking/findings.md`).
- **읽기는 가리기를 지난다.** `project_read`는 첨부와 같은 `file-parse` 길이다. 처리하지 못하면 읽지 않는다.
- **크기 상한**: 읽기 하나는 첨부와 같은 상한(0035). 색인은 기존 로컬 검색과 같다. 폴더가 커도 끊지 않고, 색인은 처음 고를 때 한 번, 그 뒤로는 바뀐 파일만이다.
- **8GB PC**: 색인은 껍데기 뒷단의 기존 색인기를 쓰고 새 프로세스를 띄우지 않는다. 0단계에서 파일 1만 개 폴더로 잰다.
- `PRIVACY.md`에 더할 것: 프로젝트를 고른 요청에 지침·기억·파일 이름 목록이 실린다, AI가 읽은 폴더 파일의 글이 실린다, 지침·기억·대화가 그 폴더에 남고 동기화 폴더면 그 서비스로 올라간다, 사람이 친 글이 기억될 수 있다.

## 8. 이미 있는 것과의 관계

- **에이전트 모드**: 시작 화면의 "프로젝트 폴더(최근 8개, `app-settings.json`의 `agent.recentFolders`)"를 이 프로젝트 목록으로 바꾼다. 폴더별 설정(`agentProjectPrefs`)과 스킬 승인(`agentProjectSkills`)은 그대로 폴더 경로를 열쇠로 쓴다. 에이전트 세션도 지침·기억을 받고, 대화는 같은 `chats/`에 남는다(프로그램 종류를 표시). 나중에 AI 창의 고르기 옆에 "도구 켜기(에이전트)"를 두어 같은 프로젝트로 에이전트 창을 여는 길을 생각한다. 이번에는 하지 않는다.
- **홈 AI 질문의 대화**: 지금은 메모리에만 있다(`KbAskPanel.tsx:65-67`). 프로젝트를 고르면 그 대화는 폴더의 `chats/`에 남는다. 고르지 않으면 지금처럼 메모리에만 둔다.
- **별표 그룹**: 그대로 둔다. 그룹은 따로 목록이 없고 별표 항목에 붙은 이름일 뿐이다(`starred.json`). 홈 AI 질문의 범위 고르기에 프로젝트가 함께 보인다. 그룹 메뉴에 "이 그룹으로 프로젝트 만들기"(새 폴더에 파일을 복사하지 않고, 그룹 파일들이 있는 폴더 하나를 고르게)는 필요하면 나중에 더한다.
- **`@` 붙이기(0051)**: 목록에 "이 프로젝트의 파일"(최근 고친 순 50개)을 열린 문서 다음, 최근 문서 앞에 둔다. 프로젝트 파일은 붙이지 않아도 AI가 읽을 수 있으므로 `@`는 "이 파일을 꼭 보라"는 뜻이 된다.
- **작업대(초안)**: 프로젝트가 맥락을 담고, 작업대는 그 안에서 여러 문서를 오가는 일을 지휘한다. 순서는 이 계획이 먼저다. 맡기기 구조 없이도 모든 AI 창이 바로 좋아진다.
- **`project-store`**: 원본에서 온 패키지라 크게 고치지 않는다. 폴더 안 대화의 읽기·쓰기는 같은 JSONL 형식과 상한(본문 32,000자, 도구 필드 16,000자, 끝 8MiB 읽기)을 따르는 새 저장소로 둔다. 같은 코드를 쓸 수 있으면 생성자에 다른 뿌리 경로를 주는 방식으로 쓴다(0단계에서 확인).

## 10. 결정 기록

1~4단계에서 정한 것은 **결정 0088**(프로젝트 폴더) 하나에 모았다. 그 결정이 고치는 기존 결정과 규칙:

- 0061과 `security.md`("복구 사본과 세션 기록")의 "사용자 폴더에 파일을 저절로 만들지 않는다": 프로젝트 폴더의 `.ieumoffice/`와 프로젝트에서 AI가 만든 새 문서는 예외가 된다.
- 0020: 범위 값에 "프로젝트 폴더" 종류가 더해진다.
- 0064: 지문 확인을 지침·기억에 넓히되, 처음 한 번만 묻는다.
- 0048: 스킬 저장은 카드 승인이지만 기억은 승인 없이 쌓는다. 까닭을 0088에 적었다.
- `project-store`의 "경로 해시가 열쇠": 프로젝트를 고른 대화는 폴더 안에 따로 둔다.

5단계(에이전트 모드가 같은 목록·지침·기억·대화를 씀, `.ieumoffice/` 쓰기 거부)는 할 때 따로 결정을 쓴다(0032, 0064를 고침).

## 11. 저장소 주인이 정한 것

2026-10-29에 정했다.

1. **하위 폴더**: 모두 포함하고 `ignore`로 뺀다.
2. **새 프로젝트를 만들 곳**: 기본 저장 폴더 아래 `<이름>`이고, 만들기 칸에서 [다른 곳…]으로 고를 수 있다. 처음에는 `문서\이음오피스\<이름>`이라고 했으나, 기본 저장 폴더가 이미 `문서\IeumOffice`(설정으로 바꿀 수 있음)라는 것을 듣고 그 아래로 정했다.
3. **루트의 `AGENTS.md`·`CLAUDE.md`**: 있으면 함께 읽는다(에이전트 모드와 같음). 프로젝트 화면에서 끌 수 있다.
4. **앱 밖에서 바뀐 지침·기억**: 처음 쓸 때 한 번 확인하고, 그 뒤로는 바뀌어도 묻지 않고 쓴다. 앱 밖에서 바뀌었으면 AI 창에 "지침이 바뀌었습니다 [보기]" 줄만 보인다(5.4).
5. **대화를 이어 갈 범위**: 같은 프로젝트면 어느 편집기에서든 이어 간다(4.4).

묻지 않고 정한 기본값(바꾸고 싶으면 말해 달라): 고정·최근은 이 PC에만 둔다, 폴더를 골랐다는 것만으로 `.ieumoffice/`를 만들지 않는다, 클라우드 전용 파일은 내려받지 않는다, 기억 정리는 사람이 누를 때만 한다, 프로젝트를 고르지 않은 대화는 지금처럼 앱 데이터에 둔다.

## 12. 위험과 열린 질문

- 지침·기억·파일 목록이 매 요청에 붙어 한도를 더 쓴다. 0단계 측정 뒤 상한을 정하고, 사용량 표시에서 프로젝트 몫을 따로 보일지 본다.
- 대화를 다른 편집기에서 이어 가면 AI가 그 편집기에 없는 도구를 부르려 할 수 있다. 지시문에 "지금 쓸 수 있는 도구는 이 편집기 것뿐"을 넣는다.
- 동기화 폴더에서 두 PC가 같은 `memory.md`를 동시에 쓰면 동기화 서비스가 사본 파일을 만든다. 사본이 보이면 프로젝트 화면이 알린다.
- 학교·기관 공유 폴더(네트워크 드라이브)에서 여러 사람이 같은 프로젝트를 쓰면 기억이 섞인다. 막지 않되 도움말에 적는다.
- 대화 저장 경로(`project:*` IPC)는 지금 문서 경로 → 대화 id로만 찾는다(`resolveChatForFile`). 프로젝트 대화는 "프로젝트 id + 대화 id"로 찾는 새 요청이 필요하고, 홈 화면 preload에는 `projectApi`가 아예 없다.
