# PDF 읽기 도우미 계획

상태: **구현됨**(2026-10-20, 결정 0043). 초안은 2026-10-19에 썼다. 8절의 "정한 것"과 버린 대안은 결정 0043으로 옮겼다. 구현하면서 바뀐 것은 본문에 반영했다. 동작 규칙은 `docs/business-rules.md`의 "PDF 읽기 도우미"와 "문서 작업"에 있다.

## 1. 무엇을 하려는가

PDF 편집기는 고치는 기능은 많은데, 긴 문서를 **읽는** 일을 돕는 기능은 흩어져 있거나 결과가 남지 않는다. 이 계획은 읽는 사람이 다음 네 가지를 한 화면에서 하게 만든다.

1. 표시하고 메모한 것을 모아 보고, 그것을 다른 문서로 이어 쓴다.
2. 모르는 구절을 AI에게 물어본 답이 대화창에서 사라지지 않고 그 자리에 남는다.
3. 외국어 문서를 원문과 번역을 나란히 놓고 읽는다.
4. AI가 문서의 핵심 문장을 골라 표시하고, 사람이 받아들인 것만 실제 주석이 된다.

대상은 논문 독자만이 아니다. 계약서·약관을 검토하는 사람, 외국어 보고서를 읽는 사무직, 교재를 공부하는 학생이 모두 같은 기능을 쓴다. 예시와 화면 문구도 그렇게 고른다.

## 3. 모든 단계에서 지킬 선

1. **AI는 사람이 누를 때만 나간다.** 스크롤, 문서 열기, 패널 펼치기, 보기 켜기로는 아무것도 보내지 않는다. 새로 생기는 시작점(단축키 `E`·`T`, 카드의 "다시 만들기", 추천 질문, 개요 만들기, 페이지 번역, 문단 다시 번역, AI 핵심 표시)은 모두 `docs/business-rules.md`의 "AI 실행 하나의 일생" 목록에 더한다.
2. **여러 번 보내는 일은 문서 작업 규칙을 따른다.** AI 핵심 표시, 긴 문서의 개요, "모든 페이지 번역"은 시작 전 확인(예상 호출 수, 제공자, 요금 문구)을 거치고 `documentJobRoute`로 정한 제공자에 고정한다. 한 번만 보내는 일(구절 설명·번역, 블록 하나 다시 번역, 짧은 문서의 개요)은 AI 창과 같은 `useAiSendGate`를 거친다. 예외는 대역 보기의 페이지 번역 하나다(5번).
3. **PDF 파일은 사람이 고를 때만 바뀐다.** AI 결과는 기본적으로 보관소에 둔다. "메모로 남기기"나 "받아들이기"를 눌러야 편집 중인 문서에 표준 주석이 생기고, PDF를 저장할 때 파일에 들어간다. "파일에 들어갔다"는 상태(카드의 `savedAsNote`, 제안의 `accepted`)는 그 저장이 성공한 뒤에만 보관소에 쓴다. 그 전에는 "저장 대기"로 보인다. 원본 PDF 바이트를 몰래 고치는 길은 만들지 않는다.
4. **모델 답은 문서 데이터다.** 설명·요약·표시 제안의 답에 든 지시를 따르지 않는다. 이 계획의 모델 호출에는 도구를 주지 않는다. AI 창 대화만 지금처럼 도구를 쓴다.
5. **보관소의 기존 열쇠와 배치는 바꾸지 않는다.** 새 결과는 새 폴더에 둔다. 기존 항목에 필드를 더할 때는 선택 필드로만 더해, 예전 앱과 터미널 명령어가 그대로 읽게 한다.
6. **새 전송 경로는 문서에 적는다.** `PRIVACY.md`, `docs/security.md`의 "문서 내용"과 "PDF 결과 보관소"를 같은 변경에서 고친다(9절).
7. **문구는 21개 언어를 모두 채운다.** 새 기능의 문자열은 기능마다 언어별 조각(`i18n/<기능>/<언어>.ts`, 기능은 `reading`, `annot-panel`, `ai-reading`, `bilingual`, `highlight`, `notes`, `zh`가 키 집합)에 둔다. 도움말도 21개 언어로 더한다(`check:help-langs`).
8. **문서 엔진 패키지는 고치지 않는다.** `pdf2docx`와 문서 엔진의 출력은 그대로다. 주석 저장(`apps/pdf/src/main/save-pdf.ts`)에 선택 필드를 더하는 일은 있다(6번). 이때는 기존 주석의 저장 결과가 바이트 단위로 같은지 테스트로 확인한다.

## 4. 1단계: 작고 바로 체감되는 것

### 1번. 선택 메뉴 단축키

**무엇.** 글자를 선택해 선택 막대가 떠 있는 동안 한 글자로 바로 실행한다.

| 키      | 동작                    | 비고                                        |
| ------- | ----------------------- | ------------------------------------------- |
| `H`     | 형광펜                  | 이미 칠해져 있으면 지우기(지금 단추와 같다) |
| `U`     | 밑줄                    | 막대의 표시 글자 `U`와 맞춘다               |
| `S`     | 취소선                  | 막대의 표시 글자 `S`와 맞춘다               |
| `N`     | 메모 달기               | 선택 끝 위치에 빈 메모를 만들고 입력을 연다 |
| `E`     | AI 설명                 | 2번의 구절 카드로 답한다                    |
| `T`     | AI 번역                 | 2번의 구절 카드로 답한다                    |
| `Enter` | AI에게 묻기 입력창 열기 | 지금의 `AiAskPopover`                       |

**구현 메모.**

- 선택 막대에는 형광펜·밑줄·취소선·메모 단추가 있고, 메모 단추는 `N`과 같은 동작을 한다(선택 영역 끝에 메모를 달고 입력을 연다).
- `e.key`가 아니라 `e.code`(`KeyH` 등)로 판정한다. 한글 입력 상태에서 `H`를 누르면 `e.key`는 `ㅗ`가 된다. `e.isComposing`이면 무시한다.
- 선택 막대가 보이고 포커스가 입력란 밖일 때만 받는다. Ctrl·Alt·Meta가 눌려 있으면 받지 않는다(복사 `Ctrl+C`와 겹치지 않게).
- 단추 툴팁과 접근성 이름에 키를 함께 적는다(예: "형광펜 (H)").
- 암호가 걸려 고칠 수 없는 문서에서는 `H`·`U`·`S`·`N`이 동작하지 않고, 지금 단추처럼 이유를 보인다.

**시험.** 키마다 동작, 한글 입력 상태, 조합 중 무시, 입력란 포커스 무시, 수정 키 무시, 읽기 전용 문서.

### 2번. AI 설명·번역을 구절 카드로 남기기

**무엇.** `E`·`T`나 "AI에게 묻기"의 설명·번역 칩을 누르면, 답이 선택 위치 옆의 작은 카드로 나온다. 카드는 보관소에 저장되어 다시 열어도 남고, 3번 패널에 모인다.

**카드에서 할 수 있는 것.**

- 복사
- **메모로 남기기**: 그 위치에 `/Text` 메모를 만든다. 지금의 메모 저장 경로를 그대로 쓰고, PDF를 저장할 때 파일에 들어간다. 저장이 성공하기 전에는 카드에 "저장 대기"가 보인다. 메모 첫 줄에 "AI 설명" 또는 "AI 번역(언어)"을 붙여 사람이 쓴 메모와 구분한다. 작성자(`/T`)는 사람이 쓴 메모와 같은 값(PC 계정 이름)이다(8절 2번).
- AI 창에서 이어 묻기: 구절과 답을 AI 창의 선택 칩으로 넘긴다. 보내지는 않는다.
- 노트에 넣기(9번)
- 다시 만들기: 누를 때만 다시 보내고 같은 카드를 덮어쓴다.
- 지우기(보관소에서만 지운다. 이미 메모로 남긴 것은 그대로다)

"AI에게 묻기"의 설명·번역 칩도 카드로 답한다. "구절 요약"·"구절 고쳐 쓰기" 칩과 직접 적은 질문은 지금처럼 AI 창으로 간다. 카드가 있는 구절 밑에는 옅은 점선을 그리고(화면 전용, 보기 탭에서 끄고 켠다), 누르면 카드가 다시 열린다.

**보내는 것.** 선택한 구절, 같은 페이지의 PDF.js 글자 층에서 구절 앞뒤로 합쳐 최대 1,500자, 문서 제목. 모델 호출 한 번, 도구 없음. 호출은 `doc-jobs/model-call.ts`와 같은 `ai:stream` 경로를 쓰고, 보내기 전에 `useAiSendGate`를 거친다. 번역의 목표 언어는 번역 작업의 기본 목표 언어 규칙을 따른다.

**보관.** 새 폴더 `docs/<문서 해시>/passages/<카드 id>.json`.

```ts
interface PassageCard {
  id: string
  kind: 'explain' | 'translate'
  page: number // 1-based original page at creation; re-found by pageFingerprint on open
  pageFingerprint: string
  quads: number[][] // PDF user space, same shape as MarkupInput.quads
  excerpt: string // the selected text
  passageHash: string // hash of the normalized excerpt; dedup key with pageFingerprint+kind+lang
  lang?: string // translate only
  text: string // the answer
  provider: string
  model: string
  createdAt: number
  savedAt: number // last write; the newer card wins in a migration
  savedAsNote?: true // only after a PDF save that contained the note succeeded
}
```

- 쓰기 종류 `{ kind: 'passage'; docHash; card }`, `{ kind: 'deletePassage'; docHash; id }`를 `PdfStoreWriteRequest`에 더한다. 셸의 처리 코드도 함께 고친다.
- 앱 안 저장으로 해시가 바뀌면 `migrateDocument`가 지문이 같은 페이지의 카드를 옮긴다(번역 블록과 같은 규칙).
- 같은 구절(페이지 지문 + 구절 글 해시 + 종류 + 언어)이 이미 있으면 보내지 않고 그 카드를 연다. "다시 만들기"는 사람이 누를 때만이다.

**시험.** 확인 없이 보내지 않는지, 같은 구절은 다시 보내지 않는지, 메모로 남기기가 표준 `/Text` 메모를 쓰는지(다시 읽어 확인), 보관소 왕복, 해시가 바뀐 뒤 옮겨지는지, 모델이 지시문을 돌려줘도 글로만 쓰는지.

### 3번. 주석 모아 보기 패널

**무엇.** 사이드바에 세 번째 보기 "주석"을 더한다(`'thumbs' | 'outline' | 'notes'`). 리본 보기 탭의 축소판·목차 단추 옆에 단추를 둔다. 패널 도구 줄에는 "노트 열기"(9번)가 있다.

**목록에 나오는 것.**

| 종류                 | 출처                                         | 보이는 글                          |
| -------------------- | -------------------------------------------- | ---------------------------------- |
| 형광펜·밑줄·취소선   | 파일의 주석 + 아직 저장하지 않은 표시        | 표시 아래의 글                     |
| 메모                 | 파일의 `/Text`, 답글 수 + 저장 안 한 메모    | 메모 내용 첫 두 줄                 |
| 손그림·도형·그림도장 | 파일의 `/Ink`·`/Square`·`/Circle`·`/Line` 등 | 종류 이름만                        |
| AI 설명·번역         | 2번의 구절 카드                              | 구절과 답 첫 줄                    |
| AI 표시 제안         | 6번의 제안(받아들이기 전)                    | 분류 이름과 문장(미리 보기일 때만) |

- 표시 아래의 글은 PDF.js의 `getTextContent` 위치와 주석의 `QuadPoints`가 겹치는 글자로 뽑는다. 다른 프로그램이 만든 주석과 회전된 페이지도 같은 방법으로 보인다.
- 화면의 PDF.js는 `/Subj`를 읽지 않으므로, 받아들인 AI 형광펜의 분류는 메인 프로세스가 그 창에 허가된 파일에서 읽어 준다(`pdf:annot-subjects`).
- 거르기: 종류, 색, 페이지 범위, 글 검색. 정렬: 페이지 순(기본), 만든 순.
- 누르면 그 위치로 가고 잠깐 깜빡인다. 메모는 여백의 대화를 연다.

**이어 쓰기.** 패널 위의 메뉴 하나에 셋을 둔다.

1. Markdown으로 복사
2. **마크다운 문서로 열기**
3. **워드 문서로 열기**

마크다운·워드 문서는 AI 창의 `create_document` 도구가 쓰는 채널(`PDF_CHANNELS.createDocument`, preload의 `createDocument({ type, title, content })`)로 만든다. 기본 폴더에 새 파일을 쓰고 새 탭으로 연다. 이 채널은 받은 내용을 그대로 쓰므로 AI는 부르지 않는다. 내용은 거른 결과 그대로다.

```markdown
# <문서 제목> — 주석 모음

## p.3

> 표시한 글
>
> — 형광펜

메모: 메모 내용
```

AI에게 정리를 시키고 싶으면 AI 창에 "주석을 정리해 줘"라고 하면 된다. 그 흐름은 이미 있다.

**시험.** 목록 만들기(저장된 것 + 저장 안 한 것 + 카드), 겹침으로 글 뽑기, 회전된 페이지, 거르기·검색, 내보내기 글의 모양, 새 문서 만들기 주입이 없는 단독 실행에서 메뉴가 이유를 보이는지.

### 4번. AI 창의 추천 질문

**무엇.** 대화가 비어 있을 때 빈 화면 안내 아래에 질문 단추 세 개를 둔다. 누르면 그 질문을 보낸다(보내기 판단은 지금과 같다). 원래 있던 빠른 단추 둘("전체 요약", "핵심 추출")은 그 위에 그대로 둔다.

| ko                                     | en                                     |
| -------------------------------------- | -------------------------------------- |
| 이 문서의 핵심을 정리해 줘             | Summarize the key points               |
| 결론과 그 근거를 페이지와 함께 알려 줘 | What are the conclusions and evidence? |
| 빠졌거나 약한 부분이 있어?             | What is missing or weak?               |

논문에만 맞는 질문은 넣지 않는다. 계약서에도 보고서에도 통하는 질문으로 고른다.

**시험.** 비어 있을 때만 보이는지, 누르면 한 번만 보내는지, 연결이 없을 때 연결 안내로 가는지.

## 5. 2단계: 뷰어 안에서 원문과 번역 나란히 보기

### 5번. 대역 보기

**무엇.** 보기 탭에 "번역 나란히"를 더한다. 켜면 페이지마다 오른쪽에 같은 높이의 번역 칸이 붙고, 원문과 함께 스크롤된다. 두 쪽 보기와는 함께 켜지지 않는다(켜면 한 쪽 보기로 바뀐다).

**데이터.** 새로 번역 엔진을 만들지 않는다.

1. 켜는 순간 저장된 파일로 문서 나무를 한 번 만든다(`structure.tree`, 셸의 구조 프로세스). AI로 읽은 페이지는 그 결과로 바꾼다. 대역 보기가 켜져 있는 동안만 기억하고, 끄면 버린다.
2. 페이지의 블록마다 보관소의 번역 블록을 찾는다. 열쇠는 기존 규칙(시작 페이지 지문 + 정규화한 원문 글의 해시 + 순번) 그대로다.
3. 번역이 있는 블록은 번역문을, 없는 블록은 흐린 원문을 보인다.

그래서 문서 번역 창으로 이미 번역해 둔 문서는 켜자마자 번역이 보인다. 반대로 여기서 번역한 블록은 나중에 번역 PDF·Markdown·EPUB을 만들 때 다시 보내지 않는다.

**번역 시작.** 스크롤만으로는 보내지 않는다.

- 번역이 비어 있는 페이지의 번역 칸 위에 "이 페이지 번역" 단추를 둔다. 일부만 번역돼 있으면 "남은 문단 번역(N)"이다. **구독으로 쓰는 중이면 한 번 누르면 바로 번역한다.** 확인 창은 띄우지 않는다. 대신 무엇이 나가는지 누르기 전에 보이게 한다. 단추 옆에 쓰일 제공자를 작게 적고(예: "Claude"), 툴팁에 "이 페이지의 글을 〈제공자〉에 보냅니다"를 적는다.
- **요금이 나가는 경로(키 제공자, 허용된 종량 로그인)면 예외다.** 처음 누를 때 그 자리에서 "〈제공자〉에서 요금이 부과됩니다 · 번역 / 취소"로 바뀐다. 그 탭에서 한 번 "번역"을 고르면 이후 페이지는 바로 번역한다. 제공자가 바뀌면 다시 묻는다.
- 페이지 범위를 그 페이지로 준 번역 작업이고, 엔진(`startTranslationJob`)과 보관소는 기존 것을 쓴다. 제공자 고정(`documentJobRoute`, `jobRouteRefusal`)과 한도 소진에서 멈추기도 그대로다.
- 이 번역은 이어 할 작업이 아니다. 기존 번역 작업 기록(`translate.<언어>.json`)과 이어하기 제안을 건드리지 않고, 도는 동안만 별도 기록(`translate-page.<언어>.json`)을 남긴다. 그 언어의 번역 메타가 없을 때만 만든다. 보관된 번역이 다른 제공자로 만들어졌어도 알리지 않는다. 서로 다른 AI의 번역이 섞여도 된다.
- 이것은 "문서 작업은 시작 전 확인을 거친다"는 규칙의 예외다. 예외는 대역 보기의 페이지 하나 번역에만 둔다. `docs/business-rules.md`의 "문서 작업"에 예외와 그 근거(사람이 그 페이지를 보며 누른 단추이고, 호출이 1~2회로 작다)를 적는다.
- "모든 페이지 번역…"은 지금의 문서 번역 창을 연다. 형식 고르기는 "보관만(파일 만들지 않음)"을 하나 더한다.
- 한 문서에 작업 하나 규칙은 그대로다. 페이지 번역이 도는 동안 다른 페이지 단추는 기다림 표시가 된다.

**원문과 번역 잇기.**

- 번역 문단에 마우스를 올리면 원문 페이지의 그 블록 상자(`regions`)에 옅은 테두리를 그린다. 반대로 원문 글자 위에 올리면 그 글자가 든 블록의 번역 문단을 강조한다.
- AI로 읽은 페이지의 블록은 상자가 없다. 그 페이지는 순서대로만 보이고 잇기 표시는 없다.
- 여러 페이지에 걸친 문단은 시작 페이지의 번역 칸에 한 번만 보이고, 다음 페이지 칸에는 "앞 페이지에서 이어짐" 표시만 둔다.

**번역 칸에서 할 수 있는 것.**

- **고치기**: 문단을 두 번 누르면 입력란이 된다. 저장하면 그 번역 블록을 사람이 고친 것으로 보관한다(`TranslationBlockInput`에 선택 필드 `edited?: true`). 고친 블록은 서식 표시가 없는 글이고, 서식이 있던 문단이면 입력란에 "서식이 빠집니다"를 보인다. 고친 글은 번역 PDF·Markdown·EPUB과 터미널 명령어 `pdf translate`의 출력에도 그대로 쓰인다.
- **다시 번역**: 그 블록 하나만 다시 보낸다(호출 1회, `useAiSendGate`). 실패로 기록된 문단에도 있다. 고친 블록이면 "고친 내용을 버리고 다시 번역할까요?"를 먼저 묻는다.
- 번역 글자 크기(번역 칸에만 적용, 보기 설정에 기억)
- 번역 칸 폭 조절. 창이 좁아 원문 페이지가 너무 작아지면(원문 폭 480px 미만) "번역 칸을 접을까요?"를 한 번 알린다.

**"처음부터 다시 번역"과 고친 블록.** 지금은 그 언어의 보관된 번역을 다 지운다. 고친 블록이 있으면 확인 창에 "사람이 고친 문단 N개도 지웁니다 / 고친 문단은 남기기"를 고르게 한다. 터미널의 `pdf translate --restart`는 물을 수 없으므로 언제나 고친 블록을 남긴다.

**저장하지 않은 페이지 편집.** 화면에 저장하지 않은 페이지 넣기·지우기·순서 바꾸기가 있으면 대역 보기 위에 "저장하면 번역 칸이 맞춰집니다"를 보인다.

**8GB PC.** 번역 칸은 보이는 페이지와 앞뒤 2페이지만 DOM으로 그린다(`BILINGUAL_RENDER_PAD`). 문서 나무는 탭마다 하나만 기억하고, 대역 보기를 끄면 버린다.

**시험.** 보관된 번역이 열쇠로 맞게 붙는지, 스크롤만으로 보내지 않는지, 구독일 때 한 번 누르면 그 페이지만 보내는지, 요금 경로일 때 처음 한 번은 요금 문구를 거치는지와 제공자가 바뀌면 다시 묻는지, 페이지 하나 번역이 기존 엔진·보관소를 쓰는지, 상자 잇기(회전 페이지 포함), 고친 블록 왕복과 번역 PDF·Markdown 출력 반영, 다시 번역 확인, 처음부터 다시의 선택지, 이어지는 문단 표시, 한 문서 작업 하나.

## 6. 3단계: AI가 문서를 고치는 앱다운 기능

구현 순서는 7번 → 8번 → 6번 → 9번이다. 7·8번이 작고, 6번이 크고, 9번은 다른 편집기(마크다운)와 이어진다.

### 6번. AI 핵심 표시: 미리 보기 → 받아들이기

**무엇.** AI가 문서에서 중요한 문장을 분류별로 골라 색으로 제안한다. 제안은 화면에만 보이는 미리 보기다. 사람이 받아들인 것만 표준 형광펜 주석이 된다.

**분류 고르기.** 시작 창에서 분류 묶음을 고른다. 묶음마다 분류는 다섯 개까지, 색은 분류마다 하나.

| 묶음        | 분류                        |
| ----------- | --------------------------- |
| 연구·보고서 | 핵심 주장, 방법, 결과, 한계 |
| 계약서·약관 | 의무, 기한, 금액, 해지·위약 |
| 교재·설명서 | 정의, 핵심 개념, 예시, 주의 |
| 직접 정하기 | 사람이 적은 이름 1~5개      |

**보내는 것.** 고른 페이지 범위의 글 블록을 약 2,500토큰씩 묶어 보낸다(번역과 같은 묶음 크기). 블록 id와 글, 분류 목록, "블록 글 안에 실제로 있는 문장만 그대로 옮겨 적으라"는 지시. 문서 작업이므로 시작 전 확인(예상 호출 수)을 거친다. 작업 종류 `highlight`를 문서 작업 엔진에 더하고, 한 문서에 작업 하나 규칙에 넣는다. 고칠 수 없는 문서에서는 시작 단추를 막는다. 저장된 파일의 글이 기준이라, 저장하지 않은 편집이 있으면 시작 전 확인에 그렇다고 적는다.

**답 검사.** 답은 `{ blockId, label, quote }[]`다.

- `quote`가 그 블록의 글에 정확히 들어 있지 않으면 버린다(공백 정규화만 허용). 지어낸 문장이 주석이 되지 않게 한다.
- 모르는 분류, 모르는 블록 id는 버린다. 한 블록에 같은 문장이 둘이면 하나만 남긴다.
- 받은 수, 버린 수, 위치를 찾지 못한 수는 끝난 뒤 보고에 적는다.

**미리 보기와 받아들이기.**

- 문장을 PDF.js 글자 층에서 찾아 그 위치에 반투명 색 상자를 덧그린다. 덧그림은 주석이 아니라 저장되지 않는다.
- 3번 패널에 "AI 표시 제안"이 분류별로 묶여 나온다. 하나씩 받아들이기·버리기, 분류 단위로 모두 받아들이기, 전체 버리기.
- 받아들이면 그 분류 색의 형광펜(`MarkupInput`)이 된다. 분류 이름은 주석의 제목(`/Subj`)에 남긴다(8절 5번). `MarkupInput`에 선택 필드 `subject?: string`을 더하고 `save-pdf.ts`가 `/Subj`로 쓴다. 필드가 없는 기존 주석의 저장 결과는 그대로여야 한다(3절 8번). 3번 패널은 `/Subj`를 읽어 분류로 거른다.
- 글자 층(스캔 페이지는 OCR 결과 포함)에서 찾지 못한 문장(OCR 하지 않은 스캔 페이지, AI로 읽은 페이지)은 미리 보기에 그리지 못한다. 패널에는 "위치를 찾지 못함"으로 보이고 받아들일 수 없다.
- 버리기는 곧바로 보관소에 남는다. 받아들인 것은 PDF 저장이 성공한 뒤에 `accepted`가 된다.

**보관.** 새 폴더 `docs/<문서 해시>/highlights/<runId>/`. `run.json`에 묶음·분류·고른 페이지·제공자를, `blocks/<페이지 지문>/<글 해시>.<순번>.json`에 블록마다 제안과 받아들이기·버리기 상태를 둔다. `runId`는 묶음 id와 분류 이름 목록(순서대로)의 해시라, 분류가 다르면 새로 돌린 것이다. 그 문서에 다른 `runId`의 제안이 있으면 시작 전 확인에서 "예전 제안을 지울까요"(지우기 / 남기기)를 묻고, 미리 보기와 패널은 가장 최근 것만 보인다. 번역 블록과 같은 열쇠라 페이지 범위를 바꾸거나 이어 가도 이미 한 블록은 보내지 않는다. 멈추면 다음에 열 때 이어하기 제안이 "AI 핵심 표시"로 보이고, "이어서 하기"는 그때의 분류와 페이지를 채운 시작 창을 연다.

**시험.** 확인 전에 보내지 않는지, 블록에 없는 문장·모르는 분류·모르는 id를 버리는지, 미리 보기가 파일을 바꾸지 않는지(저장 결과 비교), 받아들인 것만 `/Highlight`로 저장되는지와 `/Subj`, `subject`가 없을 때 기존 저장 결과가 바이트 단위로 같은지, 이어하기와 보관소 왕복, 위치를 못 찾은 문장.

### 7번. 문단까지 가는 인용

**무엇.** AI 창의 답이 근거를 댈 때 페이지만이 아니라 그 문장으로 간다.

**링크 모양.** `pdfnav://page/N?q=<짧은 인용, URL 인코딩>`. 지금의 `pdfnav://page/N`도 계속 받는다.

- `pdf-skill.ts`의 지시문에 "근거를 댈 때는 그 페이지의 원문에서 8~20단어를 그대로 옮겨 `q`에 넣으라"를 더한다.
- 누르면 그 페이지로 가서 글자 층에서 인용을 찾아(공백·줄바꿈·하이픈 줄넘김 정규화) 2초간 강조한다. 못 찾으면 지금처럼 페이지로만 가고, 링크에 "위치를 찾지 못함"을 잠깐 보인다.
- `parsePdfNavHref`는 `{ page, quote? }`를 돌려주도록 바꾼다. 다른 모양의 주소는 지금처럼 버린다.

블록 id를 `read_pages` 출력에 넣는 방법은 버렸다(7절). 매 페이지마다 토큰이 늘고, AI로 읽은 페이지와 OCR 글에는 블록 id가 없다.

**시험.** 주소 해석(예전 모양, `q` 있음, 깨진 인코딩, 다른 스킴), 인용 찾기의 정규화, 못 찾았을 때 페이지로만 가는지.

### 8번. 요약 카드 (누를 때만 만든다)

**무엇.** AI 창 맨 위에 접을 수 있는 "문서 개요" 칸을 둔다. 처음에는 "개요 만들기" 단추만 있다. 누르면 세 가지를 만든다.

1. 세 줄 요약
2. 요약(문단 몇 개)
3. 핵심 용어: 용어, 문서 안에서의 뜻, 처음 나오는 페이지. 용어를 누르면 뷰어 검색으로 찾는다.

**보내는 것.** 문서 전체의 구조화 글(`treeToStructuredText`). AI로 읽은 페이지는 그 결과로 바꿔 보낸다.

- 한 번에 들어가는 길이(약 60,000자)면 호출 1회, `useAiSendGate`를 거친다.
- 넘으면 문서 작업(`summary`)이 된다. 묶음마다 부분 요약을 받고 마지막에 한 번 합친다. 시작 전 확인에 예상 호출 수를 보인다. 멈추면 이어 하지 않는다. 다시 누르면 처음부터다.

**보관.** `docs/<문서 해시>/insights/<언어>.json`에 세 가지와 제공자·모델·만든 때·쓴 페이지 지문 목록을 둔다. 다시 열면 보관된 것을 보인다. "다시 만들기"는 누를 때만이다. 앱 안 저장으로 해시가 바뀌면 쓴 페이지 지문이 모두 같을 때만 옮기고, 하나라도 다르면 "문서가 바뀌었습니다 · 다시 만들기"를 보인다.

카드마다 복사, 9번 노트에 넣기가 있다.

**시험.** 누르기 전에 보내지 않는지, 길이 기준으로 한 번/문서 작업이 갈리는지, 보관소 왕복, 해시가 바뀐 뒤의 두 경우, 용어 누르기가 검색을 여는지.

### 9번. PDF마다 노트

**무엇.** PDF 하나에 마크다운 노트 하나를 잇는다. 리본과 3번 패널의 "노트 열기"를 누르면 마크다운 편집기 탭으로 연다. 메모장을 PDF 편집기 안에 새로 만들지 않고, 이미 있는 마크다운 편집기를 쓴다.

**노트에 넣기.** 3번 패널의 항목, 2번 카드, 8번 카드에 "노트에 넣기"를 둔다. 노트 탭을 열거나 앞으로 가져온 뒤, 그 탭의 편집기 문서 끝에 이런 모양으로 넣고 "바뀜" 상태로 만든다. 파일에 직접 쓰지 않는다. 마크다운 편집기가 바깥 변경을 다시 읽지 않아, 파일에 쓰면 열린 탭과 어긋나기 때문이다. 저장은 노트 탭에서 사람이 한다.

```markdown
> 표시한 글 ([p.12](보고서.pdf#page=12))

메모나 AI 설명
```

개요 카드에서 넣을 때는 첫 줄의 인용 대신 `## 문서 개요`(화면 언어)를 쓴다. 여러 줄인 인용은 줄마다 `> `를 붙이고, 링크는 마지막 줄 끝에 붙인다.

**노트 파일의 자리**(8절 3번). 처음 "노트 열기"를 누르면 저장 창을 띄운다. 기본 위치는 PDF와 같은 폴더, 기본 이름은 `<PDF 이름> 노트.md`("노트"는 화면 언어로)다. 사람이 고른 경로만 쓴다(메인 프로세스의 저장 창이 고른 것). 고른 파일이 이미 있으면 덮어쓰지 않고 그 파일을 잇는다. Windows의 저장 창이 바꾸기 확인을 띄워도 파일은 그대로다. 없으면 `# <PDF 제목, 없으면 파일 이름>` 한 줄로 만든다. 저장된 경로가 없는 PDF에서는 노트 단추를 막고 "PDF를 먼저 저장하세요"를 보인다.

고른 경로는 보관소의 `pdf-store/note-links.json`에 기억해 두고 다음부터는 바로 연다. 처음 계획은 문서 해시 폴더(`docs/<문서 해시>/note.json`)였지만, 그러면 PDF를 저장해 해시가 바뀔 때마다 노트를 잃는다. 그래서 PDF 파일 경로를 열쇠로 먼저 찾고, 없으면 같은 문서 해시의 가장 최근 노트를 찾는다. 이것은 보관소의 "경로를 열쇠로 쓰지 않는다" 규칙의 예외로 `docs/security.md`에 적었다. 기억한 파일이 없어졌으면 다시 묻는다. 노트가 이미 탭에 열려 있으면 그 탭을 앞으로 가져온다.

**PDF로 돌아가는 링크**(8절 4번). 노트에 넣는 페이지 표시는 처음부터 표준 링크 `<PDF 파일 이름>.pdf#page=N`(노트 기준 상대 경로, `/` 구분, 경로 조각마다 퍼센트 인코딩)로 쓴다. 노트와 PDF가 다른 드라이브에 있으면 `file:///` 절대 주소를 쓴다. 이 모양은 브라우저와 Acrobat 등 다른 프로그램에서도 그 페이지로 열린다. 앱 안의 마크다운 편집기에서 이 링크를 눌러 PDF 탭의 그 페이지로 가는 일은 이 계획 다음의 작은 과제로 둔다. 마크다운 편집기에는 지금 로컬 파일 링크를 여는 길이 없어서, 셸을 거쳐 PDF 탭을 여는 새 길이 필요하다.

**시험.** 노트 잇기와 다시 열기, 경로 → 해시 순 찾기, 저장 뒤 해시 갱신, 있는 파일을 덮어쓰지 않는지, 노트에 넣기의 글 모양과 링크 인코딩, 노트 탭이 닫혀 있을 때 열고 붙이는지, 화면이 보낸 경로를 받지 않는지.

## 8. 정한 것 (2026-10-19)

1. **페이지 하나 번역은 한 번 누르면 바로 한다.** 구독일 때는 확인 창 없이 보내고, 쓰일 제공자를 단추 옆에 미리 보인다. 요금 경로일 때만 그 탭에서 처음 한 번 요금 문구를 거친다. 여러 페이지는 지금의 확인 창을 쓴다. 자세한 것은 5번.
2. **AI 결과를 메모로 남길 때의 작성자 — 사람이 쓴 메모와 같은 값(PC 계정 이름).**
   - PDF 메모에는 작성자 칸(`/T`)이 있고, Acrobat 같은 다른 뷰어가 메모 옆에 그 이름을 보인다. 지금 앱은 사람이 새로 단 메모에 PC 계정 이름을 넣고, 이름을 모를 때만 코드의 기본값 `GenOffice`를 넣는다.
   - AI 메모에 `GenOffice`를 넣으면 다른 사람이 파일을 열었을 때 원본 프로그램 이름이 작성자로 보인다. "AI"로 넣으면 누가 남긴 메모인지 사라지고, 작성자로 거르면 한 사람의 메모가 둘로 갈린다.
   - 메모로 남기기는 사람이 눌러야 일어나는 일이니 그 사람이 작성자다. AI가 만든 글이라는 표시는 메모 첫 줄("AI 설명", "AI 번역(언어)")로 한다. 이 값은 파일에 저장되어 나중에 바꾸기 어려워서 여기에 정해 둔다.
3. **노트 파일의 자리 — 처음 한 번 저장 창으로 묻고, 기본값은 PDF 옆.** 사람이 노트를 다른 PC로 옮기거나 다른 프로그램으로 열 수 있어야 노트가 쓸모 있다. 보관소 안에 숨기면 앱을 지우거나 PC를 바꿀 때 노트를 잃는다. 다만 폴더에 파일이 생기는 것을 싫어할 수 있으니, 정해 버리지 않고 저장 창으로 위치를 고르게 한다. 고른 경로는 보관소에 PDF 파일 경로를 열쇠로 기억해 다음부터는 묻지 않는다. 자세한 것은 9번.
4. **노트에서 PDF로 돌아가는 링크 — 링크 모양만 이번에 정하고, 앱 안에서 누르기는 다음 과제로.** 노트에 `보고서.pdf#page=12` 같은 표준 링크를 쓰면 다른 프로그램에서는 지금도 그 페이지로 열린다. 이 모양으로 써 두면 나중에 앱 안 누르기를 붙여도 이미 쓴 노트를 고칠 필요가 없다. 앱 안 누르기는 마크다운 편집기와 셸에 새 길을 내야 해서, 이 계획에 넣으면 9번이 커진다.
5. **AI 핵심 표시의 분류 이름 — 남긴다. 메모 내용(`/Contents`)이 아니라 주석 제목(`/Subj`)에.** 색만 남기면 파일을 다른 사람에게 보냈을 때 노란색이 "결과"인지 "기한"인지 알 수 없다. `/Contents`에 넣으면 다른 뷰어에서 형광펜마다 메모 아이콘과 글이 붙어 거슬린다. `/Subj`는 Acrobat의 주석 목록에서 "Highlight" 대신 그 이름("기한" 등)으로 보이고, 화면에는 아무것도 덧붙지 않는다. `save-pdf.ts`에 선택 필드 하나를 더하는 작은 일이고, 필드가 없으면 저장 결과가 지금과 바이트 단위로 같아야 한다.
