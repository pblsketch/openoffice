# 발표 모드 계획

2026-10-23에 받은 의견이다. "현재 문서를 프레젠테이션 용도로 전체화면으로 보여주는 모드"를 F5·Ctrl+F5·F11 느낌으로 쓸 수 있게 해 달라는 요청. 지금은 슬라이드에만 F5 쇼가 있고, 워드에는 리본을 숨기는 읽기 모드가 있으며, HTML에는 발표(전체화면)가 따로 있다. 나머지 편집기는 전체화면 창(F11)까지는 되지만 문서에 맞춘 발표 화면은 없다. 같은 날 마인드맵(F5), 워드(F5·Ctrl+F5), PDF(F5·Ctrl+F5)에 먼저 넣었다.

## 목표

- **F5**: 지금 문서를 처음부터 발표한다. 앱의 탭 줄과 편집기의 도구 줄을 숨기고, 문서를 화면에 맞춘다.
- **Ctrl+F5 · Shift+F5**: 지금 위치에서 발표한다. 슬라이드는 현재 슬라이드, PDF·워드는 현재 쪽, 엑셀은 현재 셀 근처, 마인드맵은 지금 시트. 워드는 전체화면 없이 읽기 모드만 켠다.
- **F11**: 창만 전체화면으로 만든다(지금 Electron의 `togglefullscreen` 역할). 편집기의 도구 줄은 그대로 둔다.
- **Esc**: 발표 모드를 끝낸다. 발표 중에는 편집기의 Esc(선택 해제 등)보다 먼저 받는다.
- 발표 중에는 F5를 다시 누르면 끝난다. 발표 중 문서를 고칠 수 없게 할지는 편집기별로 정한다(워드 읽기 모드처럼 읽기 전용이 자연스럽다).

## 지금 있는 것

| 편집기   | 지금 되는 것                                                 |
| -------- | ------------------------------------------------------------ |
| 슬라이드 | F5 처음부터, Shift+F5 현재 슬라이드부터, 발표자 보기, 리허설 |
| 워드     | 읽기 모드(리본 숨김, Esc로 종료). 전체화면과 이어지지 않는다 |
| HTML     | 발표: 탭 안, 전체화면, 새 탭/창 세 가지                      |
| 마인드맵 | 화면 맞춤(`zoomFit`)과 확대/축소만 있다                      |
| PDF      | 한 쪽 보기·확대만 있다                                       |
| 엑셀     | 화면 맞춤 없음                                               |
| 한글     | 화면 맞춤 없음                                               |

## 설계

- **껍데기가 창과 탭 줄을 맡는다.** 발표 중에는 탭 줄을 숨기고 편집기 뷰를 창 전체(탭 줄 높이 0)에 놓는다. 창은 `setFullScreen(true)`로 만든다. Esc·F5는 껍데기가 `before-input-event`에서 먼저 받아 끝낸다. 이미 HTML 발표와 슬라이드 쇼가 쓰는 길(`TabManager.setContentBleed`, `enter-html-full-screen`)이 있으므로 같은 길을 쓴다. **지금 구현(2026-10-23)은 편집기가 HTML 전체화면을 직접 요청하고, 셸의 기존 `enter-html-full-screen` 처리가 탭 줄을 덮는다.** 나중에 창구를 껍데기로 모으면 macOS의 전체화면 애니메이션과 창 밖 모니터 동작을 한 곳에서 다룰 수 있다.
- **편집기는 내용 맞춤만 맡는다.** 껍데기가 활성 편집기에 "발표 시작/끝"을 알리는 새 창구를 하나 만든다. 편집기는 그 창구를 받으면 자기 도구 줄·패널을 숨기고 문서를 화면에 맞춘다. 창구를 등록하지 않은 편집기는 껍데기만 전체화면이 되고 도구 줄은 그대로 남는다(첫 단계의 안전한 기본값).
- **Ctrl+F5는 "지금 위치"를 편집기가 정한다.** 껍데기는 `from: 'start' | 'current'`만 넘기고, 슬라이드는 현재 슬라이드, PDF·워드는 현재 쪽, 마인드맵은 지금 시트를 쓴다.
- **F11은 지금 그대로 둔다.** Electron의 `togglefullscreen` 역할이 이미 F11을 받는다. 발표 모드와 겹치지 않게 F11은 탭 줄을 숨기지 않는다.
- **읽기 전용은 편집기 몫이다.** 워드는 기존 읽기 모드를 그대로 쓰고, 슬라이드는 쇼, 마인드맵은 편집 입력 상자를 닫은 뒤 발표한다. 발표 중 저장·인쇄 같은 메뉴는 그대로 둔다(메뉴를 누르면 발표가 끝나지 않는다).

## 편집기별 할 일

1. **껍데기**: 발표 상태, 탭 줄 숨김 레이아웃, 새 창구(`present:enter`·`present:exit`), F5·Ctrl+F5·Esc 처리, 메뉴 항목(보기 → 발표)과 21개 언어 문구.
2. **슬라이드**: F5·Shift+F5를 새 창구에 맞춘다(지금 키를 그대로 두고, 발표 중에는 껍데기가 F5를 가로채지 않게 예외).
3. **워드**: 2026-10-23에 F5(읽기 모드 + 전체화면), Ctrl+F5·Shift+F5(읽기 모드만, 이 창에서), Esc/F5 종료까지 넣었다. 읽기 모드의 기존 1:1 확대 대신 발표에서는 쪽 맞춤을 쓴다.
4. **마인드맵**: 2026-10-23에 F5·전체화면·도구 줄/시트 탭/패널 숨김·`zoomFit`까지 넣었다. 남은 것: 발표 중 드래그·편집 막기, 나가는 안내.
5. **PDF**: 2026-10-23에 F5(첫 쪽부터), Ctrl+F5·Shift+F5(지금 쪽부터), 전체화면·한 쪽 맞춤까지 넣었다.
6. **HTML·마크다운**: 2026-10-23에 HTML은 F5(전체화면 발표), Ctrl/Shift+F5(탭 안 발표), Esc 종료로 기존 발표 메뉴와 연결했고, 마크다운은 F5(전체화면, 원문 보기였으면 닫았다가 복원)를 넣었다.
7. **엑셀·한글**: 2026-10-23에 Ctrl+F5(A1부터)·Shift+F5(지금 셀부터) 전체화면 발표를 엑셀에 넣었고(엑셀의 F5는 기존 Go To로 남긴다), 한글은 F5 전체화면과 편집기 자체 메뉴·도구 줄·상태 줄 숨김까지 넣었다. 화면 맞춤(엑셀 인쇄 영역, 한글 쪽 너비)은 남았다.
8. **도움말**: 단축키 문서(21개 언어)에 "발표 모드" 절(F5·Ctrl/Shift+F5·Esc, 엑셀의 Ctrl/Shift+F5, F11은 창 전체화면)을 넣었다. 마인드맵 도움말 주제 자체는 아직 없다.

## 시험

- 껍데기: F5·Ctrl+F5·Esc가 발표 상태를 바꾸고, 탭 줄이 숨는 레이아웃, 발표 중 탭 전환 키(Ctrl+Tab)는 막거나 발표를 끝낸다.
- 편집기: 창구를 받았을 때 도구 줄이 숨고 화면 맞춤이 불리는지, Esc·F5로 끝나는지.
- 실제 빌드한 앱에서 각 편집기의 발표 화면을 눈으로 확인한다.

## 이번에 하지 않은 것

- **Ctrl+1·2·3…으로 탭 고르기.** 브라우저에서는 익숙하지만 이 앱에서는 워드의 줄 간격(Ctrl+1·2·5), 엑셀의 셀 서식(Ctrl+1)·취소선(Ctrl+5)·행 숨기기(Ctrl+9)와 정면으로 겹친다. 이번에는 Ctrl+Tab·Ctrl+Shift+Tab만 넣고, 번호로 탭을 고르는 키는 나중에 "편집기가 쓰지 않는 조합"을 정하거나 사용자가 바꿀 수 있게 할 때 함께 넣는다.
