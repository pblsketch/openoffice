# PDF 도구 모음 계획

상태: **방향 확정**(2026-10-15). "정한 것"(10절)은 결정 기록 [0030](../tracking/decisions/0030-pdf-tools-hub.md)에 옮겼다. 단계별 세부는 구현하면서 이 문서를 고친다.

## 1. 무엇을 하려는가

PDF로 자주 하는 일(합치기, 나누기, 용량 줄이기, 인쇄 준비, 변환 등)을 **할 일부터 고르는 화면**에 모아 둔다. 파일을 열고 리본을 뒤질 필요 없이 카드 하나를 고르면 그 일에 필요한 파일 수와 옵션만 보인다.

지금 PDF 편집기에는 이런 일의 절반 이상이 이미 있다. 다만 리본 여러 탭에 흩어져 있고, PDF를 먼저 열어야만 쓸 수 있다. 그래서 이 계획의 큰 줄기는 두 가지다.

1. 이미 있는 기능을 **찾기 쉽게** 한다(도구 화면).
2. 빠진 기능을 **필요한 만큼만** 채운다.

모든 도구는 이 PC 안에서만 처리하고, AI를 쓰지 않으며, 결과는 **새 파일**로 저장한다. 원본 파일은 바꾸지 않는다.

## 2. 참고한 것과 주의할 점

| 참고 대상             | 무엇인가                                  | 가져올 것                                                             | 가져오지 않을 것                                                                     |
| --------------------- | ----------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| PDF LAB               | 교사용 웹 앱. 브라우저 안에서만 처리      | "도구 먼저 / PDF 먼저" 두 입구, 카드마다 한 줄 설명과 태그, 활용 예시 | **교사·학교 전용 용어와 예시**(생활기록부, 학생별 등), 제작자 표기, 화면 디자인 자체 |
| iLovePDF              | 일반용 웹 서비스. 파일을 서버에 올려 처리 | 범주 나누기(정리·최적화·변환·편집·보안), 도구 목록의 폭               | 서버 업로드, 휴대폰 스캔 전송, 사용량 제한, 회원 가입                                |
| 이음오피스 PDF 편집기 | 이미 있는 기능과 화면 용어                | 기존 이름(병합, 분할, 모아찍기, 추출, 역순 정렬)을 그대로 씀          | –                                                                                    |

이음오피스는 특정 직업군용이 아니다(`CLAUDE.md`). 교사뿐 아니라 사무직, 연구자, 학생, 자영업자 등 문서를 다루는 누구나 쓴다. 그리고 화면은 21개 언어로 나간다. 한국 학교 제도의 이름은 다른 언어로 옮길 수 없다.

## 3. 용어 원칙

1. **특정 직업·기관의 서류 이름을 쓰지 않는다.** "생활기록부", "학생", "공문"이 아니라 "문서", "파일", "묶음"으로 쓴다. 예시는 여러 직군이 함께 겪는 상황으로 든다.
2. **앱에 이미 있는 이름을 먼저 쓴다.** 같은 기능에 이름을 둘 만들지 않는다. 예: 이미 "PDF 병합"이 있으니 도구 카드도 "PDF 병합"이다("합치기"로 새로 짓지 않는다).
3. **이름에 결과까지 드러낸다.** "찾기"만 하는지 "지우기"까지 하는지 이름에서 알 수 있게 한다.
4. **다른 기능과 겹치는 말을 피한다.** 앱에는 이미 "양식 입력란"(form)과 "페이지 추출"이 있다. 그래서 "양식 합치기", "텍스트 추출"처럼 헷갈리는 이름은 쓰지 않는다.
5. **도구 화면에서는 "페이지"로 통일한다.** 지금 편집기 문구에는 "페이지"와 "쪽"이 섞여 있다. 이 정리는 별도 과제다.
6. **결과가 새 파일이라는 것을 화면에서 항상 밝힌다.**

## 4. 화면 구조

```
[홈]  ─ "PDF 도구" 카드 ──▶ [PDF 도구 창]
                                │ ① 도구 고르기 (범주별 카드)
                                │ ② 파일 고르기 (도구마다 1개 / 여러 개 / 이미지)
                                │ ③ 옵션 (그 도구에 필요한 것만)
                                │ ④ 실행 → 새 파일 저장
                                └ ⑤ 결과: "탭에서 열기" / "폴더 열기"

[PDF 편집기] ─ 리본(홈·주석·편집·페이지·보기) ─ 지금 연 문서에 같은 도구 적용
```

- **도구 먼저(홈)**: 홈에 "PDF 도구" 카드를 두고 누르면 별도 창이 뜬다. 셸의 "만들기 창"(`apps/shell/src/main/generate/`)과 같은 방식이다. 여러 파일을 받는 도구(병합, 이미지로 PDF 만들기, 양면 인쇄 맞추기)는 여기서 바로 처리한다.
- **페이지를 보며 골라야 하는 도구**(빈 페이지 찾아 지우기, 순서 바꾸기, 주석 한꺼번에 지우기의 검토)는 도구 창에서 파일을 고르면 PDF 편집기 탭을 열고 그 기능의 패널을 띄운다.
- **PDF 먼저(편집기)**: 새 리본 탭을 만들지 않고, 새 기능을 기존 탭의 알맞은 자리에 넣는다(페이지 탭: 빈 페이지, 양면 인쇄 맞추기, 배경 겹치기 / 홈 탭의 내보내기·변환 쪽: 텍스트로 저장, 용량 줄이기, 암호).

## 6. 기술 방침

- **처리 코드는 PDF 편집기 모듈(`apps/pdf/src/main`)에 둔다.** 이미 있는 `save-pdf.ts`의 함수를 그대로 쓰고, 새 함수도 그 옆에 둔다. 도구 창(셸)은 IPC로 부르기만 한다.
- **문서 엔진 패키지는 고치지 않는다.** pdf-lib, PDF.js, PDFium은 의존성으로 쓸 뿐이다. 엔진 패키지(`packages/*-engine`)를 고쳐야 할 것 같으면 멈추고 묻는다.
- **원본은 바꾸지 않는다.** 결과는 항상 새 파일이다. 저장 위치는 메인 프로세스의 대화 상자로 고르고, 렌더러가 보낸 경로를 그대로 읽거나 쓰지 않는다(`apps/pdf/AGENTS.md`의 경로 허가 규칙).
- **AI를 쓰지 않는다.** 도구는 구독 한도를 쓰지 않고, 문서 내용을 어디에도 보내지 않는다. "장별로 나누기"도 AI 없이 문서 나무만 쓴다.
- **오래 걸리는 일은 별도 프로세스에서 돌린다.** 용량 줄이기, 빈 페이지 판정처럼 페이지를 모두 그리는 일은 PDF 구조 작업처럼 셸이 띄우는 작업 프로세스에서 돌린다. 진행 표시와 취소를 둔다.
- **새 의존성은 3단계에서 qpdf 하나다.** 넣기 전에 `npm run licenses`, `NOTICE` 갱신, 설치 파일 크기 증가를 확인한다.
- **문구는 21개 언어를 모두 채운다.** 새 문구는 언어별 조각 파일(`i18n/pdf-tools/<언어>.ts`, `zh`가 키 집합)에 둔다. 한국어·영어는 직접 쓰고 나머지 19개는 번역한다.
- 터미널 명령어·MCP 도구로 내놓는 것은 이번 범위가 아니다. 내놓으면 `docs/contracts.md`의 약속이 된다.

단계마다 따로 가지를 만들고 PR을 연다. 2단계는 도구 하나씩 나눠 올려도 된다.

### 1단계에서 실제로 한 것

- 창에서 바로 처리하는 도구 8개: PDF 병합, PDF 분할, 페이지 추출, 역순 정렬, 모두 회전, 페이지 모아찍기, 페이지 크기, 페이지 분할. 모두 편집기의 같은 함수(`apps/pdf/src/main/save-pdf.ts`)를 부른다.
- 편집기로 넘기는 카드 5개: 워터마크·머리글/바닥글, 페이지 자르기, 이미지 내보내기, PDF 변환, 편집·서명·가림. 워터마크는 한중일 글자를 화면의 그림판으로 그려야 해서, 페이지 자르기는 영역을 눈으로 골라야 해서 창에서 하지 않는다.
- 도구 이름과 선택지 이름(`tool*`, `opt*` 일부)은 편집기 리본의 문구를 그대로 복사했다. 테스트가 둘이 같은지 확인한다.
- 암호가 걸린 PDF는 고를 때 "쓸 수 없음"으로 알린다. 3단계부터는 "암호 풀기"로 먼저 풀라고 알린다.
- 결과를 저장할 곳이 원본이거나, 저장하지 않은 변경이 있는 채로 열린 파일이면 저장하지 않는다.

### 2단계에서 지금까지 한 것

- **이미지로 PDF 만들기**(`apps/pdf/src/main/images-to-pdf.ts`): JPG·PNG 여러 장을 고른 순서대로 한 장에 한 페이지로 넣는다. 용지(A3·A4·A5·Letter·Legal, 넓은 그림은 가로로) 또는 "그림 크기 그대로"(96dpi), 여백 없음·좁게·넓게. JPEG는 다시 압축하지 않고 그대로 넣으며, 휴대폰 사진의 EXIF 회전 정보를 반영한다. 그 밖의 그림 형식(HEIC, WebP 등)은 아직 받지 않는다.
- **양면 인쇄 맞추기**(`apps/pdf/src/main/print-prep.ts`): PDF를 하나 이상 받아, 파일마다 빈 페이지를 넣어 짝수로 맞춘 뒤 고른 순서대로 합친다. "나중에 한 면에 모아찍을 페이지 수"를 고르면 그 두 배의 배수로 맞춰, 모아찍기 뒤에도 파일마다 새 종이의 앞면에서 시작한다. 빈 페이지는 그 파일의 마지막 페이지와 크기·회전이 같다. 모아찍기 자체는 하지 않는다(따로 "페이지 모아찍기").
- **배경 겹치기**(`apps/pdf/src/main/overlay.ts`, 새 "꾸미기" 묶음): 문서 하나와 배경으로 쓸 PDF를 따로 고르고, 배경 PDF의 한 페이지를 모든 페이지(또는 고른 페이지)의 내용 뒤나 앞에 그린다. 배경은 각 페이지의 보이는 영역(CropBox) 안에 비율을 지켜 가운데로 맞추고, 돌려 저장된 페이지(`/Rotate`)에서도 똑바로 선다. 배경 페이지 자신의 회전, 링크·입력란·주석은 옮기지 않는다. 내용이 없는 배경 페이지를 고르면 아무것도 겹치지 않은 사본이 된다.
- **주석 한꺼번에 지우기**(`apps/pdf/src/main/annot-strip.ts`, 새 "정리하기" 묶음): 메모, 형광펜·밑줄·취소선, 그리기·도형, 도장, 링크, 그 밖의 주석을 골라 모든 페이지(또는 고른 페이지)에서 지운다. 링크는 기본으로 남기고, 입력란(위젯)은 이 도구가 지우지 않는다. 지운 주석에 딸린 팝업, 그 주석에 단 답글(`/IRT`)도 함께 지운다. 페이지에서 빼는 데서 그치지 않고 주석 객체와 그 모양 스트림을 파일에서 지워, 지운 메모의 글이 새 파일에 남지 않는다. 고른 종류가 하나도 없으면 저장 창을 띄우지 않고 알린다. 계획에 있던 "편집기에서 검토 후 지우기"는 하지 않았다(종류·페이지로 고르는 것으로 대신함).
- **빈 페이지 찾아 지우기**(`apps/pdf/src/main/blank-pages.ts`, "페이지 정리" 묶음): 찾기는 셸의 PDF 구조 작업 프로세스에서 돈다(작업 종류 `blankPages`, 진행 표시와 "그만 찾기", 답하면·취소하면·창을 닫으면 프로세스가 끝난다). 판정은 "빈 페이지가 아니다" 쪽으로 기운다. 글자 층에 보이는 글자가 하나라도 있으면(보이지 않는 OCR 글자 포함) 후보가 아니고, 그리는 것이 하나도 없으면 "아무것도 없음", 그 밖에는 긴 변 600px로 그려 여백(각 변 4%)을 뺀 안쪽의 어두운 점이 0.5% 미만이면서 12px 칸 하나에라도 15% 넘게 모인 곳이 없을 때만 "거의 흰 페이지"다. 후보는 긴 변 240px 축소판으로 보여 준다. 처음에는 "아무것도 없음"만 골라 두고, 사용자가 고른 페이지만 지운다. 뒷단은 찾기 결과에 없던 페이지를 지우라는 요청과 모든 페이지를 지우라는 요청을 거절한다. 지우기는 편집기의 저장(`applySaveRequest`의 `deletedPages`)을 그대로 써서 책갈피와 양식을 남긴다. 계획에는 편집기 탭에서 검토한다고 적었지만, 도구 창 안에서 축소판으로 검토하게 했다.
- **텍스트로 저장**: 편집기의 `read-text.ts`로 글자를 페이지 순서대로 읽어 UTF-8 TXT로 저장한다. 페이지 사이에는 빈 줄을 둔다. 글자 층이 하나도 없는 PDF(스캔)는 저장 대화 상자를 띄우지 않고 이유를 알린다. 편집기가 화면에서 인식한 글자(OCR)는 쓰지 않는다.
- 카드 아이콘은 편집기 리본의 같은 명령 아이콘(`apps/pdf/src/renderer/icons.tsx`)을 그대로 쓴다. 새 도구의 아이콘도 같은 파일에 같은 화풍으로 그려 둔다(리본에 넣을 때 그대로 쓴다).
- 편집기에는 도구마다 리본 명령을 따로 만들지 않고, 페이지 탭 끝에 **PDF 도구** 메뉴 하나를 두었다(빈 페이지 찾아 지우기, 양면 인쇄 맞추기, 배경 겹치기, 주석 한꺼번에 지우기, 텍스트로 저장). 고르면 저장하지 않은 편집을 먼저 저장하고(리본의 다른 파일 작업과 같은 `flushThen`), 그 탭의 파일이 고른 상태로 도구 창이 그 도구로 열린다. 창이 이미 열려 있으면 그 도구로 바뀐다. 처리 코드와 검토 화면이 한 곳에만 있게 하려는 것이다(사용자가 2026-10-15에 이 방식을 골랐다). 메뉴와 항목 이름은 도구 창의 문구와 같고 테스트가 지킨다.
- 도움말 주제 "PDF 도구"(`pdf-tools`)를 21개 언어로 더했다. 도구와 버튼 이름은 도구 창 문구에서 그대로 가져왔다.

### 3단계에서 지금까지 한 것

- **용량 줄이기**(`apps/pdf/src/main/compress.ts`, 새 "용량·보안" 묶음): 큰 그림(48KB 이상)을 단계(약 3000px·85, 보통 2000px·75, 강 1400px·60)에 맞춰 줄이고 JPEG로 다시 넣은 뒤, 개체 스트림으로 다시 쓴다. 새 그림이 원래보다 작을 때만 바꾸고, 파일 전체가 작아지지 않으면 저장 창을 띄우지 않고 알린다. 결과에는 "원래 크기 → 새 크기"를 보인다. 색상 키 마스크·`/Decode`·이미지 마스크·CMYK와 그 밖의 색 공간·8비트가 아닌 것·여러 필터·예측자가 있는 Flate, 소프트 마스크 자체, EXIF 회전이 있는 JPEG는 건드리지 않는다. 소프트 마스크는 그대로 둔다.
- 그림의 해독·크기 조정·JPEG 인코딩은 앱의 크로미움(`nativeImage`, `apps/shell/src/main/pdf-tools/image-recode.ts`)이 한다. 계획은 작업 프로세스에서 돌리기로 했지만, 그 프로세스(Electron utilityProcess)에는 `nativeImage`가 없고(시험해 보니 `net`, `systemPreferences`만 있음), CanvasKit(7MB)을 설치 파일에 더하는 것은 과하다고 보았다. 그래서 메인 프로세스에서 그림 한 장마다 이벤트 루프에 한 번 양보하며 돌리고, 진행 표시와 "그만하기"를 둔다. 해독한 크기가 PDF에 적힌 크기와 다르면 그 그림은 바꾸지 않는다.
- 파일 복구는 계획과 달리 qpdf가 아니라 앱에 이미 있는 PDFium으로 하기로 했다. 시험한 WebAssembly판 qpdf(`@neslinesli93/qpdf-wasm` 0.3.0, qpdf 12.2.0)는 C++ 예외를 잡지 못하게 빌드되어 손상된 파일을 다시 짜 맞추는 단계로 가지 못했고, PDFium은 시험한 손상 네 가지(상호 참조 위치 어긋남, startxref 틀림, 상호 참조 표 없음, 끝부분 잘림)를 모두 읽고 다시 썼다. 암호 걸기·풀기는 그 qpdf로 된다(AES-256 걸기, 바른 암호로 풀기, 틀린 암호 거절을 확인함). PDFium의 "보안 빼고 저장"은 결과에 /Encrypt가 남아 쓰지 않는다.
- **암호 걸기**(`apps/pdf/src/main/qpdf.ts`): 열 때 쓸 암호를 두 번 입력받아 AES-256으로 건다. "인쇄·복사·편집 막기"를 고르면 그것을 풀 암호를 따로 받고(열 때 쓸 암호와 같으면 거절), 인쇄·변경·복사·주석을 모두 막는다. 막기를 고르지 않으면 권한 암호는 아무도 모르는 임의의 값이다. 암호는 입력한 그대로 쓰고(앞뒤 공백도 암호), UTF-8로 127바이트를 넘으면 거절한다. 다시 입력한 암호는 화면에서만 비교하고 보내지 않는다. 저장하고 나면 입력란을 비운다.
- **암호 풀기**: 암호가 걸린 PDF만 고를 수 있다(암호가 없는 파일은 고를 때 알린다). 지금 걸린 암호를 받아 PDFium으로 먼저 열어 보고, 틀리면 "암호가 맞지 않습니다"로 알린다. 맞으면 qpdf가 암호 없는 사본을 쓴다. 암호를 모르는 파일을 여는 기능은 없다.
- **파일 복구**(`apps/pdf/src/main/repair.ts`): 다른 도구가 읽지 못하는 PDF도 고를 수 있다(페이지 수는 모르므로 크기만 보인다). PDFium으로 다시 쓰고, PDFium이 읽지 못하면 pdf-lib가 찾아낸 온전한 페이지만 새 파일에 옮긴다(`salvagePdfBytes`). 내려받다 끊긴 파일처럼 끝이 잘린 파일은 PDFium이 하나도 읽지 못했고, 이 경로로 남은 페이지를 되살렸다. 그림을 그리는 내용이 사라진 페이지는 빈 페이지로 되살리지 않고 뺀다.
- 세 도구는 메인이 아니라 PDF 구조 작업 프로세스에서 돈다(작업 종류 `encrypt`, `decrypt`, `repair`, `runWindowJob`). 진행 표시는 없고 "그만하기"로 그 프로세스를 끝낼 수 있다. 결과는 메인이 다시 읽어 약속대로인지 확인한다: 암호 걸기의 결과는 암호를 묻고, 풀기와 복구의 결과는 다른 도구가 읽을 수 있어야 저장 창을 띄운다. 암호는 그 작업에만 실려 가고 로그·오류 메시지에 담기지 않는다.
- 이 WebAssembly판 qpdf는 `wasmBinary` 옵션을 무시하고 자기 스크립트 옆의 `qpdf.wasm`을 읽는다. 묶어 빌드한 작업 프로세스 옆에는 그 파일이 없어서 `locateFile`로 경로를 준다(단위 테스트는 node_modules에서 돌아 이 문제를 놓쳤고, 빌드한 앱의 e2e에서 드러났다).
- 편집기 페이지 탭의 **PDF 도구** 메뉴에 용량 줄이기, 암호 걸기, 암호 풀기, 파일 복구를 더했다. 2단계의 다섯 도구처럼 그 탭의 파일로 도구 창을 연다. 계획에 적은 "홈 탭에 넣기"는 하지 않고 이 메뉴 하나로 모았다.
- qpdf.wasm은 1.33MB(gzip 0.44MB)이고 설치 파일의 `resources/wasm`에 들어간다. 라이선스는 Apache-2.0(qpdf), 감싼 패키지는 ISC다.

## 8. 확인 방법

- 도구마다 결과 PDF를 다시 읽어 확인하는 단위 테스트를 붙인다(페이지 수, 페이지 크기, 회전, 남은 주석 종류, 글자 추출 결과).
- 원본 파일이 바뀌지 않았는지(바이트 비교) 확인한다.
- 용량 줄이기: 결과가 원본보다 작은지, 글자가 그대로 추출되는지, 이미 작은 파일에서 원본을 유지하는지 확인한다.
- 주석 한꺼번에 지우기: 링크·입력란이 남는지 확인한다.
- 빈 페이지 판정: 흰 배경에 아주 작은 글자만 있는 페이지, 스캔한 빈 페이지(잡티)를 시험 자료로 넣는다.
- 합치기 전 검사(`docs/standards.md`), 그리고 `npm run check:help-langs`, `npm run licenses`.
- 빌드한 앱(Windows)에서 홈 카드 → 도구 창 → 결과 탭 열기까지 사람이 확인한다.

## 9. 위험과 대응

| 위험                                             | 대응                                                                    |
| ------------------------------------------------ | ----------------------------------------------------------------------- |
| 빈 페이지를 잘못 판정해 내용 있는 페이지를 지움  | 자동으로 지우지 않는다. 후보를 크게 보여 주고 사용자가 고른 것만 지운다 |
| 용량 줄이기로 그림 화질이 너무 떨어짐            | 단계(약·중·강)를 고르게 하고, 결과 크기를 미리 알려 준다                |
| 이미 압축된 파일이 오히려 커짐                   | 원본보다 크면 저장하지 않고 알린다                                      |
| 주석을 지우다 링크·입력란까지 사라짐             | 기본으로 남기고, 지우려면 따로 골라야 한다                              |
| 암호 기능이 남의 파일 잠금 풀기로 쓰임           | 암호를 아는 경우만 푼다. 암호를 알아내는 기능은 만들지 않는다           |
| 큰 파일에서 앱이 멈춤                            | 작업 프로세스에서 돌리고 진행 표시와 취소를 둔다                        |
| 21개 언어 번역 분량                              | 문구를 짧게 쓰고, 카드 설명은 한 줄로 제한한다                          |
| 기능이 리본과 도구 창 두 곳에 생겨 이름이 어긋남 | 문구 키를 같은 것으로 쓰고, 용어표를 기준으로 삼는다                    |

## 10. 정한 것

| #   | 질문                                                   | 정한 것                                                                                           |
| --- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 1   | 도구 화면의 입구                                       | 홈 카드 + 별도 창(만들기 창과 같은 방식). 편집기에는 새 탭 없이 기존 리본에 넣음                  |
| 2   | 첫 배포 범위                                           | 1단계 + 2단계(새 의존성 없음)                                                                     |
| 3   | qpdf를 들일지                                          | 들임. 암호 걸기·풀기에만 쓰고(qpdf.wasm 1.33MB), 파일 복구는 PDFium과 pdf-lib로 함                |
| 4   | 기존 용어(병합·분할)를 쉬운 말(합치기·나누기)로 바꿀지 | 바꾸지 않음. 앱 전체와 21개 언어 문구가 이미 그 이름이다. 카드의 한 줄 설명에서 쉬운 말로 풀어 줌 |
| 5   | "페이지"와 "쪽" 혼용 정리                              | 도구 화면은 "페이지"로 씀. 편집기 전체의 정리는 별도 과제                                         |
| 6   | 도움말 주제를 새로 만들지                              | 2단계 끝에 "PDF 도구" 주제 하나를 21개 언어로 추가                                                |
