# 다이어그램 편집기 계획

상태: **초안**(2026-11-03). 편집기로 무엇을 쓸지 고르고, PC 안에서만 도는지 시험했다(2절). 범위와 들이는 방식은 저장소 주인이 아직 정하지 않았다(8절). 정하면 결정 기록 0103으로 옮긴다.

## 1. 무엇을 하려는가

2026-11-03 의견 보내기로 들어온 제안이다. 개발 일을 하는 사람이 순서도·구성도를 그릴 때 diagrams.net(draw.io)을 많이 쓰니 이 편집기도 같이 들어가면 좋겠다는 내용이다.

이 계획은 **`.drawio` 다이어그램을 탭에서 열고, 고치고, 저장하는 편집기**를 더한다. 그림을 그리는 화면은 draw.io 본체(jgraph/drawio, Apache-2.0)를 그대로 싣는다. 새로 만드는 것은 파일 열기와 저장, 셸에 붙이기, 바깥 연결 막기, 그리고 AI 창이다. 화면에 보이는 이름은 "다이어그램"이다.

## 2. 확인한 것 (2026-11-03)

시험 도구는 `F:\ieum-scratch\drawio-probe`에 있다. draw.io v32.6.9 배포본(`draw.war`)을 풀어, 저장소의 Electron 43.7.6 창에 `file://`로 띄웠다. 창의 세션에서 `file:`·`data:`·`blob:`이 아닌 요청은 모두 막고 기록했다.

- **바깥 요청 0건.** 시작, 다이어그램 불러오기, 내보내기 세 가지, 그리고 기능 20여 개(도형 더 보기, 새 다이어그램, 템플릿, Mermaid·PlantUML 창, 그림 넣기, PNG·SVG 내보내기, 다이어그램 XML 고치기, 찾기, SQL·글에서 만들기, 개요, 레이어 등)를 실행하는 동안 막힌 요청이 하나도 없었다. 시작 인자는 `embed=1&proto=json&offline=1&stealth=1&lockdown=1&lang=ko`이다.
- **Mermaid·PlantUML 변환도 PC 안에서 된다.** `parseMermaidDiagram`, `parseMermaidImage`, `parsePlantUmlImage` 모두 바깥 요청 없이 결과를 돌려줬다. 변환기는 배포본 안의 `js/mermaid`·`js/plantuml`이다.
- **임베드 방식이 그대로 돈다.** 공식 문서는 임베드 방식을 `embed.diagrams.net`에서만 지원한다고 적지만, 부모 창과 `postMessage`(JSON)로 주고받는 방식은 PC 안 파일에서도 똑같이 돌았다. `init` → `load` → `export`(`xmlsvg`, `xmlpng`, `xml`) 순서로 확인했다. 열리는 데 1.8초 걸렸다.
- **파일이 서로 맞는다.** `xmlsvg`로 낸 SVG는 `content` 속성에 다이어그램 원본을 담고, `xmlpng`로 낸 PNG는 그림 안에 원본을 담는다. draw.io에서 그대로 다시 열 수 있는 `.drawio.svg`·`.drawio.png`가 된다. 한글 글자도 그림과 내보내기 모두에서 제대로 나왔다.
- **draw.io 자체 AI는 꺼져 있다.** `Editor.enableAi`가 `false`다. 다만 배포본 안에 OpenAI·Gemini·Claude 호출 설정(`Editor.aiConfigs`)이 들어 있으니, 설정으로도 확실히 끈다(4절).
- **새 창으로 나가려는 것은 셋.** 도움말(`resources/help_ko.html`)과 단축키 표(`shortcuts.svg`)는 PC 안 파일이고, "지원"은 GitHub 위키 주소다. 창 열기는 모두 막고, 바깥 주소는 다른 편집기와 같은 규칙으로 다룬다(4절).
- **화면 언어 21개를 모두 갖췄다.** `resources/dia_<언어>.txt`에 우리 언어가 다 있다(번체 중국어는 `dia_zh-tw.txt`).
- **크기.** 배포본을 풀면 114MB다. 개발용 원본 소스(`js/diagramly`, `js/grapheditor`), 서버용 파일(`WEB-INF`), 쓰지 않는 묶음(`integrate.min.js`, `viewer.min.js`), 클라우드 연결 화면을 빼면 68MB이고, gzip으로 묶으면 42MB다. 설치 파일은 30~40MB쯤 늘 것으로 본다. 한 번 쓰는 동안 실제로 읽힌 파일은 57개, 32.8MB였다(도형 묶음·템플릿은 열 때마다 더 읽는다).

## 3. 고른 것과 고르지 않은 것

| 후보                             | 라이선스      | 판단                                                                                                        |
| -------------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------- |
| draw.io 본체                     | Apache-2.0    | **고름.** 제안한 사람이 쓰는 편집기 그 자체이고 파일이 그대로 오간다. 관리가 활발하다(v32.6.9, 2026-10-30). |
| draw.io 데스크톱판, VS Code 확장 | GPL-3.0       | 코드를 가져오지 않는다. 설계만 참고한다. 우리 껍데기는 직접 짠다.                                           |
| maxGraph                         | Apache-2.0    | 그리기 라이브러리만 있고 편집 화면이 없다. 아직 1.0 전(v0.25.1)이다.                                        |
| Excalidraw                       | MIT           | 손그림 화이트보드라 정밀한 구성도와 쓰임이 다르다. 외부 PR #68이 따로 열려 있다(8절).                       |
| tldraw                           | 자체 라이선스 | 배포에 라이선스 키가 필요하고, 무료판은 화면에 워터마크를 띄워야 한다.                                      |

## 4. 짜임

```
apps/shell ── 탭 ── apps/diagram (뒷단: 파일 읽기·쓰기, 저장 확인, 이름 바뀜)
                       │
                       └─ 화면(React) ─ AI 창
                             │
                             └─ iframe: drawio-app://editor/index.html?embed=1&proto=json&...
                                  (draw.io 본체, 우리 다리 스크립트 하나)
```

- **새 편집기 `apps/diagram`.** 셸에 붙이는 방식은 마인드맵·EPUB 편집기와 같다. 파일을 읽고 쓰는 일은 뒷단이 하고, 화면은 draw.io와 `postMessage`로 주고받는다. draw.io가 그림의 모델을 들고 있으니 따로 엔진 패키지는 만들지 않는다. 파일 형식 판정(아래)만 작은 순수 함수로 둔다.
- **draw.io 파일은 `drawio-app://` 프로토콜로 낸다.** 실은 파일만 내고, 경로가 그 폴더 밖으로 나가지 못하게 한다. `file://`로 띄우지 않는다.
- **바깥 연결은 세 겹으로 막는다.**
  1. 시작 인자 `offline=1&stealth=1&lockdown=1`과 설정(`DRAWIO_CONFIG`)으로 클라우드 저장소, 글꼴 내려받기, 플러그인, 자체 AI를 끈다.
  2. 다이어그램 탭 전용 세션 파티션에서 `drawio-app:`·`data:`·`blob:` 밖의 요청은 모두 거절한다. 위 1이 빠뜨린 기능이 있어도 밖으로 나가지 못한다.
  3. 새 창 열기는 모두 거절한다. `http:`·`https:`·`mailto:` 링크만 마인드맵 편집기와 같은 규칙으로 기본 브라우저에서 연다.
- **다리 스크립트.** draw.io 파일은 고치지 않는다. 프로토콜이 `index.html`을 낼 때 우리 스크립트 하나를 끼운다. 이 스크립트는 두 가지만 한다. draw.io의 시작 그림(draw.io 로고)을 우리 진행 표시로 바꾸고, AI 도구가 모델을 고칠 수 있는 좁은 창구를 연다. 고친 것은 되돌리기 한 번이 되도록 draw.io 모델의 한 묶음 갱신으로 넣는다.
- **화면에서 빼는 것.** draw.io 로고와 "draw.io 정보", 바깥 사이트로 가는 도움말 항목, 클라우드 저장소 메뉴, 게시·공유 메뉴. 우리 도움말 주제로 바꾼다.

## 5. 파일

| 형식              | 열기                        | 저장                                           |
| ----------------- | --------------------------- | ---------------------------------------------- |
| `.drawio`, `.dio` | XML(압축된 다이어그램 포함) | XML. 연 파일이 압축 형식이었으면 압축으로 쓴다 |
| `.drawio.svg`     | SVG 안의 `content` 속성     | `xmlsvg` 내보내기                              |
| `.drawio.png`     | PNG 안의 원본               | `xmlpng` 내보내기                              |

- 바뀐 것이 없으면 파일을 다시 쓰지 않는다.
- 원본이 들어 있지 않은 일반 SVG·PNG는 이 편집기로 열지 않는다(이미지로 둔다).
- 내보내기: PNG, SVG, PDF. PDF는 draw.io가 인쇄 창을 띄우므로 쓰지 않고, SVG를 받아 Electron `printToPDF`로 만든다.
- 홈의 새 문서 타일과 "연결 프로그램" 등록은 8절에서 정한다.

## 6. AI 창

다른 편집기와 같은 공용 AI 창을 붙인다. 구독·키 제공자 선택, 보내기 전 판단, 가리기는 공용 부품 그대로다.

- **읽기.** 쪽 목록과, 쪽마다 도형·선의 id, 글, 스타일, 위치, 연결 관계를 짧은 표로 넘긴다. 원본 XML을 통째로 넘기지 않는다.
- **고치기 도구.** 도형·선 더하기, 고치기, 지우기, 쪽 더하기. 한 번의 도구 호출이 되돌리기 한 번이다. 하나라도 거절되면 그 호출 전체를 거절한다.
- **Mermaid로 그리기.** AI가 Mermaid 글을 쓰면 draw.io의 변환기(`parseMermaidDiagram`)가 PC 안에서 도형으로 바꿔 넣는다. 순서도·순차도·ER 같은 것을 새로 그릴 때 좌표를 하나하나 정하지 않아도 된다.
- draw.io 자체의 AI(OpenAI·Gemini·Claude 키를 받는 기능)는 끈 채로 둔다. AI는 이음오피스의 AI 창 하나로만 쓴다.

## 7. 라이선스와 상표

- **draw.io 본체**: Apache-2.0. `LICENSE`와 바꾼 점(빼낸 파일, 끼운 스크립트)을 `THIRD-PARTY-NOTICES.txt`에 적는다.
- **템플릿**(`templates/`): CC BY 4.0. 출처를 밝힌다.
- **도형·아이콘 모음**(`img/`, `shapes/`, `stencils/`): Atlassian 제품과 그 마켓 안에서 쓰지 말라는 제한이 붙어 있다. 우리와는 상관이 없지만 고지에 그대로 옮긴다. 사용자가 만든 그림에는 제한이 없다고 적혀 있다.
- **경로 자동 우회 부품**(`js/libavoid-js`): LGPL-2.1. 고치지 않고 따로 된 파일로 싣거나 뺀다(8절).
- **PlantUML 변환기**(`js/plantuml`): Apache-2.0 묶음 안에 LGPL-3.0 조각(ascii2image)이 들어 있다. 싣거나 뺀다(8절).
- **상표**: draw.io는 EU 등록 상표이고, 제휴·보증처럼 보이게 이름과 로고를 쓰지 말라고 적혀 있다. 화면 이름은 "다이어그램"이다. "draw.io 파일(.drawio)을 열고 고친다"처럼 어떤 파일을 다루는지 알리는 데만 이름을 쓴다(결정 0052). 로고는 쓰지 않는다.
- draw.io는 바깥 기여를 받지 않는다. 우리가 고칠 것이 생기면 rhwp처럼 우리 쪽에 패치로 둔다. 다만 본체 파일은 고치지 않는 것이 원칙이다(4절의 다리 스크립트).

## 8. 정할 것

1. **첫 단계의 범위.** 안: 열기·고치기·저장(5절의 세 형식), PNG·SVG·PDF 내보내기, AI 창(6절)까지. AI 창을 다음 단계로 미루면 첫 단계가 절반쯤으로 준다.
2. **draw.io 파일을 들이는 방법.** (가) 고정한 버전의 `draw.war`를 SHA-256으로 확인해 빌드 때 내려받고 캐시에 둔다. 저장소에는 버전·해시·빼낼 목록만 커밋한다. (나) 정리한 68MB를 저장소에 커밋한다. draw.io는 거의 매주 새 버전을 내므로, 올릴 때마다 수십 MB씩 저장소가 커지는 (나)보다 (가)를 권한다.
3. **PlantUML 변환기와 경로 자동 우회를 실을지.** LGPL 조각이 섞여 있다. 싣는다면 고치지 않은 파일과 원본 위치를 고지에 적는다. 빼면 그 두 기능만 메뉴에서 사라진다.
4. **외부 PR #68(Excalidraw)과의 관계.** #68에서 "새 편집기를 받을지는 결정 기록과 함께 정한다"고 답해 두었다. (가) 다이어그램만 받고 #68은 닫는다 (나) 둘 다 받는다 (다) 다이어그램을 먼저 하고 #68은 따로 정한다.
5. **Windows 등록.** EPUB처럼 "연결 프로그램"에만 올리고 기본 프로그램은 바꾸지 않는 쪽을 권한다. 홈의 새 문서 타일("다이어그램")을 둘지도 정한다.
6. **`.vsdx` 가져오기.** draw.io에 Visio 파일 가져오기(`js/vsd`)가 들어 있다. 첫 단계에서는 빼고, 다음 단계에서 PC 안에서만 도는지 따로 시험한다.

## 9. 시험

- 바깥 요청 0건 검사: 다이어그램 탭 세션에서 막힌 요청이 생기면 실패하는 E2E(2절의 시험을 옮긴 것).
- 열기·저장 왕복: 세 형식을 열어 바꾸지 않고 저장하면 파일을 쓰지 않는다. 바꿔서 저장한 파일을 다시 열면 같은 다이어그램이다.
- 다리 스크립트: AI 도구 호출 하나가 되돌리기 한 번인지, 거절된 호출이 모델을 바꾸지 않는지.
- 사람이 확인할 것: 실제 draw.io(웹·데스크톱)에서 우리가 저장한 세 형식이 열리는지, 21개 언어 화면, Mac·Linux 설치본.
