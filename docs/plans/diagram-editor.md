# 다이어그램 편집기 계획

상태: **구현됨, 사람 확인 남음**(2026-11-03). 범위와 들이는 방식은 저장소 주인이 정했다. 정한 것과 그 이유는 결정 기록 [0103](../tracking/decisions/0103-diagram-editor.md)에 있다. 사람이 확인할 것은 9절과 `docs/tracking/status.md`에, 알려진 한계는 `docs/tracking/findings.md`와 `apps/diagram/AGENTS.md`에 있다.

## 1. 무엇을 하려는가

2026-11-03 의견 보내기로 들어온 제안이다. 개발 일을 하는 사람이 순서도·구성도를 그릴 때 diagrams.net(draw.io)을 많이 쓰니 이 편집기도 같이 들어가면 좋겠다는 내용이다.

이 계획은 **draw.io 다이어그램을 탭에서 열고, 고치고, 저장하고, 내보내는 편집기**를 더한다. 그림을 그리는 화면은 draw.io 본체(jgraph/drawio, Apache-2.0)를 그대로 싣는다. 새로 만든 것은 파일 열기와 저장, 셸에 붙이기, 바깥 연결 막기, AI 창, 그리고 앱 안 MCP와 터미널 명령어의 다이어그램 도구다. 화면에 보이는 이름은 "다이어그램"이다.

## 2. 확인한 것 (2026-11-03)

시험 도구는 `F:\ieum-scratch\drawio-probe`에 있다. draw.io v32.6.9 배포본(`draw.war`)을 풀어, 저장소의 Electron 43.7.6 창에 `file://`로 띄웠다. 창의 세션에서 `file:`·`data:`·`blob:`이 아닌 요청은 모두 막고 기록했다.

- **바깥 요청 0건.** 시작, 다이어그램 불러오기, 내보내기 세 가지, 그리고 기능 20여 개(도형 더 보기, 새 다이어그램, 템플릿, Mermaid·PlantUML 창, 그림 넣기, PNG·SVG 내보내기, 다이어그램 XML 고치기, 찾기, SQL·글에서 만들기, 개요, 레이어 등)를 실행하는 동안 막힌 요청이 하나도 없었다. 시작 인자는 `embed=1&proto=json&offline=1&stealth=1&lockdown=1&lang=ko`이다.
- **Mermaid·PlantUML 변환도 PC 안에서 된다.** `parseMermaidDiagram`, `parseMermaidImage`, `parsePlantUmlImage` 모두 바깥 요청 없이 결과를 돌려줬다. 변환기는 배포본 안의 `js/mermaid`·`js/plantuml`이다.
- **ELK를 빼도 Mermaid 결과가 같은지에 대한 처음 시험은 잘못 본 것이었다.** 처음에는 `js/elk` 폴더를 빼고도 Mermaid 변환이 같다고 보았다. 그런데 시작 때 반드시 읽는 `js/extensions.min.js` 안에 ELK와 libavoid가 바이트 그대로 들어 있어, 폴더를 빼도 ELK가 실려 있었다. 그 두 부분을 잘라낸 사본(5절)으로 다시 시험했고, 편집기가 열리고 Mermaid 결과가 같았으며 바깥 요청은 0건이었다. ELK가 없으면 draw.io의 Mermaid 변환은 dagre(MIT) 배치로 돈다. 그래서 변환 결과의 배치가 draw.io 웹판과 조금 다를 수 있고, 이 차이는 받아들였다.
- **임베드 방식이 그대로 돈다.** 공식 문서는 임베드 방식을 `embed.diagrams.net`에서만 지원한다고 적지만, 부모 창과 `postMessage`(JSON)로 주고받는 방식은 PC 안 파일에서도 똑같이 돌았다. `init` → `load` → `export`(`xmlsvg`, `xmlpng`, `xml`) 순서로 확인했다. 열리는 데 1.8초 걸렸다.
- **파일이 서로 맞는다.** `xmlsvg`로 낸 SVG는 `content` 속성에 다이어그램 원본을 담고, `xmlpng`로 낸 PNG는 그림 안에 원본을 담는다. draw.io에서 그대로 다시 열 수 있는 `.drawio.svg`·`.drawio.png`가 된다. 한글 글자도 그림과 내보내기 모두에서 제대로 나왔다.
- **draw.io 자체 AI는 꺼져 있다.** `Editor.enableAi`가 `false`다. 다만 배포본 안에 OpenAI·Gemini·Claude 호출 설정(`Editor.aiConfigs`)이 들어 있으니, 설정으로도 확실히 끈다(4절).
- **새 창으로 나가려는 것은 셋.** 도움말(`resources/help_ko.html`)과 단축키 표(`shortcuts.svg`)는 PC 안 파일이고, "지원"은 GitHub 위키 주소다. 창 열기는 모두 막고, 바깥 주소는 다른 편집기와 같은 규칙으로 다룬다(4절).
- **화면 언어 21개를 모두 갖췄다.** `resources/dia_<언어>.txt`에 우리 언어가 다 있다(번체 중국어는 `dia_zh-tw.txt`).
- **크기.** 배포본을 풀면 114MB다. 개발용 원본 소스(`js/diagramly`, `js/grapheditor`), 서버용 파일(`WEB-INF`), 쓰지 않는 묶음(`integrate.min.js`, `viewer.min.js`), 클라우드 연결 화면을 빼면 68MB이고, gzip으로 묶으면 42MB다. 설치 파일은 30~40MB쯤 늘 것으로 본다. 한 번 쓰는 동안 실제로 읽힌 파일은 57개, 32.8MB였다(도형 묶음·템플릿은 열 때마다 더 읽는다).

## 3. 고른 것과 고르지 않은 것

| 후보                             | 라이선스      | 판단                                                                                                        |
| -------------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------- |
| draw.io 본체                     | Apache-2.0    | **고름.** 제안한 사람이 쓰는 편집기 그 자체이고 파일이 그대로 오간다. 관리가 활발하다(v32.6.9, 2026-10-30). |
| draw.io 데스크톱판, VS Code 확장 | GPL-3.0       | 코드를 가져오지 않는다. 우리 껍데기는 직접 짰다.                                                            |
| maxGraph                         | Apache-2.0    | 그리기 라이브러리만 있고 편집 화면이 없다. 아직 1.0 전(v0.25.1)이다.                                        |
| Excalidraw                       | MIT           | 손그림 화이트보드라 정밀한 구성도와 쓰임이 다르다. 외부 PR #68은 따로 정한다(8절).                          |
| tldraw                           | 자체 라이선스 | 배포에 라이선스 키가 필요하고, 무료판은 화면에 워터마크를 띄워야 한다.                                      |

화면은 draw.io의 것을 그대로 쓴다(저장소 주인이 골랐다). 다른 편집기처럼 우리 리본으로 감싸는 안은 일이 크고, draw.io가 바뀔 때마다 맞춰야 해서 버렸다.

## 4. 짜임

```
apps/shell ── 탭 ── apps/diagram (뒷단: 파일 읽기·쓰기, 저장 확인, 내보내기·인쇄, 앱 안 MCP 질문)
                       │
                       └─ 화면(React) ─ AI 창
                             │
                             └─ iframe: drawio-app://editor/index.html?embed=1&proto=json&...
                                  (draw.io 본체, 우리 다리 스크립트 하나)

packages/drawio-model ── 형식 판정, 원본 꺼내기, 읽기 표, 연산 검사와 기본 변경, XML 쓰기
                         (편집기 화면, 셸, 터미널 명령어, file-parse가 같이 쓴다)
```

- **새 편집기 `apps/diagram`.** 셸에 붙이는 방식은 마인드맵·EPUB 편집기와 같다. 파일을 읽고 쓰는 일은 뒷단이 하고, 화면은 draw.io와 `postMessage`로 주고받는다. 앱 안에서는 draw.io가 그림의 모델을 들고 있다.
- **새 패키지 `packages/drawio-model`.** 처음 계획은 형식 판정만 작은 함수로 두는 것이었다. 터미널 명령어와 첨부 읽기도 다이어그램을 다루게 되어, 읽기 표와 연산의 뜻을 이 패키지 한 곳에 두었다. 앱 안에서는 그 기본 변경을 draw.io 모델에 넣고, 터미널에서는 XML에 직접 쓴다. 두 길의 결과가 같다.
- **draw.io 파일은 `drawio-app://` 프로토콜로 낸다.** 실은 파일만 내고, 경로가 그 폴더 밖으로 나가지 못하게 한다. `file://`로 띄우지 않는다.
- **바깥 연결은 세 겹으로 막는다.**
  1. 시작 인자 `offline=1&stealth=1&lockdown=1`과 설정(`DRAWIO_CONFIG`)으로 클라우드 저장소, 글꼴 내려받기, 내보내기 서버, 플러그인, 자체 AI를 끈다.
  2. 다이어그램 탭 전용 지속 세션 파티션(`persist:ieum-diagram`)에서 앱의 프로토콜·`drawio-app:`·`data:`·`blob:` 밖의 요청은 모두 거절한다. 위 1이 빠뜨린 기능이 있어도 밖으로 나가지 못한다.
  3. 새 창 열기와 다른 주소로의 이동은 모두 거절한다. 사람이 누른 `http:`·`https:`·`mailto:` 링크만 마인드맵 편집기와 같은 규칙으로 기본 브라우저에서 연다.
- **CSP.** 여기에 draw.io 쪽 CSP(스크립트는 우리 프로토콜에서만, 바깥 연결 없음)가 더해진다. 자세한 것은 `docs/security.md`의 "다이어그램 탭"에 있다.
- **다리 스크립트.** draw.io 파일은 고치지 않는다. 프로토콜이 `index.html`을 낼 때 우리 스크립트 하나를 끼운다. 이 스크립트는 설정을 고정하고, 시작 그림(draw.io 로고)을 숨기고, 화면에서 뺄 동작을 숨기고, 앱이 대신할 동작(도움말, 인쇄, PNG·SVG·PDF 내보내기, 저장)과 단축키를 앱으로 보내고, AI 도구가 모델을 고칠 수 있는 좁은 창구를 연다. 고친 것은 되돌리기 한 번이 되도록 draw.io 모델의 한 묶음 갱신으로 넣는다.
- **화면에서 빼는 것.** draw.io 로고와 "draw.io 정보", 바깥 사이트로 가는 도움말·지원·의견 항목, 클라우드 저장소·게시·공유·임베드 메뉴, 플러그인, draw.io 자체 AI, PlantUML, 웹 글꼴 고르기, draw.io의 모양·테마·언어 바꾸기, 끝내기 단추. draw.io의 "도움말"은 앱 안 도움말의 다이어그램 주제를 연다.
- **언어와 테마는 앱을 따른다.** 앱이 어두우면 draw.io의 어두운 보기를 켠다. 화면의 그림 색은 바뀌지만 저장 파일, PNG, PDF, 인쇄는 두 테마에서 같다(결정 0103의 "화면 색" 예외). 앱 언어가 바뀌면 저장하지 않은 내용을 지킨 채 편집기를 다시 띄운다.

## 5. 파일과 draw.io 묶음

| 형식              | 열기                                              | 저장                                           |
| ----------------- | ------------------------------------------------- | ---------------------------------------------- |
| `.drawio`, `.dio` | XML(압축된 쪽 포함)                               | XML. 연 파일이 압축 형식이었으면 압축으로 쓴다 |
| `.drawio.svg`     | SVG 안의 `content` 속성                           | `xmlsvg` 내보내기                              |
| `.drawio.png`     | PNG 안의 원본                                     | `xmlpng` 내보내기(웹판처럼 첫 쪽 그림)         |
| `.vsdx`           | draw.io의 Visio 가져오기로 새 다이어그램을 만든다 | 하지 않는다. 첫 저장은 `.drawio`를 제안한다    |

- 바뀐 것이 없으면 파일을 다시 쓰지 않는다. 새 다이어그램의 첫 저장은 `.drawio`를 먼저 제안한다.
- 원본이 들어 있지 않은 일반 SVG·PNG는 이 편집기로 열지 않는다. 깨진 파일은 탭에 열지 않고 이유를 보인다.
- 내보내기: PNG, SVG, PDF. 내보내기 창에서 모든 쪽과 지금 쪽만을 고른다. PDF와 인쇄는 draw.io의 인쇄 창을 쓰지 않고, 쪽마다 한 장인 문서를 앱이 Electron으로 만든다.
- 복구 사본과 자동 저장은 다른 편집기와 같다(결정 0061, 0069).
- **draw.io 묶음은 빌드 때 내려받는다**(저장소 주인이 골랐다). 저장소에는 판, 주소, SHA-256, 뺄 목록, 잘라내기, 라이선스 목록만 둔다. 절차와 목록은 `vendor/drawio/README.md`, 판 올리기는 `docs/operations.md`에 있다.
- **허용 목록 밖 부품은 싣지 않는다**(저장소 주인이 골랐다). PlantUML 변환기, libavoid, ELK, Glyphicons 공유 아이콘을 뺐다. 시작 때 반드시 읽는 `js/extensions.min.js`만은 그 안에 든 ELK·libavoid 부분을 독립 파일과 바이트로 맞춰 찾아 잘라낸 사본을 싣는다(저장소 주인 승인, 2026-11-03). 찾지 못하면 빌드가 실패하고, 결과 해시를 고정해 둔다.

## 6. AI 창

다른 편집기와 같은 공용 AI 창을 붙였다. 구독·키 제공자 선택, 보내기 전 판단, 오류 글, 첨부·검색은 공용 부품 그대로다. 다이어그램에는 가리기 표시가 없다.

- **읽기.** 쪽 목록과, 쪽마다 도형·선의 id, 글, 도형 이름, 위치, 연결 관계를 짧은 표로 넘긴다. 사람이 고르고 있는 도형의 id도 함께 간다. 원본 XML을 통째로 넘기지 않고, 그림은 보내지 않는다(저장소 주인이 골랐다).
- **고치기 도구.** 도형·선 더하기, 고치기, 지우기, 쪽 더하기·이름 바꾸기·지우기. 한 번의 도구 호출이 되돌리기 한 번이다. 하나라도 거절되면 그 호출 전체를 거절한다.
- **Mermaid로 그리기.** AI가 Mermaid 글을 쓰면 draw.io의 변환기(`parseMermaidDiagram`)가 PC 안에서 도형으로 바꿔 넣는다. 순서도·순차도·ER 같은 것을 새로 그릴 때 좌표를 하나하나 정하지 않아도 된다. 변환에 실패하면 그 까닭을 AI에게 돌려준다.
- draw.io 자체의 AI(OpenAI·Gemini·Claude 키를 받는 기능)는 끈 채로 둔다. AI는 이음오피스의 AI 창 하나로만 쓴다.

## 7. 다른 곳에서 다이어그램 다루기

- **첨부와 색인.** 다른 편집기 AI 창의 첨부, `@문서`, 홈의 파일 검색·지식 자료 색인이 `.drawio`·`.dio`·`.drawio.svg`·`.drawio.png`를 6절의 읽기 표 글로 읽는다. `.vsdx`는 읽지 않는다.
- **앱 안 MCP**(설정 → 연동). 열린 다이어그램의 목록·읽기·저장·닫기와 고치기 도구(`read_diagram`, `apply_diagram_ops`)를 둔다. 규칙은 AI 창과 같다(저장소 주인이 골랐다).
- **터미널 명령어와 명령어 쪽 MCP.** `diagram read`, `diagram apply`, `create --type drawio`(Mermaid로 새로 만들기 포함), `convert`(PNG·SVG·PDF), `guide diagram`. `.drawio`·`.dio`를 고칠 때는 앱 없이 하고, 고치지 않은 쪽은 원래 바이트 그대로 둔다. 그림 형식, Mermaid, 내보내기는 앱을 창 없이 띄워 한다. 약속은 `docs/contracts.md`와 `docs/headless-pdf-export.md`에 있다.
- **에이전트 모드**(결정 0032)의 세션 MCP 서버에는 다이어그램 도구를 더하지 않았다. 그 서버의 `open_documents`는 지금처럼 열린 탭을 모두 보이므로 다이어그램 탭도 목록에 나오고 글로 읽힌다.

- **템플릿**(`templates/`): CC BY 4.0. 출처를 밝힌다.
- **도형·아이콘 모음**(`img/`, `shapes/`, `stencils/`): Atlassian 제품과 그 마켓 안에서 쓰지 말라는 제한이 붙어 있다. 우리와는 상관이 없지만 고지에 그대로 옮긴다. 사용자가 만든 그림에는 제한이 없다고 적혀 있다.
- **상표**: draw.io는 EU 등록 상표이고, 제휴·보증처럼 보이게 이름과 로고를 쓰지 말라고 적혀 있다. 화면 이름은 "다이어그램"이다. "draw.io 파일(.drawio)을 열고 고친다"처럼 어떤 파일을 다루는지 알리는 데만 이름을 쓴다(결정 0052). 로고는 쓰지 않는다.
- draw.io는 바깥 기여를 받지 않는다. 우리가 고칠 것이 생기면 다리 스크립트와 설정으로 한다. 본체 파일은 고치지 않는다.
- **Windows 등록**(저장소 주인이 골랐다): `.drawio`·`.dio`는 다른 문서 형식처럼 기본 프로그램 자리에도 등록한다. `.vsdx`는 "연결 프로그램"에만 올린다. 홈에 "다이어그램" 새 문서 타일을 둔다.
- **Visio 가져오기**(저장소 주인이 골랐다): 이번에 넣었다. draw.io의 가져오기가 PC 안에서 바꾸고, 바꾸지 못한 그림이 있으면 그 수를 알린다. 예전 형식 `.vsd`·`.vss`는 열지 않는다.
- **외부 PR #68(Excalidraw)**: 저장소 주인이 따로 정하기로 했다. 이 작업에서는 그 PR에 아무것도 하지 않았다.

## 9. 시험과 사람이 확인할 것

- 연산 모듈 단위 시험: 모든 연산과 거절 이유, 압축된 쪽 읽기·쓰기, 고치지 않은 쪽의 바이트 보존, 세 형식에서 원본 꺼내기(`packages/drawio-model`).
- 번들 검사: 싣는 파일이 라이선스 목록에 다 있고 모두 허용 목록 안이며, 뺄 목록의 파일이 하나도 실리지 않는다(`npm run licenses`의 `tools/check-drawio-bundle.mjs`).
- 편집기 단위 시험: 프로토콜·CSP, 요청 허용·이동·새 창·링크, 메시지 출처, 기본 변경의 한 번 되돌리기, AI 도구, Visio 가져오기(`apps/diagram/tests`).
- 터미널: `diagram read`·`apply`·`create`·`convert`의 성공·실패 경로와 `app_unavailable`, 탭에 열린 파일 거절(`packages/cli/tests`).
- E2E(빌드한 앱): 열기·편집·저장·내보내기·Mermaid 넣기 동안 바깥 요청 0건, 바꾸지 않은 저장은 파일을 쓰지 않음, 밝은·어두운 테마의 저장 파일·PNG·PDF가 같음, AI 도구 호출 하나가 되돌리기 한 번(`e2e/diagram-*.spec.ts`).
- 사람이 확인할 것: 실제 draw.io(웹·데스크톱)에서 우리가 저장한 네 형식이 열리는지, 실제 Visio로 만든 `.vsdx`, 21개 언어 화면과 도움말, Mac·Linux 설치본과 파일 연결, 실제 구독으로 AI 창의 읽기·고치기·Mermaid 그리기. 목록은 `docs/tracking/status.md`에 있다.
