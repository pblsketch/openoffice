# 로컬 LLM 연결 리서치와 계획 — 모델은 사용자가 고른다

상태: **조사·계획**(2026-10-25). 아직 코드를 바꾸지 않았다. 이 문서는 "지금 무엇이 되고, 무엇이 막히며, 공공기관 폐쇄망에 내놓으려면 무엇을 더해야 하는가"를 먼저 정리한 것이다.

## 0. 한 장 요약

- **지금도 데모는 된다.** 설정 → AI의 `Custom` 제공자에 `http://127.0.0.1:11434/v1`과 Ollama 모델 이름을 넣으면 대화와 도구 호출까지 동작한다. 여러 엔드포인트, 모델 목록 자동 조회, 연결 테스트, 모델 선택기도 이미 있다.
- **그런데 "공공기관에 납품할 수 있는 로컬 AI"는 아직 아니다.** 문맥 길이(일반 사무용 PC에서 Ollama 기본 4k), 도구 스키마 크기(워드 도구만 약 3.4만 자), 60초 연결 제한, 오프라인 모드 부재, 설치 파일 미서명, 감사·표시 의무 같은 것들이 그대로 걸린다.
- **가장 큰 기술적 제약은 모델 성능이 아니라 문맥과 도구다.** 워드 AI는 문서를 고치려면 수십 개 도구와 긴 지시문을 매 턴 보낸다. 이걸 작은 모델과 4k 문맥에 넣으면 모델이 도구 이름을 틀리거나 문서를 엉뚱하게 고친다. 그래서 앱은 **모델을 고르는 대신, 그 모델이 도구를 쓰는지·문맥이 얼마인지·실제로 얼마나 빠른지 확인해서 보여 주고**, 사용자가 고르게 해야 한다.
- **권고는 "Ollama를 앱에 넣자"가 아니라 "모델을 가리지 않는 로컬 모드"를 만들자는 것이다.** ① 개인 PC의 Ollama, ② 기관 GPU 서버의 vLLM/LM Studio, ③ 완전 폐쇄망 번들. 셋 다 같은 `Custom` 연결 위에 얹고, 오프라인 스위치·문맥 경고·능력(도구/비전) 표시·텍스트 모드를 더한다.
- **모델은 앱이 고르지 않는다.** 사용자가 자기 환경에 맞는 모델을 고른다. 앱은 연결·탐색·능력 확인·경고만 하고, 특정 모델을 추천하거나 기본값으로 넣지 않는다. 모델을 설치 파일에 넣지도 않는다. 라이선스와 요구 사양은 사용자가 판단할 수 있게 보여 준다.
- **예상 일정.** 혼자 개발한다면 데모 확인 3~~5일, 파일럿 가능한 1차 6~~8주, 기관 납품·인증까지 3~6개월. 인증과 서명은 코드 밖의 일이 더 오래 걸린다.

## 1. 무엇을 하려는가

공공기관 중에는 아직 업무망과 인터넷망이 분리된 곳이 많다. 2026년 5월 국가 망 보안체계(N2SF)로 제도가 바뀌었지만, "모든 기관이 즉시 망분리를 없앴다"는 뜻이 아니다. 기밀(C)·민감(S) 등급과 기존 폐쇄망은 그대로 남아 있고, 그 안에서는 외부 AI API를 부를 수 없다.

이음오피스는 이미 Claude Code·Codex 구독, 키 제공자, 사용자 지정 OpenAI 호환 엔드포인트를 지원한다. 여기에 **기관 안에서 돌아가는 모델**을 같은 방식으로 붙이면, 문서가 PC 밖으로 나가지 않으면서 AI로 문서를 고칠 수 있다. 이 계획은 그 연결을 "설정에 주소 넣는 기능"에서 "공공기관이 검토하고 설치할 수 있는 모드"로 끌어올리는 일을 다룬다.

이 계획이 지키는 것은 하나다. **앱은 모델을 고르지 않는다.** 사용자가 자기 PC·서버·문서에 맞는 모델을 고르고, 앱은 그 선택이 실제로 동작하는지 확인할 수 있는 환경을 만든다.

- 서버 종류(Ollama, LM Studio, vLLM, llama.cpp 등)만 프리셋으로 안다. 모델 목록은 서버가 알려 주는 것을 보여 준다.
- 모델의 능력(도구·비전·문맥)은 서버 메타데이터, 사용자 설정, 실제 테스트로 확인한다. 모르면 "확인 필요"로 두고, 앱이 이름만 보고 추측하지 않는다.
- 어떤 OpenAI 호환 서버든 주소와 키(있으면)로 연결할 수 있다. 특정 회사·특정 모델에 묶지 않는다.
- 모델이 도구를 못 쓰면 편집 기능을 약속하지 않고 "글만" 모드로 내려간다. 이 판단도 사용자가 덮어쓸 수 있다.

## 2. 지금 코드로 되는 것

### 2.1 연결

- `Custom` 제공자는 OpenAI 호환 `POST {baseUrl}/chat/completions`를 쓴다(`packages/ai-provider/src/protocols/openai-compatible.ts`). Ollama, LM Studio, vLLM, llama.cpp server가 모두 이 규격을 제공한다.
- API 키는 선택이다. `isKeyProviderConfigured`는 `baseUrl`과 모델만 있으면 연결된 것으로 본다(`provider-selection.ts`). Ollama처럼 키가 없는 서버를 그대로 쓸 수 있다.
- 엔드포인트를 여러 개 저장하고 이름을 붙일 수 있다(`custom-endpoints.ts`). 주소를 바꾸면 그 주소의 모델 목록을 다시 읽고, 목록은 저장된다(`SettingsModal.tsx`).
- 연결 테스트 버튼이 있다. 테스트는 실제 모델에 한 번 요청한다.

### 2.2 모델 목록

- `GET {baseUrl}/models`를 읽어 모델 id를 가져온다(`custom-models.ts`). Ollama의 `/v1/models`, LM Studio의 `/v1/models`가 여기 해당한다.
- 목록은 설정 화면의 모델 상자와 편집기 AI 창의 모델 선택기에 접힌다. 사용자가 직접 친 모델 id는 목록 맨 위에 고정된다.
- 모델 선택기는 `로컬 Ollama / 모델 이름`처럼 엔드포인트별 그룹으로 보여 준다(`packages/ui/src/ai-model-picker-options.ts`). 스크린샷의 "Codex 구독 / 로컬 Ollama" 구조와 같은 뼈대다.

### 2.3 대화와 도구

- 스트리밍, 도구 호출, 도구 결과, 사용량, 중단, 재시도는 이미 한 계약으로 묶여 있다(`stream.ts`, `agent-core/src/loop.ts`).
- 로컬 서버의 특이한 동작도 일부 반영되어 있다. 예를 들어 도구 이름을 매 조각마다 다시 보내는 서버를 위해 이름이 늘어나는 조각을 이어 붙이는 처리가 들어 있다(`openai-compatible.ts`).
- 워드·PPT·엑셀·PDF·한글 AI는 모두 이 루프 위에서 돈다. 한글은 표·누름틀·서식까지 도구로 다룬다.

### 2.4 그래서 오늘 해볼 수 있는 데모

1. 인터넷이 되는 PC에 Ollama를 설치한다.
2. `ollama pull <모델>`로 사용할 모델을 받는다. 예: `ollama pull gemma4:12b`. 어떤 모델이든 좋다. 도구 호출을 지원하는 모델이면 더 많은 기능을 시험할 수 있다.
3. Ollama가 4k 문맥으로 뜨지 않도록 `OLLAMA_CONTEXT_LENGTH=32768`을 설정하고 Ollama를 다시 시작한다. (Windows는 시스템 환경 변수 또는 Ollama 앱 설정)
4. 이음오피스 설정 → AI → 고급 → `Custom`에서 엔드포인트를 추가한다.
   - 이름: `로컬 Ollama`
   - 주소: `http://127.0.0.1:11434/v1`
   - 모델: 받은 모델 이름
   - API 키: 비움
5. "연결 테스트"를 누르고, 편집기 AI 창의 모델 선택기에서 `로컬 Ollama`를 고른다.
6. "이 문단을 다듬어 줘"처럼 도구가 필요한 요청을 해본다. 도구 호출이 실패하면 다른 모델을 고르거나, 아래의 "텍스트 모드"가 필요하다는 신호다.

이 데모는 **폐쇄망 설치 절차가 아니다.** 모델을 인터넷에서 받고, Ollama를 사용자가 직접 설치하며, 앱은 여전히 업데이트를 확인하고 검색 도구를 제공한다. 기관에 내놓으려면 3장의 빈틈을 메워야 한다.

### 3.1 문맥이 왜 이렇게 중요한가

워드 AI의 도구 정의(`apps/docs/src/renderer/ai/tools.ts`의 `AGENT_TOOLS`)는 약 3만 4천 자다. 여기에 시스템 지시문, 문서 뼈대, 대화, 첨부가 더해진다. 한국어는 대략 1~2자에 1토큰이므로, 도구와 지시문만으로 2만 토큰 안팎이 될 수 있다.

- 일반 사무용 PC(24GB 미만 VRAM)에서 Ollama의 기본 문맥은 4k다. 앱 설정이나 `OLLAMA_CONTEXT_LENGTH`로 바꾸지 않으면 그대로다.
- 32k로 올려도 긴 문서와 여러 턴이 쌓이면 금방 넘친다.
- 넘치면 Ollama는 조용히 앞부분을 자른다. 모델은 도구 설명을 잃고, 사용자는 "왜 갑자기 엉뚱한 답을 하나"라고 느낀다.

그래서 로컬 모드에서는 **도구를 줄이는 것**이 문맥을 늘리는 것보다 먼저다. 예를 들어 워드에서 "문단 다듬기"에 필요한 도구는 `read_document`, `replace_text`, `apply_format` 정도다. 표·각주·스타일 도구는 그 요청에 필요하지 않다.

이 판단을 앱이 대신하지 않는다. 앱은 "이 모델의 문맥은 8k이고, 이 요청은 도구를 다 넣으면 20k다"를 보여 주고, 사용자가 모델을 바꾸거나 간단 도구 모드를 고르게 한다.

## 4. 정책·시장 배경

### 4.1 N2SF: 망분리는 "폐지"가 아니라 "등급별"

2026년 5월 1일 국가 사이버보안 기본지침이 개정되어, 업무망과 인터넷망을 획일적으로 나누던 제40조가 삭제되고 국가 망 보안체계(N2SF)가 들어갔다. 정보를 기밀(C)·민감(S)·공개(O)로 나누고, 등급에 맞춰 통제를 달리한다.

중요한 것은 **망분리가 즉시 사라진 것이 아니라는 점**이다. 기관은 등급별 보안대책을 보고 기존 망분리를 유지할 수도, 일부 완화할 수도 있다. 기밀·민감 등급은 여전히 외부 클라우드로 보내기 어렵다. 폐쇄망과 VDI 환경도 남아 있다.

- 공개 등급: 인터넷·클라우드 활용 여지가 커졌다.
- 민감 등급: N2SF 통제를 갖춘 클라우드도 가능해졌지만, 여전히 까다롭다.
- 기밀 등급: 내부 처리 원칙.

따라서 로컬 LLM의 시장은 "망분리 때문에 아무것도 못 하는 곳"이 아니라, **"민감·기밀 데이터를 다루면서 AI를 쓰고 싶은 곳"**이다. 공개 등급만 다루는 부서는 클라우드 AI로도 충분할 수 있다. 이 구분이 영업과 제품 모두에 중요하다.

제안서에서는 "망분리"보다 "폐쇄망·내부망 AI"라고 쓰는 편이 안전하다. 2026년 제도 용어는 N2SF지만, 현장 담당자는 여전히 망분리라고 말하고, 기관마다 전환 속도가 다르다.

### 4.2 국정원 AI보안 가이드북(2025-12)

국가·공공기관 AI보안 가이드북은 15개 위협과 30개 보안대책, 57개 체크리스트를 제시한다. AI 시스템을 세 가지로 나눈다.

1. 내부망 전용 AI 시스템
2. 내부업무용 AI 시스템의 외부망 연계
3. 대민서비스용 AI 시스템의 내부망 연계

로컬 LLM은 1번이다. 핵심은 데이터 등급에 맞는 사용, 최소 권한, 민감 명령 승인, 로깅·모니터링, 입출력 필터링, 모델 가중치 보호, 비상 정지, 설명 가능성, 요청 속도 제한이다.

이음오피스가 이미 가진 것과 연결하면:

- 최소 권한: AI는 열린 문서와 첨부만 본다. 프로젝트 폴더 밖 파일은 읽지 않는다(에이전트 모드는 별도 규칙).
- 민감 명령 승인: 문서 변경은 도구 하나가 실행 취소 한 단계로 묶인다. 사람이 멈추고 되돌릴 수 있다.
- 비상 정지: AI 창의 중단 버튼이 스트림과 자식 프로세스를 끝낸다.
- 설명 가능성: 도구 카드에 무엇을 했는지 남는다.
- 부족한 것: 감사 로그, 입출력 필터, 모델 가중치 무결성 확인, 요청 속도 제한.

### 4.3 AI 기본법(2026-01-22 시행)

생성형 AI 사업자는 ① AI 활용 사실을 미리 고지하고 ② 생성물에 AI 생성 사실을 표시해야 한다. 텍스트는 문서 머리말이나 파일 메타데이터로 표시할 수 있다. 내부 업무용처럼 외부 유통이 없는 경우에는 의무의 전부 또는 일부가 적용되지 않을 수 있지만, 공공기관 문서는 외부로 나가는 일이 많다.

이음오피스는 "AI가 쓴 글"을 문서에 표시하는 기능이 없다. 로컬 모드와 함께 **문서 메타데이터에 `AI 생성` 표시를 남기는 선택지**를 넣는 것이 안전하다. docx·pptx·xlsx·HWP의 코어 속성에 넣고, 필요하면 머리말/꼬리말에 한 줄을 넣는다.

### 4.4 공공 AI법과 범정부 AI 공통기반(2026-08-28 시행)

「인공지능 및 데이터 기반 행정 활성화에 관한 법률」은 공공기관이 AI 서비스를 구축할 때 범정부 AI 공통기반을 우선 활용하도록 한다. 행안부·NIA의 「공공부문 AI 도입·활용 가이드」는 기획→예산→계약→구축→운영 5단계와, 기관 데이터를 붙이는 네 가지 방식을 제시한다.

이 조항이 "로컬 LLM은 안 된다"는 뜻은 아니다. 공통기반은 공용 AI 자원이고, 내부망·폐쇄망·민감 데이터는 여전히 기관 자체 구축으로만 처리할 수 있는 경우가 남는다. 다만 공공기관 영업에서는 "왜 공통기반을 안 쓰고 자체 구축하나"라는 질문이 반드시 나온다. 답은 명확해야 한다.

- 기밀·민감 데이터가 외부로 나갈 수 없다.
- 문서 편집은 지연이 짧아야 하고, 오프라인에서도 동작해야 한다.
- 기관이 모델과 데이터를 직접 통제해야 한다.
- 공통기반은 범용 AI 서비스에 가깝고, 문서 편집기의 도구 호출 통합은 현재로선 기관별 구현이 필요하다.

반대로 공통기반이 OpenAI 호환 API를 제공한다면 같은 `Custom` 경로로 연결할 수 있다. 로컬 모드와 공통기반은 배타적이지 않다. 나중에 "기관 AI 서버" 프로필 하나로 둘 다 받는 구조가 좋다.

### 4.5 조달·인증

- **GS 인증(소프트웨어 품질인증)**: 공공기관 직접구매·수의계약·우선구매와 연결된다. 한컴오피스 AI 패키지는 GS 1등급을 받았다. 이음오피스는 아직 없다. 초기에는 무료 배포·지원 계약으로 들어가고, 기관 요구가 있으면 GS를 검토한다.
- **나라장터/디지털서비스몰/혁신장터**: SaaS는 디지털서비스 전문계약, 패키지는 일반 조달. 로컬 설치는 일반 조달 또는 기관 직접 구매에 가깝다.
- **보안성 검토**: 기관 정보보안 부서가 소스·SBOM·취약점 대응·서명을 본다. 설치 파일 서명이 없으면 여기서 막힌다.
- **유지보수**: 공공기관은 "누가 패치해 주나"를 묻는다. 무료 오픈소스만으로는 불안해한다. 지원 계약이나 파트너가 필요하다.

## 6. 모델은 사용자가 고른다

### 6.1 앱이 하지 않는 것

- **특정 모델을 추천하거나 기본값으로 넣지 않는다.** "이 모델을 쓰세요"라는 화면도, 모델 순위도 만들지 않는다. 사용자가 자기 PC·서버·문서에 맞는 모델을 고른다.
- **모델 이름만 보고 도구 지원을 단정하지 않는다.** 서버가 알려 주면 그 값을 쓰고, 아니면 사용자가 확인한 값을 쓴다. 추정이 필요하면 "추정"이라고 표시하고 수정할 수 있게 한다.
- **모델을 설치 파일에 넣지 않는다.** "검증된 모델" 화이트리스트를 기본으로 두지 않는다. 기관 관리자가 원할 때만 허용 목록을 켤 수 있게 한다.
- **모델 다운로드·설치·업데이트를 앱이 대신하지 않는다.** 서버(Ollama 등)의 몫이고, 앱은 이미 있는 모델을 보여 준다. "모델 받기" 버튼을 만들어 프로그램을 실행하는 일은 하지 않는다.
- **모델별 벤치마크를 제품의 선택 기준으로 쓰지 않는다.** 필요한 것은 "이 모델이 내 문서 작업에 되는가"이지 "우리 순위 1위"가 아니다.
- **로컬 모델을 `auto`로 자동 선택하지 않는다.** 사용자가 명시적으로 고른 경우에만 그 모델로 요청한다. 기존 `auto`가 구독만 고르는 규칙과 같다.

### 6.2 앱이 보여 주는 것

- 서버가 알려 주는 값: 모델 id, 크기, 양자화, 문맥, `capabilities`(tools/vision/thinking).
- 사용자가 직접 확인하거나 덮어쓸 수 있는 값: 문맥, 도구 지원, 비전 지원, 최대 출력, 샘플링 값.
- 실제 측정값: 연결 테스트의 대화·도구 호출 성공 여부, 첫 토큰까지 걸린 시간, 가능하면 생성 속도.
- 라이선스: 모델 카드 주소나 라이선스 이름을 사용자가 적을 수 있게 한다. 앱이 라이선스를 판단하거나 대신 동의하지 않는다.

### 6.3 참고용 예시(권장 아님)

2026-10 기준 공개 자료를 정리한 예시다. 앱은 이 표를 기본값으로 쓰지 않고, 모델을 고르는 화면에 순위로 표시하지도 않는다.

| 모델            | 라이선스          | 크기(가중치 / Ollama 태그) | 문맥 | 도구 | 메모                                                                      |
| --------------- | ----------------- | -------------------------- | ---- | ---- | ------------------------------------------------------------------------- |
| Gemma 4 E2B     | Apache-2.0        | 0.8GB / 4~7GB              | 128k | O    | 8GB 이하 PC에서 대화·요약을 시도하는 예                                   |
| Gemma 4 E4B     | Apache-2.0        | 2.3GB / 6~9GB              | 128k | O    | 16GB PC에서 간단한 도구 호출을 시도하는 예                                |
| Gemma 4 12B     | Apache-2.0        | 7.6GB / 7.2GB(QAT)         | 256k | O    | 도구 호출 품질이 E4B보다 나은 예. 전체 도구에는 32k 문맥이 필요할 수 있음 |
| Gemma 4 26B A4B | Apache-2.0        | 16.2GB                     | 256k | O    | 24GB GPU/32GB RAM 서버 예                                                 |
| Gemma 4 31B     | Apache-2.0        | 19.2GB                     | 256k | O    | 24GB GPU 서버 예                                                          |
| Qwen3.5-4B      | Apache-2.0        | ~2.5GB                     | 262k | O    | 작은 모델 예                                                              |
| Qwen3.5-9B      | Apache-2.0        | ~5.5GB                     | 262k | O    | 16GB/8GB GPU 예                                                           |
| Qwen3.8-27B     | Apache-2.0        | 16.5GB                     | 262k | O    | 24GB GPU 서버 예                                                          |
| Kanana-2 3B     | KananaOpenLicense | ~2GB                       | 32k  | O    | 국내 특화 예. 라이선스 확인 필요                                          |
| EXAONE 4.0/4.5  | **NC(비상업)**    | 7~32B                      | -    | O    | 상업 배포 금지                                                            |

Gemma 4의 E2B/E4B는 "effective" 파라미터 모델이라 가중치 크기와 Ollama가 실제로 내려받는 태그 크기가 다르다. E4B는 모델 카드 기준 2.3GB지만 Ollama 태그는 6~9GB다. 메모리 계획은 태그 크기로 잡아야 한다.

Gemma 4의 도구 호출 벤치마크(τ2 평균, 제조사 발표)는 E4B 42.2, 12B 69.0, 26B 68.2, 31B 76.9다. 참고용 수치이며, 앱이 이 값으로 모델을 고르지는 않는다.

### 6.4 라이선스는 사용자 책임

- **EXAONE 4.x는 비상업(NC) 라이선스다.** 연구·평가에는 써도, 별도 상업 라이선스 없이 이음오피스에 넣어 기관에 배포하면 안 된다. 앱은 이 사실을 안내할 수 있지만, 모델을 자동으로 고르거나 배포하지 않는다.
- **Kanana-2 3B/1.3B는 KananaOpenLicense다.** Apache-2.0이 아니다. 상업 이용 조항을 확인하고, 재배포·API 제공 조건을 지켜야 한다.
- **Llama는 커뮤니티 라이선스**다. 대규모 MAU 제한과 명칭 표시 조건이 있다.
- **모델을 설치 파일에 넣지 않는다.** 앱은 Apache-2.0이지만 모델은 별도 라이선스다. 기관이 직접 받고, 앱은 사용자가 적은 라이선스 정보와 SHA256을 보여 줄 뿐이다.

## 7. 하드웨어와 속도

아래는 특정 모델을 고르기 위한 표가 아니라, 사용자가 자기 환경을 가늠할 수 있게 하는 **참고 예시**다. 앱은 이 표를 기본값으로 쓰지 않고, 사용자가 고른 모델의 실제 측정값을 보여 준다. 수치는 추정이므로 0단계에서 실측한다.

| 환경                | 예시 모델       | 문맥   | 첫 응답  | 생성 속도   | 대략 되는 일                    |
| ------------------- | --------------- | ------ | -------- | ----------- | ------------------------------- |
| 8GB RAM, CPU        | E2B(태그 4~7GB) | 4~8k   | 30초~2분 | 5~12 tok/s  | 대화, 요약, 짧은 글             |
| 16GB RAM, CPU       | E4B(태그 6~9GB) | 8~16k  | 1~3분    | 4~8 tok/s   | 글 제안, 간단한 도구 호출(느림) |
| 16GB RAM, CPU       | 12B(태그 7.2GB) | 8~16k  | 3~8분    | 2~4 tok/s   | 도구 편집은 어려움              |
| 16GB RAM + 8GB GPU  | 12B q4          | 16~32k | 20~60초  | 15~30 tok/s | 도구 편집 시도 가능             |
| 32GB RAM + 24GB GPU | 26B/31B q4      | 32k    | 30~90초  | 10~25 tok/s | 도구 편집, 다중 작업            |
| 48GB+ GPU 서버      | 31B/70B         | 32~64k | 1~5초    | 30~60 tok/s | 여러 명 동시 사용               |

핵심은 **첫 토큰까지의 시간**이다. CPU에서 큰 모델에 2만 토큰 프롬프트를 넣으면 prefill만 몇 분 걸린다. 앱의 현재 연결 제한 60초로는 실패한다. 반대로 8k 프롬프트에 작은 모델이면 1분 안팎으로 들어올 수 있다. 그래서 "도구를 줄여 프롬프트를 줄이는 일"이 성능 개선과 같은 효과를 낸다.

앱은 "이 환경에서는 이 모델"이라고 정하지 않는다. 대신 연결 테스트에서 첫 토큰 시간과 도구 호출 성공 여부를 재서 보여 주고, 사용자가 모델·문맥·도구를 바꿔 가며 자기 환경에 맞는 조합을 찾게 한다.

## 8. 설계

### 8.1 원칙

1. **새 제공자 계층을 만들지 않는다.** 기존 `Custom` OpenAI 호환 경로를 그대로 쓴다. 새 프로토콜은 유지비가 크다.
2. **모델을 앱에 넣지 않는다.** 실행기(Ollama/vLLM)와 모델은 기관이 준비한다.
3. **자동으로 다른 길로 넘어가지 않는다.** 로컬이 막히면 클라우드로 몰래 보내지 않는다. 기존 원칙 그대로다.
4. **오프라인은 화면이 아니라 뒷단에서 강제한다.** 렌더러가 실수해도 요청이 나가지 않아야 한다.
5. **문서 편집과 글 제안을 구분한다.** 도구를 못 쓰는 모델에는 편집 기능을 약속하지 않는다.
6. **모델 이름을 코드에 넣지 않는다.** 프리셋은 서버 종류(Ollama/LM Studio/vLLM)일 뿐, 모델 목록이 아니다. 알려진 모델 표가 필요하면 참고용으로만 두고 사용자가 수정할 수 있게 한다.
7. **대화 경로는 OpenAI 호환 하나로 통일한다.** 대부분의 로컬 서버가 이 규격을 제공한다. 예외는 탐색용 Ollama 네이티브 API(`/api/tags`, `/api/show`, `/api/ps`)뿐이고, 대화는 `/v1/chat/completions`로 보낸다. OpenAI 호환을 제공하지 않는 서버는 1차 범위 밖이며, 필요하면 서버 종류 단위의 어댑터를 더한다. 모델별 어댑터는 만들지 않는다.
8. **모델별 예외는 설정으로.** 서버가 보내는 신호로 처리할 수 없는 quirks(도구 이름 재전송, reasoning echo 등)는 모델 이름 분기 대신 모델 프로필의 옵션으로 둔다. 코드에 특정 모델 이름을 넣지 않는다.

### 8.2 화면

설정 → AI 맨 위에 "로컬 AI" 카드를 둔다. 스크린샷의 구조를 따른다. 여러 서버를 동시에 등록하고, 편집기 AI 창에서 요청마다 다른 서버·모델을 고를 수 있다.

- 서버 목록: 이름, 주소, 상태(연결됨/꺼짐/오류), 모델 수.
- "서버 추가": Ollama(기본 `http://127.0.0.1:11434`), LM Studio(`http://127.0.0.1:1234`), vLLM(주소 입력), 그 밖의 OpenAI 호환 서버(직접 주소). 프리셋은 편의일 뿐이고, 어떤 서버든 주소로 연결할 수 있다.
- 연결 테스트: ① 서버 응답 ② 모델 존재 ③ 대화 1회 ④ 도구 호출 1회. 네 개를 각각 통과/실패로 보여 주고, 테스트에도 로컬 시간 제한을 쓴다.
- 모델 목록: 이름, 파라미터, 양자화, 크기, 문맥, 도구/비전 배지. "추천" 배지는 붙이지 않고 `확인됨/확인 안 됨/사용자 설정`만 보여 준다.
- 첫 응답 제한: 기본 5분, 1~10분.
- "이 모델로 문서 편집": 확인된 도구 지원이 없으면 기본적으로 비활성으로 두고 이유를 표시하되, 고급 설정에서 사용자가 강제로 켤 수 있다.

편집기 AI 창의 모델 선택기는 지금처럼 엔드포인트별 그룹을 쓰되, 모델 이름 옆에 `도구`/`글만` 배지를 붙인다. 스크린샷의 low/medium/high는 2단계에서 "빠르게/깊게"(thinking on/off)로 붙일 수 있다.

### 8.3 연결과 탐색

- Ollama 프리셋은 주소를 `http://127.0.0.1:11434/v1`로 저장한다. 사용자가 `/v1` 없이 넣어도 보정한다. 지금은 `/v1`을 빼면 `/chat/completions`로 가서 404가 난다.
- Ollama면 `/api/tags`를 읽어 모델별 `size`, `details.parameter_size`, `details.quantization_level`을 얻는다. `/api/tags`는 `/v1`을 뗀 뿌리 주소(`http://127.0.0.1:11434`)로 부른다.
- 모델을 고르면 `/api/show`로 `capabilities`(completion, tools, vision, thinking)와 `model_info.<arch>.context_length`를 읽는다.
- `/api/ps`로 지금 로드된 모델의 실제 `context_length`를 확인할 수 있다. 로드되지 않았으면 "기본 4k일 수 있음" 경고를 띄운다.
- LM Studio/vLLM은 `/v1/models`만 읽고 능력을 알려 주지 않을 수 있다. 그때는 앱이 모델 이름으로 단정하지 않고, "확인 필요"로 두고 사용자가 테스트하거나 직접 설정하게 한다. 참고 표를 쓰더라도 "추정"이라고 표시하고 수정할 수 있게 한다.
- 모델 목록은 저장하되, 서버 주소가 바뀌면 이전 목록을 지운다(지금 동작과 같다).

모델마다 이런 프로필을 저장한다. 값의 출처를 함께 남겨, 나중에 서버가 알려 준 값과 사용자가 고친 값을 구분한다.

| 칸                                | 내용                         | 출처               |
| --------------------------------- | ---------------------------- | ------------------ |
| `id`                              | 서버가 받는 모델 이름        | 서버               |
| `context`                         | 문맥 토큰 수                 | 서버·사용자·테스트 |
| `tools`                           | 도구 호출 지원               | 서버·사용자·테스트 |
| `vision`                          | 이미지 입력 지원             | 서버·사용자·테스트 |
| `maxOutput`                       | 한 번에 낼 최대 토큰         | 사용자             |
| `temperature` / `omitTemperature` | 샘플링 값                    | 사용자             |
| `notes`                           | 라이선스·모델 카드 주소·메모 | 사용자             |
| `checkedAt`                       | 마지막으로 확인한 시각       | 앱                 |

### 8.4 문맥

- 요청을 보내기 전에 대략적인 토큰을 센다. 정확한 토크나이저는 모델마다 다르므로, 한국어 1.5자/토큰, 영어 4자/토큰 정도의 보수적 추정으로 충분하다.
- `도구 + 시스템 + 대화 + 문서`가 모델 문맥의 80%를 넘으면 보내기 전에 경고한다.
  - "이 모델의 문맥은 8,192토큰인데 이 요청은 약 12,000토큰입니다. 대화를 새로 시작하거나, 간단 도구 모드를 켜세요."
- "간단 도구 모드"는 편집기별 핵심 도구만 남긴다. 예: 워드 `read_document`, `replace_text`, `insert_paragraph`, `apply_format`.
- 문맥을 늘리는 방법도 안내한다. Ollama는 `OLLAMA_CONTEXT_LENGTH` 또는 Modelfile `num_ctx`를 쓰고, 앱 설정에는 모델별 문맥 값을 저장하는 슬라이더를 더한다. Modelfile 예:

```text
FROM <사용자가 받은 모델>
PARAMETER num_ctx 32768
```

`ollama create <새 이름> -f Modelfile`로 새 이름을 만들고, 앱에서는 그 이름을 고른다.

- 2단계에서 Ollama 네이티브 `/api/chat` 어댑터를 검토한다. `options.num_ctx`와 `keep_alive`를 직접 줄 수 있어 UX가 좋아진다. 다만 프로토콜이 하나 늘어나므로 1단계에서는 OpenAI 호환 + 안내로 간다.

### 8.5 도구

- 모델 능력에 `tools`가 없으면 편집 도구를 보내지 않는다. 대신 "글만" 모드로 안내한다. 이 판단은 서버 메타데이터나 사용자 설정을 따르고, 사용자가 "이 모델은 도구를 쓴다"고 직접 켤 수 있게 한다.
- `tools`가 있어도 문맥이 작으면 "간단 도구"를 선택지로 보여 준다. 강제하지 않는다.
- 도구 호출이 2턴 연속 JSON 파싱에 실패하면, 같은 요청을 도구 없이 한 번 더 시도할지 사용자에게 묻는다. 자동으로 문서를 고치지 않는다.
- 로컬 모델의 도구 이름은 짧고 명확하게 유지한다. `replace_text`처럼 동사+대상 형태가 좋다.
- 샘플링 값은 모델별로 실측한다. 지금은 모든 OpenAI 호환 요청에 `temperature: 0.3`을 보내는데, 일부 thinking 모델은 기본값이 더 나을 수 있다. `omitTemperature`를 로컬 모델에도 적용할 수 있게 표를 넓힌다.

### 8.6 텍스트 모드

도구를 못 쓰는 모델에도 쓸모는 있다.

- 선택한 글 다듬기/번역/요약 → 결과를 보여 주고 "넣기" 버튼.
- 긴 글 초안 → `runDocWriter`(이미 도구 없이 동작한다, `apps/docs/src/renderer/ai/AiPanel.tsx`).
- PDF AI 읽기·번역 → 이미 도구 없이 동작한다.
- 슬라이드 개요·발표 노트 → 도구 없이 글만 받아 앱이 적용.
- 홈의 문서 질문 → 검색 도구만 빼고 답변.

이 모드는 "문서를 직접 고치지 않는다"고 화면에 명시한다. 사용자가 기대를 잘못 갖는 것이 가장 큰 위험이다.

### 8.7 오프라인 모드

`app-settings.json` 또는 `ai-settings.json`에 `offlineMode: true`를 둔다. 켜지면 뒷단에서 다음을 강제한다.

- `Custom` 중 루프백(`127.0.0.1`, `::1`)과 기관이 명시적으로 허용한 주소만 허용. 사내 DNS 이름은 해석된 모든 주소가 사설 대역인지 확인하고, 아니면 실행하지 않는다. 저장은 하되 이유를 알린다.
- Claude/Codex 구독, 키 제공자, 무료 AI 카드 숨김.
- `web_search`, `read_url`, `generate_image`, `analyze_media`, 드라이브 검색 도구를 도구 목록에서 제거.
- 업데이트 확인 중지(`updater.ts`의 첫 확인과 주기 확인을 모두 건너뛴다).
- GitHub 스킬 가져오기·업데이트, 의견 보내기 설문, 무료 모델 점검 비활성.
- 화면 상단에 "오프라인" 배지.

테스트는 `fetch`를 가짜로 두고, 오프라인 모드에서 루프백이 아닌 요청이 0건인지 확인한다. "화면에서 버튼을 숨겼다"로 끝내지 않는다.

### 8.8 시간 제한과 오류

- 로컬 연결 제한: 기본 5분(설정 가능). 유휴 제한: 기본 5분.
- 화면 쪽 침묵 감시(현재 240초)도 로컬에서는 함께 늘리거나, 모델을 불러오는 동안 하트비트를 보낸다. 뒷단만 늘리면 화면이 먼저 포기한다.
- 모델 로드가 길면 "모델을 불러오는 중" 상태를 보여 준다. Ollama는 첫 요청 때 모델을 메모리에 올린다.
- 오류 종류:
  - `local-server-offline`: 서버가 꺼져 있음.
  - `local-model-missing`: 모델 이름이 서버에 없음.
  - `local-context-overflow`: 문맥 초과.
  - `local-out-of-memory`: 메모리 부족.
  - `local-tool-unsupported`: 모델이 도구를 지원하지 않음.
  - `local-slow`: 첫 응답 시간 초과.
- 오류 문장은 한국어로, "무엇을 하면 되는지"를 한 줄 포함한다. 진단 복사에는 모델명·문맥·서버 주소만 넣고 문서 내용은 넣지 않는다.

### 8.9 중앙 서버

- 주소, 베어러 토큰, 사내 CA 인증서 경로를 받는다.
- HTTPS를 기본으로 하고, 인증서 검증을 끄는 옵션은 만들지 않는다. 사내 CA는 Windows 신뢰 저장소에 설치하는 것을 안내하고, Node 쪽 요청에는 `NODE_EXTRA_CA_CERTS`로 같은 CA를 넘긴다.
- 모델 허용 목록: 기관이 승인한 모델 id만 선택지에 올린다.
- 상태 확인: `/v1/models`와 짧은 대화 1회. 서버가 느리면 "대기 중"을 표시.
- vLLM은 모델·버전별로 tool parser 버그가 있으므로, 기관이 고른 모델·버전 조합을 검증해 문서에 고정한다.

기관 서버의 출발점은 이런 명령이다. 모델·버전·문맥은 기관 GPU에 맞춰 조정하고, `--tool-call-parser` 이름은 모델 계열마다 다르므로 고른 모델의 문서를 따른다.

```bash
vllm serve <모델> \
  --max-model-len 32768 \
  --enable-auto-tool-choice \
  --tool-call-parser <모델 계열> \
  --reasoning-parser <모델 계열> \
  --chat-template <모델의 tool chat template>
```

### 8.10 보안·감사

- 로컬 서버는 기본적으로 루프백에만 붙는다. `OLLAMA_HOST=0.0.0.0`으로 열려 있으면 앱이 경고한다.
- Ollama 로그에는 요청 정보가 남을 수 있다. 앱은 `OLLAMA_DEBUG`를 켜지 말라고 안내하고, 기관에는 로그 보존·삭제 정책을 문서로 준다.
- 감사 로그(선택): `<userData>/ai-audit.jsonl`에 시각, 제공자, 모델, 도구 이름, 성공/실패, 문서 해시, 토큰 수만 남긴다. 문서 내용·경로·프롬프트는 넣지 않는다.
- AI 생성 표시: docx·pptx·xlsx는 코어 속성, HWP는 문서 정보(요약)나 머리말에 "AI 생성" 한 줄. 형식별로 어디까지 쓸 수 있는지 먼저 확인한다.
- 민감 명령 승인: 2단계에서 "일괄 바꾸기 전 확인" 옵션을 검토한다. 지금은 실행 취소로 되돌릴 수 있지만, 공공기관은 사전 확인을 원할 수 있다.

### 8.11 배포

- **오프라인 설치 파일**: NSIS EXE + SHA256 + 릴리스 노트. 자동 업데이트는 끈다.
- **코드 서명**: OV/EV 인증서. 서명이 없으면 SmartScreen·EDR·AppLocker에서 막힌다. 공공기관 납품의 실질적 전제다.
- **모델 번들**: GGUF + SHA256 + 라이선스 + `Modelfile` + `ollama create` 안내. 앱 설치 파일과 분리한다.
- **업데이트**: 초기에는 오프라인 설치 파일을 기관 담당자가 배포한다. 나중에 내부 미러(HTTP)나 SCCM 패키지를 검토한다.
- **SBOM/서드파티 고지**: 앱의 Apache-2.0, 원본 GenOffice 고지와 NOTICE, Chromium/Electron 취약점 대응 절차를 문서로 준비한다. 모델 라이선스는 앱 라이선스와 별도로 표시한다.

## 9. 보안 체크리스트 매핑

국정원 AI보안 가이드북의 큰 항목을 이음오피스 기능에 대응시키면 다음과 같다.

| 가이드 항목        | 지금                          | 로컬 모드에서 더할 것                                  |
| ------------------ | ----------------------------- | ------------------------------------------------------ |
| 데이터 등급별 사용 | 사용자가 고른 제공자로만 전송 | 오프라인 모드, 로컬 주소만 허용, 기관 모델 허용 목록   |
| 최소 권한          | 열린 문서·첨부만 접근         | 로컬 도구 프로필, 프로젝트 폴더 밖 거절(에이전트 모드) |
| 민감 명령 승인     | 실행 취소, 중단               | 일괄 변경 전 확인 옵션                                 |
| 로깅·모니터링      | 없음                          | 내용 없는 감사 로그, 실패·시간 초과 기록               |
| 입출력 필터        | 가리기(redaction), 첨부 제한  | 로컬 모델용 프롬프트 인젝션 경고, 출력 길이 제한       |
| 모델 가중치 보호   | 해당 없음                     | 모델 파일 SHA256 확인, 기관 배포 절차 문서             |
| 비상 정지          | 중단 버튼, 프로세스 종료      | "모델 내리기" 버튼, 서버 측 타임아웃                   |

## 10. 단계별 계획

### 0단계: 호환성 실측(3~5일, 코드 변경 없음)

목적은 "우리 모델을 고르는 것"이 아니라 **여러 서버와 모델에서 앱이 무엇을 알아낼 수 있고, 어디서 깨지는지**를 보는 것이다.

- 서버 세 종류 이상: Ollama, LM Studio, vLLM(가능하면 llama.cpp server도).
- 모델은 크기·계열을 섞어 5~8개: 작은 모델, 중간 모델, 큰 모델, 도구 호출을 잘하는 모델, 한국어에 강한 모델. 사용자가 실제로 가질 법한 조합을 본다.
- 워드 5개 과제: 문단 다듬기, 5쪽 요약, 문구 일괄 바꾸기, 표 넣기, 보고서 초안.
- 한글 3개 과제: 누름틀 채우기, 표 칸 채우기, 문단 다듬기.
- 서버별로 기록: 모델 목록 형식, 문맥·능력 메타데이터 유무, 도구 호출 형식, 오류 응답 모양, 첫 토큰 시간, 생성 속도, 메모리.
- 결과물: 호환성 매트릭스, 감지하지 못한 값의 목록, 사용자에게 보여 줄 경고 문구 초안.
- 이 단계에서 "최소 사양 모델"을 정하지 않는다. 그건 사용자의 환경과 문서에 따라 달라진다.

### 1단계: 로컬 연결 UX(2~3주)

- 설정 → AI의 "로컬 AI" 카드와 서버 프리셋 3종(모델 프리셋은 두지 않는다).
- Ollama `/api/tags`·`/api/show` 탐색, 모델 능력·문맥·크기 표시, 모르는 값은 "확인 필요"로 표시.
- 연결 테스트 4단계(서버/모델/대화/도구), 사용자가 직접 확인·덮어쓰기.
- 문맥 프리플라이트와 경고, 로컬 시간 제한.
- 로컬 오류 문장과 진단 복사.
- 테스트: 가짜 Ollama 서버로 탐색·문맥·오류 경로, 실제 Ollama는 수동 확인.

### 2단계: 오프라인 모드와 텍스트 모드(3~4주)

- `offlineMode` 뒷단 강제, 나가는 도구 제거, 업데이트·검색·드라이브·GitHub 차단.
- 모델 능력별 도구 프로필, 간단 도구 모드.
- 텍스트 모드(선택 글 다듬기·번역·요약, 긴 글 초안).
- AI 생성 표시, 선택적 감사 로그.
- 테스트: 오프라인에서 비루프백 요청 0건, 도구 없는 모델에서 편집 도구 미전송, 텍스트 모드 경로.

### 3단계: 기관 서버와 배포(4~8주)

- 중앙 서버 프로필(HTTPS·토큰·사내 CA·모델 허용 목록).
- 오프라인 설치 파일, 코드 서명, 모델 번들 문서.
- 기관 1~2곳 파일럿(한글 중심 부서 우선).
- 파일럿 결과로 GS·보안성 검토 필요 여부 결정.

### 하지 않는 것

- Ollama 실행 파일과 모델을 설치 파일에 넣지 않는다.
- 로컬이 막혔을 때 클라우드로 자동 전환하지 않는다.
- 모델 이름만으로 "문서 편집 가능"을 약속하지 않는다. 도구 지원과 문맥은 서버·모델·설정마다 다르다.
- 라이선스가 확인되지 않은 모델을 앱이 대신 배포하지 않는다.
- 모델 추천 순위나 "추천" 배지를 만들지 않는다.
- 인증서 검증을 끄는 편의 옵션을 만들지 않는다.

## 11. 리스크와 열린 질문

### 리스크

- **품질**: 사용자가 고른 모델에 따라 편차가 크다. 어떤 모델은 긴 한국어 공문서에서 숫자·고유명사를 틀린다. 앱은 품질을 보증하지 않고, 사람 검토가 필요하다는 것을 화면과 문서에 분명히 해야 한다.
- **도구 호출**: 서버·모델·파서 버전의 조합에 따라 도구 호출이 깨진다. 예를 들어 vLLM의 Gemma 4 parser는 2026년에도 버그 보고가 있다. 앱은 특정 조합을 정답으로 두지 말고, 연결 테스트와 회귀 시험으로 확인한다.
- **하드웨어**: 모델마다 요구 사양이 다르고, 8GB PC도 여전히 조달 목록에 많다. 앱이 특정 모델을 "기본 사양"처럼 약속하지 않는다. 사용자가 고른 모델의 실제 메모리·속도를 보고 판단하게 한다.
- **자동 감지의 한계**: 서버가 문맥·도구·비전을 알려 주지 않을 수 있다. 앱은 모르는 값을 추측으로 채우지 말고 "확인 필요"로 두고, 사용자가 테스트하거나 직접 설정하게 해야 한다.
- **지원**: 사용자마다 서버와 모델이 달라 장애 재현이 어렵고, 기관은 장애 때 연락할 곳을 원한다. 진단 정보(서버 종류·모델 id·문맥·능력·오류 종류), 호환성 문서, 지원 파트너가 필요하다.
- **서명·인증**: 코드 서명과 GS 없이는 조달이 막힌다. 이는 코드보다 오래 걸린다.
- **정책 변화**: N2SF 전환과 공통기반 우선 이용으로 "왜 자체 구축인가"를 계속 설명해야 한다. 로컬이 필요한 이유를 데이터 등급으로 명확히 해야 한다.
- **모델 라이선스**: 기관이 이미 상업 라이선스를 가진 모델인지 확인하지 않고 안내하면 위험하다. 앱은 라이선스를 판단하지 말고, 사용자가 적은 정보와 원문 링크만 보여 준다.

이 문서의 모델 크기·속도·벤치마크는 제조사 발표와 공개 자료를 정리한 것이며, 이 PC에서 실측한 값이 아니다. 정책 일정과 인용 내용도 바뀔 수 있으므로, 실제 판단 전에 원문과 날짜를 다시 확인한다.

### 열린 질문

1. 첫 목표는 개인 PC(Ollama)인가, 기관 서버(vLLM)인가? (권고: 파일럿은 개인 PC, 납품은 기관 서버)
2. 앱이 모델을 전혀 다루지 않을 것인가, 설치 안내·SHA256 확인 도구까지만 둘 것인가? (권고: 후자. 모델 자체는 사용자가 준비)
3. 자동 감지한 능력을 어디까지 신뢰할 것인가? 모르는 값을 "확인 필요"로 두고 사용자가 얼마나 덮어쓸 수 있게 할 것인가?
4. 서버 프리셋은 어디까지 둘 것인가? (Ollama/LM Studio/vLLM/llama.cpp, 그 밖의 OpenAI 호환 서버는 직접 주소)
5. 알려진 모델 참고 표를 제품에 둘 것인가? (권고: 참고용으로만 두고, 사용자가 수정 가능하게)
6. 기관 관리자가 모델 허용 목록을 강제할 수 있게 할 것인가? (권고: 선택 기능)
7. 오프라인 모드를 앱 전체 설정으로 둘 것인가, AI 설정으로 둘 것인가? (권고: 앱 전체)
8. AI 생성 표시와 감사 로그를 기본으로 켤 것인가? (권고: 둘 다 기본 꺼짐, 기관 정책에 따라 켬)
9. GS 인증과 코드 서명을 언제 할 것인가? (권고: 파일럿 전에 코드 서명, GS는 파일럿 후 결정)
10. 한글 AI를 1차 대상으로 할 것인가? (권고: 그렇다. 공공기관의 실제 문서는 HWP다)
