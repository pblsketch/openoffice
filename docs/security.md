# 보안 정책

이 프로그램에는 운영하는 서버도, 회원 계정도, 여러 사람이 나눠 쓰는 상태도 없다. 지킬 것은 네 가지다. 사용자의 구독 로그인, 사용자의 돈(요금이 나가는 경로), 사용자 문서의 내용, 그리고 이 PC 안팎의 다른 프로그램이 앱에 시킬 수 있는 일의 범위.

## 구독 로그인: 앱은 로그인에 관여하지 않는다

로그인은 Anthropic·OpenAI의 프로그램이 한다. 앱이 하는 일은 그 프로그램을 실행하는 것뿐이다. 예외는 ChatGPT 직접 연결 하나이고, 아래 "ChatGPT 직접 연결"에 따로 적는다(결정 0081).

| 단계          | 앱이 하는 일                                                                                                                   | 실패하면                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 프로그램 찾기 | 사용자가 지정한 경로, PATH, 흔한 설치 위치(`%APPDATA%\npm` 포함)에서 찾고, 껍데기 파일(`.cmd`) 뒤의 실제 실행 파일을 찾아낸다  | 상태 `not-installed`                                                   |
| 상태 묻기     | 프로그램의 버전·로그인 상태 명령을 실행한다                                                                                    | 20초 안에 답이 없거나 실행이 깨지면 상태 `error`                       |
| 로그인 띄우기 | 프로그램 자신의 로그인 명령을 실행한다. 로그인 화면은 그 회사의 웹 페이지다. 다른 계정으로 바꿀 때도 같은 명령을 다시 실행한다 | 10분 안에 끝나지 않거나 사용자가 닫으면 상태는 그대로                  |
| 로그아웃      | 프로그램 자신의 로그아웃 명령을 실행하고(Claude `auth logout`, Codex `logout`), 끝나면 상태를 다시 묻는다                      | 20초 안에 끝나지 않으면 프로그램을 끝내고 실패로 알린다                |
| 모델 목록     | 앱이 쓸 수 있는 로그인(구독, 또는 허용된 종량)의 프로그램에 모델 목록을 묻는다. 모델 호출이 아니다                             | 목록 없이 간다. 화면에는 앱에 들어 있는 고정 목록이 나온다             |
| 요청 보내기   | 로그인된 프로그램에 한 차례의 질문을 넘기고 답을 읽는다                                                                        | 로그인 만료는 `signed-out`, 한도 소진은 `rate-limit`으로 실행이 멈춘다 |

**하지 않는 일 (어떤 이유로도, 시험·디버깅 중에도):**

- Codex의 로그인 파일(`~/.codex/auth.json`)과 Claude의 로그인 저장소를 읽거나, 복사하거나, 다른 곳에 저장하지 않는다. 로그인 파일을 임시 폴더로 복사해 다른 실행에 쓰는 방식도 여기에 든다.
- 앱 화면에 Claude·ChatGPT 로그인 양식을 만들지 않는다.
- 두 회사의 프로그램을 고치거나 감싸서 로그인 방식을 바꾸지 않는다. 배포된 그대로 실행한다.
- 프로그램이 알려 준 조직 이름을 상태 값, 파일, 로그에 남기지 않는다. 프로그램의 답에서 상태에 담는 것은 다섯 가지뿐이다. 프로그램 버전, 로그인 방식의 종류(정해진 목록 안의 값. 모르는 값은 `unknown`), 요금제 이름(식별자 모양일 때만), 계정 이메일(이메일 주소 모양일 때만), 모델 목록(프로그램이 받는 식별자 모양의 값과 길이를 자른 표시 이름).
- 계정 이메일은 설정 화면의 구독 카드에 보여 주는 데만 쓴다. 앱이 켜져 있는 동안 메모리에만 있고, 설정 파일, 종량 허용 기록, 실행해 둔 프로그램의 기록, 로그 어디에도 쓰지 않는다. 뒷단이 제공자를 정하거나 도구에 넘기는 상태 사본에서는 뺀다. 터미널 명령어와 MCP가 만드는 상태에서도 뺀다.
- 프로그램의 출력 글을 상태·파일·로그에 그대로 싣지 않는다. 오류 상태의 글은 "종류: 고정된 영어 설명" 꼴이고, 화면은 종류를 보고 번역된 문구를 보여 준다.

## ChatGPT 직접 연결 (결정 0081)

앱이 OpenAI의 "Sign in with ChatGPT"(오픈소스 앱용)로 사용자의 ChatGPT 요금제에 직접 연결한다. 앱은 OpenAI에 자기 이름으로 등록되고, 토큰은 이 앱에 발급된 것이다. Codex 프로그램의 로그인을 읽거나 빌리지 않는다.

- 로그인 화면은 시스템 브라우저에 뜨는 OpenAI의 것이다. 앱 안에 로그인 양식은 없고, 앱은 비밀번호를 보지 않는다. 클라이언트 비밀값도 없다.
- 브라우저가 돌아올 곳은 `127.0.0.1`의 빈 포트에 연 임시 서버 하나다(OpenAI가 `localhost`를 받지 않는다). `/callback` 요청 가운데 `state`가 맞는 하나에만 답하고, 나머지는 404다. 끝나거나 취소되거나 10분이 지나면 닫는다. 돌려주는 페이지는 스크립트도 바깥 자원도 없는 고정 글이다.
- 시도마다 PKCE(S256) 검증값, `state`, `nonce`를 새로 만든다. 받은 코드는 검증값과 함께 보내야만 토큰이 된다.
- ID 토큰은 OpenAI가 공개한 키(`auth.openai.com/.well-known/jwks.json`)로 서명을 확인하고, 발급자, 대상(발급된 `client_id`), 만료, `nonce`를 본다. 하나라도 맞지 않으면 로그인은 실패다.
- 요금제 사용 범위(`chatgpt.tokens.use.direct`)가 없는 로그인은 저장하지 않는다. 토큰의 범위가 그 요금제 안이라, 이 연결에는 종량 로그인이 없다.
- 토큰은 데이터 폴더의 `chatgpt-connection.json`에 둔다. 접근·갱신·ID 토큰은 설정 파일의 키와 같은 봉인을 거친다(결정 0063). 파일은 임시 이름으로 쓴 뒤 바꾸고, 소유자만 읽게 만든다. 이메일은 쓰지 않는다. 화면의 계정 표시는 그 실행 중 확인한 ID 토큰에서 읽어 메모리에만 둔다. 토큰과 ID 토큰은 로그, 오류 글, 주소에 싣지 않는다.
- 갱신은 한 번에 하나다. 바뀐 갱신 토큰은 나머지 값과 함께 한 번에 쓴다. 갱신이 거절되면(`invalid_grant` 등) 세션을 지우고 `signed-out`이 된다. 요청이 401이나 `subscription_sharing_invalid_user`로 거절돼도 같다(사용자가 ChatGPT 설정에서 이 앱을 끊은 경우).
- 연결 끊기는 OIDC 설정의 `revocation_endpoint`에 갱신 토큰을 보낸다. 그 주소가 `https://auth.openai.com`이 아니면 보내지 않는다. 폐기가 실패해도 PC의 토큰은 지운다. 이 연결을 끊어도 PC의 다른 프로그램은 그대로다.
- 요청은 `https://api.openai.com/v1/responses`와 `/v1/models` 둘뿐이다. ChatGPT의 비공개 주소(`backend-api`)는 쓰지 않는다. 요청에는 `store: false`를 넣는다. 도구를 API 형식으로 주지 않는다. 앱의 도구 목록은 입력 글에 적고, 모델의 답은 앱이 검사한다(Claude 연결부와 같은 규약). 목록에 없는 도구 호출은 실행하지 않는다.
- 프로그램을 띄우지 않으므로 셸, 사용자 설정, 훅, MCP가 끼어들 자리가 없다.
- 터미널 명령어와 MCP에는 이 연결을 열지 않는다. 갱신 토큰을 두 프로세스가 나눠 쓰면 한쪽이 무효가 된다. 명령어에서 `chatgpt`는 늘 `signed-out`이다.

## 요금 경로: 돈이 나가는 쪽으로 스스로 가지 않는다

| 연결                         | 누가 고르나                                    | 자동으로 쓰이나               |
| ---------------------------- | ---------------------------------------------- | ----------------------------- |
| 구독 로그인(`ready`)         | `auto` 또는 사용자                             | 예. `auto`의 유일한 후보다    |
| ChatGPT 직접 연결(`ready`)   | `auto` 또는 사용자                             | 예. 요금제 범위 토큰뿐이다    |
| 종량 로그인(`metered`)       | 사용자가 "그래도 사용"으로 허용한 뒤 직접 고름 | 아니오                        |
| 키 제공자(대화용)            | 사용자가 직접 고름                             | 아니오                        |
| 무료 연결(OpenRouter·Gemini) | 사용자가 카드에서 연결 버튼을 누름             | 아니오. 누른 것이 고른 것이다 |
| 이미지·분석·검색용 키        | 사용자가 그 용도로 넣음                        | 그 용도 안에서만              |
| GitHub 읽기 토큰(`read_url`) | 사용자가 그 용도로 넣음                        | 그 용도 안에서만              |

- GitHub 읽기 토큰은 `ai-settings.json`에 AI 키와 같은 방식으로 저장되고(Windows·Linux는 봉인, 결정 0063), `api.github.com` 요청에만 실린다. 다른 사이트나 리다이렉트 홉에는 보내지 않는다.
- 실행 중 막혀도 요금이 나가는 연결로 넘어가는 버튼은 만들지 않는다.
- 무료 연결로 만든 OpenRouter 설정은 `:free` 모델만 고를 수 있다. 그 계정에 충전된 돈이 있어도 무료 연결이 유료 모델로 가지 않게 하기 위해서다. Gemini 키는 무료와 유료를 구분할 수 없으므로 카드에 요금 가능성을 적는다.
- 프로그램을 실행할 때 요금 경로를 바꾸는 환경변수를 넘기지 않는다. 대상: `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_USE_MANTLE`, `CLAUDE_CODE_USE_ANTHROPIC_AWS`, `CLAUDE_CODE_USE_ANTHROPIC_GOOGLE_CLOUD`, `ANTHROPIC_CUSTOM_HEADERS`, `ANTHROPIC_PROFILE`, `ANTHROPIC_FEDERATION_RULE_ID`, `CODEX_API_KEY`, `CODEX_ACCESS_TOKEN`. Windows에서는 대소문자를 가리지 않고 뺀다. 원래 환경은 바꾸지 않고 사본을 만든다.
- Codex는 실행 직전에 계정 종류를 다시 읽는다. 상태 확인 때와 달라졌으면(구독이었는데 종량으로 바뀜) 그 실행은 `metered-not-accepted`로 거부된다. Claude에는 이 재확인이 없다. 상태 확인(앱 시작, 설정 열기, 창으로 돌아오기) 사이에 로그인 방식을 바꾼 경우는 다음 확인 때까지 잡히지 않는다.
- 종량 허용은 설정값 하나만으로 유효하지 않다. 데이터 폴더의 기록에 적힌 로그인 종류와 지금 감지된 종류가 같을 때만 유효하다.

## 프로그램 실행: 사용자 글이 명령이 되지 않게

- AI 실행과 상태 확인에서 프로그램은 실제 실행 파일 경로로 직접 실행한다. 셸을 거치지 않는다. 문서 내용이나 사용자가 적은 글이 명령으로 해석되는 길을 막기 위해서다.
- 예외는 설치 버튼과 업데이트 버튼 둘이다(업데이트는 결정 0047). 둘 다 고정된 글자 그대로의 공식 명령을 새 터미널 창에서 실행하고, 사용자 입력이 섞이지 않는다. Codex 업데이트 명령은 찾은 파일의 위치로 고른 두 상수 중 하나다(npm, winget). Claude 업데이트는 앱이 찾은 실행 파일을 이름이 아니라 경로로 부르는데, 그 경로와 인자는 명령 글에 끼워 넣지 않고 환경변수 두 개(`GENOFFICE_SUBSCRIPTION_UPDATE_EXE`·`_ARGS`)에 값으로 넘기며 프로그램을 띄우기 전에 지운다. 명령 글 자체는 상수다. 환경은 다른 실행과 같이 `subscriptionChildEnv`로 만든다.
- 설치와 로그인 창을 띄우는 PowerShell, 프로세스를 끝내는 `taskkill`, 남은 프로세스를 찾는 조회는 이름으로 찾지 않고 Windows 시스템 폴더의 전체 경로로 실행하며, 작업 폴더도 시스템 폴더로 둔다. 앱을 문서 더블클릭으로 켰을 때의 작업 폴더(문서가 있는 폴더)에 같은 이름의 실행 파일이 있어도 실행되지 않는다.
- 프로그램을 찾을 때 PATH의 빈 항목과 상대 경로 항목은 건너뛴다. 문서 폴더에 놓인 `claude.cmd`나 `codex.exe`가 선택되는 일을 막는다.
- 문서 내용 같은 긴 입력은 명령줄 인자로 넘기지 않고 표준 입력으로 넘긴다. 명령줄에는 사용자가 준 글이 한 글자도 없다. 모델 이름은 정해진 글자 모양일 때만 받아들인다. Claude의 문서 편집 차례에는 응답 형식(앱 도구 이름만 든 스키마)이 더 오른다(결정 0082).
- 프로그램은 빈 임시 폴더를 작업 폴더로 삼아 실행한다.
- 로그아웃은 창을 띄우지 않는다. 다른 상태 명령과 똑같이 실제 실행 파일을 인자 배열로 직접 실행하고, 셸을 거치지 않으며, 요금 경로를 바꾸는 환경변수를 뺀 환경에서 돌린다. 프로그램이 출력한 글은 결과에 싣지 않는다.
- 로그아웃과 계정 바꾸기는 이 PC의 그 프로그램 전체에 적용된다. 터미널에서 따로 쓰는 것도 함께 바뀐다. 그래서 화면이 프로그램 이름과 이 사실을 알리고 확인을 받은 뒤에만 실행한다. 로그아웃 창구를 화면에 내주는 것은 껍데기 앱의 preload뿐이고, 편집기 창은 부를 수 없다. 계정 바꾸기는 로그인 창구를 다시 쓰는 것이라 편집기 창에도 그 창구가 있지만, 누르기 전의 확인은 설정 화면이 받고 편집기 화면에는 그 버튼이 없다.
- 모델 목록을 물을 때 Claude는 일반 대화 한 차례와 똑같은 인자(응답 형식 없음, 도구 0개), 빈 임시 폴더, 같은 환경으로 띄운다. 시작 요청 하나만 보내고 그 답을 읽으면 표준 입력을 닫아 끝낸다. 사용자 글을 보내지 않으므로 모델은 불리지 않는다. 프로그램이 답 대신 다른 것을 요청하거나 출력을 내기 시작하면 하위 프로세스까지 끝낸다. 15초 안에 답이 없을 때와 확인이 취소됐을 때도 같다. Codex는 이미 떠 있는 `app-server`에 목록을 묻고, 대화를 열지 않는다.
- 로그인 버튼은 고정된 PowerShell 글로 프로그램에 콘솔 하나를 준다. 처음에는 그 콘솔을 숨기고(`-WindowStyle Hidden`), 사용자는 프로그램이 연 브라우저에서 로그인한다. 브라우저가 열리지 않는 경우를 위해 카드의 링크를 누르면 숨긴 로그인을 끝내고 같은 명령을 보이는 창으로 다시 띄운다. 보이는 창은 앱의 두 번째 PowerShell이 연다. 창 제목과 화면 언어의 안내를 먼저 찍고, 같은 콘솔에서 프로그램을 실행하며, 프로그램이 로그인을 끝내지 못하고 나가면 Enter를 누를 때까지 창을 남긴다(결정 0059). 코드는 사용자가 그 창에 직접 붙여 넣고 콘솔을 거쳐 프로그램으로 바로 간다. 앱은 코드를 받거나 전달하지 않는다. 숨긴 로그인은 10분이 지나면 끝낸다(`HIDDEN_LOGIN_TIMEOUT_MS`). 숨긴 글과 보이는 창의 두 글은 모두 상수다. 프로그램 경로와 인자, 창 제목과 안내 글은 그 글에 끼워 넣지 않고 환경변수에 담아 값으로 넘기며, 프로그램이 시작하기 전에 그 변수들을 지운다. 사용자가 설정한 경로가 PowerShell 코드로 읽히는 일이 없다. 안내 글은 앱의 번역 사전에 고정된 글이고, 창을 연 화면이 보낸 글이 아니다. 보이는 창의 PowerShell에 넘기는 글에는 큰따옴표가 없어야 한다. `Start-Process`가 인자를 공백으로 이어 넘기고 그 PowerShell이 명령줄에서 다시 합치는 동안 큰따옴표가 사라지기 때문이다.
- 사용자 PC의 개인 설정, 훅, 플러그인, MCP 연결은 실행에서 뺀다.
- Claude의 대화 한 차례와 모델 목록 물음에는 `DISABLE_AUTOUPDATER=1`, `DISABLE_TELEMETRY=1`을 더한다. 한 차례만 사는 프로세스가 스스로 업데이트를 시작했다가 끝날 때 끊기는 일을 막는다. 두 변수는 로그인과 요금 경로에 닿지 않는다. 상태 확인, 로그인, 로그아웃에는 넣지 않는다.

**Claude: 보고한 도구가 정해 둔 목록과 같을 때만 진행한다**

- 내장 도구를 끄는 옵션을 주지만 그 옵션을 믿지 않는다. 프로그램이 시작하면서 보고하는 도구 목록과 MCP 서버 목록을 확인한다.
- 정해 둔 목록은 둘이다. 일반 대화와 모델 목록 읽기는 도구 0개다. 문서 편집 차례는 구조화 응답 옵션(`--json-schema`)이 붙이는 `StructuredOutput` 하나다(결정 0082). 그 도구는 모델이 낸 답을 프로그램 안에서 형식에 맞는지 확인하고 돌려줄 뿐, 파일·명령·네트워크에 닿지 않는다.
- 목록이 정해 둔 것과 다르거나, MCP 서버가 붙었거나, 다른 도구의 사용 조각, `StructuredOutput` 호출의 확인이 아닌 도구 결과, 권한 요청이 오면 그 실행을 끝내고 `unsafe-tools`로 거부한다. 그때까지의 모델 출력은 쓰지 않는다.
- `--json-schema`에 넘기는 스키마에는 앱 도구의 이름만 들어간다. 이름은 모델 API가 받는 모양(`^[A-Za-z0-9_-]{1,64}$`)이어야 하고, 아니면 프로그램을 띄우지 않는다. 사용자 글과 도구 설명은 명령줄에 오르지 않는다.
- 문서 편집 차례의 답은 `StructuredOutput` 호출로 온 것만 받는다. 호출 밖에 쓴 글은 답으로 쓰지 않는다.
- 모델이 앱 도구를 `toolCalls`에 넣지 않고 바로 부르는 일이 있다(편집기 지시문이 도구 이름을 말한다). 프로그램에는 그런 도구가 없어 실행될 수 없다. 이름이 그 차례의 앱 도구 목록에 있으면 그 호출을 이번 차례의 요청으로 받아 `toolCalls`와 똑같이 검사해 앱이 실행하고, 프로그램은 그 호출에 답하기 전에 끝낸다. 앱 도구 목록에 없는 이름이면 지금처럼 끝내고 거부한다. `StructuredOutput`과 함께 온 직접 호출은 쓰지 않으며, 프로그램이 그 호출에 오류가 아닌 결과를 돌려주면 실행된 것으로 보고 끝낸다.
- 구독 로그인을 읽지 않는 최소 모드(`--bare`)는 쓰지 않는다.
- 앱이 넘긴 도구 목록에 없는 도구 호출은 실행하지 않는다. 오류로 표시해 모델에게 돌려준다.

**Codex: 꺼지는 것과 남는 것**

- Codex에는 사용자 설정 전체를 무시하는 옵션이 없다. 그래서 훅·플러그인·앱·메모리와 Codex 자체 웹 검색(`web_search="disabled"`)을 설정 덮어쓰기로 끄고, 대화마다 사용자의 MCP 서버를 하나씩 꺼서 임시 대화를 연다. 열고 난 뒤 켜진 MCP 서버나 도구가 하나라도 보이면 프로세스를 끝내고 `unsafe-tools`로 거부한다.
- 읽기 전용 권한, 승인 없음으로 실행한다.
- 남는 것: Codex 자신의 셸 도구는 끌 수 없다. 지시문으로 쓰지 말라고 하고, 권한 프로필로 읽기를 플랫폼 경로와 실행용 임시 폴더로 좁힌다. 프로필을 받지 않는 예전 Codex이거나 사용자 설정에 `sandbox_mode`가 있으면 읽기 전용 샌드박스로 내려가는데, 이때 그 도구는 디스크 전체를 **읽을** 수 있다. 쓰기와 승인은 어느 경우에도 없다.
- 남는 것: `~/.codex/AGENTS.md`는 여전히 대화에 들어간다. 앱이 덮어쓰지 않는 설정은 그대로 적용된다.
- 대화 기록과 세션 파일은 남기지 않게 한다. Codex가 따로 쓰는 진단 기록 파일은 남는다.

## 무료 연결: 브라우저 로그인과 붙여넣은 키

- OpenRouter 연결은 OpenRouter가 공개한 OAuth PKCE 흐름이다. 앱은 OpenRouter 비밀번호를 보지 않고, 앱 안에 로그인 양식을 만들지 않는다. 로그인 화면은 시스템 브라우저에 뜨는 OpenRouter의 것이다. 클라이언트 비밀값은 없고, 실행마다 새로 만든 검증값(`code_verifier`)이 유일한 증명이다.
- 브라우저가 돌아올 곳으로 앱은 이 PC의 루프백 주소(`127.0.0.1`, 있으면 `::1`)에만 임시 서버를 연다. 포트는 운영체제가 고른 빈 포트다. 다른 PC에서는 닿지 않는다. 서버는 `/callback` 요청 하나에만 답하고, 연결이 끝나거나 취소되거나 10분이 지나면 닫힌다. 돌려주는 페이지는 스크립트도 바깥 자원도 없는 고정 글이다.
- 그 요청에 실려 온 코드는 검증값과 함께 OpenRouter에 보내야만 키가 된다. 이 PC의 다른 프로그램이 가짜 코드를 보내도 키를 얻지 못하고 연결 실패로 끝난다.
- 받은 키는 뒷단(main)이 바로 설정 파일에 쓴다. 화면 쪽 창에는 넘기지 않는다. 그 뒤로는 다른 키 제공자의 키와 같다(아래 "키와 기록의 보관").
- 붙여넣은 Gemini 키는 한 덩어리의 키 모양(영문·숫자·`.`·`_`·`-`, 20~256자)일 때만 Google에 보낸다. 확인은 모델 목록 조회 한 번이고, 무료 사용량을 쓰지 않는다.
- 브라우저로 여는 주소는 코드에 고정된 것뿐이다(OpenRouter 로그인, OpenRouter 키 페이지, Google AI Studio 키 페이지). 화면은 제공자 이름만 넘긴다.
- 앱이 직접 보내는 요청: `https://openrouter.ai/api/v1/auth/keys`(코드 → 키), `https://openrouter.ai/api/v1/models`(무료 모델 목록, 키 없이), `https://openrouter.ai/api/v1/key`(오늘 남은 무료 요청 수, 저장된 키로), `https://generativelanguage.googleapis.com/v1beta/models`(Gemini 키 확인).

## 키 제공자의 모델 목록 (결정 0087)

- 뒷단은 키가 들어 있는 키 제공자마다 그 회사의 모델 목록을 묻는다. 앱을 켠 뒤 한 번, 그리고 그 제공자의 키나 주소가 바뀌어 저장됐을 때다. 키가 없는 제공자, 구독 제공자, 사용자 서버(`custom`)에는 묻지 않는다.
- 요청은 대화가 쓰는 주소(저장된 base URL 포함)와 같은 인증 방식으로 간다. 키는 머리글에만 싣고 주소에 넣지 않는다. 목록 조회는 모델 호출이 아니어서 요금과 무료 사용량을 쓰지 않는다. 사용자 글이나 문서 내용은 실리지 않는다.
- 답은 모델 식별자만 남긴다(256자 이하, 2,000개까지). 설정 파일의 `providers.<id>.models`는 뒷단만 쓰고, 화면이 보낸 값은 버린다.
- 목록에 보이는 것은 고를 수 있다는 뜻일 뿐이다. 대화가 키 제공자로 가는 조건(사용자가 그 제공자를 골랐을 때)은 바뀌지 않는다.

## Google 드라이브: 앱이 Google 앱으로 로그인한다 (결정 0033, 0085)

구독 로그인과 달리, 드라이브는 앱 자신이 Google에 등록한 앱으로서 연결한다. 회사 프로그램의 로그인을 대신하는 일이 아니다.

- 로그인 화면은 시스템 브라우저에 뜨는 Google의 것이다. 앱은 Google 비밀번호를 보지 않고, 앱 안에 로그인 양식을 만들지 않는다. 흐름은 Google이 설치형 앱에 권하는 OAuth(PKCE S256)다. 실행마다 새 검증값과 `state`를 만들고, 브라우저가 돌아오는 서버는 `127.0.0.1`의 빈 포트에만 연다. 그 서버는 `/callback` 요청 가운데 `state`가 맞는 하나에만 답하고, 끝나거나 취소되거나 10분이 지나면 닫힌다. 돌려주는 페이지는 스크립트도 바깥 자원도 없는 고정 글이다.
- 받는 권한은 `https://www.googleapis.com/auth/drive.file` 하나다. 사용자가 Google 선택 창에서 고른 파일과 앱이 만든 파일만 읽고 쓴다. 드라이브의 나머지는 보지 못한다. 다른 권한(`openid`, `email` 등)은 받지 않고, 계정 표시는 드라이브의 `about`에서 읽는다.
- 파일 고르기는 Google의 선택 창이다. 로그인과 같은 흐름에 `trigger_onepick=true`를 붙여 동의 화면에서 고르게 하고, 돌아온 `picked_file_ids`는 드라이브 ID 모양인 것만 50개까지 받는다. 앱이 그린 드라이브 목록에서 고르는 일은 없다.
- 고를 때마다 새 갱신 토큰이 온다. 새 것만 보관하고 이전 것은 폐기하지 않는다. 폐기는 그 계정에 대한 앱의 허락 전체를 끝내, 전에 고른 파일에도 닿지 못하게 할 수 있다. 폐기는 사람이 누른 연결 끊기 때만 한다.
- 클라이언트 ID와 비밀값은 빌드가 넣는다. Google은 데스크톱 앱의 비밀값을 비밀로 보지 않는다. 저장소에는 적지 않아, 다른 사람이 소스로 만든 빌드는 이 앱의 Google 등록을 쓰지 않는다.
- 갱신 토큰은 운영체제 암호화로만 보관한다(`google-drive.json`). 키 제공자의 키와 달리 평문으로 두는 경우가 없다. 암호화를 쓸 수 없으면 저장하지 않고 앱이 켜져 있는 동안만 연결된다. Linux에서는 키링(GNOME 키링·KWallet)이 열쇠를 쥘 때만 암호화로 친다. 키링이 없을 때의 `basic_text`는 프로그램에 든 열쇠라 감싼 모양만 남기 때문이다(`driveTokenSeals`). 접근 토큰은 뒷단 메모리에만 있다. 화면 쪽 창, 터미널 명령어, MCP, 로그에는 어느 토큰도 나가지 않는다.
- 연결 끊기는 Google에 토큰 폐기를 요청하고(`oauth2.googleapis.com/revoke`) 파일을 지운다. 폐기 요청이 실패해도 PC의 토큰은 지운다.
- 갱신이 `invalid_grant`로 거절될 때만 연결을 끝낸다. 네트워크 실패로는 끊지 않는다.

**드라이브에 쓰는 것은 사람의 저장뿐이다.**

- 드라이브 파일은 데이터 폴더의 `drive-cache`에 내려받아 탭으로 연다. 저장은 보통 파일처럼 그 사본에 쓰이고, 그 폴더를 지켜보는 뒷단이 드라이브에 올린다.
- 올리기 전에 드라이브 쪽 파일이 사본을 만든 뒤에 바뀌었는지(내용 해시, 해시가 없으면 변경 시각) 본다. 바뀌었거나 이 계정이 고칠 수 없거나 파일이 없어졌으면 덮어쓰지 않고 사람에게 묻는다.
- Google 문서·스프레드시트·프레젠테이션은 덮어쓰지 않는다. 처음 저장할 때 같은 폴더에 Office 파일을 새로 만들고, 그 폴더에 쓸 수 없거나 앱이 볼 수 없는 폴더면 내 드라이브에 만든다.
- 올리기 세션 주소는 Google의 올리기 주소일 때만 따라간다. 접근 토큰이 다른 주소로 가지 않게 하기 위해서다.
- AI 도구는 읽기만 한다(`drive_search`, `drive_read`). 드라이브 파일을 쓰고, 지우고, 옮기고, 공유하는 도구는 없다.

**AI가 드라이브를 읽을 때**

- Google Workspace 정책은 드라이브 데이터를 학습하는 AI 서비스로 넘기는 것을 금지한다(결정 0085). 그래서 사람이 설정 → 연동에서 "드라이브 파일과 함께 쓰는 AI 계정에서 모델 학습을 껐습니다"(`driveTrainingAck`)에 체크하기 전에는 연결, 고르기, 첨부, AI의 드라이브 도구가 모두 멈춘다. 뒷단이 그 값을 매번 다시 본다.
- 무료 연결(Gemini, `:free` 모델의 OpenRouter)은 학습을 끌 수 없어 드라이브 파일을 받지 않는다. 드라이브에서 첨부는 선택 창을 열기 전에 거절하고, `drive_search`·`drive_read`는 거절을 돌려주고, 드라이브 사본을 연 탭의 AI 요청은 워드 계열·슬라이드·엑셀 뒷단의 실행 입구(`aiRunRefusal`)에서 거절한다.

- 사람이 설정의 "AI가 드라이브에서 파일을 찾아 읽기"를 켜 두었을 때만(연결하면 켜짐) 편집기 AI 창에 두 도구가 생긴다. 터미널 명령어, MCP, 에이전트 모드에는 없다.
- 읽기는 파일을 임시 폴더로 받아 `parseFileToText`로 읽고 지운다. 가리기가 다른 파일 읽기와 같이 적용된다(결정 0016). 읽은 글은 몇 분 동안 뒷단 메모리에만 둔다.
- 대화에 드라이브에서 읽은 내용이 들어간 뒤로는, 모델이 정한 글을 밖으로 내보내거나 주소로 무언가를 가져오는 도구(웹·이미지 검색, 이미지 생성과 변형, 미디어 분석, 주소로 그림 넣기, 주소로 문서 읽기(`read_url`), 입력의 `url`·`src`에 웹 주소가 든 호출)를 그 대화가 새로 시작될 때까지 거절한다. 문서 속 글에 조종당한 모델이 드라이브 내용을 검색어나 주소에 실어 내보내는 길을 막기 위해서다. 대화가 저장됐다가 다시 열려도 기록에 드라이브 읽기가 있으면 같다.
- 드라이브에서 첨부는 사람이 Google 선택 창에서 직접 고른 파일만 받는다. 한 번에 20개다. 받은 파일은 임시 폴더(`<temp>/ieumoffice-drive-attach`)에 파일마다 따로 두고, 편집기는 PC 파일 첨부와 같은 창구로 그 경로를 첨부한다. 가리기는 첨부 읽기에서 그대로 적용된다. 일주일 지난 사본은 그 폴더를 처음 쓸 때 지운다. AI가 스스로 읽은 것이 아니므로 바깥 도구를 막지 않는다. PC 파일 첨부와 같은 위험이다.
- 드라이브 검색어는 쿼리 구조를 바꿀 수 없게 따옴표를 처리해 넣는다. 파일 id는 정해진 글자 모양일 때만 받는다.

## 실행해 둔 프로그램은 앱보다 오래 살지 않는다

| 때               | 처리                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------- |
| 사용자가 중단    | 그 실행의 프로그램을 하위 프로세스까지 끝낸다                                                |
| 앱 정상 종료     | 추적 중인 프로그램 전부를 하위 프로세스까지 끝낸다(동기 처리)                                |
| 앱이 강제로 꺼짐 | 실행해 둔 프로그램의 기록이 데이터 폴더에 남아 있다. 다음에 켤 때 아직 살아 있는 것을 끝낸다 |

- 다음 실행 때의 정리는 **이 앱이 띄운 것만** 대상으로 한다. 사용자가 터미널에서 따로 쓰고 있는 Claude·Codex를 끝내면 안 된다.
- 앱이 로그인이나 로그아웃을 실행하고 나면, 떠 있던 Codex 프로세스는 더 쓰지 않는다. 그 프로세스가 시작할 때의 로그인을 그대로 쥐고 있을 수 있기 때문이다. 쓰는 실행이 없으면 바로 끝내고, 있으면 그 실행이 끝난 뒤 끝낸다. 다음 요청은 새 프로세스가 받는다.
- 쓰지 않는 Codex 프로세스는 2분 뒤 스스로 끝난다. Claude는 차례마다 띄우고 답이 끝나면 끝난다(끝나지 않으면 5초 뒤 강제로 끝낸다).

## 에이전트 모드 (결정 0032, 0049)

사람이 홈의 "에이전트" 창에서 프로젝트 폴더를 골라 시작했을 때만, 구독 프로그램이 자기 도구를 켠 채로 그 폴더에서 일한다. CLAUDE.md 3번의 "정해 둔 도구"는 결정 0049부터 Claude Code의 10개 도구와 앱 MCP 서버의 13개 도구, Codex의 격리된 자체 도구와 같은 13개 앱 도구를 뜻한다. 기본 AI 창의 규칙(도구 0개, 문서 편집 차례는 `StructuredOutput` 하나)은 그대로이고, 이 창의 실행에만 아래 규칙이 대신 적용된다.

**시작 조건**

- 처음 쓰는 사람은 경고(명령이 파일과 인터넷에 닿는다, 디스크의 파일은 가리기가 적용되지 않는다, 한도를 많이 쓴다)를 읽고 확인해야 한다. 확인한 경고의 판(`AGENT_WARNING_VERSION`)을 앱 설정에 남기고, 뒷단이 시작할 때마다 다시 본다.
- 폴더는 사람이 대화 상자로 고른 절대 경로여야 한다. 드라이브 전체, 사용자 폴더 전체, 아래의 보호 폴더이거나 그것을 품은 폴더는 거절한다.
- 구독 로그인(`ready`)이거나 사람이 허용한 종량 로그인일 때만 시작한다(`subscriptionConnection`). Codex는 대화를 열기 전에 계정 종류를 다시 읽는다.

**보호 폴더**: `~/.claude`(로그인 저장소 포함), `~/.codex`, `~/.genoffice`, `~/.ieumoffice`, 앱 데이터 폴더(키가 든 `ai-settings.json` 포함). 앱의 판단은 이 경로를 읽거나 쓰는 요청과 이 경로를 적은 명령을 어느 허락 방식에서든 거절한다. Claude에는 같은 경로의 읽기·쓰기 거부 규칙을, Codex에는 권한 프로필의 거부(`deny`) 경로로 함께 준다.

**Claude Code**

- 고정된 인자로 띄운다. `--restricted`, `--setting-sources ""`, `--strict-mcp-config`(사용자 설정·훅·플러그인·MCP 없음), `--tools`로 정한 10개 도구(Read, Edit, Write, Glob, Grep, Bash, PowerShell, Skill, WebSearch, WebFetch), `--permission-prompts host --permission-prompt-tool stdio`(권한 요청이 앱으로 온다). `bypassPermissions`와 `--dangerously-skip-permissions`는 쓰지 않는다.
- 설정(`blockReadsOutsideWorkingDirectories`, 거부 규칙)과 MCP 연결 정보(토큰 포함)는 세션 임시 폴더의 파일로 넘긴다. 명령줄에 오르는 가변 값은 모델 이름과 앱이 만든 경로뿐이다.
- 시작 보고의 도구 목록이 위 10개와 앱 MCP 서버의 정해진 13개 도구(`mcp__ieumoffice-editor__〈이름〉`)를 벗어나거나, 다른 MCP 서버가 붙어 있거나, 보고 전에 답이나 권한 요청이 오면 `unsafe-tools`로 끝낸다.
- **Windows에서 명령을 격리하지 못한다.** 허락받은 명령은 사용자 권한으로 PC 전체와 인터넷에 닿는다. 그래서 "이 프로젝트는 믿고 맡기기"도 앱이 모두 허락하는 방식으로 만들지 않고, Claude Code 자체의 `auto` 모드(별도 모델이 행동마다 검사)로 돌린다. `auto`를 쓸 수 없는 세션은 Claude Code가 수동 확인으로 시작한다.
- 웹 도구는 Claude Code 앱의 기본처럼 처음에 묻는다. 묻는 두 방식에서 `WebSearch`는 처음 쓸 때, `WebFetch`는 사이트(호스트)마다 묻고, "이번 세션 동안" 허락은 세션 메모리에만 둔다. "믿고 맡기기"에서는 `auto` 모드가 판단하고, 앱까지 온 요청은 "그 밖의 도구"처럼 묻는다.

**Codex**

- 기본 AI 창과 같은 설정 덮어쓰기로 띄운다. Codex 스스로의 스킬 찾기도 기본 창처럼 끈다(`skills.include_instructions=false`). 스킬은 앱이 만든 묶음으로 준다(아래 "스킬"). 사용자의 MCP 서버는 대화마다 끄고, 앱 MCP 서버만 붙인 뒤 목록으로 확인한다. 앱 MCP 서버의 도구가 정해진 13개를 벗어나면 `unsafe-tools`로 끝낸다.
- 웹 검색은 Codex 앱의 기본처럼 저장된 결과(`web_search="cached"`)로 켜 둔다. 사람이 에이전트 창 시작 화면에서 프로젝트 폴더마다 "실시간"이나 "끄기"로 바꿀 수 있고, 그 값은 세션 전용 프로그램의 덮어쓰기 맨 뒤에 붙어 기본 창의 `web_search="disabled"`를 이긴다(2026-10-21 이 PC의 codex-cli 0.159.2에서 `config/read`로 확인).
- 명령의 인터넷 접속은 기본 꺼짐이다. 사람이 프로젝트 폴더마다 켤 수 있고, 켜면 세션 권한 프로필의 네트워크(`permissions.ieumoffice-agent.network.enabled = true`)를 연다. 사이트 목록은 두지 않는다(Codex 앱의 켜기와 같다). 켤 때 경고를 보인다. 파일 권한, 보호 폴더 거부, MXC 격리는 그대로다. 2026-10-21 이 PC에서 `codex sandbox`로 확인했다: 꺼진 상태는 주소 해석부터 실패하고, 켠 상태는 바깥 주소에 닿고, 두 경우 모두 거부 폴더는 읽히지 않았다. 네트워크를 끈 대화가 네트워크 열림을 보고하면 `unsafe-tools`로 끝낸다.
- Codex의 MXC 격리(`windows.sandbox="mxc"`)로 띄우고 권한 프로필 `ieumoffice-agent`로 대화를 연다. 읽기는 운영체제 최소 경로(`:minimal`)와 PATH에 있는 프로그램 폴더(드라이브 루트, 보호 폴더, 프로젝트 폴더 제외)만 열린다. 프로젝트 폴더는 쓰기, 탭에 열린 문서와 스킬 묶음은 읽기 전용, 보호 폴더는 거부(`deny`), 인터넷은 사람이 켜지 않는 한 막힌다. 2026-10-15 이 PC(Windows 11 빌드 26200, codex-cli 0.159.2)에서 확인했다. Codex 로그인 폴더, 문서 폴더, 인터넷은 거부됐고 프로젝트 쓰기와 node·python 실행은 됐다. 사용자 설정이 `sandbox_mode = "danger-full-access"`여도 이 프로필이 이긴다.
- 세션을 열기 전에 이 PC에서 격리를 직접 시험한다(Windows, 모델 호출 없음, 약 0.5초). 같은 프로필에 시험용 읽기 폴더와 거부 폴더를 더해 `codex sandbox`로 `findstr`를 돌린다. 거부한 표식 파일이 읽히면 `unsafe-tools`로, 허용한 표식 파일도 읽히지 않으면(격리가 뜨지 않음) `sandbox-unavailable`로 시작하지 않고 이유를 창에 알린다.
- MXC를 쓸 수 없는 PC에서는 대화가 시작되지 않는다. 다른 격리 방식으로 낮춰 돌리지 않는다. 권한 상승 방식 격리는 디스크 전체 읽기(`:root`)가 있어야 시작하고, `~/.codex`를 막으면 시작이 끝나지 않거나 80초 넘게 걸려 쓰지 않는다.
- 승인 정책은 묻는 두 방식에서 `untrusted`, "믿고 맡기기"에서 `never`다. `on-request`는 쓰지 않는다. 그 정책에서 허락받은 명령은 격리 밖에서 실행된다(2026-10-15 확인: 허락한 문서 폴더 쓰기가 됐다). `untrusted`에서는 허락받은 명령도 격리 안에서 실행되어 같은 쓰기가 거부됐다. 대화가 요청한 프로필이나 승인 정책과 다르게 열리면 끝낸다.
- 앱 MCP 서버에는 `default_tools_approval_mode = "approve"`를 준다. 앱이 만든 도구이고 스스로 제한(가리기, 열린 문서만)을 지키기 때문이다. 이것이 없으면 `never` 정책("믿고 맡기기")에서 Codex가 앱 도구를 묻지 않고 거절한다(2026-10-15 확인).
- Codex가 보내는 요청 가운데 앱이 답하는 것은 명령·파일 변경 승인(앱의 판단을 거친다)과 앱 MCP 서버의 도구 호출 확인(MCP elicitation 중 `codex_approval_kind: mcp_tool_call`, 허락. 위 설정이 있으면 보통 오지 않는다)뿐이다. 더 넓은 권한, 질문, 다른 서버의 elicitation, 로그인 토큰 갱신 요청은 거절한다.

**허락 방식**과 앱의 판단은 `docs/business-rules.md`의 "에이전트 모드"에 있다. 어느 방식에서든 탭에 열린 문서의 파일 쓰기, 프로젝트 폴더 밖 쓰기, 보호 폴더는 거절된다.

**앱 MCP 서버(세션 전용)**: 세션마다 따로 연다. 루프백, 운영체제가 고른 빈 포트, 세션마다 새로 만든 토큰(`Authorization: Bearer`)을 요구한다. 사람이 연동에서 켜는 앱 안 MCP 서버와 별개이고, 그것이 꺼져 있어도 세션 동안만 열린다. 도구는 13개다. 열린 문서의 읽기·고치기, 프로젝트 폴더 안의 한글·PDF 읽기, 그리고 스킬 둘이다. `propose_skill`은 에이전트 창에 스킬 카드를 띄우기만 하고, `propose_skill_install`은 깃허브 미리보기를 띄우기만 한다. 둘 다 파일을 쓰거나 설치하지 않으며, 저장과 설치는 사람이 창에서 누를 때 앱이 한다. 탭 닫기, 자체 편집 세션, 창 없는 파일 만들기는 없다.

**가리기**: 앱 MCP 서버의 읽기는 가린 자리를 `{{이름}}`으로 내보낸다(PPT는 덱 읽기, 마크다운·HTML은 `file-parse`의 함수). 가린 내용이 있는 PPT는 이 서버로 고치지 않는다. 그러나 **프로그램이 디스크에서 직접 읽는 파일에는 가리기가 적용되지 않는다.** 허락받은 명령이 읽는 파일도 같다. 저장소 주인이 이 한계를 받아들였고(2026-10-15), 시작 경고와 개인정보 문서가 알린다. 워드 문서는 원래 가리기가 닿지 않는다.

**스킬**: 세션을 시작할 때 켜진 스킬("사용자 스킬" 절)과 그 프로젝트의 스킬(`.claude/skills`, `.agents/skills`. 사람이 그 폴더에서 켰고 그 뒤로 파일이 바뀌지 않았을 때만, 결정 0064)을 앱이 묶음 폴더 하나(`%LOCALAPPDATA%\IeumOffice\agent-skills`)로 복사한다. 보호 폴더인 앱 데이터 폴더에 두면 프로그램이 읽지 못해 이 위치에 둔다. 복사는 스킬 폴더 밖으로 이어지는 링크를 따라가지 않는다. 같은 이름은 우선순위에서 밀린 것을 `〈이름〉--〈출처〉`로 넣고, "부를 때만" 스킬은 사본 앞머리에 `disable-model-invocation: true`를 넣는다. Claude에는 이 묶음을 플러그인(`--plugin-dir`)으로, Codex에는 읽기 경로와 지시문의 목록(이름, 설명, `SKILL.md` 절대 경로)으로 준다. 설치된 Claude 플러그인의 스킬이면 `${CLAUDE_PLUGIN_ROOT}`가 가리키는 파일을 위해 그 플러그인 루트의 `scripts`, `references`, `assets` 세 폴더만 묶음 루트로 함께 복사한다. 플러그인 루트의 다른 파일과 폴더(훅, MCP·LSP 서버 설정, `monitors`, `bin`, `settings.json`, 에이전트, 명령 등)는 복사하지 않는다. 그중 일부는 도구 호출도 권한 요청도 없이 프로세스를 띄우기 때문이다. 사용자 설정을 그대로 읽게 하지 않는 것도 같은 까닭이다. 그렇게 하면 모델을 부르기 전에 사용자 훅이 실행됐다(2026-10-15 확인). 묶음은 모든 세션이 같이 쓰므로, 도는 세션이 있는 동안 다른 세션을 시작하면 사본이 바뀔 수 있다.

**수명**: 프로그램은 실제 실행 파일로 셸 없이 띄우고 자식 등록부에 올린다. 사람이 멈추거나, 에이전트 창을 닫거나, 30분 동안 쓰지 않거나, 앱이 끝나면 하위 프로세스까지 끝낸다. 세션 임시 폴더와 세션 MCP 서버도 함께 정리한다.

## 사용자 스킬 (결정 0048)

**읽는 곳과 쓰는 곳.** 스킬은 기본(앱 설치 폴더), 내 스킬(`~/.ieumoffice/skills`), Claude 스킬 폴더(`~/.claude/skills`), 설치된 Claude 플러그인의 `skills`, Codex 스킬 폴더(`~/.agents/skills`)에서 읽는다. 에이전트 창은 프로젝트 폴더의 `.claude/skills`, `.agents/skills`를 더 읽는다.

- `~/.codex` 안은 어떤 경로로도 읽지 않는다. 출처 폴더와 스킬 폴더를 실제 경로로 풀어 확인하고, 스킬 폴더 안에서는 폴더 밖으로 이어지는 링크를 따라가지 않는다(`SKILL.md`가 그런 링크면 읽을 수 없는 스킬로 본다).
- 이름이 `genoffice`, `ieumoffice`인 스킬은 어느 출처에서든 읽지도 보이지도 않는다. 숨은 폴더(`.`으로 시작)도 스킬로 보지 않는다.
- 파일을 쓰는 곳은 `~/.ieumoffice/skills` 하나다. 다른 출처는 읽기만 한다. 지우기는 운영체제 휴지통으로 옮긴다. 설치·저장은 임시 폴더에 다 쓴 뒤 옮겨 반쯤 쓴 폴더를 남기지 않는다.
- 켜기·끄기, 가져오기, 설치, 업데이트, 내보내기, 지우기는 설정 창(메인 창)에서 온 요청만 받는다. 에이전트 창에는 깃허브 설치 미리보기에 필요한 세 가지(`importGitHub`, `cancelImport`, `install`)만 더 열려 있고, 설치는 사람이 [설치]를 눌러야 된다.

**기본 AI 창에서 쓰는 방식.** 구독 프로그램은 지금처럼 앱 밖에 닿는 도구 없이(도구 0개, 문서 편집 차례는 `StructuredOutput` 하나), 슬래시 명령 끔, 스킬 지시문 끔으로 띄운다. 스킬은 앱이 본문을 읽어 요청에 넣는다. 스킬 관련 도구(`use_skill`, `read_skill_file`, `propose_skill`)는 앱이 정의하고 앱이 실행한다. 스킬의 스크립트는 기본 AI 창에서 어떤 경우에도 실행되지 않는다. 본문의 `` !`명령` `` 같은 표기도 글자 그대로 보낼 뿐이다. 프로그램의 스킬 기능을 켜면 스킬 본문의 셸 명령이 모델 호출 전에 실행될 수 있어 쓰지 않는다.

- `read_skill_file`은 켜진 스킬 폴더 안의 글 파일만, 200KB까지 읽는다. 꺼진 스킬, 에이전트 창 전용 스킬, 폴더 밖 경로는 거절한다. 뒷단이 다시 확인한다.
- `propose_skill`은 파일을 쓰지 않는다. 카드의 [저장]을 눌러야 앱이 쓴다.

**깃허브에서 받기.** 사람이 가져오기나 업데이트 확인을 누를 때만 연결한다. 연결하는 곳은 `github.com`, `api.github.com`, `codeload.github.com` 셋뿐이고, 넘겨받는 주소도 이 셋이어야 한다. 쿠키와 인증 머리글은 보내지 않는다.

- 받는 압축본은 50MB까지다. 풀기 전에 압축 폭탄 검사를 거친다. 절대 경로·`..`·백슬래시 같은 위험한 경로는 압축본 어디에 있든 전체를 거부하고, 링크 항목은 가져오는 경로 안에 있으면 거부한다.
- 미리보기(파일, 스크립트 포함 여부, 글 안의 웹 주소, 라이선스)를 거치지 않는 설치 길은 없다. 화면은 "믿을 수 있는 곳에서 받은 스킬만 설치하세요"를 늘 보인다.

**양식 문서.** 스킬에 넣는 양식은 문서의 바이트 사본이다. 가린 내용이 있는 문서는 "원래 문서 그대로 저장"으로 양식이 되지 않는다. 가리기를 인식하지 않는 형식(워드 등)은 막을 표시가 없다. 에이전트 창에서 탭에 열린 PDF처럼 판정할 수 없는 문서도 "그대로 저장"을 막는다.

## 프로젝트 폴더 (결정 0088)

사람이 AI 창에서 프로젝트(PC의 폴더 하나)를 고르면, 그 폴더의 지침·기억·파일 이름 목록이 요청에 붙고 AI가 그 폴더의 파일을 읽을 수 있다. 지침·기억·대화는 그 폴더의 `.ieumoffice/`에 쌓인다. 동작 규칙은 `docs/business-rules.md`의 "프로젝트 폴더", 폴더 안 파일의 모양은 `docs/contracts.md`의 "프로젝트 폴더"에 있다. 에이전트 모드와 이어 붙이는 일은 이번 범위 밖이다(아래 "남는 것").

**사용자 폴더에 쓰는 것.** 앱이 사람의 저장 없이 사용자 폴더에 쓰는 것은 둘뿐이다. 하나는 등록된 프로젝트 폴더의 `.ieumoffice/` 아래 파일이고, 다른 하나는 프로젝트를 고른 실행에서 AI가 만든 새 문서다(그 프로젝트 폴더 안에, 이름이 겹치면 `(2)`를 붙여 덮어쓰지 않고, 만들기가 성공했을 때만).

- 쓰는 곳은 껍데기 앱 뒷단의 프로젝트 길잡이(`apps/shell/src/main/projects/`) 하나다. 모든 쓰기가 같은 확인 함수를 지난다. 쓰는 경로를 정식 경로로 풀어, 그 프로젝트 폴더 아래이고 `.ieumoffice/` 안(또는 새 문서)인지 매번 본다. 링크를 따라가지 않는다.
- JSON·MD는 같은 폴더의 임시 파일에 쓴 뒤 이름을 바꾼다. 같은 파일에 대한 쓰기는 뒷단에서 한 줄로 세운다. 기억은 쓰기 직전에 파일을 다시 읽어 그 위에 고친다.
- `.ieumoffice/`는 폴더를 고른 것만으로 만들지 않는다. 처음 무엇을 써야 할 때(지침 저장, 기억, 대화, 이름 바꾸기) 만든다. 사람이 고르지 않은 폴더에는 만들지 않고, 프로젝트 폴더 밖에는 쓰지 않는다.
- 등록할 수 없는 폴더는 에이전트 모드와 같다. 드라이브 전체, 사용자 폴더 전체, 보호 폴더(`~/.claude`, `~/.codex`, `~/.genoffice`, `~/.ieumoffice`, 앱 데이터 폴더)이거나 그것을 품은 폴더는 거절하고 까닭을 보인다.
- 복구 사본과 제목 없는 문서는 지금처럼 앱 데이터에만 둔다(아래 "복구 사본과 세션 기록").

**폴더에 쓸 수 없을 때.** 읽기 전용 공유 폴더, 권한 없음, 빠진 USB 등으로 `.ieumoffice/`에 쓰지 못하면, 그 프로젝트를 앱이 켜져 있는 동안 "쓸 수 없음"으로 표시하고 AI 창에 "이 폴더에 쓸 수 없어 대화·기억이 저장되지 않습니다"를 보인다. 미리 시험 삼아 써 보지 않는다(고른 것만으로 `.ieumoffice/`를 만들지 않으므로). 지침과 파일 읽기는 그대로 쓰고, 대화는 그 창이 열려 있는 동안 화면과 모델 입력에만 있으며, `project_remember`는 목록에서 빠진다. 앱 데이터로 몰래 대신 저장하지 않는다. 실패를 삼키지 않는다. 다음 실행이나 프로젝트 화면의 [다시 시도] 때 다시 쓴다.

**도구와 범위.** 새 도구 넷(`project_list_files`, `project_search`, `project_read`, `project_remember`)은 앱이 정의하고 앱이 실행한다. 구독 프로그램에 도구를 더 켜지 않는다(절대 규칙 3, 결정 0001, 0082).

- 범위는 뒷단이 지킨다. 화면은 프로젝트 id만 넘기고, 뒷단이 그 실행의 범위 값을 만든다(결정 0020의 방식에 "프로젝트 폴더" 종류를 더함). 화면이 보낸 경로나 목록을 믿지 않는다.
- 호출마다 뒷단이 다시 본다. 경로가 프로젝트 폴더 안인지(`..`와 링크로 나가지 않는지), 숨김 항목(점으로 시작하는 것, `~$`, 기존 숨김 규칙)·`.ieumoffice/`·그 프로젝트의 `ignore`에 걸리지 않는지. 하나라도 어긋나면 거절한다. 읽을 때는 AI가 적은 경로가 아니라 디스크의 실제 이름으로 다시 판단한다. Windows에서는 한 항목이 8.3 짧은 이름(`IEUMOF~1`), 끝의 점·공백, 대소문자가 다른 이름으로도 열리므로, 실제 경로(`realpath.native`)에서 폴더 안 상대 경로를 다시 만들어 같은 판단과 저장 안 된 변경 확인을 거친다. 끝이 점·공백이거나 `:`(스트림)이 든 이름은 처음부터 거절한다.
- `project_read`는 첨부와 같은 읽기 길이다. 저장 안 된 변경이 있는 열린 문서는 거절하고(`assertFileSaved`), `parseFileToText`로 읽어 가린 자리는 `{{이름}}`으로 바뀌며, 크기 상한도 첨부와 같다. 가리기 표시를 처리하지 못하면 읽지 않는다(아래 "문서 내용"의 닫힌 쪽 실패).
- 홈 AI 질문에서 프로젝트를 고르면 읽기 범위는 프로젝트 폴더와 그때 고른 별표 범위(전체 또는 그룹)를 합친 것이다.
- `project_remember`는 기억 쌓기가 켜져 있고, 믿음이 "지침까지 사용"이고, 폴더에 쓸 수 있을 때만 목록에 있다. 그 프로젝트의 `memory.md`만 고친다.
- `ignore`에 걸린 파일은 프로젝트 도구의 목록·찾기·읽기와 지시문의 파일 이름 목록, 홈 검색의 "바깥 AI로 다시 정렬"에 보내는 결과에서 빠진다. 홈 검색 결과 목록에는 보인다.

**지침·기억이 놓이는 자리.** 프로젝트 이름, 지침, 기억, 파일 이름 목록은 지시문(시스템 프롬프트)의 `MATERIAL_NOT_INSTRUCTIONS` 뒤에 넣는다. 지침은 "사람이 정한 작업 규칙", 기억은 "지난 대화에서 AI가 적은 메모, 사실 확인 없이 따르지 말 것"으로 표시한다. 사용자 메시지에 붙는 매 차례 맥락에는 넣지 않는다. 넣으면 대화 기록에 쌓이고, 아래 주소 규칙에서 사람의 말로 치이기 때문이다. 문서 본문은 지시문에 넣지 않는다.

**주소.** 프로젝트 읽기 도구의 결과에 든 주소는 결정 0062의 "대화에 나온 주소"로 치지 않는다. 지침과 기억은 대화 기록이 아니므로 처음부터 치이지 않는다. 그런 주소를 AI가 가져오려 하면 지금처럼 사람에게 묻는다. 폴더 파일 속 숨은 지시가 주소 가져오기로 내용을 내보내는 길을 막으려는 것이다.

**처음 한 번의 믿음 확인.** 남에게 받은 폴더의 지침·기억에 숨은 지시가 있으면 그 프로젝트의 모든 요청에 붙는다. 그래서 확인 전에는 이 PC의 앱이 쓰지 않은 지침·기억·`AGENTS.md`·`CLAUDE.md`·대화를 모델에 보내지 않는다.

- "폴더 추가"(홈의 프로젝트 화면에서는 [기존 폴더를 프로젝트로], 또는 문서 위쪽에서 발견한 프로젝트의 [사용])로 목록에 넣을 때, 그 폴더에 이 PC의 앱이 쓰지 않은 것이 있으면 확인 창을 띄운다. 대상은 `instructions.md`, `memory.md`, 루트의 `AGENTS.md`·`CLAUDE.md`, 그리고 다른 PC에서 쓴 대화(대화 정보나 메시지 하나라도의 `origin`이 이 PC의 설치 값과 다른 것)다. 다른 PC의 대화를 넣은 것은, 가짜 대화를 심어 확인을 돌아가는 길을 막으려는 것이다. 창은 앞의 넷의 내용과 그런 대화의 목록(제목, 시각)을 보이고 [지침까지 사용]·[지침 없이 사용]을 고르게 한다. [취소]를 누르거나 고르지 않고 닫으면 추가를 취소한다.
- [지침 없이 사용]이면 지침·기억·`AGENTS.md`·`CLAUDE.md`를 요청에 넣지 않고, 다른 PC의 대화를 목록에 보이지 않으며, 기억 쌓기를 멈춘다. 파일 읽기 도구와 이 PC의 대화는 쓴다.
- 이 PC의 앱이 "새 프로젝트"로 만든 폴더와 확인할 것이 없는 폴더는 묻지 않는다. 믿음 기록은 폴더가 아니라 이 PC의 `app-settings.json`에 있다.
- 그 뒤로는 묻지 않는다. 앱이 쓰거나 프로젝트 화면에서 고칠 때마다 내용의 해시를 적고, 실행 때 해시가 다르면(앱 밖에서 바뀜) 그대로 붙이되 AI 창에 "지침이 바뀌었습니다 [보기]"를 한 번 보인다. 옛 내용은 이 PC에 남기지 않는다. 매번 물으면 읽지 않고 누르게 되기 때문이다(결정 0064가 "시작할 때마다 묻기"를 버린 이유와 같다).
- **남는 위험.** 한 번 믿은 동기화·공유 폴더의 지침을 남이 바꾸면 다음 요청부터 붙는다. "바뀜" 줄이 이것을 알린다. 기본 AI 창은 프로그램 도구가 없어 숨은 지시가 닿는 범위는 그 편집기의 문서 고치기와 앱 도구이고, 주소 가져오기는 위 규칙대로 사람에게 묻는다. 저장소 주인이 이 위험을 받아들였다.
- 문서 파일 자체는 지금처럼 확인하지 않는다. 자료이지 지시가 아니다(`MATERIAL_NOT_INSTRUCTIONS`).

**클라우드 전용 파일.** 동기화 폴더의 "PC에 없는" 파일은 여는 순간 내려받기가 일어난다.

- 프로젝트 폴더 안에서는 그런 파일(Windows 파일 특성 `RECALL_ON_DATA_ACCESS`·`RECALL_ON_OPEN`·`OFFLINE` 중 하나)을 앱이 스스로 열지 않는다. 판정할 때도 파일 내용을 열지 않는다. 색인에는 이름만 넣고, 파일 목록에는 "PC에 없음"으로 보인다.
- AI가 `project_read`로 그런 파일을 읽으려 하면 껍데기 뒷단의 대화 상자로 "'<파일>'은 PC에 없어 내려받아야 합니다. 내려받을까요?"를 묻는다. 사람이 [내려받기]를 누를 때만 읽고, 아니면 도구가 "사람이 내려받기를 거절했다"를 돌려준다.
- 특성을 알아낼 수 없는 PC(Mac·Linux, 판정이 실패한 경우)에서는 알려진 동기화 폴더(`OneDrive`·`OneDriveConsumer`·`OneDriveCommercial` 환경 변수의 폴더, Google 드라이브 데스크톱의 드라이브·폴더) 아래 파일을 모두 그런 파일로 본다.
- 이 규칙은 경로로 정한다. 프로젝트 폴더가 홈에서 더한 폴더나 기본 저장 폴더 안에 있어도 프로젝트 폴더 안 파일에는 이 규칙이 적용된다. 프로젝트 폴더 밖(홈에서 더한 폴더 등)의 지금 색인 동작은 바꾸지 않았다.
- 사람이 직접 고른 것(홈 검색 결과 열기, `@`나 첨부로 고른 파일, 별표 파일)은 지금처럼 다룬다. 묻지 않는다.

**동기화 폴더.** 동기화 폴더를 처음 프로젝트로 고를 때 한 번 "이 폴더는 동기화 폴더라 지침·기억·대화도 그 서비스로 올라갑니다"를 알린다. 사람이 고른 폴더이므로 막지 않는다. `PRIVACY.md`에 적었다.

**남는 것.** 에이전트 모드의 세션은 프로젝트 폴더에 쓸 수 있으므로 그 폴더의 `.ieumoffice/`(지침·기억·대화)도 바꿀 수 있다. 앱의 쓰기 확인과 믿음 확인을 거치지 않는 길이다. 에이전트 쪽의 쓰기 거부는 결정 0088의 5단계에서 넣는다(`docs/tracking/findings.md`).

## 자동 호출 경로

- 터미널 명령어와 MCP로 들어온 요청은 화면을 보는 사람이 아니라 프로그램이 보낸 것이다. 구독 사용은 기본 꺼짐이고, 사용자가 경고를 읽고 켠 뒤에만 된다. 경고는 시간당 한도가 없다는 것, 문서 전체의 글과 페이지 그림이 보내질 수 있다는 것, 계정이 제한될 수 있다는 것을 알린다.
- 켜 둔 스위치는 동의한 경고의 판(`headlessSubscriptionConsentVersion`)과 함께만 유효하다. 시간당 한도가 있던 예전 경고에 동의한 스위치는 꺼진 것으로 읽고, 새 경고에 다시 동의받는다. 사용자가 동의하지 않은 조건으로 구독이 쓰이지 않게 하려는 것이다.
- 켜져 있으면 횟수 한도가 없다. 이 경로의 모든 요청(검색·사진 분석·PDF 명령·EPUB 번역)에 같다. 남는 것은 요청을 하나씩 차례로 처리하는 것뿐이다. 차례는 요청 단위라 긴 작업이 다른 호출자를 막지 않는다. 장부에는 최근 한 시간의 요청 수가 정보로만 남고, 장부가 망가져도 요청을 막지 않는다.
- 횟수 한도가 없으므로 에이전트가 반복 호출하면 구독 한도를 다 쓰거나 계정이 제한될 수 있다. 이 위험은 켤 때의 경고로 알리고, 사용자가 받아들인 경우에만 켜진다(결정 기록 0011).
- PDF의 AI 페이지 읽기와 번역, EPUB 책 번역(`epub translate`, `epub_translate`)은 `--yes`(MCP는 `yes`)가 있어야 보낸다. 요금이 나가는 경로면 `--allow-paid`(`allow_paid`)도 있어야 한다. 대화용으로 키 제공자를 골라 둔 경우도 같다.
- 이 경로는 앱의 설정 파일과 종량 허용 기록을 읽기만 한다. PDF 명령과 EPUB 번역은 보관소(아래 "PDF 결과 보관소")를 읽고 쓴다.

## 바깥 호출자

앱에 일을 시킬 수 있는 바깥 프로그램은 넷이다. 각각 무엇을 할 수 있고 무엇을 할 수 없는지:

| 누가                                             | 할 수 있는 일                                                          | 조건                                                                                                                                             | 할 수 없는 일                                                                                       |
| ------------------------------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| 터미널에서 `ieumoffice`를 부르는 사용자·에이전트 | 파일 읽기·만들기·고치기·변환, 검색·이미지·미디어·주소로 문서 읽기 명령 | 그 사용자 권한 그대로. `GENOFFICE_ALLOWED_ROOTS`가 있으면 그 폴더들 안에서만                                                                     | 구독 사용(사용자가 설정에서 켜기 전에는). `GENOFFICE_ALLOWED_ROOTS`가 없으면 경로 제한은 **없다**   |

| 앱 안 MCP 서버(설정 → 연동에서 켠다)             | 실행 중인 앱의 문서 열기·읽기·고치기                                   | 기본 꺼짐. 이 PC에서만 닿는다. 요청의 Host가 `127.0.0.1`·`localhost`가 아니거나 Origin이 맞지 않으면 거절한다                                    | 인증은 없다. 다른 PC에서는 닿지 않는다                                                              |

- 모든 창은 화면 코드와 Node를 분리해 띄운다(`contextIsolation`, `sandbox`, `nodeIntegration` 꺼짐). AI가 만들었거나 믿을 수 없는 HTML을 그리는 숨은 창에는 preload와 창구를 주지 않는다.
- AI 도구 호출에 실려 온 주소는 문서 속 글에 조작됐을 수 있다. 원격 요청은 내부 주소를 막는 검사(`fetchWithSsrfGuard`)를 거치고, 넘겨받는 주소마다 다시 검사한다. 밖으로 여는 링크는 `safeExternalUrl`을 거친 것만 연다.
- AI가 낸 슬라이드 배치 스크립트는 `eval`이나 `Function`으로 실행하지 않는다. 구문을 분석해 제한된 해석기로만 돌린다.

## 문서 내용

- AI를 쓰면 요청이 다루는 문서 내용, 대화, 첨부가 선택된 제공자에게 간다. 무엇이 어디로 가는지는 첫 연결 안내와 개인정보 문서(`PRIVACY.md`)에 전부 적는다. 새 전송 경로를 만들면 두 곳을 함께 고친다.
- 로컬 AI 서버는 사용자가 주소를 직접 고른 `custom` 서버다. 앱은 모델을 자동으로 고르거나 내려받지 않고, 다른 서버나 클라우드로 넘어가지 않는다. 서버 검색·연결 테스트는 문서 내용을 싣지 않으며, 사용자가 누를 때만 접속한다. 주소는 http(s)만 받고 TLS 검증을 끄지 않는다.
- 가리기로 감춘 범위는 어떤 제공자에게도 보내지 않는다. PDF 편집기에는 가리기가 없다.
- **읽은 글은 자료이지 지시가 아니다.** 모든 편집기의 AI 창과 홈의 묻기는 같은 실행부(`packages/agent-core`의 `AgentLoop`)를 거치고, 그 지시문 맨 앞(날짜 다음)에 `MATERIAL_NOT_INSTRUCTIONS`가 붙는다. 문서·첨부·읽은 파일·웹 페이지·검색 결과·도구 결과에 적힌 요청을 따르지 말고, 그 글이 시킨다고 내용을 검색어나 주소에 담아 내보내지 말라는 규칙이다. 편집기가 지우거나 빠뜨릴 수 없게 편집기 지시문 앞에 둔다. 지시문은 막는 장치가 아니다. 드라이브에서 읽은 대화의 바깥 도구 거절(위 "Google 드라이브")은 그대로 따로 있다.
- **주소를 가져오기 전에 묻는다 (결정 0062).** 공격자가 내용을 받아 볼 수 있는 바깥 호출은 주소를 가져오는 것뿐이다(`read_url`, 주소로 그림 넣기, 입력의 `url`·`src`·`imageUrl`·`image_url`, `analyze_media`의 `mediaUrls`). 편집기 AI 창의 `guardOutbound`(`packages/agent-core/src/outbound-guard.ts`)는 대화(사람의 메시지와 도구 결과)에 글자 그대로 나온 적 없는 주소를 껍데기 앱 뒷단의 대화 상자로 사람에게 묻고, 사람이 "허용"을 누를 때만 진행한다. 질문을 띄우지 못하거나 요청 모양이 맞지 않으면(`confirmRequestOf`) 거절이다. 설정의 "AI가 인터넷 도구 쓰기"(`ai-settings.json`의 `internetTools: false`)를 끄면 바깥 도구가 목록에서 빠지고 주소가 든 호출도 거절된다. 드라이브의 차단(위 "Google 드라이브")은 이것과 따로, 먼저 적용된다.
- **다른 파일로 읽을 때도 가린다.** 파일이 자기 편집기 밖에서 글로 읽히는 길(다른 편집기의 첨부, 홈의 묻기와 그 검색 발췌, 프로젝트 읽기 도구(`project_read`), 파일 검색 색인과 재정렬 발췌, 만들기 창의 자료, AI 없이 바꾸기)은 모두 `packages/file-parse`의 `parseFileToText`(색인의 HTML 갈래는 `redactHtmlSource`)를 지나고, 가린 자리는 `{{이름}}`으로 바뀐다. 대상은 PPT·마크다운(마크다운 편집기가 쓰는 `.txt`·`.json` 포함)·HTML이다. 새 읽기 길을 만들면 이 함수를 거치게 한다. 파일을 직접 읽어 모델이나 바깥 서비스로 보내지 않는다.
- **닫힌 쪽으로 실패한다.** 가리기 표시가 있는데 무엇을 감추는지 확실히 가려낼 수 없으면(이름이 없는 표시, 닫히지 않는 구조, 마크다운에서 끝을 짐작해야 하는 구간, HTML 파서와 검사가 엇갈리는 표시) 원문을 내주지 않고 읽기 실패(`RedactionMarkError` → `{ ok: false }`)를 낸다. 그 파일은 첨부되지 않고 색인에 본문이 들어가지 않는다. 덜 가리느니 읽지 않는다.
- **저장하지 않은 파일은 읽지 않는다.** 가리기 표시는 저장해야 파일에 들어간다. 다른 탭에 열려 있고 저장하지 않은 변경이 있는 파일은 첨부, 묻기의 읽기, 프로젝트 읽기 도구, 엑셀의 첨부 통합 문서 합치기에서 거절되고(`assertFileSaved`), 만들기 창에서는 그 자료 때문에 만들기가 막히고(`fileHasUnsavedChanges`), 묻기의 검색 발췌와 재정렬 발췌에서 빠진다(`withoutUnsavedFiles`). 열린 탭 목록은 껍데기 앱만 알고, 편집기 뒷단은 `packages/electron-utils`의 `unsaved-files.ts`로 묻는다.
- PC 밖으로 나가는 색인 발췌(묻기의 검색, 재정렬)는 색인된 뒤로 디스크에서 바뀌지 않은 파일에서만 뽑는다(`pathsIndexedAsOnDisk`). 가리기를 넣고 저장했지만 아직 다시 색인되지 않은 파일의 예전 본문이 나가지 않게 하기 위해서다. 이 규칙 전에 만든 색인은 처음 실행될 때 통째로 지우고 새로 만든다(색인의 `extract` 판 번호).
- **미치지 않는 곳.** 워드(`.docx`)의 가리기 표시는 다른 파일로 읽을 때 적용되지 않고, 워드 편집기 자신도 인식하지 않는다. 표시의 모양을 원본 프로그램의 코드로 확인하지 못했기 때문이다. 터미널 명령어(`ieumoffice`), 그 MCP 서버, 앱 안 MCP 서버의 읽기는 가리기를 적용하지 않는다. 에이전트 모드의 프로그램이 디스크에서 직접 읽는 파일도 같다(위 "에이전트 모드"). 둘 다 `docs/tracking/findings.md`와 `PRIVACY.md`에 적어 두었다.
- **만들기의 자료도 첨부다.** 만들기 창은 자료의 글 길이만 재고 글을 버린다. 자료는 만들 문서 쪽 편집기의 첨부로 들어가 그 편집기의 첨부 읽기(위 규칙)로 읽히고, 실행은 그 편집기의 보내기 전 판단을 지난다. AI 없이 바꾸기는 바깥으로 아무것도 보내지 않는다.
- **"이음오피스 문서에서 첨부"도 같은 규칙을 지난다 (결정 0035).** 고르기 창은 껍데기 앱이 띄우는 별도 창(preload `doc-picker`)이다. 저장된 문서의 식별자는 그 경로이고 창은 폴더도 보여 준다. 껍데기 앱은 방금 창에 건넨 목록에서 고를 수 있는 상태(`ok`)인 식별자일 때만(정해진 길이 상한 안에서) 받아들인다. 편집기 화면은 이미 아무 경로나 첨부로 읽게 할 수 있으므로 경로를 감추는 것은 보호가 아니고, 막는 것은 이 목록 확인이다. 저장 안 된 변경이 있는 문서(`modified`)와 저장하지 않은 문서는 고를 수 없다. 입력란의 `@` 목록(결정 0051, 요청 `doc:attach-list`)도 같은 목록을 편집기 화면에 경로와 함께 건네고, 고른 문서는 같은 첨부 길로 읽힌다. 고른 파일은 그 편집기의 PC 파일 첨부와 같은 길로 읽히므로 위의 가리기·저장하지 않은 파일 거절이 그대로 적용된다. 목록을 만들 때도 형식과 크기만 보고 파일 내용은 열어 보지 않는다.
- PDF 편집기의 문서 작업은 대화보다 많이 보낸다. 모두 사용자가 시작을 확인했을 때만 보내고, 대화와 같은 제공자 선택을 따른다.
  - AI 페이지 읽기: 고른 페이지마다 그 페이지의 그림(150~200dpi 상당) 한 장과 읽기 지시문.
  - 문서 번역: 고른 범위(기본은 문서 전체)의 글 블록 전부. 약 2,500토큰씩 묶어 보낸다. 링크 주소, 수식, 각주 표시는 자리 표시자로 바꿔 보낸다.
  - 책 정보 "AI로 채우기": 앞쪽 페이지의 글(3~12쪽, 12,000자까지) 한 번.
  - 터미널 명령어(`pdf ai-read`, `pdf translate`)와 MCP 도구(`pdf_ai_read`, `pdf_translate`)도 같은 것을 보낸다.
- EPUB 책 번역(결정 0066)이 보내는 것. 사용자가 시작을 확인했을 때만 보내고, 대화와 같은 제공자 선택을 따른다. 고른 장의 고칠 수 있는 블록 글 전부를 PDF 번역과 같은 크기로 묶어 보낸다. 굵게·기울임은 `<b>`·`<i>`로, 그 밖의 인라인 요소(링크, 각주 표시, 루비 등)는 번호 붙인 자리 표시로 바꿔 보내고 링크 주소와 속성은 보내지 않는다. 루비의 읽기(`rt`)는 보내지 않는다. 책 제목과 목차 항목 글도 보낸다. 터미널 명령어(`epub translate`)와 MCP 도구(`epub_translate`)도 같은 것을 보낸다. 번역 확인 창은 이 내용을 EPUB 문구로 알린다.
- EPUB 편집기의 AI 창은 대화와 같다. AI가 도구로 읽은 장의 블록 글(같은 표기)과 찾은 글이 그 대화에 실려 간다.
- PDF 읽기 도우미(결정 0043)가 보내는 것. 모두 사람이 누를 때만 보내고, 대화와 같은 제공자 선택을 따른다. 한 번 보내는 것은 AI 창과 같은 보내기 전 판단을, 여러 번 보내는 것은 위 문서 작업의 시작 전 확인을 거친다. 예외는 대역 보기의 페이지 번역 하나로, 구독이면 확인 없이 한 번 누름에 보내고 요금 경로면 탭마다 처음 한 번 요금 문구를 거친다(`docs/business-rules.md`의 "문서 작업").
  - 구절 카드(`E`·`T`, "AI에게 묻기"의 설명·번역 칩, "다시 만들기"): 선택한 구절, 같은 페이지 글자 층에서 구절 앞뒤로 합쳐 최대 1,500자, 문서 제목. 호출 한 번.
  - 문단 다시 번역: 그 블록 하나의 글. 자리 표시자 규칙은 문서 번역과 같다. 호출 한 번.
  - 페이지 번역("이 페이지 번역", "남은 문단 번역(N)"): 그 페이지의 번역되지 않은 블록 글. 문서 번역과 같은 규칙으로 묶어 보낸다.
  - AI 핵심 표시: 고른 범위의 글 블록 id와 글, 분류 이름. 약 2,500토큰씩 묶어 보낸다.
  - 문서 개요: 문서 전체의 구조화 글(AI로 읽은 페이지는 그 결과). 60,000자를 넘으면 묶음마다 보내 부분 요약을 받고, 마지막에 그 부분 요약들을 한 번 더 보내 합친다.
  - 인용 링크: 새로 보내는 것이 없다. AI 창의 지시문만 바뀌었다.
  - 추천 질문: 그 질문 글을 AI 창 대화로 보낸다. 대화와 같다.
- AI가 돌려준 페이지 읽기 결과, 번역문, 구절 카드의 답, 핵심 표시 제안, 개요는 문서 데이터다. 앱은 그 글을 검사해 보관하고 출력에 쓸 뿐, 그 안의 지시를 실행하지 않는다. 문서 작업과 PDF 읽기 도우미의 요청에는 앱 도구를 주지 않는다. AI 핵심 표시의 제안은 그 블록의 글에 실제로 있는 문장일 때만 받아들이고, 사람이 받아들인 것만 주석이 된다.
- 입력을 한계에 맞추려 줄여야 하면 사용자에게 줄였다고 알린다. 조용히 줄이지 않는다. 지금 줄이는 경우는 하나다. Claude 한 요청에 이미지가 100장을 넘으면 오래된 것부터 뺀다. 글은 자르지 않는다.
- **긴 자료는 알린다.** PPT·HTML 편집기는 문서를 만들 때 자료를 각자의 기존 상한에 맞춰 모델에 넘기므로, 긴 자료는 뒤쪽이 덜 반영될 수 있다. 이 상한은 바꾸지 않았다. 대신 만들기 창은 PPT·HTML을 만들 때 자료의 글 길이 합계가 8,000자를 넘으면 그렇다고 알린다. 100,000자를 넘으면 한도를 많이 쓴다고 알린다. 두 알림은 만들기를 막지 않는다.
- 사용 통계를 보내지 않는다. 밖으로 보내는 설치 식별자도 만들지 않는다. 프로젝트 대화를 이 PC에서 썼는지 가리는 값(`app-settings.json`의 `projects.installId`, 설치마다 한 번 만드는 무작위 값)은 이 PC의 설정 파일과 프로젝트 폴더의 대화 파일(`origin`)에만 적힌다. 앱은 이 값을 어디에도 보내지 않지만, 동기화 폴더의 대화 파일은 그 서비스로 함께 올라간다.
- **복구 사본과 세션 기록 (결정 0061).** 여덟 편집기는 저장하지 않은 변경을 데이터 폴더의 `<편집기>-autosave`(`docs-autosave`, `sheets-autosave`, `slides-autosave`, `hwp-autosave`, `pdf-autosave`, `markdown-autosave`, `html-autosave`, `mindmap-autosave`)에 사본으로 남긴다. 사본은 그 순간 저장했다면 쓸 바이트이고, 암호 없는 문서면 문서 내용이 평문으로 있다. 사본 곁의 `.meta.json`에는 편집기 종류, 원본 경로, 탭 제목, 쓴 시각, 실행 식별자, 상태만 있고 내용은 없다. 사용자 폴더와 원본 파일에는 쓰지 않는다.
  - **EPUB은 사본을 만들지 않는다.** 책 화면의 자동 저장이 책 파일에 바로 쓰므로 저장하지 않은 내용이 오래 남지 않고, 데이터 폴더에 책 내용이 따로 쌓이지도 않는다. 갑자기 꺼졌을 때는 세션 기록으로 탭만 되살아난다(결정 0061, 0066).
  - **제목 없는 문서도 앱 데이터 안에만 둔다.** 한 번도 저장하지 않은 문서의 사본은 `<편집기>-autosave/untitled/`에 둔다. 사용자 폴더(문서 폴더, 기본 저장 폴더)에 파일을 저절로 만들지 않는다. 예외는 결정 0088의 두 가지뿐이다. 사람이 등록한 프로젝트 폴더의 `.ieumoffice/` 아래 파일과, 프로젝트를 고른 실행에서 AI가 만든 새 문서다(위 "프로젝트 폴더"). 복구 사본은 프로젝트 폴더 안의 문서여도 앱 데이터에 둔다. 편집기가 작업 파일을 따로 두는 경우는 운영체제 임시 폴더에 둔다. 엑셀의 새 통합 문서(`genoffice-imports`)와 PDF의 되살린 제목 없는 문서(`genoffice-pdf-recovery`, 지금은 지우지 않는다)다. 사용자 폴더에 파일을 만드는 예외로 남은 두 길은 `docs/tracking/findings.md`에 적었다.
  - **지우는 때가 정해져 있다.** 저장, "저장 안 함"과 도구의 저장 없이 닫기, 시작 목록이나 물음의 "버리기", 고친 것 없이 닫은 탭(그 탭이 쓴 사본만), 30일 넘게 손대지 않은 사본(켤 때). 파일이 사본보다 새로워도 조용히 지우지 않는다.
  - **앱이 끝나는 중에는 지우지 않는다.** 종료가 시작되면(`before-quit`, 운영체제의 세션 종료) 공용 저장소의 종료 래치(`markAppShuttingDown`)가 서고, 그 뒤로는 저장 성공과 사람이 고른 "저장 안 함" 말고는 어떤 지우기도 거절된다. 편집기의 닫기 정리가 방금 쓴 사본을 지우지 못하게 하려는 것이다. 닫기가 취소되면 래치를 내린다.
  - **세션 기록**(`session-record.json`)에는 열린 문서 탭의 종류, 파일 경로(제목 없는 문서는 사본의 식별자와 탭 제목), 순서, 앞에 있던 탭, 나눔 상태, 정상 종료 표시, 실행 시작 시각만 있다. 문서 내용은 없다. 크래시 기록(`crash-log.jsonl`, 경로·내용 금지)과 섞지 않는다. 창 없는 PDF 내보내기와 두 번째 실행은 이 기록을 읽지도 쓰지도 않는다.
  - 사본과 세션 기록은 PC 밖으로 나가지 않는다.
- **열기 암호가 걸린 파일 (결정 0041).** 워드·엑셀·파워포인트 파일의 열기 암호는 그 탭의 뒷단 메모리에만 두고, 탭을 닫으면 버린다. 파일·설정·로그에 쓰지 않는다. 저장은 다시 잠근 바이트만 사용자 파일에 쓴다. 엑셀 처리 프로그램은 파일 경로로만 일하므로, 탭이 열려 있는 동안 암호를 푼 사본과 저장 중간 결과가 운영체제 임시 폴더(`genoffice-imports`, `genoffice-sheets-sessions`)에 평문으로 있다. 탭을 닫으면 지우지만, 앱이 비정상으로 끝나면 남을 수 있다. 복구 사본(결정 0061)은 암호를 푼 내용을 평문으로 남기지 않는다. 워드·파워포인트의 복구 사본과 파워포인트의 AI 초안은 같은 암호로 잠그고, 사본을 그렇게 지킬 수 없는 암호 엑셀·암호 한글·암호 PDF는 사본을 만들지 않는다. 그 탭이 처음 열릴 때 한 번 "갑자기 꺼지면 되살릴 수 없다"고 알린다(`unprotectableNoticeText`). 다른 파일로 읽기(첨부, 색인, 빠른 보기)는 암호 파일을 읽지 않고 "암호가 걸린 파일"이라고 알린다.

## EPUB 책을 그리고 고칠 때

- 책은 남이 만든 파일이다. 책 안의 스크립트는 돌리지 않는다. 장은 `sandbox`에서 `allow-scripts`를 뺀 틀(`srcdoc`, `allow-same-origin`)에 그리고, 그리는 사본에서 `script`, `on…` 속성, `javascript:` 주소, 틀과 플러그인, 책의 `base`와 `meta refresh`를 지운다. 사본 머리에 스크립트를 막고 자원을 `epub-asset:`에서만 받는 CSP를 넣는다.
- 그림·스타일·글꼴은 `epub-asset://`로만 받는다. 이 주소는 그 보기에 열린 책 하나의 토큰을 가지고, 그 책 zip 안의 항목만 GET·HEAD로 내준다. zip 밖으로 나가는 경로와 스크립트 항목은 거절하고, 응답에 CSP와 `nosniff`를 붙인다. 원격 그림·글꼴·스타일은 불러오지 않는다. 소리·영상은 재생하지 않는다.
- 책의 zip은 열기 전에 압축 폭탄 관문(`zip-gate`)을 지난다. DRM이 걸린 책은 열지 않는다.
- 바깥 링크는 다른 편집기와 같이 안전한 주소만 기본 브라우저로 연다.
- 편집은 뒷단이 받은 블록 범위 바꾸기로만 일어나고, 번역이 도는 동안과 읽기 전용 장에서는 뒷단이 거절한다. 번역 결과 책은 저장 창에서 사람이 고른 경로에만 쓰고, 원본 책과 다른 탭에 열린 파일의 경로는 거절한다.

## 키와 기록의 보관

- 키 제공자의 키, 이미지·분석·검색 제공자의 키, 직접 운영하는 서버의 키, GitHub 읽기 토큰은 데이터 폴더의 `ai-settings.json`에, 홈 검색의 재정렬 키는 `app-settings.json`에 있다. Windows(DPAPI)와 Linux(GNOME 키링·KWallet이 있을 때)에서는 운영체제 암호화(`safeStorage`)로 봉인해 `sealed:v1:`로 쓴다(결정 0063). 같은 계정으로 도는 프로그램은 풀 수 있고, 파일을 다른 PC나 계정으로 옮기면 풀리지 않는다. 터미널 명령어는 앱을 창 없이 `--reveal-ai-secrets`로 띄워 풀고 메모리에만 둔다. macOS와 키링이 없는 Linux는 평문이다. 사용자 프로필을 읽을 수 있는 사람은 읽을 수 있다. macOS는 ad hoc 서명이라 봉인하면 업데이트마다 키체인 확인 창이 떠서, 개발자 서명 전에는 켜지 않는다.
- Google 드라이브의 갱신 토큰은 예외로, 운영체제 암호화로만 저장한다(위 "Google 드라이브"). 드라이브에서 연 파일의 사본(`drive-cache`)은 문서 내용이고 평문이다.
- 감사 기록은 하나다. 터미널 명령어 실행 기록(`~/.ieumoffice/cli-audit.jsonl`). 명령마다 시각, 인자, 결과, 출력 경로를 한 줄씩 남긴다. `GENOFFICE_AUDIT_LOG=off`로 끌 수 있다.
- 자동 호출 장부에는 요청 시각만 남는다. 내용은 없다.

## PDF 결과 보관소

- 위치는 데이터 폴더 안의 `pdf-store`다(설치본 `%APPDATA%\IeumOffice\pdf-store`). 앱과 터미널 명령어가 같은 곳을 쓴다. `~/.genoffice`는 읽지도 쓰지도 않는다.
- 담는 것: AI가 읽은 페이지의 글(제목·표·수식·각주 포함), 번역문과 그것을 만든 제공자·모델 이름(사람이 고친 번역 블록은 고친 글), 구절 카드(선택한 구절, 그 위치, AI의 답, 제공자·모델), AI 핵심 표시의 분류·고른 페이지와 제안 문장·상태, 문서 개요(세 줄 요약, 요약, 핵심 용어), 끝나지 않은 작업의 기록(종류, 언어 또는 핵심 표시의 분류 열쇠, 진행, 멈춘 이유, 결과 파일 경로), 노트 연결 기록(`note-links.json`: PDF 파일 경로, 노트 파일 경로, 문서 해시, 시각). 문서 내용이 평문 JSON으로 남는다. 암호화하지 않는다. 사용자 프로필을 읽을 수 있는 사람은 읽을 수 있다. 암호가 걸린 PDF의 내용도 마찬가지로 남는다.
- 문서는 파일 내용의 해시로, 페이지는 페이지 내용의 해시로 찾는다. 파일 경로나 이름은 열쇠로 쓰지 않는다. 예외는 둘이다. 작업 기록의 결과 파일 경로, 그리고 `note-links.json`이다. 노트 연결은 PDF 파일 경로(Windows에서는 소문자로 바꾼 절대 경로)를 열쇠로 쓴다. 내용 해시로만 기억하면 PDF를 저장할 때마다 해시가 바뀌어 노트를 잃기 때문이다. 경로로 못 찾을 때만 문서 해시로 찾는다. 그래서 이 파일에는 사용자가 연 PDF와 노트의 경로가 남는다.
- 지우는 법: 설정 → 일반의 "AI 결과 보관소" → "모두 지우기"(EPUB 책 번역과 노트 연결 기록 포함, 노트 파일은 남는다), 또는 PDF 편집기의 "이 문서의 AI 보관분 지우기"(노트 연결 기록과 노트 파일은 남는다). 앱을 지워도 폴더는 남을 수 있다.
- 앱 화면은 보관소의 경로를 직접 다루지 않는다. 편집기 화면은 뒷단이 그 창에 열린 파일에서 계산한 문서 해시로만 읽고 쓰며, 다른 해시는 거절된다.
- **노트 파일의 경로는 허가된 것만 쓴다.** `note-links.json`은 PDF 편집기 메인 프로세스만 읽고 쓴다. 노트 경로로 들어가는 것은 메인 프로세스의 저장 창에서 사람이 고른 경로뿐이고, 메인 프로세스는 이 기록에서 읽은 경로만 노트로 연다. 노트를 여는 채널과 넣는 채널(`pdf:note-open`, `pdf:note-insert`), 저장 여부를 묻는 채널(`pdf:note-unsaved`)은 경로를 받지 않는다. 요청에는 글 조각(구절, 페이지 번호, 본문, 제목)만 실리고, PDF는 그 창에 열린 자기 문서다. 셸도 그 경로가 실제로 있는 `.md` 파일인지 다시 본다. 노트 파일은 처음 만들 때 한 번(없을 때만, 제목 한 줄)만 쓰고, 그 뒤의 "노트에 넣기"는 파일이 아니라 열린 마크다운 탭의 편집기에 넣는다. 이미 있는 파일을 고르면 덮어쓰지 않는다. 넣는 글에서는 그림 문법(`![…]`)과 `<img>`를 백슬래시로 무력화해, 문서 글이나 AI 답 때문에 노트 편집기가 바깥 그림을 받아 오지 않게 한다.
- **주석의 `/Subj` 읽기는 그 창에 허가된 파일만.** 화면의 PDF.js는 주석 제목을 읽지 않으므로, 메인 프로세스가 파일의 주석에서 `/Subj`를 읽어 주는 채널(`pdf:annot-subjects`)이 있다. 그 창에 허가된 경로가 아니면 거절한다.
- 항목 하나가 파일 하나이고 통째로 원자적으로 쓴다. 앱과 터미널이 같은 항목을 동시에 써도 망가지지 않고 나중에 쓴 쪽이 이긴다. 읽을 수 없는 항목은 없는 것으로 보고 다시 만든다.
- 브라우저 저장소에는 작업에 고른 페이지 번호(이어하기 제안용)와 보기 설정(구절 점선·핵심 표시 미리 보기·개요 칸을 켜고 끈 상태, 번역 칸 폭과 글자 크기, 새 PDF를 열 때의 보기)만 둔다. 문서 내용은 없다.

## 설치 파일

- Windows 설치 파일에는 코드 서명이 없다. 자동 업데이트는 서명 없이 동작해야 한다.
- Mac 설치 파일은 ad hoc 서명만 하고 공증하지 않는다(결정 0031). 처음 열 때 사용자가 시스템 설정에서 직접 허용해야 한다. Mac 앱은 업데이트를 내려받거나 설치하지 않고, 새 버전이 있으면 이 저장소의 릴리스 페이지만 연다. 업데이트 정보에 적힌 주소는 따라가지 않는다.
- Mac 설치 파일은 GitHub Actions에서 만들며 저장소의 비밀 값을 쓰지 않는다. 릴리스에 쓰는 권한은 따로 떨어진 작업 하나만 가지며, 그 작업은 `main`에서 손으로 시작한 실행이 태그를 받았을 때만 돈다. 이미 공개된 릴리스에 파일을 붙이기만 하고, 빌드한 버전과 태그가 다르면 멈춘다. 끌어오기 요청(PR)에서 도는 빌드는 읽기 권한만 가진다.
- 보안 문제 신고는 공개 이슈가 아니라 GitHub의 비공개 취약점 신고로 받는다.
