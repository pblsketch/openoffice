# Подключение ИИ-агента

GenOffice говорит на языке Model Context Protocol, поэтому агент для программирования может читать, писать и рендерить ваши документы теми же движками, что и приложение. Агент не угадывает формат файла: он получает типизированные схемы op из тех же определений, по которым исполнитель проверяет допустимость.

## Регистрация из приложения

Делать это нужно в **Настройки ▸ Интеграции**. Панель состоит из двух половин, и можно пользоваться любой из них или обеими сразу.

**Скилл.** По строке на каждого найденного на этой машине агента для программирования — Claude Code, Codex, Cursor, Gemini CLI, Copilot CLI, OpenCode, Windsurf —, в каждой строке есть **Установить**, **Обновить** и **Удалить**, а кроме того **Установить в другую папку…**, **Скачать скилл (zip)** и **Копировать путь**. Если вашего помощника в списке нет, укажите GenOffice папку, из которой он читает `SKILL.md`, или сохраните zip и позвольте помощнику установить его самому. Скилл и MCP могут стоять рядом: помощник выбирает что-то одно, а делают они ровно одно и то же.

**MCP.** Предлагаются два пути: **Запускает ассистент (рекомендуется)** — здесь вы добавляете показанную конфигурацию в свой клиент, а помощник запускает сервер сам, — и **Локальный HTTP-сервер**, который приложение запускает за вас. Так или иначе помощник в итоге говорит с GenOffice, и вам ни разу не приходится вводить команду.

## Регистрация из командной строки

То же самое из терминала — это продвинутый путь, и к нему стоит обращаться, когда агент находится там, где панель его не найдёт:

```sh
ieumoffice mcp install all
```

Она находит на этой машине агентов для программирования и записывает запись stdio-сервера в конфигурацию каждого из них, оставляя остальную часть того файла ровно такой, какой нашла. Запись называется `ieumoffice`. Вручную для Claude Code та же регистрация выглядит так: `claude mcp add --transport stdio ieumoffice -- ieumoffice mcp`.

```sh
ieumoffice mcp list             # where each agent stands
ieumoffice mcp install cursor    # just one
ieumoffice mcp uninstall cursor  # take it back out
```

Агент, установленный в необычное место, принимает `--dir <path>`; `--force` перезаписывает запись, которая уже там есть.

`ieumoffice mcp --help` показывает на одном экране всё, что принимает сервер: формы регистрации, удаления и списка, раздачу по HTTP и два флага схем.

## Запуск без помощника

Для клиента на другой машине отдайте сервер по HTTP:

```sh
ieumoffice mcp --http 8765 --token <secret>
```

`--host <addr>` меняет, где он слушает. Передайте клиенту тот же токен.

По HTTP ходят и файлы: `PUT /files/<name>` загружает один файл, каждый инструмент принимает URL `http(s)` вместо пути, а результаты возвращаются как URL для скачивания — а когда они достаточно небольшие, то и как встроенные ресурсы. Op, spec и Markdown в любом случае передаются прямо внутри.

## Что получает агент

Каждая команда — это инструмент. Интересные из них:

- **`docs`, `sheet`, `slides`** — прочитать и отредактировать файл по пути записи самого приложения, по одной **op** за раз. Новая презентация идёт `deck_start`, `deck_page`, `deck_build`.
- **`render`** — по одному PNG на страницу, разложенные рендерером приложения, так что агент может посмотреть на слайд, а не гадать о нём.
- **`pdf`** — текстовый слой PDF постранично, без процесса приложения.
- **`info`** — метаданные и сводка структуры; обычно это самый дешёвый первый вызов для незнакомого файла.
- **`search`, `image`, `media`** — поиск в вебе и поиск изображений, генерация изображений и анализ медиа через то, что настроено в приложении, так что агенту не нужны собственные ключи. В следующем разделе сказано, чем они могут пользоваться.
- **`merge`** — заполнение шаблона `{{key}}`.

## Поиск, изображения и медиа: чем может пользоваться агент

Запрос от команды `ieumoffice` или от MCP-клиента вы не вводили в приложении сами, поэтому GenOffice обращается с ним осторожно.

- **Поиск** работает всегда и по умолчанию бесплатен. Ключ поискового провайдера используется, только если вы его выбрали.
- **Создание изображения** требует ключа провайдера изображений. В этой версии подписка не создаёт изображения.
- **Описание изображения** использует провайдера с ключом, если он настроен. Ваша подписка Claude или Codex **не используется, пока вы этого не разрешите**.
- **Видео и аудио** требуют провайдера с ключом, который поддерживает видео.

Чтобы разрешить использование подписки, откройте Настройки ▸ ИИ ▸ **Дополнительно** и включите **Разрешить автоматическим запросам использовать подписку**. Сначала появится предупреждение — «Почасового лимита нет: программа может отправлять сколько угодно запросов, и в них может попасть весь текст документа и изображения его страниц. Ни одна из двух компаний не рекомендует позволять программе автоматически использовать подписку, и ваш аккаунт может быть ограничен.» — и переключатель включится только после нажатия **Всё равно включить**.

Даже при включённом переключателе:

- Запросы обрабатываются по одному. Остальные ждут своей очереди.
- Почасового лимита нет. Очередь идёт по отдельным запросам, а не по заданиям, поэтому длинный перевод PDF чередуется с другими вызовами, а не задерживает их. Переключатель, включённый при прежнем предупреждении, выключен: прочитайте новое предупреждение и включите его снова.
- Вход с оплатой по расходу, который вы разрешили кнопкой **Всё равно использовать**, здесь не считается подпиской. С ним обращаются как с ключом: если вы выбрали его как используемый ИИ, описания изображений идут через него независимо от переключателя, и каждое оплачивается.

Если переключатель выключен и ни один ключ не настроен, инструмент отвечает, что функция недоступна, и называет эту настройку. Агент может проверить это заранее инструментом `capabilities`; см. [Командная строка и агенты](help://cli).

## Схемы и меньший бюджет

`apply` и `create` объявляют свои параметры `ops`, `cells` и `data` вместе с типизированной схемой для каждой op, сгенерированной из `ieumoffice guide <domain> --json`. Это точно, но не компактно. Клиент с тесным контекстным окном может попросить обычные массивы:

```sh
ieumoffice mcp --compact-schemas
GENOFFICE_MCP_COMPACT_SCHEMAS=1 ieumoffice mcp
```

## Зачем нужен скилл

Агент, который не знает словаря op, будет гадать. Скилл несёт справочник и руководства по дизайну — тот же материал, который печатает `ieumoffice guide`, — так что помощник пишет op, спецификацию которых он действительно читал. Поставьте его из панели выше или командой `ieumoffice skill` из терминала.

## Что он может зацепить в приложении

Сервер ограничен не только файлами на диске. Пока GenOffice запущен, агент может работать и через окно:

- **`open_in_genoffice`** открывает файл во вкладке и выводит её на передний план.
- **`open_documents`** перечисляет каждый открытый у вас документ — id, тип, путь и есть ли несохранённые изменения —, а затем читает актуальное содержимое одного из них, сохраняет его на месте или закрывает его, предварительно сохраняя, если только вы не ведите ему выбросить.
- **Инструменты работы с содержимым** принимают этот id (или путь) как аргумент `document`, поэтому правка попадает во вкладку, которую вы уже открыли, а окно переключается на её показ.

Две вещи остаются вне досягаемости: панели ИИ здесь нет, а диалог обновления внутри приложения не действует.

## Панель локального HTTP-сервера

В разделе **Локальный HTTP-сервер** приложение запускает сервер само, вместо того чтобы оставлять это помощнику: тумблер включения, поле **Порт**, индикатор **Работает / Остановлен** и **Фоновая генерация** (записывать документы прямо по пути, не открывая интерфейс), а также **Пример конфигурации клиента**, который можно скопировать. Раскрытие **Дополнительно** добавляет два адреса подключения — Streamable HTTP и старый адрес SSE —, адрес **Проверки состояния** и тумблер **Журналирование**, записывающий работу сервера и инструментов в локальный файл, который оттуда можно **Открыть**, **Обновить** или **Очистить**. Слушает он только на localhost.
