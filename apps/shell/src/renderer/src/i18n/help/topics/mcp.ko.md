# 코딩 에이전트 연결

GenOffice는 Model Context Protocol을 말하므로, 코딩 에이전트가 앱이 쓰는 바로 그 엔진으로 문서를 읽고, 쓰고, 렌더링할 수 있습니다. 에이전트가 파일 형식을 추측하는 일은 없습니다. executor가 검증하는 바로 그 정의에서 타입이 붙은 op 스키마를 받습니다.

## 앱에서 등록하기

**설정 ▸ 연동**이 할 일입니다. 이 패널은 두 부분으로 나뉘어 있어서, 한쪽만 써도 되고 둘 다 써도 됩니다.

**스킬.**이 컴퓨터에서 찾은 코딩 에이전트마다 한 줄씩 나옵니다(Claude Code, Codex, Cursor, Gemini CLI, Copilot CLI, OpenCode, Windsurf). 각 줄에는 **설치**, **업데이트**, **제거**가 있고, 여기에 **다른 폴더에 설치…**, **스킬 다운로드 (zip)**, **경로 복사**가 더해집니다. 어시스턴트가 목록에 없다면, `SKILL.md`를 읽는 폴더를 GenOffice에 지정하거나, zip을 저장해 두었다가 어시스턴트가 직접 설치하게 하면 됩니다. 스킬과 MCP는 나란히 둘 수 있습니다. 어시스턴트가 둘 중 하나를 고르고, 하는 일은 똑같습니다.

**MCP.**두 가지 경로를 고를 수 있습니다. **어시스턴트가 실행(권장)**에서는 표시된 설정을 클라이언트에 넣으면 어시스턴트가 서버를 직접 띄웁니다. **로컬 HTTP 서버**는 앱이 대신 실행해 줍니다. 어느 쪽이든 어시스턴트는 결국 GenOffice를 통해 일하고, 당신은 명령을 직접 입력하지 않습니다.

## 명령줄에서 등록하기

같은 일을 터미널에서도 할 수 있습니다. 이것이 고급 경로이고, 패널이 찾지 못하는 곳에 에이전트가 있을 때 쓰는 방법입니다.

```sh
ieumoffice mcp install all
```

이 컴퓨터에 있는 코딩 에이전트를 찾아, 각자의 설정에 stdio 서버 항목을 씁니다. 그 파일의 나머지는 있는 그대로 둡니다. 항목 이름은 `ieumoffice`입니다. Claude Code에 손으로 등록한다면 `claude mcp add --transport stdio ieumoffice -- ieumoffice mcp`가 같은 일을 합니다.

```sh
ieumoffice mcp list             # where each agent stands
ieumoffice mcp install cursor    # just one
ieumoffice mcp uninstall cursor  # take it back out
```

평소와 다른 곳에 설치한 에이전트에는 `--dir <path>`를 줍니다. `--force`는 이미 있는 항목을 다시 씁니다.

서버가 받는 것은 `ieumoffice mcp --help` 한 화면에 다 들어 있습니다. 등록, 제거, 목록 형태, HTTP로 서비스하기, 그리고 두 스키마 플래그까지.

## 어시스턴트 없이 실행하기

다른 컴퓨터에 있는 클라이언트라면 HTTP로 내보내세요.

```sh
ieumoffice mcp --http 8765 --token <secret>
```

`--host <addr>`는 어디에서 받을지를 바꿉니다. 클라이언트에는 같은 토큰을 넘기세요.

HTTP로도 파일이 오갑니다. `PUT /files/<name>`으로 하나를 올리고, 모든 도구는 경로 대신 `http(s)` URL을 받습니다. 출력은 다운로드 URL로 돌아오고, 충분히 작으면 포함 리소스로도 돌아옵니다. op, spec, Markdown은 어느 쪽이든 인라인으로 넘깁니다.

## 에이전트가 얻는 것

모든 명령이 도구입니다. 그중 흥미로운 것들:

- **`docs`, `sheet`, `slides`** — 앱 자체 쓰기 경로로 파일을 읽고 편집합니다. 한 번에 **op** 하나씩. 새 덱은 `deck_start`, `deck_page`, `deck_build`로 갑니다.
- **`render`** — 한 페이지에 한 장씩 PNG를, 앱의 렌더러가 배치한 그대로 내보내므로 에이전트가 슬라이드를 추측하지 않고 볼 수 있습니다.
- **`pdf`** — 앱 프로세스 없이 PDF의 텍스트 층을 한 페이지씩 읽습니다.
- **`info`** — 메타데이터와 구조 요약으로, 낯선 파일에 대한 첫 호출로는 거의 항상 가장 쌉니다.
- **`search`, `image`, `media`** — 웹·이미지 검색, 이미지 생성, 미디어 분석을 앱에 설정해 둔 것으로 처리하므로 에이전트가 따로 키를 준비할 필요가 없습니다. 무엇을 쓸 수 있는지는 다음 절에 있습니다.
- **`merge`** — `{{key}}` 템플릿을 채웁니다.

## 검색·이미지·미디어: 에이전트가 쓸 수 있는 것

`ieumoffice` 명령이나 MCP 클라이언트에서 들어온 요청은 사용자가 앱 화면에서 직접 시킨 것이 아닙니다. 그래서 GenOffice는 이런 요청을 조심해서 다룹니다.

- **검색**은 언제나 되고, 기본은 무료입니다. 검색 제공업체의 키는 골라 둔 경우에만 씁니다.
- **그림 만들기**에는 이미지 제공업체의 키가 필요합니다. 이 버전에서는 구독으로 이미지를 만들지 않습니다.
- **그림 설명하기**는 설정해 둔 키 방식 제공업체가 있으면 그것을 씁니다. Claude나 Codex 구독은 **허용하기 전에는 쓰지 않습니다**.
- **동영상과 음성**에는 동영상을 지원하는 키 방식 제공업체가 필요합니다.

구독을 쓰게 하려면 설정 ▸ AI ▸ **고급**에서 **자동 호출에 구독 사용**을 켭니다. 켜기 전에 경고가 먼저 나옵니다. "시간당 한도가 없어 프로그램이 요청을 얼마든지 보낼 수 있고, 그 요청에 문서 전체의 글과 페이지 그림이 담길 수 있습니다. 프로그램이 자동으로 구독을 쓰는 것은 두 회사가 권장하지 않으며, 계정에 제한이 걸릴 수 있습니다." **그래도 켜기**를 눌러야 켜집니다.

켜 둔 뒤에도 다음은 지켜집니다.

- 요청은 한 번에 하나씩 처리합니다. 나머지는 차례를 기다립니다.
- 시간당 한도는 없습니다. 차례는 작업이 아니라 요청 하나 단위로 돌아가므로, 긴 PDF 번역도 다른 요청을 막지 않고 번갈아 처리됩니다. 예전 경고에 동의해 켜 둔 스위치는 꺼진 상태로 돌아갔습니다. 새 경고를 읽고 다시 켜야 합니다.
- **그래도 사용**으로 허용해 둔 "쓴 만큼 요금이 나가는 로그인"은 여기서 구독으로 치지 않습니다. 키와 똑같이 다룹니다. 그것을 사용할 AI로 골라 두었다면 그림 설명 요청은 스위치와 상관없이 그 로그인으로 처리되고, 요청마다 요금이 나갑니다.

스위치가 꺼져 있고 설정해 둔 키도 없으면, 도구는 그 기능을 쓸 수 없다고 답하면서 이 설정의 위치를 알려 줍니다. 에이전트는 `capabilities` 도구로 미리 확인할 수 있습니다. [명령줄과 에이전트](help://cli)를 보세요.

## 스키마와 더 작은 예산

`apply`와 `create`는 `ops`, `cells`, `data` 매개변수를 op마다 타입이 붙은 스키마로 알립니다. 그 스키마는 `ieumoffice guide <domain> --json`에서 만들어집니다. 정확하지만 크지는 않습니다. 컨텍스트 창이 좁은 클라이언트는 대신 단순 배열을 요청할 수 있습니다:

```sh
ieumoffice mcp --compact-schemas
GENOFFICE_MCP_COMPACT_SCHEMAS=1 ieumoffice mcp
```

## 스킬이 필요한 이유

op 어휘를 모르는 에이전트는 추측합니다. 스킬에는 레퍼런스와 디자인 가이드가 들어 있습니다. `ieumoffice guide`가 출력하는 것과 같은 내용이라, 어시스턴트가 실제로 읽어 본 스펙에 맞춰 op를 쓰게 됩니다. 위 패널에서 설치하거나, 터미널의 `ieumoffice skill`로 넣으세요.

## 앱 안에서 무엇에 닿을 수 있나

서버는 디스크의 파일로만 제한되지 않습니다. GenOffice가 실행되는 동안, 에이전트는 창을 통해서도 일할 수 있습니다.

- **`open_in_genoffice`**는 파일을 탭으로 열고 그 탭을 활성화합니다.
- **`open_documents`**는 열어 둔 모든 문서를 id, 형식, 경로, 저장 안 된 변경이 있는지까지 나열하고, 문서 하나를 읽거나 제자리에 저장하거나 닫습니다. 닫을 때는 먼저 저장하지만, 버리라고 하면 저장하지 않습니다.
- **콘텐츠 도구들**은 그 id(또는 경로)를 `document` 인자로 받으므로, 편집은 이미 열어 둔 탭에 반영되고 창도 그 탭으로 넘어갑니다.

닿지 못하는 것이 두 개 있습니다. AI 패널이 없고, 앱 안의 업데이트 대화상자는 적용되지 않습니다.

## 로컬 HTTP 서버 패널

**로컬 HTTP 서버**에는 어시스턴트에 맡기지 않고 앱이 직접 서버를 실행하는 설정이 모여 있습니다. 켜기 스위치, **포트** 입력란, **실행 중 / 중지됨** 표시, **백그라운드 생성**(UI를 열지 않고 문서를 경로에 그대로 씁니다), 복사해 쓸 수 있는 **클라이언트 설정 예시**입니다. **고급**을 펼치면 연결 URL 두 개(Streamable HTTP와 예전 SSE용), **상태 확인** URL, 그리고 서버와 도구 활동을 로컬 파일에 남기는 **로그** 스위치가 더해지고, 그 파일은 거기서 **열기**, **새로 고침**, **지우기**로 다룰 수 있습니다. localhost에서만 수신합니다.
