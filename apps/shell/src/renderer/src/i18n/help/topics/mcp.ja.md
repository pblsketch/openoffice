# コーディングエージェントの接続

GenOffice は Model Context Protocol を話せます。コーディングエージェントは、アプリが使うのと同じエンジンであなたの文書を読み、書き、レンダリングできます。エージェントがファイル形式を当て推量しているわけではありません。executor が検証するのと同じ定義から、型付きの op スキーマを受け取ります。

## アプリから登録する

**設定 ▸ 連携**が今回の操作場所になります。このパネルは 2 つの半分に分かれていて、片方だけでも、両方使ってもかまいません。

**スキル。**このマシンにあるコーディングエージェントが 1 つにつき 1 行ずつ並んでいます——Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、OpenCode、Windsurf——どの行にも **インストール**、**更新**、**アンインストール** があり、さらに **別のフォルダにインストール…**、**skill をダウンロード（zip）**、**パスをコピー** が付きます。お使いのアシスタントが一覧にない場合は、`SKILL.md` を読むフォルダを GenOffice に指定するか、zip を保存してアシスタントにインストールさせましょう。スキルと MCP は並べて置けます。アシスタントはどちらかを自分で選び、そして做的事情はまったく同じです。

**MCP。**用意されている経路は 2 つです。**アシスタントが起動する（推奨）** では、表示された設定をクライアントに追加すれば、アシスタントが自分でサーバーを起動します。**ローカル HTTP サーバー** は、アプリが代わりに実行してくれます。どちらを選んでも、アシスタントは最終的に GenOffice とやり取りし、あなたがコマンドを 1 つも入力することはありません。

## コマンドラインから登録する

同じことをターミナルから行うこともできます——これは上級者向けの経路で、パネルが見つけられない場所にエージェントがいるときはこちらを使ってください：

```sh
ieumoffice mcp install all
```

このマシンにあるコーディングエージェントを見つけ、それぞれの設定に stdio サーバーのエントリを書き、そのファイルの残りは見つかったときの様子のままにしておきます。エントリの名前は `ieumoffice` です。Claude Code に手動で登録する場合、同じ登録は `claude mcp add --transport stdio ieumoffice -- ieumoffice mcp` で行えます。

```sh
ieumoffice mcp list             # where each agent stands
ieumoffice mcp install cursor    # just one
ieumoffice mcp uninstall cursor  # take it back out
```

通常以外の場所にインストールしたエージェントには `--dir <path>` を指定します。`--force` を付けると、すでに存在するエントリを上書きします。

`ieumoffice mcp --help` を実行すると、サーバーが受け取れるものが 1 画面にまとまって表示されます。登録・削除・一覧の各形、HTTP での配信、そして 2 つのスキーマ用のフラグです。

## アシスタントなしで動かす

別のマシンにあるクライアントには、代わりに HTTP で配信します。

```sh
ieumoffice mcp --http 8765 --token <secret>
```

`--host <addr>` で待ち受ける先が変わります。クライアントには同じトークンを渡してください。

HTTP の上でもファイルは運べます。`PUT /files/<name>` で 1 つをアップロードでき、各ツールはパスの代わりに `http(s)` の URL を受け取ります。出力はダウンロード URL として戻り、小さい場合は埋め込みリソースとしても返ります。op、spec、Markdown はいずれの場合もインラインで渡します。

## エージェントが手に入るもの

すべてのコマンドがツールになります。中でも覚えておきたいのは次のものです：

- **`docs`、`sheet`、`slides`** — アプリ自身の書き込み経路でファイルを読み書きします。1 回の **op** 単位で。新規のデッキは `deck_start`、`deck_page`、`deck_build` の順です。
- **`render`** — 1 ページ 1 枚の PNG をアプリのレンダラーが配置して出力するので、エージェントはスライドを推測せずに見た目で確認できます。
- **`pdf`** — アプリプロセスを起動せずに、PDF のテキスト層をページ単位で読み取ります。
- **`info`** — メタデータと構造の概要。見慣れないファイルに対して、たいてい最も安い最初の一手です。
- **`search`、`image`、`media`** — アプリで設定した内容を通じて、Web 検索と画像検索、画像生成、メディア解析を行います。エージェントが自分のキーを用意する必要はありません。何を使えるかは次の節で説明します。
- **`merge`** — `{{key}}` テンプレートを埋めます。

## 検索・画像・メディア：エージェントが使えるもの

`ieumoffice` コマンドや MCP クライアントからのリクエストは、アプリの中でご自身が入力したものではないため、GenOffice は慎重に扱います。

- **検索** は常に使え、既定では無料です。検索プロバイダーのキーが使われるのは、ご自身で選択した場合だけです。
- **画像の生成** には画像プロバイダーのキーが必要です。このバージョンでは、サブスクリプションで画像は生成できません。
- **画像の説明** は、キー方式のプロバイダーが設定されていればそれを使います。Claude や Codex のサブスクリプションは、**許可しないかぎり使われません**。
- **動画と音声** には、動画に対応したキー方式のプロバイダーが必要です。

サブスクリプションの使用を許可するには、設定 ▸ AI ▸ **詳細設定** を開き、**自動呼び出しでサブスクリプションを使う** をオンにします。最初に警告が表示されます —「1 時間あたりの上限はないため、プログラムはいくらでも要求を送ることができ、その要求には文書全体のテキストやページの画像が含まれることがあります。プログラムがサブスクリプションを自動的に使うことは両社とも推奨しておらず、アカウントが制限される可能性があります。」— そして **それでもオンにする** を押して初めて、スイッチがオンになります。

スイッチをオンにしていても、次のように扱われます。

- リクエストは 1 件ずつ処理されます。ほかのリクエストは順番を待ちます。
- 1 時間あたりの上限はありません。順番はジョブ単位ではなくリクエスト 1 件単位で回るため、長い PDF の翻訳もほかの呼び出しを止めずに交互に処理されます。以前の警告に同意してオンにしていたスイッチはオフに戻っています。新しい警告を読んでから、もう一度オンにしてください。
- **それでも使用** で許可した従量課金のログインは、ここではサブスクリプションとして扱われません。キーと同じ扱いになります。使用する AI として選んでいれば、スイッチの状態にかかわらず画像の説明はそのログインを通り、1 回ごとに課金されます。

スイッチがオフで、キーも設定されていない場合、ツールはその機能が使えないと答え、この設定の名前を示します。エージェントは `capabilities` ツールで先に確認できます。[コマンドラインとエージェント](help://cli) を参照してください。

## スキーマと小さめの予算

`apply` と `create` は `ops`、`cells`、`data` パラメーターを、op ごとの型付きスキーマ付きで公開します。そのスキーマは `ieumoffice guide <domain> --json` から生成されます。正確ですが、大きなものです。コンテキストウィンドウの狭いクライアントは、代わりに単純な配列を要求できます：

```sh
ieumoffice mcp --compact-schemas
GENOFFICE_MCP_COMPACT_SCHEMAS=1 ieumoffice mcp
```

## なぜスキルなのか

op の語彙を知らないエージェントは当て推量します。スキルにはリファレンスとデザインガイド—— `ieumoffice guide` が出すのと同じ内容——が入っているので、アシスタントは実際に spec を読んでから op を書けます。上のパネルからインストールするか、ターミナルの `ieumoffice skill` で入れてください。

## アプリの中で何に手が届くか

サーバーはディスク上のファイルだけに限られません。GenOffice が動いている間、エージェントはウィンドウ越しにも作業できます：

- **`open_in_genoffice`** はファイルをタブで開き、そのタブを前面に出します。
- **`open_documents`** は、開いているすべてのドキュメントを id・種類・パス・未保存の変更の有無まで一覧し、あるドキュメントの内容をその場で読むか、そのまま保存するか、閉じるかを行います。閉じる前に保存しますが、破棄するよう指示されれば保存しません。
- **コンテンツツール群** は、その id（またはパス）を `document` 引数として取るので、編集はすでに開いているタブに反映され、ウィンドウもそのタブを表示に切り替わります。

届かないものが 2 つあります。AI パネルは存在しませんし、アプリ内の更新ダイアログは適用されません。

## ローカル HTTP サーバーのパネル

**ローカル HTTP サーバー** には、アシスタントに任せずにアプリ自身がサーバーを実行する設定がまとまっています。有効にするスイッチ、**ポート** の入力欄、**実行中 / 停止中** の表示、**バックグラウンド生成**（UI を開かずにドキュメントをそのままパスへ書き出す）、そしてコピー用の**クライアント設定例**です。**詳細** を開くと、2 つの接続 URL（Streamable HTTP と従来の SSE 用）、**ヘルスチェック** の URL、そしてサーバーとツールの動きをローカルファイルに記録する**ログ**スイッチが加わり、そのファイルはそこから**開く**、**更新**、**クリア**できます。listen するのは localhost だけです。
