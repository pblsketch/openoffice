# packages/ai-provider (`@genoffice/ai-provider`)

모델에게 한 턴을 맡기는 계층이다. 사용자가 PC에 설치해 로그인해 둔 Claude Code·Codex 프로그램을 "한 턴짜리 두뇌"로 띄우는 브리지와, 사용자가 직접 고른 API 키 제공자의 HTTP 프로토콜을 한 계약으로 묶는다.

## 맡은 범위

- 제공자 카탈로그와 설정: `AI_PROVIDERS`(`src/providers.ts`), 어댑터 표 `AI_PROVIDER_ADAPTERS`(`src/registry.ts`), 저장 파일 정규화 `normalizeAiSettings`(`src/legacy-settings.ts`), 렌더러가 보낸 설정 검사 `sanitizeAiSettings`(`src/ai-settings-guard.ts`), 키와 토큰의 봉인·풀기 `sealAiSecrets`·`openAiSecrets`와 프로세스가 등록하는 `setAiSecretCodec`(`src/settings-secrets.ts`, 결정 0063).
- 어느 제공자로 실행할지: `selectAiProvider`·`subscriptionConnection`(`src/provider-selection.ts`). 순수 함수이며 렌더러(무엇을 보여 줄지)와 메인(무엇을 실행할지)이 같은 함수를 쓴다.
- 한 턴 라우팅: `streamForProvider`(`src/stream.ts`), `chatForProvider`(`src/chat.ts`), 프로그램이 읽는 실패 이유 `AiRunError`·`aiStreamErrorFields`(`src/run-error.ts`).
- 구독 프로그램 공통 계층 `src/subscription/`: 실행 파일 찾기(`locate.ts`), 환경(`env.ts`), 시작·종료와 자식 등록부(`process.ts`), 강제 종료 뒤 정리(`leftovers.ts`), 연결 상태(`status.ts`, `service.ts`), 프로그램의 모델 목록(`models.ts`), 종량제 로그인 동의(`metered.ts`), 로그인·로그아웃·설치 실행(`launch.ts`), IPC 계약과 메인 측 핸들러(`contract.ts`, `ipc.ts`).
- 두 브리지 `src/claude-code-cli.ts`, `src/codex-app-server.ts`와 키 기반 이미지·미디어 프로토콜(`src/media.ts`, `src/media-protocols.ts`, `src/image-backend.ts`).
- 에이전트 모드(결정 0032)의 실행부 `src/agent-session/`(진입점 `/agent-session`, Node 전용): 허락 판단 `agentPolicyVerdict`(`policy.ts`), Claude Code 세션(`claude.ts`), Codex 세션(`codex.ts`), 두 프로그램이 같이 받는 스킬 묶음(`skills.ts`, 켜진 스킬과 프로젝트 스킬, 결정 0049), 프로그램에 돌려주는 거절 문장(`messages.ts`).
- 사용자 스킬의 코어 `src/user-skills/`(Node 전용, 대표 진입점에서 내보냄): 출처 목록과 읽기(`userSkillSources`·`listUserSkills`, `~/.codex`는 읽지 않음, `genoffice`·`ieumoffice` 이름 제외), 한 폴더의 판정(읽을 수 없는 이유, 스크립트 포함, 양식), 식별자(`userSkillId`), 켜기·끄기 상태 합치기(`resolveUserSkillStates`)와 켜진 것 사이의 우선순위(`pickEnabledUserSkills`), 앞머리 읽기·쓰기(`parseSkillMd`·`renderSkillMd`), 새 이름 규칙과 제안, 폴더 내용 해시(`skillContentHash`), 웹 주소 찾기, `builtin-skills.json` 읽기.
- 사용자 스킬 가져오기·내보내기·업데이트(결정 0048, 같은 폴더): 폴더·zip·깃허브에서 찾아 미리보기를 만들고(`prepareFolderImport`·`prepareZipImport`·`prepareGitHubImport`, `import.ts`), 임시 폴더에 다 쓴 뒤 옮겨 설치하고(`installImportedSkills`), 깃허브 출처 기록(`.ieum-source.json`, `source-record.ts`)으로 업데이트를 확인·적용하고(`update.ts`), zip으로 내보낸다(`export.ts`, 출처 기록 제외). 깃허브 연결은 `github.ts`의 세 호스트(`GITHUB_SKILL_HOSTS`)뿐이고, 압축 풀기는 `archive.ts`가 폭탄 검사와 경로 검사를 거친다.
- 무료 연결: 화면용 규칙과 상수(`src/free-ai.ts`, `/browser`로 내보냄: 무료 모델 목록, 연결·해제한 설정, 카드의 "연결됨" 판정, IPC 채널 이름과 답 판독, 오늘 무료 사용량 소진 판정 `freeLimitOf`)와 뒷단 전용 연결부(`src/free-connect.ts`, `/free-connect`: OpenRouter OAuth PKCE와 루프백 서버, Gemini 키 확인, 무료 모델 고르기, 남은 무료 요청 수).

## 맡지 않는 것 (경계)

- 도구 실행과 에이전트 루프는 이 모듈의 범위가 아니다. 브리지는 모델이 "요청한" 호출을 `onToolCall`로 넘길 뿐이고, 실행은 `packages/agent-core`의 루프와 각 에디터의 skill이 한다.
- 웹·이미지 검색, `generate_image`/`analyze_media` 도구, 화면 경로와 자동 호출 경로의 구분, 자동 호출의 차례 처리와 사용 횟수 장부는 `packages/ai-search`의 범위다. 여기에는 그 판단에 쓰이는 순수 함수(`resolveImageBackend`)만 둔다.
- 사용자에게 보이는 문장과 연결 카드·알림 컴포넌트는 `packages/ui`의 범위다. 이 모듈이 만드는 오류 문장은 영어 예비 문구이고, 화면은 `AiRunErrorKind`와 `subscriptionStatusErrorKind`로 번역한다.
- Electron을 import하지 않는다. `ipcMain`은 `SubscriptionIpcMain` 모양으로 주입받고, 어느 앱의 메인이 등록할지·설정 파일을 어디에 쓸지는 `apps/*/src/main`이 정한다.
- 벤더 프로그램 자체는 고치거나 감싸지 않는다. 앱 안에 Claude·ChatGPT 로그인 폼을 만드는 일도 범위 밖이며 하지 않는다.

## 항상 지켜야 하는 것

- 설정 파일을 디스크에 쓰는 곳은 쓰기 직전에 `sealAiSecrets`를 거친다. 읽기는 `resolveAiSettings`가 맨 앞에서 `openAiSecrets`로 푼다. 풀지 못한 봉인 값은 빈 키가 되고, `sealed:v1:` 글자가 키로 나가는 일은 없어야 한다(결정 0063).
- 로그인 정보(`~/.codex/auth.json`, Claude 자격 증명 저장소, 세션 토큰)를 읽거나 복사하거나 저장하지 않는다. 테스트와 디버깅에서도 같다. 연결 상태는 프로그램 자신의 답(`claude auth status --json`, `codex login status`, app-server의 `account/read`)으로만 판단한다.
- 프로그램이 출력한 글자는 상태·파일·로그 어디에도 복사하지 않는다. 출력은 `status.ts`가 나열한 값(`SUBSCRIPTION_LOGIN_KINDS`)과 대조만 하고, 모르는 값은 고정 토큰 `unknown`이 된다. 통과시키는 값은 셋뿐이고 각각 좁은 모양일 때만이다. 요금제 이름은 식별자 모양(`planLabel`), 계정은 이메일 주소 모양(`subscriptionAccountOf`), 모델 목록은 프로그램이 받는 식별자 모양과 길이를 자른 이름(`subscriptionModelsOf`). 조직 이름은 읽지 않는다. "알려진 패턴을 지우는" 방식으로 바꾸지 않는다(예상 밖 형식의 출력에서 조직 이름이 새어 나간다).
- 계정(`AiSubscriptionStatus.account`)은 설정 화면의 카드에 보여 주는 값이고 그 밖의 용도가 없다. 메모리의 상태에만 있고 어디에도 쓰지 않는다. 설정 파일(`setMeteredAccepted`가 받는 것은 제공자와 불리언뿐이다), 동의 파일(로그인 종류만 남는다), 자식 프로세스 기록, 오류 문장에 들어가지 않는다. 메인이 판단에 쓰는 사본(`sharedSubscriptionStatuses`)과 자동 호출 경로의 상태(`packages/cli`의 `withoutAccount`)에서는 뺀다. 계정을 싣는 길은 IPC 응답과 `changed` 방송뿐이다. 로그인이 없는 상태(`signed-out`, `not-installed`, `error`, `checking`)에는 계정도 모델 목록도 붙지 않는다.
- 구독 프로그램은 `spawnSubscriptionProgram`·`runSubscriptionProgram`으로만 시작한다. 찾아낸 실제 실행 파일 경로와 인자 배열로 시작하고 셸을 거치지 않는다. Windows의 npm `.cmd` shim은 직접 실행하지 않고 그 뒤의 실제 프로그램을 찾는다(`locate.ts`). Codex는 Windows에서 데스크톱 앱의 bin 트리를 PATH보다 먼저 쓰고, macOS에서는 데스크톱 앱 번들(`/Applications/Codex.app/Contents/Resources/codex`, `ChatGPT.app`)과 PATH의 사본 가운데 더 최근에 쓰인 것을 쓴다. 사용자가 설정한 `cliPath`가 둘보다 앞선다. 예외는 보이는 터미널에서 실행하는 두 버튼뿐이다. 설치 버튼의 고정 문자열 `SUBSCRIPTION_INSTALL_COMMANDS`, 그리고 업데이트 버튼(`launchSubscriptionUpdate`, 결정 0047)이다. 업데이트의 명령 글도 상수이고(`SUBSCRIPTION_CODEX_UPDATE_COMMANDS`, 또는 찾은 Claude를 환경변수로 받아 `update`를 주는 고정 스크립트), 무엇을 쓸지는 `subscriptionUpdatePlan`이 찾은 파일의 위치로 정한다. 설치 경로를 모르는 사본에는 명령을 만들지 않는다.
- 앱이 띄운 로그인은 `cancelLogin`(IPC `ai:subscription-cancel-login`)으로 끝낼 수 있다. 진행 중인 로그인을 목록에서 먼저 빼고 "로그인하는 중" 표시를 지운 뒤 프로세스 나무를 끝내고 다시 확인한다.
- 사용자가 입력했거나 문서에 들어 있는 글자를 명령줄에 올리지 않는다. 프롬프트·대화·이미지는 stdin으로 보낸다. Claude 명령줄에 올라가는 가변 값은 `MODEL_NAME` 정규식을 통과한 모델 이름뿐이고, 로그인 창 스크립트(`LOGIN_WINDOW_SCRIPT`와 그 창의 PowerShell이 도는 `LOGIN_GUIDED_SCRIPT`, 창을 숨긴 `LOGIN_HIDDEN_SCRIPT`)는 상수이며 경로·인자·창의 글(`SubscriptionLoginWindowText`)은 환경 변수로 값으로만 전달된다. `LOGIN_GUIDED_SCRIPT`에는 큰따옴표를 넣지 않는다(`Start-Process`를 거치며 사라진다. 시험이 지킨다).
- 자식 환경은 `subscriptionChildEnv`로 만든다. `SUBSCRIPTION_STRIPPED_ENV_VARS`(API 키, base URL, 클라우드 플랫폼 스위치 등 구독에서 다른 과금 경로로 옮기는 변수)를 뺀 사본이며 `process.env`는 고치지 않는다. Windows에서는 변수 이름의 대소문자를 구분하지 않고 지운다. `CLAUDE_CODE_OAUTH_TOKEN`은 지우지 않는다. 그 로그인은 상태 확인에서 `unknown`으로 읽혀 `metered`가 된다.
- 사용자 설정·hook·plugin·MCP를 실행에 들이지 않는다. Claude는 `claudeCodeCliLaunchArgs`의 고정 플래그(`--tools ""`, `--restricted`, `--strict-mcp-config`, `--setting-sources ""`, `--disable-slash-commands`, `--no-session-persistence`)와 실행마다 새로 만든 빈 임시 폴더를 쓴다. `--bare`는 쓰지 않는다(구독 로그인을 읽지 못한다). `--json-schema`도 쓰지 않는다(`StructuredOutput` 도구가 세션에 추가되어 아래 0-도구 규칙이 깨진다). 스키마는 지시문으로 주고 답은 `parseClaudeCodeTurn`이 검증한다.
- Claude 턴은 프로그램이 도구 0개를 보고했을 때만 진행한다. `init` 이벤트의 `tools`가 빈 배열이고 `mcp_servers`가 없어야 `verified`가 되고, 그 전에 도착한 답, 도구 블록, `can_use_tool` 권한 요청은 모두 `unsafe-tools`로 프로세스 트리를 끝낸다. 플래그를 믿지 않고 보고를 확인하는 구조이므로 플래그를 추가했다고 이 확인을 빼지 않는다. 한계도 있다. Claude Code는 첫 메시지를 stdin으로 받은 뒤에야 도구 목록을 알리므로 확인은 그 시점에 이뤄지고, 실패하면 모델의 출력은 하나도 쓰지 않지만 Windows의 트리 종료는 비동기다.
- Codex에는 사용자 `config.toml`을 통째로 무시하는 스위치가 없다. 그래서 `CODEX_CONFIG_OVERRIDES`로 하나씩 덮고(`-c features.<name>=false`를 쓴다. `--disable` 뒤에 모르는 이름이 오면 Codex가 시작하지 못한다), MCP 서버는 스레드마다 `codexMcpServerOverrides`로 끈 뒤 `mcpServerStatus/list`로 실제로 꺼졌는지 확인한다. 확인할 수 없는 스레드는 안전하지 않은 것으로 보고 `unsafe-tools`로 끝낸다. 모델도 항상 명시한다(`defaultModelFor`). 비워 두면 Codex가 사용자 설정 파일의 모델을 쓴다. 덮지 못하는 것도 있다. Codex 홈 폴더(`~/.codex/`)의 사용자 지침 파일은 Codex가 여전히 대화에 넣고, Codex 자체의 진단 로그는 앱이 끄지 못한다.
- Codex 자신의 셸 도구는 끌 수 없다. `codexThreadStartParams`가 권한 프로필(`CODEX_PERMISSION_PROFILE`)로 읽기를 플랫폼 경로와 임시 폴더로 좁히고, 프로필이 적용되지 않으면(예전 Codex, 사용자 설정의 `sandbox_mode`) `sandbox: 'read-only'`로 내려간다. 내려간 경우 그 도구는 디스크 전체를 읽을 수 있다. 이 대체 경로를 넓히지 않는다. 쓰기 권한이나 승인을 여는 값은 어느 경로에도 넣지 않는다.
- 모델 목록은 모델을 부르지 않고 얻는다. Claude는 `listClaudeCodeModels`가 턴과 똑같이 띄운 프로세스(`claudeCodeCliLaunchArgs`, 새 임시 폴더, `subscriptionChildEnv`)에 `initialize` 요청 하나만 보내고, 답의 `models`만 읽은 뒤 stdin을 닫아 끝낸다. 사용자 메시지를 보내지 않으므로 모델 출력이 없고, 그런데도 프로그램이 권한 요청·답·결과를 내기 시작하면 프로세스 트리를 끝낸다. 시간 초과와 취소 때도 같다. 같은 답에 들어 있는 `account`는 읽지 않는다. Codex는 `listCodexSubscriptionModels`가 app-server의 `model/list`를 읽고 스레드를 열지 않는다.
- 모델 목록은 상태를 늦추거나 실패시키지 않는다. 상태 서비스는 상태를 먼저 내보내고, 앱이 쓸 수 있는 로그인(`ready`, 또는 사용자가 허용한 `metered`)에 한해 목록을 따로 읽어 달라질 때만 `changed`로 다시 내보낸다. 허용하지 않은 종량제 로그인으로는 목록 때문에 프로그램을 띄우지 않고 상태에 `models`도 싣지 않는다(화면은 고정 목록을 쓴다). 사용자가 허용하면 그때 읽는다. 읽기 실패·시간 초과·낡은 프로그램은 모두 "목록 없음"이고 오류가 아니다. 목록은 프로세스 동안 쥐고 있다가 다시 확인할 때 새로 읽고, 로그아웃되면 버린다(이전 로그인의 목록을 다음 로그인에 쓰지 않는다). 목록을 읽을지는 `listModels` 의존성이 정한다. 앱(`createSubscriptionIpcDeps`)만 넣고 자동 호출 경로는 넣지 않으므로, 명령줄은 목록 때문에 프로그램을 더 띄우지 않는다.
- 저장되는 모델 선택값은 프로그램이 받는 값(`id`)이고 표시 이름이 아니다. Claude 목록의 `default` 항목은 빈 `id`로 옮긴다(빈 선택값은 `--model` 없이 실행된다). 브리지가 `--model`에 넘기는 값의 검사(`MODEL_NAME`)는 그대로다.
- 로그아웃은 프로그램 자신의 명령이다(`launchSubscriptionLogout`: Claude `auth logout`, Codex `logout`). `runSubscriptionProgram`으로 끝까지 돌리고(실제 실행 파일, 셸 없음, 정리된 환경, 20초 제한), 출력은 결과에 싣지 않는다. 채널 `ai:subscription-logout`의 핸들러는 답하기 전에 그 제공자를 다시 확인한다. 이 확인과 로그인 창이 닫힌 뒤의 확인은 `check(…, { fresh: true })`로 한다. 그냥 `check`는 진행 중인 확인을 함께 쓰는데, 그 확인은 로그인·로그아웃이 끝나기 전에 프로그램에 물었을 수 있어 카드에 이전 계정이 남는다. `fresh`는 진행 중인 확인이 끝나기를 기다린 뒤 한 번 더 묻는다(기다림 한 번, 확인 한 번). 이 PC 전체에 적용되는 동작이므로 사용자 확인은 화면(shell)이 받는다. 이 계층에는 확인 없이 부르는 호출부를 만들지 않는다.
- 앱이 시작한 로그인은 `createSubscriptionIpcDeps`가 제공자마다 하나씩 쥔다. Windows에서 첫 로그인은 창을 숨기고(`window: 'hidden'`), 그것이 도는 중에 다시 부르면 숨긴 로그인을 끝내고 보이는 창으로 띄운다. 창이 열려 있으면 다시 불러도 아무것도 띄우지 않는다. 도는 동안 상태 서비스의 `setSigningIn`이 상태에 `signingIn`을 얹는다(감지한 값은 바꾸지 않는다). 숨긴 로그인은 `HIDDEN_LOGIN_TIMEOUT_MS`(10분) 뒤 끝낸다. 숨긴 로그인이 창으로 바뀌며 끝난 것은 표시를 지우지 않는다. 보이는 창의 제목·안내·끝나지 않았을 때의 글은 앱이 `SubscriptionIpcSetup.loginWindowText`로 주고(편집기 뒷단 셋이 `@genoffice/ui/ai-subscription-login-window`를 넘긴다, 결정 0059), 창을 열 때만 묻는다. 그 함수가 실패해도 창은 글 없이 열린다. 이 모듈은 화면 언어의 글을 갖지 않는다. 테스트는 `SubscriptionIpcSetup`의 `spawn`·`locate`·`platform`·`killTree`로 실제 프로그램과 `taskkill`에 닿지 않는다(`tests/subscription-login-window.test.ts`).
- 앱이 로그인이나 로그아웃을 끝까지 실행하면 `notifySubscriptionLoginChange`가 불린다. `registerSubscriptionIpc`는 이때 그 제공자의 종량 허용을 지운다(`clearMeteredAcceptance`: 설정의 플래그와 동의 파일의 기록 둘 다. 저장된 것이 없으면 아무것도 쓰지 않는다). 로그인 종류만으로는 같은 종류의 다른 계정으로 바뀐 것을 알 수 없기 때문이다. Codex 브리지는 이때 풀에 있던 app-server를 더 쓰지 않는다(시작할 때의 로그인을 쥐고 있을 수 있으므로). 쓰는 실행이 없으면 바로, 있으면 끝난 뒤 종료한다.
- Codex 실행 직전에 로그인을 한 번 더 본다(`assertRunnableAccount`). 로그아웃됐으면 `signed-out`, 상태 확인이 마지막으로 본 것과 다른 종류의 종량제 로그인으로 바뀌어 있으면 `metered-not-accepted`로 멈춘다. 사용자가 동의한 것은 "그때 그 로그인"이기 때문이다.
- `auto`는 `ready`인 구독만 고른다. 순서는 `AI_SUBSCRIPTION_PROVIDERS`(Claude 다음 Codex)이고, 키 제공자와 종량제 로그인은 후보가 아니다. `ready`는 로그인 방식이 `subscription`일 때만이고 알 수 없는 로그인은 `metered`다. 종량제 로그인은 설정의 `meteredAccepted[provider]`와 상태의 `meteredAccepted`가 둘 다 참일 때만 쓴다(로그인이 바뀐 뒤 남은 플래그로 유료 실행이 시작되지 않게).
- 막힌 실행은 멈춘다. 명시적으로 고른 제공자가 실행될 수 없으면 `connected: false`와 원인을 돌려주고, 브리지는 `AiRunError`를 던진다. 어느 쪽도 다른 제공자로 스스로 넘어가지 않는다. `streamForProvider`에 `auto`를 넘기면 `Unknown provider: auto`로 실패한다. 호출자가 먼저 `selectAiProvider`로 풀어야 한다.
- 앱이 띄운 자식은 앱보다 오래 살지 않는다. 취소는 `killProcessTree`(Windows에서는 System32의 `taskkill.exe`를 전체 경로로 불러 `/T /F`), 종료는 동기 함수 `shutdownSubscriptionChildren`, 강제 종료된 뒤의 다음 시작은 `initSubscriptionChildTracking`이 `subscription-children-<앱 pid>.json` 기록을 읽어 pid·프로그램 파일·시작 시각이 모두 맞는 프로세스만 끝낸다. 사용자가 직접 띄운 claude·codex는 기록에 없으므로 건드리지 않는다. 이 과정에서 띄우는 Windows 시스템 도구(`taskkill.exe`, 프로세스 조회용 PowerShell)도 로그인·설치 창과 마찬가지로 전체 경로로, 작업 폴더를 `windowsSystemDir`로 두고 시작한다. 앱의 작업 폴더는 문서가 있는 폴더일 수 있어 물려주지 않는다.
- 무료 연결은 키 제공자다. 연결 버튼이 그 제공자를 "사용할 AI"로 저장하는 것은 사용자가 고른 것이기 때문이고, `auto`의 후보는 여전히 구독뿐이다. OpenRouter 무료 연결의 모델 목록(`keyProviderModels`)은 `:free` 모델만 담는다. 무료 연결이 유료 모델로 가지 않게 하는 장치이므로 유료 모델을 섞지 않는다. `OPENROUTER_FREE_MODELS`에는 `npm run free-models:trial`로 앱에서 두 요청을 해낸 모델만 넣는다. 도구 호출을 지원한다고 나온 모델도 앱에서는 멈추거나 거절당한다(`docs/operations.md`의 "무료 모델 점검").
- OpenRouter 브라우저 연결의 서버는 루프백 주소(`127.0.0.1`, 되면 `::1`)에만 열고 `/callback` 한 번만 받는다. 열어 두는 시간은 `OPENROUTER_SIGN_IN_TIMEOUT_MS`(10분)이고 취소·끝·시간 초과 어느 쪽이든 닫는다. 키는 뒷단이 설정 파일에 쓰고 화면으로 돌려주지 않는다. 브라우저가 돌아왔을 때 보이는 페이지에는 스크립트와 바깥 자원을 넣지 않는다.
- `aiFetch`는 503·529와 "오늘 무료 사용량 소진"이 아닌 429를, 답을 읽기 전이고 본문을 다시 보낼 수 있을 때 두 번까지 다시 보낸다(2초, 5초. `Retry-After`가 20초를 넘으면 기다리지 않는다). 취소되면 바로 그만둔다. 테스트에서 거절 응답을 그대로 보고 싶으면 `setAiTransientRetryDelays([])`로 끈다.
- 오늘 무료 사용량 소진은 `aiStreamErrorFields`가 혼잡(`overloaded`)보다 먼저 `free-limit`으로 가른다. 판정은 오류 글에 실린 제공자의 본문으로 한다(OpenRouter `free-models-per-day`와 본문의 `X-RateLimit-Reset`, Gemini의 하루 단위 무료 등급 할당량 이름). 분당 한도는 `free-limit`이 아니다.
- 입력을 말없이 자르지 않는다. Claude 브리지가 줄이는 것은 이미지 100장(`MAX_CLAUDE_CODE_IMAGES`) 초과분뿐이고, 오래된 것부터 빼며 반드시 `onInputTruncated`를 부른다. 글자는 자르지 않는다.
- 구독 IPC 채널은 프로세스당 한 번, `ensureSubscriptionIpc`로만 등록한다. 패키징된 앱은 여러 에디터의 메인 코드가 한 프로세스에서 돌고 같은 채널을 두 번 등록하면 예외가 나므로 `registerSubscriptionIpc`를 앱에서 직접 부르지 않는다. 등록은 상태 확인을 시작하지 않는다. 첫 `statuses` 요청이 첫 확인을 시작하므로, AI를 보여 주지 않는 프로세스(headless export 등)는 벤더 프로그램을 띄우지 않는다.

- **에이전트 세션은 두뇌 방식의 규칙을 빌려 쓰지 않고 따로 지킨다.** 위의 "도구 0개"와 "Codex 읽기 전용" 규칙은 기본 AI 창의 것이고, 에이전트 세션의 코드를 두뇌 방식 브리지에 섞지 않는다. 대신 이렇게 한다. Claude는 `claudeAgentLaunchArgs`의 고정 인자(`--restricted`, `--setting-sources ""`, `--strict-mcp-config`, `--tools`의 8개, `--permission-prompts host --permission-prompt-tool stdio`)로 띄우고, 시작 보고가 `claudeAgentInitProblem`을 통과해야 진행한다. Codex는 `codexAgentLaunchArgs`(두뇌 방식 덮어쓰기에 스킬 지시문만 켬)로 띄우고, 권한 프로필 `ieumoffice-agent`가 적용됐다는 답과 MCP 목록 확인이 있어야 진행한다. 프로필이 적용되지 않으면 낮춰 돌리지 않고 끝낸다.
- 에이전트 세션의 모든 권한 요청은 `agentPolicyVerdict`를 거친다. 프로그램의 옵션(`acceptEdits`, 샌드박스)을 믿고 판단을 건너뛰지 않는다. 탭에 열린 문서의 파일 쓰기, 프로젝트 폴더 밖 쓰기, 보호 경로는 어느 허락 방식에서도 거절이다. 판단 규칙을 바꾸면 `tests/agent-session-policy.test.ts`의 표를 함께 고친다.
- Claude에 `bypassPermissions`·`--dangerously-skip-permissions`를 주지 않는다. "믿고 맡기기"는 Claude Code의 `auto` 모드다. Windows에서 Claude의 명령은 격리되지 않기 때문이다.
- Codex 에이전트 세션은 MXC 격리(`windows.sandbox="mxc"`)와 `deny`가 든 권한 프로필로만 연다. 승인 정책에 `on-request`를 쓰지 않는다. 그 정책에서 허락한 명령은 격리 밖에서 돈다. `thread/start`의 답에서 프로필과 승인 정책이 요청과 같은지 확인한다. Windows에서는 그 전에 `probeCodexSandbox`(`codex-sandbox-probe.ts`)로 격리가 뜨고 거부를 지키는지 시험하고, 통과하지 못하면 시작하지 않는다.
- 에이전트 세션도 명령줄에 사용자 글을 올리지 않는다. 설정과 MCP 토큰은 세션 폴더의 파일로, 지시문은 표준 입력(Claude `initialize`의 `appendSystemPrompt`, Codex `developerInstructions`)으로 넘긴다.
- 스킬은 사용자 설정을 읽게 해서 싣지 않는다(훅이 실행된다). `buildAgentSkillBundle`이 스킬 폴더만 복사한 플러그인 폴더를 만들고, 디렉터리 연결은 쓰지 않는다(연결이 실제 위치로 풀려 작업 폴더 밖으로 막힌다).
- 사용자 스킬은 `~/.codex` 안을 어떤 경로로도 읽지 않고, 스킬 폴더 밖으로 이어지는 링크를 따라가지 않는다. 이름이 `genoffice`·`ieumoffice`인 스킬은 어느 출처에서든 목록에 넣지 않는다. 파일을 쓰는 곳은 내 스킬 폴더(`~/.ieumoffice/skills`) 하나이고, 깃허브 요청에는 쿠키와 인증 머리글을 싣지 않는다(결정 0048).

## 이 모듈의 방식

- 브리지는 "한 턴짜리 두뇌"다. 앱의 system prompt, 지금까지의 대화, 앱 도구 목록, 응답 JSON Schema를 주고 `{ text, toolCalls }` 객체 하나를 받는다. Claude는 턴마다 새 프로세스를 띄우고 끝나면 스스로 나가게 둔다(stdin을 닫고 5초 뒤에도 남아 있으면 트리 종료). Codex는 app-server 프로세스를 실행들이 공유하고 쓰는 실행이 없으면 끝낸다.
- Claude 턴은 매번 대화 전체를 사용자 메시지 하나로 다시 읽는 새 세션이다. 그래서 도구 결과 이벤트마다 "이 호출들은 이미 한 번 실행됐다"는 문장(`AFTER_TOOL_RESULTS`)을 그 이벤트 JSON의 `note` 필드로 넣는다. 작은 모델이 첫 사용자 요청에 다시 답하며 이미 실행된 호출을 또 요청해, 문단 하나가 네 번 삽입된 일이 있었다. 이 문장을 이벤트 뒤의 별도 블록으로 두지 않는다. 마지막 블록이 다음 턴에 사라지면 앞선 턴의 블록 목록이 다음 턴의 접두사가 아니게 되어, 도구 루프의 매 턴이 프롬프트 캐시 없이 전체를 다시 읽는다. 모든 도구 이벤트에 같은 글자로 넣는다.
- 도구 호출 id는 브리지가 붙인다(`claude-<uuid>`). 세션이 매번 새것이라 모델이 고유성을 지킬 수 없다. 목록에 없는 도구 이름은 실행하지 않고 `inputError`를 달아 루프로 넘긴다.
- 루프와 문자열로 맺은 계약이 둘 있다. 오류 문장 끝의 `(empty stream)`은 "아무것도 전달되지 않았으니 같은 턴을 다시 보내도 된다", `while sending tool arguments`는 "도구 호출이 전달되지 않았으니 한 번 재시도한다"는 뜻이며 `packages/agent-core/src/loop.ts`가 이 글자를 찾는다. 문구를 고치면 재시도가 조용히 사라진다.
- 상태는 한 방향으로 흐른다. `detectSubscriptionLogin` → `createSubscriptionStatusService`(저장된 종량 허용과 대조) → `ensureSubscriptionIpc`가 `SUBSCRIPTION_IPC_CHANNELS` 응답과 `changed` 방송 → preload는 `@genoffice/ai-provider/browser`의 채널 이름과 판독 함수(`subscriptionStatusMapOf`, `subscriptionLaunchResultOf`, `subscriptionMeteredResultOf`)로 읽는다. 모델 목록은 `listSubscriptionModels`(브리지가 `setSubscriptionModelSource`로 등록한 읽기 함수)가 상태 서비스에 주고, 상태에 실려 같은 길로 간다. 에디터마다 따로 채널을 만들지 않는다. 핸들러가 없거나 답이 깨졌으면 연결이 아니라 `checking`으로 읽힌다. 실행 실패의 spawn 오류 문장은 실행 파일 경로를 담을 수 있어 판독 함수에서 버린다.
- `error` 상태의 문장은 `"<kind>: <코드에 적힌 영어 문장>"` 형식이다. 화면은 `subscriptionStatusErrorKind`로 종류만 읽어 번역한다.
- 종량 허용은 불리언만으로는 "그때 그 로그인"인지 알 수 없고, 누가 로그인했는지는 저장하면 안 된다. 그래서 동의한 로그인의 종류만 `subscription-metered.json`에 남긴다. 값은 `METERED_LOGIN_FINGERPRINTS` 상수 중 하나이고 프로그램 출력으로 조립하지 않는다. 종류가 바뀌거나 로그아웃하면 동의가 지워진다. 앱이 직접 로그인·로그아웃을 실행했을 때는 종류가 같아도 지운다. 앱 밖에서 같은 종류의 다른 계정으로 바꾼 경우는 알 수 없어 그대로 남는다.
- 설정을 읽는 문은 둘이다. 디스크의 파일은 `normalizeAiSettings`(절대 throw하지 않고, 모르는 id는 기본값으로 떨어진다), 렌더러가 보낸 값은 `sanitizeAiSettings`(모르는 제공자 id면 `null`). 설정 파일의 `cliPath`는 spawn으로, `baseUrl`은 API 키와 함께 나가므로 렌더러 값을 검사 없이 쓰지 않는다.
- 키 제공자를 추가하려면 `AiProviderId`(`src/types.ts`)에 id, `AI_PROVIDERS`에 메타, `AI_PROVIDER_ADAPTERS`에 어댑터를 넣는다. 표가 `Record<AiProviderId, …>`라 하나라도 빠지면 타입 오류다. 이미지 입력을 못 받는 모델 id는 `modelLacksVision`에 함께 넣는다.
- 진입점을 가려 쓴다. 렌더러와 preload가 값으로 import하는 것은 `/browser`뿐이고, 대표 진입점에서는 타입만 import한다(`contract.ts`가 타입만 import하는 이유다). `/subscription`, `/claude-code-cli`, `/codex-app-server`는 Node 전용이다. `/codex-image`는 비어 있고 `codexImageGenerationAvailable()`은 어느 프로세스에서도 `false`다. 이미지 생성은 지금 키 기반뿐이다.

## 테스트

- 실행: `npm run test -w @genoffice/ai-provider`(또는 이 폴더에서 `npx vitest run`), `npm run typecheck -w @genoffice/ai-provider`.
- 어떤 테스트도 실제 `claude`·`codex`에 닿으면 안 된다. 닿으면 개발자의 구독 사용량이 소모된다. 주입 지점을 쓴다: `ClaudeCodeCliDeps`(`spawn`, `resolveProgram`, `registry`, `killTree`), `setCodexAppServerRuntime`, 상태 확인의 `locate`·`run`·`detect`, 상태 서비스의 `listModels`, `setSubscriptionModelSource`, 로그아웃의 `locate`·`run`·`spawn`, IPC의 `resetSharedSubscriptionIpc`와 `SubscriptionIpcSetup`의 `detect`·`listModels`, 프로세스 조회의 `inspectProcesses` 두 번째 인자. `createSubscriptionIpcDeps`가 만든 로그인·로그아웃 실행부는 실제 프로그램을 찾아 띄우므로, 그것을 거치는 테스트는 `vi.mock('../src/subscription/launch')`로 실행부를 바꾼다(`tests/subscription-account-change.test.ts`). 라우터 테스트는 `vi.mock('../src/claude-code-cli')`로 브리지를 통째로 바꾼다.
- 바꾸면 반드시 테스트하는 것: 시작 인자(플래그 하나가 빠지면 사용자 hook·MCP가 들어온다), 환경에서 지우는 변수 목록, 0-도구 확인의 모든 거절 경로, 상태 파서에 "예상과 다른 형식"의 출력을 넣었을 때 조직 이름이 상태·오류 문장·동의 파일 어디에도 남지 않는지와 계정 이메일이 상태 밖 어디에도 쓰이지 않는지(`tests/subscription-identity.test.ts`), 모델 목록 읽기가 `initialize`만 보내고 프로세스를 끝내는지(`tests/claude-code-cli.test.ts`), 목록이 상태보다 늦게 오고 실패해도 상태가 그대로인지(`tests/subscription-models.test.ts`), 로그아웃이 셸 없이 정리된 환경으로 도는지(`tests/subscription-launch.test.ts`), `selectAiProvider`가 돈이 드는 경로를 스스로 고르지 않는지.
- 경계 사례: 재전송된 답(`message_start`가 두 번 오면 이미 내보낸 글자를 건너뛴다), `max_tokens`로 잘린 구조화 답, 코드 펜스로 감싼 JSON, 개행 없이 4MB를 넘는 줄, pid 재사용(시작 시각이 다르면 건드리지 않는다), 손상된 동의 파일.
- 에이전트 세션은 가짜 프로그램으로 시험한다(`tests/agent-session-claude.test.ts`, `tests/agent-session-codex.test.ts`). 주입 지점은 `ClaudeAgentDeps`·`CodexAgentDeps`의 `resolveProgram`, `spawn`, `registry`, `killTree`, `writeFile`이다. 실제 프로그램으로 확인한 것은 결정 0032와 `.dryforge/agent-mode/design.md`에 적었다.
- Windows에서 `tests/ai-settings-guard.test.ts`의 "keeps Windows-style paths with spaces and non-ASCII" 한 건은 변경과 무관하게 실패한다(임시 폴더 아래에 `C:\…` 경로를 이어 붙여 파일을 만들려다 ENOENT).
- 실제 프로그램에 대한 확인(플래그가 버전에서 유효한지, 실제 한도 이벤트의 모양)은 사용자 구독을 쓰므로 자동 테스트에 넣지 않는다. 최소 지원 버전은 `SUBSCRIPTION_MIN_VERSIONS`에 있고, 플래그를 추가하면 그 값도 함께 본다.
